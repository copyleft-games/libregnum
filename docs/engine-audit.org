#+title: Non-networking engine capability audit
#+date: 2026-09-18

* Scope and method

This is a source-level capability audit against common game-engine needs, not
an assertion that every engine needs every feature. Checked public APIs and
implementations in core, templates, input, audio, pathfinding, editor, assets,
and atlas packing. Networking and multiplayer are excluded. Existing roadmap
entries were checked against code rather than treated as proof of absence.
This pass implements reusable gameplay timers; larger independent systems below
remain explicit follow-up work.

* Implemented: gameplay timer manager

Added =LrgTimerManager= to the public library, installation/GIR inputs, and
forward declarations. It offers one-shot/repeating timers, scaled/unscaled
clock selection, per-timer pause/resume, cancellation, remaining-time queries,
and clear. Synchronous timeout delivery tolerates handler-driven changes and
protects the manager's lifetime. Repeats coalesce missed intervals while
preserving phase. Invalid deltas and recursive updates leave state unchanged.

Every game template owns a manager and advances it once per host frame; pause,
time scaling, hit stop, raw unscaled time, and shutdown are connected. Standalone
loops can drive isolated managers explicitly. Existing specialized counters are
retained because their persistence and update semantics differ.

See [[file:modules/core/timer-manager.org][timer API, examples, delivery rules, and tests]].

* Next priorities

Audio buses, navigation meshes, and atlas algorithms need independent API and
behavioral work; this change does not claim to implement them. Start with atlas
packing to fulfill existing advertised choices, then choose navigation/audio
based on the next game's requirements. Timer persistence would require a stable
application action identifier instead of attempting to serialize signal closures.

* Validation for this change

- Full headless =make test=: 88 test binaries, 2,582 passed cases and 125
  hardware/environment skips. Dependency directory overrides reused this
  checkout's graylib, yaml-glib, and crispy builds from the parent checkout.
- Static/shared library, loader, GIR, and typelib builds completed. Existing
  duplicate-comment and annotation warnings remain in unrelated GIR inputs;
  the new timer API passed a separate =--warn-all --warn-error= scanner run.
- All nine scheduler regressions passed ASan/UBSan with leak detection and
  Valgrind with no memory errors or definite leaks. The headless template
  integration scenario also passed Valgrind with no errors or definite leaks.
- Python GI constructed the manager, called its methods, and received timeout.
- New documentation links/source blocks and =git diff --check= passed.

The full engine sanitizer suite and hardware-dependent paths were not run.
No new external dependency or host package was installed.
