#+title: Non-networking engine capability audit
#+date: 2026-09-18

* Scope and method

This is a source-level capability audit against common game-engine needs, not
an assertion that every engine needs every feature. Checked public APIs and
implementations in core, templates, input, audio, pathfinding, editor, assets,
and atlas packing. Networking and multiplayer are excluded. Existing roadmap
entries were checked against code rather than treated as proof of absence.
The first pass implemented reusable gameplay timers. The follow-up pass implements
the three engine capabilities identified for further work: audio mixer buses,
triangle navigation meshes, and the advertised atlas packing algorithms.

* Implemented: gameplay timer manager

Added =LrgTimerManager= to the public library, installation/GIR inputs, and
forward declarations. It offers one-shot/repeating timers, scaled/unscaled
clock selection, per-timer pause/resume, cancellation, remaining-time queries,
and clear. Synchronous timeout delivery tolerates handler-driven changes and
protects the manager's lifetime. Repeats coalesce missed intervals while
preserving phase. Invalid deltas and recursive updates leave state unchanged.

Every game template owns a manager and advances it once per host frame; pause,
time scaling, hit stop, raw unscaled time, and shutdown are connected. Standalone
loops can drive isolated managers explicitly. Existing specialized counters are
retained because their persistence and update semantics differ.

See [[file:modules/core/timer-manager.org][timer API, examples, delivery rules, and tests]].

* Implemented follow-ups

- [[file:modules/audio/mixer.org][Audio mixer]]: named parent buses, cycle-checked post-fader sends, gain/mute,
  low-pass and feedback-delay processing, independently owned looping/pausable
  voices, format conversion, offline rendering, and a graylib stream pump.
- [[file:modules/pathfinding/nav-mesh.org][Navigation meshes]]: atomic walkable-triangle baking with slope filtering and
  shared-edge adjacency, nearest-surface projection, polygon blocking, and
  ordered-frontier A* returning a surface-contained waypoint corridor.
- [[file:modules/atlas/packing.org][Atlas algorithms]]: MaxRects and Guillotine implementations, candidate-bin
  search, rotation for all methods, padding/overflow safety, correct power-of-two
  limits, stale-result invalidation, and reproducible packing comparisons.

Application-specific asset migration and timer action persistence were design
ideas in the first audit, not part of these three capability implementations.
They require application contracts for replacing live objects and naming actions.
The limitations of each implemented capability are stated in its API guide.

* Additional audit: data-driven construction

The registry advertised automatic built-in registration, but its implementation
was a TODO and engine startup never invoked it. Implemented a deliberately
bounded, headless scene/definition catalog and connected startup to it. See
[[file:modules/core/registry.org][catalog, YAML example, overrides, and alias ownership]]. Regression tests load
every catalog entry through YAML and verify the engine's loader needs no manual
registration. Alias replacement/removal also now avoids dangling reverse names
and preserves other names for the same type.

Independent saveable random streams remain a useful future capability: the
engine currently combines global GLib random calls with subsystem-specific
opaque GRand instances. This pass does not change existing random sequences.
Live asset dependency propagation and application-specific object migration
also remain outside the implemented catalog.

Validation for the catalog pass: full headless =make test= passed 2,630 cases
with 125 skips across 93 binaries. All 18 registry tests passed ASan/UBSan
(leak detection enabled) and Valgrind (zero errors and definite leaks).
Static/shared libraries, loader, GIR, and typelib builds passed; existing GIR
warnings remain. A Python binding smoke test registered the catalog and loaded
a positioned game object; the environment emitted a graylib shared-library
lookup warning despite the successful assertions. Full-engine sanitizer and
hardware-dependent checks were not run. No new dependencies were introduced.

* Implemented: random state and asset dependency propagation

Added [[file:modules/core/random-stream.org][saveable random streams]] with stable PCG32 output, unbiased bounds,
53-bit unit doubles, versioned snapshots, and atomic restore. Save-context
round trips preserve the next draw. Existing subsystem random sequences remain

reloads. All affected definitions are validated before publication; replacement
signals let consumers reconnect their live references. Application-specific
live-object state migration remains an application responsibility, as documented.

* Additional audit: save format compatibility

Save contexts stored a version and the error enum included a version-mismatch
code, but the manager did not enforce compatibility before calling gameplay
load methods. Version parsing also truncated integers and treated malformed or
zero values as legacy version 1. Implemented strict positive decimal parsing
and a pre-load rejection of formats newer than the manager's save version.
Older formats remain available for application-specific per-object migrations.
See [[file:modules/save/index.org][save compatibility and error behavior]].

Validation: full headless =make test= passed 2,642 cases with 125 skips across
95 binaries. All 23 save tests passed ASan/UBSan with leak detection and
Valgrind with zero errors and definite leaks. Static/shared library, loader,
GIR, and typelib builds passed; existing unrelated GIR warnings remain.
Full-engine sanitizer and hardware checks were not run. No dependency added.

* Additional audit: physics collision filtering

Rigid-body physics checked every eligible overlapping pair without layer/mask
filtering. Added 32-bit =collision-layer= and =collision-mask= properties and
public accessors, plus a symmetric =can_collide()= predicate. Simulation now
filters before overlap tests for solids and triggers. Defaults preserve existing
pairs; spatial queries remain independent. See
[[file:modules/physics/rigid-body.org][physics filter semantics and examples]]. Tests cover default/high/multiple bits,
zero filters, asymmetric acceptance, YAML properties, change notifications,
runtime re-enabling, trigger contacts, and query independence.

Validation: full headless =make test= passed 2,646 cases with 125 skips across
95 binaries. All 51 physics tests passed ASan/UBSan with leak detection and
Valgrind with zero errors or definite leaks. Five Python binding regressions
passed, including high-bit collision properties. Library, loader, GIR, and
typelib builds passed; existing unrelated GIR warnings remain. Full-engine
sanitizer and hardware checks were not run. No new dependency was introduced.
