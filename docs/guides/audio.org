** Signal path
:PROPERTIES:
:CUSTOM_ID: signal-path
:END:
#+begin_example
LrgAudioSourceComponent (bus: "sfx")                        sound banks, music
   | wave, gain x pan x pitch x occlusion low-pass               |
   v                                                             v
LrgAudioMixer:  sfx --+--> master --> GrlAudioStream ----> device mix <-- GrlSound voices
                      | (send)            ^ lrg_audio_manager_update() pumps it
                verb -+
#+end_example

A source with a bus (and a mixer on the manager) plays through the game mixer: its voice is spatialised in the mixer (gain, balance, pitch, a low-pass when occluded) and summed into its bus, then through effects, faders, ducking and sends to master; the manager feeds master to the device through a stream. Sources without a bus, sound-bank one-shots and music play as device voices beside the mixer, still spatialised by the component.

** Setting up a project mix
:PROPERTIES:
:CUSTOM_ID: project-mix
:END:
1. Write =audio/main.rmixer= (by hand or with the editor's mixer panel):

   #+begin_src yaml
   version: 1
   buses:
   - name: music
     volume: -6
   - name: sfx
     sends:
     - target: verb
       level: -14
   - name: dialogue
   - name: verb
     effects:
     - type: reverb
       params:
         preset: stone-room
   snapshots:
   - name: paused
     blend: 0.3
     volumes:
       sfx: -144
       music: -14
   ducking:
   - trigger: dialogue
     target: music
     threshold: -35
     depth: -9
     attack: 0.04
     release: 0.6
   #+end_src

2. Name it in =project.ryaml= (root level or inside =project:=):

   #+begin_src yaml
   audio:
     mixer: audio/main.rmixer
   #+end_src

3. At startup build the game mixer from it, and keep the layout for snapshots:

   #+begin_src c
   LrgAudioManager         *audio = lrg_audio_manager_get_default ();
   g_autoptr(LrgMixerAsset) mix = lrg_mixer_asset_new_for_project (level_path, NULL);

   lrg_audio_manager_load_project_mixer (audio, level_path, 48000, &error);
   #+end_src

4. Every frame call =lrg_audio_manager_update()=: it re-spatialises device voices, pumps the mixer into its stream (once an audio device is open) and drives music crossfades.

5. On game-state changes ramp the mix: =lrg_mixer_asset_apply_snapshot (mix, lrg_audio_manager_get_mixer (audio), "paused", -1.0, NULL)=, and =NULL= to come back.

=lrg_mixer_asset_find_project_mixer()= returns the resolved =.rmixer= path; a project without =audio.mixer= leaves the manager without a mixer (not an error), and every source then plays as a device voice.

** Spatial sources
:PROPERTIES:
:CUSTOM_ID: spatial
:END:
Put an =LrgAudioListenerComponent= on the camera (or player) and an =LrgAudioSourceComponent= on each emitter. Levels do this for you: AUDIO_EMITTER nodes become source components (their visual params map to properties by name). Per source:

- *Distance*: =min-distance=, =max-distance= and a =rolloff-mode=: linear, inverse (the default, steepness =rolloff=), logarithmic, or a custom =LrgKeyframeCurve= over normalised distance (=lrg_audio_source_component_set_rolloff_curve()=, or =rolloff-curve-keys: "0:1, 0.3:0.5, 1:0"= in a level). The pure function is =lrg_audio_rolloff_evaluate()=.
- *Direction*: =cone-inner-angle=, =cone-outer-angle=, =cone-outer-gain= around the entity's forward (-Z) (=lrg_audio_cone_gain()=).
- *Doppler*: =doppler-factor= and =speed-of-sound=; velocities come from movement between late updates (=lrg_audio_doppler_pitch()=).
- *Occlusion*: =occlusion= casts a ray through the world's physics each late update; each body between the listener and the source multiplies the gain by =occlusion-gain= and muffles mixer voices with =occlusion-cutoff=.
- *Routing*: =bus= picks the mixer bus (=sfx=, =ambience=...); =spatial-blend= 0 makes it a flat 2D sound.

=lrg_audio_source_component_evaluate()= computes the result for any listener without a device, which is how tests and tools check a source; =lrg_audio_source_component_debug_draw()= draws its attenuation gizmo.

** Headless and tests
:PROPERTIES:
:CUSTOM_ID: headless
:END:
Nothing above needs an audio device. Mixers render offline (=lrg_audio_mixer_render()=), the manager only opens a stream when raylib's device is already open, and sources can be pointed at an explicit =mixer= and =wave=. =tests/test-mixer-asset.c= builds a world, a private =LrgAudioManager= (=g_object_new (LRG_TYPE_AUDIO_MANAGER, NULL)=), a mixer and a source, moves entities and checks rendered samples against the analytic gains.

:PROPERTIES:
:CUSTOM_ID: manager
:END:
=LrgAudioManager= (=lrg_audio_manager_get_default()=) is the process-wide hub. Call =lrg_audio_manager_update()= once per frame.

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:
The mixer renders 2048 frames at 48 kHz stereo (4 buses, 32 voices, a low-pass, a reverb, a send and a ducking rule) in about 0.39 ms on one i7-1280P core (=taskset=, [[file:../modules/audio/mixer-asset.org::#performance][details]]). A spatial source costs one evaluation (a few square roots and an =acos=) per late update, plus one physics ray when =occlusion= is on; spatial mixer voices take the per-frame mixing path (about ten times a plain voice). Keep occlusion for sources that matter and give far sources a =max-distance=.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- A =bus= without a manager mixer (no project =audio.mixer=) falls back to a device voice; an unknown bus name plays nothing.
- Mixer voices need decodable sample files (=LrgWaveData=); a bank entry plays through the mixer only when its manifest file can be found (relative to the bank's base path).
- Doppler measures velocity from movement: teleporting an entity produces one frame of extreme pitch, clamped to 0.125 .. 8. Set =doppler-factor= 0 on sources that teleport, or move them before =play()=.
- The listener component must run its late update before sources read the listener; it is the camera's or player's entity, normally updated first. =lrg_audio_listener_component_sync()= pushes the pose at once.
- Everything audio is single-threaded on the game thread.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: editor
:END:
AUDIO_EMITTER nodes carry the source properties as visual params (=bus=, =rolloff_mode=, =rolloff_curve_keys=, =cone_inner_angle=, =occlusion=...). In lrgeditor ([[file:../editor/audio.org][Audio in the Editor]]):

- Selecting an emitter shows its *attenuation gizmo* in the viewport (min and max distance spheres, the half-volume ring, the sound cones) with drag handles for the distances and cone angles, and the inspector's *Audio Source* section (every source setting with the runtime's defaults, a gain-over-distance plot from =lrg_audio_source_component_get_distance_gain()=, a curve editor for the custom rolloff and a bus picker listing the project mixer's buses).
- The *mixer editor* edits =.rmixer= files (strips, effects, sends, snapshots, ducking, offline preview with meters) and the *Mixer panel* shows the project mixer, metering the game's mixer while play-in-editor runs (it loads the project mixer into the audio manager when play starts).
- =mixer.*= and =audio.*= IPC methods script all of it.
