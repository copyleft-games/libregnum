* Built-in Effects
:PROPERTIES:
:CUSTOM_ID: built-in-effects
:END:
Every built-in effect is an [[file:post-effect.org][LrgPostEffect]] that runs as a real shader pass in an [[file:post-processor.org][LrgPostProcessor]] chain, compiles its GLSL 330 shader lazily on its first pass (or in a prewarm: they all implement =LrgPrewarmable=), and mixes its result with its input by the base intensity (=lrg_post_effect_set_intensity()=, a stack's =weight=). *** How it renders
:PROPERTIES:
:CUSTOM_ID: bloom-algorithm
:END:
A progressive mip chain, in the effect's own render targets (RGBA16F when possible):
1. *Prefilter* the source into level 0 at half resolution (quarter at the low tier): four bilinear taps averaged, then a soft-knee threshold on the brightest channel: =w = max(soft, l - threshold) / l=, =soft = clamp(l - threshold + knee, 0, 2 knee)^2 / (4 knee)=, =knee = threshold * soft-knee=.
2. *Downsample* level /i-1/ into level /i/ (half size each): centre x4 plus four diagonal taps, /8.
3. *Upsample* from the smallest level back to level 0, adding (additive blending) a 9-tap tent of radius =blur-size= / 4 texels onto each larger level, so wide and tight halos add up.
4. *Composite* into the processor's target: =source + level0 / levels * intensity * tint * base intensity=.

The number of levels is =iterations= capped by the quality tier (low 3, medium 4, high 6, ultra 8) and by the image size (a level stops at 2 pixels). More levels make a wider, softer glow; =blur-size= widens each tap.

*** Parameters (.rpost)
:PROPERTIES:
:CUSTOM_ID: bloom-params
:END:
| Property | Range | Default | Look |
|----------+-------+---------+------|
| =threshold= | 0..10 | 0.8 | Brightness where the glow starts (0 blooms everything) |
| =soft-knee= | 0..1 | 0.5 | 0 = hard cut at the threshold, 1 = gradual |
| =intensity= | 0..5 | 1 | Glow strength |
| =blur-size= | 1..20 | 4 | Tap spread of the upsample (4 = one texel) |
| =iterations= | 1..8 | 3 | Mip levels (capped by the tier) |
| =tint-r/g/b= | 0..1 | 1 | Glow colour (=tint: [r, g, b]=) |

*** The curve
:PROPERTIES:
:CUSTOM_ID: tonemap-curve
:END:
Per channel: decode =x = c^2.2= (skipped when =linear-input=), =x *= 2^exposure=, map, clamp to 0..1, encode =m^(1/2.2)=, mix with the input by the base intensity. =lrg_tonemap_apply_rgb()= is the same arithmetic on the CPU (the GPU test compares both).
| Operator | Formula | Look |
|----------+---------+------|
| =none= | =x= | Hard clip; exposure only |
| =reinhard= | =x (1 + x / W^2) / (1 + x)= | Soft, low contrast, desaturates highlights; white at W |
| =filmic= | =h(2x) / h(W)=, =h(x) = (x(Ax+CB)+DE)/(x(Ax+B)+DF) - E/F=, A .15 B .5 C .1 D .2 E .02 F .3 | Toe in the shadows, long shoulder; white at W |
| =aces= | =x (2.51x + .03) / (x (2.43x + .59) + .14)= | Punchy contrast and saturation (the default) |

The engine's shaders write gamma-encoded colour (the lit shader decodes and re-encodes), so the default =linear-input: false= decodes first and the curves act on linear light. Mid grey at exposure 0 comes out darker with ACES than without a tonemap; raise =exposure= to compensate.

:PROPERTIES:
:CUSTOM_ID: tonemap-params
:END:
| Property | Range | Default | Look |
|----------+-------+---------+------|
| =operator= | none, reinhard, filmic, aces | aces | Curve |
| =exposure= | -16..16 | 0 | Stops before the curve |
| =white-point= | 0.1..100 | 4 | Linear value that reaches white (reinhard, filmic) |
| =linear-input= | bool | false | The image already holds linear light |

*** The grade
:PROPERTIES:
:CUSTOM_ID: the-grade
:END:
The grade is a GLSL 330 fragment shader for raylib's default vertex shader; =lrg_color_grade_apply_rgb()= is the same arithmetic on the CPU (the reference the tests check, and a way to grade colours a game draws itself, such as a clear colour).  The steps, in order, for each channel of a colour in 0 .. 1:

1. exposure: times 2^exposure (one stop doubles);
2. white balance: red times 1 + 0.2 temperature, blue times 1 - 0.2 temperature, green times 1 - 0.2 tint (multiplicative, so black stays black);
3. lift: added, then clamped at 0;
4. gamma and gain: =pow(c, 1 / gamma) * gain= (gamma above 1 brightens the midtones and keeps black and white);
5. contrast around 0.5;
6. saturation: mixed against the Rec. 709 luminance (0 is grey, 1 unchanged);
7. clamped to 0 .. 1, then mixed with the original by the effect's intensity.

=lrg_color_grade_is_identity()= is true for the neutral parameters (exposure 0, contrast 1, saturation 1, temperature 0, tint 0, lift 0, gamma 1, gain 1) or an intensity of 0; =lrg_color_grade_draw_texture()= then draws the texture plainly, without a shader pass.

The shader is compiled on first use (=lrg_color_grade_get_shader()=, %NULL without a window or when GLSL 330 does not compile; drawing then falls back to the plain texture and =lrg_color_grade_draw_texture()= returns =FALSE=).  As an =LrgPostEffect=, =apply= draws the source texture over the bound target through the shader.  A game without a post processor draws its 3D pass into a =GrlRenderTexture= and calls =lrg_color_grade_draw_texture()= with a negative source height (render textures are stored bottom up).

*** Lookup tables
:PROPERTIES:
:CUSTOM_ID: color-grade-lookup-tables
:END:
=lrg_color_grade_set_lut (grade, lut, strength)= adds a 3D lookup table ([[file:color-lut.org][LrgColorLut]]) after the grade's steps: the shader looks the graded, clamped colour up in the table (uploaded as a strip texture on unit 1 when it changes) and mixes it in by =strength=, before the effect's intensity; =lrg_color_grade_apply_rgb()= does the same on the CPU. A grade with a table is never the identity. =lrg_color_grade_bake_lut (grade, size)= samples the whole grade into a new table, e.g. to blend two grades or save one as a =.cube= file.

One pass: the luma of the centre and four diagonal neighbours; pixels whose local contrast is below =max(edge-threshold-min, max_luma * edge-threshold)= are left alone. | =edge-threshold= | 0..0.5 | 0.166 | Contrast (relative) an edge needs; lower catches more |
| =edge-threshold-min= | 0..0.1 | 0.0833 | Ignores edges in dark areas below this |

=update()= decays trauma (=decay= per second), and computes this frame's offset and rotation: =trauma^2 * max * noise(time * frequency)=, with smooth 1D value noise (a different seed per axis) so the image sways rather than jitters. =apply()= calls =update()= itself with the frame's delta unless the game already called it since the last pass (calling both does not double the decay). The pass samples the source rotated about the centre in pixel space and shifted, zoomed in just enough (overscan) to keep the borders off screen; at trauma 0 it is a plain copy. Offsets and rotation are scaled by the base intensity (a "reduce screen shake" accessibility option can set it).

| Trauma | Shake |
|--------+-------|
| 0.0 | 0% |
| 0.5 | 25% |
| 0.7 | 49% |
| 1.0 | 100% |

| Property | Range | Default | Look |
|----------+-------+---------+------|
| =trauma= | 0..1 | 0 | Current shake (usually set from code) |
| =decay= | 0..10 | 1 | Trauma lost per second |
| =frequency= | 0.1..50 | 15 | Sway speed |
| =max-rotation= | 0..45 | 5 | Degrees at full trauma |
| =max-offset-x=, =max-offset-y= | >= 0 | 20, 15 | Pixels at full trauma |

*** Example
:PROPERTIES:
:CUSTOM_ID: example-5
:END:
#+begin_src C
g_autoptr(LrgScreenShake) shake = lrg_screen_shake_new ();
lrg_screen_shake_set_max_offset (shake, 15.0f, 15.0f);
lrg_screen_shake_set_decay (shake, 2.0f);       /* full trauma gone in 0.5 s */
lrg_post_processor_add_effect (post, LRG_POST_EFFECT (shake));

lrg_screen_shake_add_trauma (shake, 0.8f);
#+end_src

** LrgHeatHaze
:PROPERTIES:
:CUSTOM_ID: lrgheathaze
:END:
A shimmering distortion in a band about the horizon, for hot air over sand and stone (=postprocess/effects/lrg-heat-haze.h=).

#+begin_src C
G_DECLARE_FINAL_TYPE (LrgHeatHaze, lrg_heat_haze, LRG, HEAT_HAZE, LrgPostEffect)

LrgHeatHaze *lrg_heat_haze_new          (void);
void         lrg_heat_haze_set_strength (LrgHeatHaze *self, gfloat strength);   /* 0 .. 0.05 of the screen */
gfloat       lrg_heat_haze_get_strength (LrgHeatHaze *self);
void         lrg_heat_haze_set_shape    (LrgHeatHaze *self, gfloat scale, gfloat speed,
                                         gfloat horizon, gfloat band);
void         lrg_heat_haze_set_time     (LrgHeatHaze *self, gfloat time);
void         lrg_heat_haze_get_offset   (LrgHeatHaze *self, gfloat u, gfloat v,
                                         gfloat *out_du, gfloat *out_dv);
gboolean     lrg_heat_haze_is_identity  (LrgHeatHaze *self);
gboolean     lrg_heat_haze_draw_texture (LrgHeatHaze *self, GrlTexture *texture,
                                         const GrlRectangle *source, const GrlRectangle *dest);
#+end_src

Each pixel samples its source shifted by two crossed sine ripples (rising with time) times a band weight exp(-d^2 k), d = (v - horizon) / band, with k = 2.5 above the horizon line (thin air) and 0.6 below (the hot ground); the vertical shift is half the horizontal. The shader reads the screen height from =gl_FragCoord=, so the band does not depend on how the source is flipped; =get_offset()= is the same arithmetic on the CPU, scaled by the effect's intensity. In a post processor =apply()= also advances the time by the frame's delta; =draw_texture()= draws one texture through the haze (plainly without a shader), as =LrgColorGrade='s does.

| Property | Range | Default | Look |
|----------+-------+---------+------|
| =strength= | 0..0.05 | 0.004 | Peak shift as a fraction of the screen |
| =scale= | > 0 | 9 | Ripple frequency |
| =speed= | any | 2.2 | Rise speed |
| =horizon= | 0..1 | 0.55 | Band centre (0 bottom, 1 top) |
| =band= | > 0 | 0.18 | Band half height |
