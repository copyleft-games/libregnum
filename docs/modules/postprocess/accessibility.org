** The matrices
:PROPERTIES:
:CUSTOM_ID: the-matrices
:END:
The filter is a single 3x3 matrix applied in linear light: the colour is raised to the power 2.2, multiplied, clamped to 0 .. 1 and taken back with the power 1 / 2.2, then mixed with the original by the effect's intensity (=lrg_post_effect_set_intensity()=).  The GLSL 330 shader (uniforms =row0=, =row1=, =row2=, =intensity=) and =lrg_colorblind_filter_apply_rgb()= run the same steps, so tests check the CPU reference and games may filter colours they draw themselves (UI fills and text).

- Simulation uses the full-severity matrices of Machado, Oliveira and Fernandes, "A Physiologically-based Model for Simulation of Color Vision Deficiency" (2009) for protanopia, deuteranopia and tritanopia; achromatopsia puts the Rec. 709 luminance on every channel.
- Correction is daltonization: the error a viewer cannot see, =I - S=, is shifted into channels they still tell apart, =M = I + D (I - S)=.  For protanopia and deuteranopia =D= moves the error into green and blue (rows =0 0 0=, =0.7 1 0=, =0.7 0 1=), for tritanopia into red and green (=1 0 0.7=, =0 1 0.7=, =0 0 0=).  Achromatopsia has no channel left: its correction is the identity.
- The strength mixes the matrix with the identity, =I + strength (M - I)=.

White and black stay themselves under every matrix (each row sums to 1).  =lrg_colorblind_filter_is_identity()= is true for no type, a strength or intensity of 0, and corrected achromatopsia; a game may skip the pass then.  =lrg_colorblind_filter_draw_texture()= draws a texture (a render texture's colour attachment) through the shader into the current target, plainly when the filter is the identity or no shader compiled.

Tests: =tests/test-accessibility-filters.c= (the identity cases, white and black, the simulations of the primaries worked by hand, half strength, correction separating red from green and blue from teal as the viewer sees them).

** Usage
:PROPERTIES:
:CUSTOM_ID: usage
:END:
*** Accessibility Option
:PROPERTIES:
:CUSTOM_ID: accessibility-option
:END:
Add a colorblind option to your game settings:

#+begin_src C
static LrgColorblindFilter *cb_filter = NULL;

void
init_accessibility (void)
{
    cb_filter = lrg_colorblind_filter_new ();
    lrg_colorblind_filter_set_mode (cb_filter, LRG_COLORBLIND_MODE_CORRECT);
    lrg_post_processor_add_effect (processor, LRG_POST_EFFECT (cb_filter));

    /* Start disabled */
    lrg_post_effect_set_enabled (LRG_POST_EFFECT (cb_filter), FALSE);
}

void
on_colorblind_setting_changed (LrgColorblindType type)
{
    if (type == LRG_COLORBLIND_NONE)
    {
        lrg_post_effect_set_enabled (LRG_POST_EFFECT (cb_filter), FALSE);
    }
    else
    {
        lrg_colorblind_filter_set_filter_type (cb_filter, type);
        lrg_post_effect_set_enabled (LRG_POST_EFFECT (cb_filter), TRUE);
    }
}
#+end_src

** Design Tips for Colorblind Accessibility
:PROPERTIES:
:CUSTOM_ID: design-tips-for-colorblind-accessibility
:END:
1. *Don't rely on color alone* - Use shapes, patterns, or icons alongside color
2. *Test with simulation mode* - See your game through colorblind eyes
3. *Use high contrast* - Ensure important elements are distinguishable
4. *Consider deuteranopia first* - It's the most common type (~6% of males)

** Common Color Confusions
:PROPERTIES:
:CUSTOM_ID: common-color-confusions
:END:
| Type          | Confused Colors                      |
|---------------+--------------------------------------|
| Deuteranopia  | Red/green, orange/green, brown/green |
| Protanopia    | Red/green, red/black, purple/blue    |
| Tritanopia    | Blue/green, yellow/pink              |
| Achromatopsia | All colors appear as grayscale       |
