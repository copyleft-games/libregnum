* LrgDebugDraw - Immediate-Mode Debug Geometry
:PROPERTIES:
:CUSTOM_ID: lrgdebugdraw
:END:
=LrgDebugDraw= is the engine's shared debug-geometry batch: any code (gameplay, physics, navigation, lights, audio, AI, the editor) records shapes into it with one call per shape, and the frame's render code draws everything in a handful of GL draw calls. It is the API the physics debug draw, nav-agent debug draw and the editor's light-range / camera-frustum / collider gizmos build on.

- Lines, polylines, arrows, axis-aligned and oriented boxes, spheres, capsules, cylinders, cones, frustums (from a view-projection or an =LrgCamera3D=), grids, transform axes, circles, points and screen-facing 3D text labels; plus 2D lines, rectangles, circles and text.
- Per primitive: colour, line thickness, a duration (one frame, or N seconds ticked by delta time), a depth-tested or always-on-top list, a solid flag (filled with alpha) and a category.
- Categories (physics, navigation, lights, audio, ai, animation, camera, particles, editor, user …) are 32 toggles, so the editor can show one switch per channel.
- A process-wide default instance (=lrg_debug_draw_get_default()=) plus any number of private instances (one per world or per editor viewport).
- Recording never needs a graphics context; tests inspect what was recorded and the CPU tessellation. Drawing without a context is a no-op.

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:
*** Recording, tessellation and drawing
:PROPERTIES:
:CUSTOM_ID: recording-tessellation-and-drawing
:END:
A recording call stores one primitive (shape, control points, the current pen, colour, lifetime) in an array: no GL, no allocation beyond the array growth (polylines and text copy their data). Before a draw (or an inspection query) the visible primitives are tessellated on the CPU into flat lists: segments and triangles for the depth-tested list, segments and triangles for the always-on-top list, 3D labels, and the 2D segments, triangles and texts. The tessellation is cached and only rebuilt after something changed.

=lrg_debug_draw_draw_3d()= submits each 3D list as at most one =GL_LINES= run and one =GL_TRIANGLES= run through rlgl's batch: a frame of debug geometry costs at most four runs whatever the number of shapes (rlgl splits a run only when its vertex buffer fills, 8192 quads' worth). =lrg_debug_draw_get_draw_calls()= reports the runs of the last draw.

*** The pen
:PROPERTIES:
:CUSTOM_ID: the-pen
:END:
State applied to the primitives recorded next, so recording calls stay short: category (=set_category()=), depth test (=set_depth_test()=), thickness (=set_thickness()=), solid (=set_solid()=), segments per circle (=set_segments()=) and text size (=set_text_size()=). =lrg_debug_draw_push()= / =lrg_debug_draw_pop()= save and restore it (16 levels), so a subsystem can switch to its category and colours without disturbing the caller.

*** Durations
:PROPERTIES:
:CUSTOM_ID: durations
:END:
Every recording call takes a =duration= in seconds:
- =0= (or negative): *one frame*. The primitive is drawn by the next draw and removed by =lrg_debug_draw_end_frame()= (which =lrg_debug_draw_flush()= calls after drawing). Ticks never remove it.
- => 0=: *timed*. =lrg_debug_draw_tick()= subtracts the frame's delta; the primitive is removed once its time is used up. Use this for events (a raycast hit, a contact) that should stay visible for a moment.

The usual frame is: =tick (delta)= in update, record during update/fixed update, =flush (camera)= in render.

*** Depth-tested and always-on-top lists
:PROPERTIES:
:CUSTOM_ID: depth-tested-and-always-on-top-lists
:END:
With the pen's depth test on (default), primitives are hidden by scene geometry already in the depth buffer. With it off they go to the always-on-top list, drawn after the depth-tested list with =GL_DEPTH_TEST= disabled. 3D labels are always on top.

*** Solid shapes
:PROPERTIES:
:CUSTOM_ID: solid-shapes
:END:
With the pen's solid flag, boxes, oriented boxes, spheres, capsules, cylinders, cones, circles and 2D rectangles/circles are filled with triangles instead of outlined. A list holding any colour with alpha below 255 is drawn with depth writes off, so translucent volumes (a trigger, a light radius) do not hide what lies behind them. Back-face culling is off for debug triangles. Lines, arrows, grids, axes, frustums, points and text ignore the flag.

*** Line thickness and GL 3.3 core
:PROPERTIES:
:CUSTOM_ID: line-thickness-and-gl-3-3-core
:END:
A GL 3.3 core (forward-compatible) context only guarantees a line width of 1: =glLineWidth()= above 1 is an error there, and drivers that accept it draw inconsistently. =LrgDebugDraw= therefore never calls =glLineWidth()=:
- thickness =<= 1=: GL lines (one pixel);
- thickness => 1=: each segment becomes a camera-facing quad, two triangles, widened at each end to cover =thickness= pixels at that end's depth (=2 * depth / (projection[5] * target height)= world units per pixel in perspective, =2 / (projection[5] * height)= in orthographic). Wide lines therefore keep their pixel width at any distance and work on every driver.

Thickness is clamped to 0.5 .. 64 pixels. 2D wide lines are quads perpendicular on screen.

*** Categories
:PROPERTIES:
:CUSTOM_ID: categories
:END:
=LrgDebugDraw:category-mask= holds one bit per category. A primitive recorded on a disabled category is dropped at once (so a switched-off channel costs one bit test per call); timed primitives recorded earlier stay but are not drawn until the category comes back (they keep ticking). Expensive producers test =lrg_debug_draw_is_category_enabled()= before walking their data. =LrgDebugDraw:enabled= = =FALSE= turns the whole batch off and clears it.

*** Default and per-world instances
:PROPERTIES:
:CUSTOM_ID: default-and-per-world-instances
:END:
=lrg_debug_draw_get_default()= is created on first use and lives for the process: code without a better place records there. A world (=LrgWorld3D= from 0.9.0 M1, a physics world, a level) or an editor viewport can own its own instance from =lrg_debug_draw_new()= so its geometry is flushed with its own camera and cleared with it.

*** Recording functions in detail
:PROPERTIES:
:CUSTOM_ID: recording-functions-in-detail
:END:
- =lrg_debug_draw_line()=: one segment.
- =lrg_debug_draw_polyline()=: copies =n_points= points (fewer than 2: ignored); =closed= adds the segment from the last point back to the first.
- =lrg_debug_draw_arrow()=: the shaft plus four barbs at =to=, each =head_size= long and half as wide; =head_size <= 0= uses a fifth of the arrow's length.
- =lrg_debug_draw_box()=: an axis-aligned box from =min= to =max= (12 edges, or 12 triangles solid).
- =lrg_debug_draw_oriented_box()=: a box of =half_extents= centred on the origin of a column-major =transform= (rotation, translation and scale all apply), e.g. an =LrgEntity3D= world matrix and its collider's extents.
- =lrg_debug_draw_sphere()=: wire = three great circles (XY, XZ, YZ planes); solid = two latitude/longitude domes.
- =lrg_debug_draw_capsule()=: hemisphere centres =a= and =b= and the radius (a physics capsule's segment). Wire = both equators, four side lines and two half circles per cap; solid = a band plus two domes.
- =lrg_debug_draw_cylinder()=: cap centres =a=, =b= (wire: both rims and four side lines; solid: band and two discs).
- =lrg_debug_draw_cone()=: =apex= and =base= centre (a spot light from its position to its range along its direction, with the radius =range * tan (outer angle)=).
- =lrg_debug_draw_frustum()=: the 12 edges of the volume a column-major *projection x view* matrix maps onto the clip cube; a singular matrix is ignored.
- =lrg_debug_draw_camera_frustum()=: builds that matrix from an =LrgCamera3D='s position, target, up, field of view and projection (orthographic cameras use =fovy= as the view height, as raylib does). =aspect <= 0= uses =LrgCamera3D:aspect=, else 16:9; =near_plane <= 0= / =far_plane <= near_plane= use rlgl's cull distances (0.05 / 4000 by default).
- =lrg_debug_draw_grid()=: =cells= x =cells= squares of =spacing= in the XZ plane through =center= (=cells + 1= lines each way).
- =lrg_debug_draw_axes()=: the transform's X, Y and Z columns (normalised, so scale does not matter) =size= long from its origin, in red, green and blue. Takes no colour.
- =lrg_debug_draw_circle()=: around a normal (zero normal: +Y).
- =lrg_debug_draw_point()=: a three-axis cross of =size= (GL points are not sized reliably on GL 3.3 core).
- =lrg_debug_draw_text()=: a label centred over a 3D anchor at the pen's text size, projected with the matrices of the last 3D draw; anchors behind the camera are skipped.
- 2D calls record in whatever 2D space the 2D draw runs in: screen pixels for =flush (NULL)= or after a 3D flush, the 2D camera's world for =flush (camera2d)=.

*** Drawing functions in detail
:PROPERTIES:
:CUSTOM_ID: drawing-functions-in-detail
:END:
- =lrg_debug_draw_draw_3d()=: call inside an open 3D mode (=BeginMode3D()=, =lrg_camera_begin()=, an editor viewport's camera), at its top level: rlgl moves a modelview pushed with =rlPushMatrix()= into a CPU-side transform the batch cannot read back, which would break wide lines and labels. Draws the depth-tested list, then the always-on-top list, then turns the depth test back on (a 3D mode runs with it on). Captures the modelview, projection and target size for the labels.
- =lrg_debug_draw_draw_labels()=: after the 3D mode, projects the labels with the captured matrices and draws them with raylib's default font. Nothing before the first =draw_3d()=.
- =lrg_debug_draw_draw_2d()=: the 2D segments, triangles and texts in the current 2D space.
- =lrg_debug_draw_flush()=: the whole frame for a camera. An =LrgCamera3D=: =lrg_camera_begin()=, =draw_3d()=, =lrg_camera_end()=, =draw_labels()=, =draw_2d()= in screen space. Any other camera (=LrgCamera2D= and subclasses): =draw_2d()= inside it, nothing 3D. =NULL=: =draw_2d()= in screen space. Then =end_frame()=; headless only the frame ends.
- =lrg_debug_draw_flush_matrices()=: as =flush()= with a 3D camera, from a column-major view and projection matrix (loads them as =BeginMode3D()= would and restores 2D afterwards). Call outside any 3D mode, e.g. inside =BeginTextureMode()= for an editor viewport.
- One batch drawn into several viewports: call =draw_3d()= / =draw_labels()= per viewport and =end_frame()= once.

*** Inspection
:PROPERTIES:
:CUSTOM_ID: inspection
:END:
Primitives are indexed in recording order (removals keep the order). Out-of-range indices return zero values / =FALSE= / =NULL=. =lrg_debug_draw_get_primitive_remaining()= is 0 for one-frame primitives. =lrg_debug_draw_get_line_count()= / =lrg_debug_draw_get_triangle_count()= tessellate the visible primitives exactly as the next draw will and count one list (wide lines are counted as segments, before they become quads); =lrg_debug_draw_get_label_count()= counts visible 3D labels. Expected sizes with the default 16 segments: line 1, arrow 5, box 12 (solid 12 triangles), sphere 48 (solid 224 triangles), capsule 68, cylinder 36, cone 20 (solid 32 triangles), frustum 12, grid of /n/ cells 2(n+1), axes 3, circle 16, point 3.

*** A game frame
:PROPERTIES:

#+begin_src C
static void
game_frame (GrlWindow   *window,
            LrgCamera3D *camera,
            gfloat       delta)
{
	LrgDebugDraw *dd;
	GrlVector3    origin = { 0.0f, 0.0f, 0.0f };
	GrlVector3    target = { 2.0f, 1.0f, 0.0f };
	GrlColor      yellow = { 253, 249, 0, 255 };

	dd = lrg_debug_draw_get_default ();

	/* update: age timed primitives, then record this frame's */
	lrg_debug_draw_tick (dd, delta);
	lrg_debug_draw_grid (dd, &origin, 1.0f, 20, &(GrlColor){ 80, 80, 80, 255 }, 0.0f);
	lrg_debug_draw_arrow (dd, &origin, &target, 0.0f, &yellow, 0.0f);
	lrg_debug_draw_text (dd, &target, "target", &yellow, 0.0f);

	/* render: after the scene, so depth-tested lines sit in it */
	grl_window_begin_drawing (window);
	/* ... draw the scene with camera ... */
	lrg_debug_draw_flush (dd, LRG_CAMERA (camera));
	grl_window_end_drawing (window);
}

#+begin_src C
/* physics_debug_draw:
 * Draws every body of a physics world on the physics channel, solid and
 * translucent, plus contacts that stay visible half a second. */
static void
physics_debug_draw (LrgDebugDraw *dd,
                    MyBody       *bodies,
                    guint         n_bodies,
                    MyContact    *contacts,
                    guint         n_contacts)
{
	GrlColor body = { 0, 200, 255, 60 };
	GrlColor hit = { 255, 40, 40, 255 };
	guint    i;

	/* skip the whole walk when the channel is off */
	if (!lrg_debug_draw_is_category_enabled (dd, LRG_DEBUG_CATEGORY_PHYSICS))
		return;

	lrg_debug_draw_push (dd);
	lrg_debug_draw_set_category (dd, LRG_DEBUG_CATEGORY_PHYSICS);
	lrg_debug_draw_set_solid (dd, TRUE);
	for (i = 0; i < n_bodies; i++)
		lrg_debug_draw_capsule (dd, &bodies[i].a, &bodies[i].b, bodies[i].radius, &body, 0.0f);

	/* contacts: wire, on top, timed */
	lrg_debug_draw_set_solid (dd, FALSE);
	lrg_debug_draw_set_depth_test (dd, FALSE);
	lrg_debug_draw_set_thickness (dd, 3.0f);
	for (i = 0; i < n_contacts; i++)
		lrg_debug_draw_arrow (dd, &contacts[i].point, &contacts[i].normal_tip, 0.1f, &hit, 0.5f);
	lrg_debug_draw_pop (dd);
}

*** Several viewports, one batch
:PROPERTIES:
:CUSTOM_ID: several-viewports-one-batch
:END:
#+begin_src C
static void
draw_viewports (LrgDebugDraw    *dd,
                RenderTexture2D *targets,
                const gfloat   (*views)[16],
                const gfloat   (*projections)[16],
                guint            n)
{
	guint i;

	for (i = 0; i < n; i++)
	{
		BeginTextureMode (targets[i]);
		/* ... the viewport's scene ... */
		rlMatrixMode (RL_PROJECTION);
		rlPushMatrix ();
		rlLoadIdentity ();
		rlMultMatrixf (projections[i]);
		rlMatrixMode (RL_MODELVIEW);
		rlLoadIdentity ();
		rlMultMatrixf (views[i]);
		rlEnableDepthTest ();
		lrg_debug_draw_draw_3d (dd);
		rlDrawRenderBatchActive ();
		rlMatrixMode (RL_PROJECTION);
		rlPopMatrix ();
		rlMatrixMode (RL_MODELVIEW);
		rlLoadIdentity ();
		lrg_debug_draw_draw_labels (dd);
		EndTextureMode ();
	}
	/* one-frame primitives go once every viewport has them */
	lrg_debug_draw_end_frame (dd);
}

** How engine systems use it
:PROPERTIES:
:CUSTOM_ID: how-engine-systems-use-it
:END:
The 0.9.0 plan routes every engine debug visualisation through this API so the editor needs one overlay and one set of toggles:
- *Physics* (=LrgDynamicsWorld=, =LrgCollisionMesh=, character controller): each world gets an optional =LrgDebugDraw= (the default instance when unset) and a =debug_draw()= pass on =LRG_DEBUG_CATEGORY_PHYSICS=: spheres, capsules, oriented boxes and triangle meshes as solid translucent shapes, contacts as timed arrows along the normal, the controller's capsule and ground probe.
- *Navigation* (=LrgNavAgent=, nav meshes): polygons as closed polylines, paths as polylines with arrows, agents as circles with velocity arrows and avoidance radii, on =LRG_DEBUG_CATEGORY_NAVIGATION=.
- *Lights* (=LrgLightSet=, =LrgShadowRenderer=): point light ranges as wire spheres, spot lights as cones, the directional light as an arrow, shadow cascades as frustums (=lrg_debug_draw_frustum()= with each cascade's view-projection), on =LRG_DEBUG_CATEGORY_LIGHTS=.
- *Audio*: emitter min/max distances as spheres, the listener as axes, on =LRG_DEBUG_CATEGORY_AUDIO=.
- *Cameras*: =lrg_debug_draw_camera_frustum()= for every non-active camera, on =LRG_DEBUG_CATEGORY_CAMERA=.
- *AI*: perception cones and state labels (=lrg_debug_draw_text()=) on =LRG_DEBUG_CATEGORY_AI=.

Producers always test =lrg_debug_draw_is_category_enabled()= first so disabled channels cost nothing.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: using-it-from-the-editor
:END:
The editor viewport owns an =LrgDebugDraw= that it flushes after the scene with the viewport's view and projection (=lrg_debug_draw_flush_matrices()=), and its overlay menu exposes one toggle per category (=lrg_debug_draw_set_category_enabled()=, mirrored by the =category-mask= property, so the toggles survive in the viewport settings as one integer). Play-in-editor sessions draw the running game's default instance in the same pass, so gameplay debug lines show in the editor viewport. Editor-only gizmos (light ranges, camera frustums, collider shapes of selected nodes) record on =LRG_DEBUG_CATEGORY_EDITOR= and the subsystem categories; the IPC/MCP surface for the toggles lands with the M5 viewport-overlay work.

** Performance notes
:PROPERTIES:
:CUSTOM_ID: performance-notes
:END:
- Recording is an array append (~150 bytes per primitive); disabled categories return after one bit test.
- Tessellation runs once per change, not per draw; a static set of timed primitives drawn in several viewports is tessellated once. Every tick that removes something, every recording and every =end_frame()= marks it dirty.
- A frame costs at most four rlgl runs for 3D and two for 2D, plus one =DrawText()= per label. Wide lines cost two triangles per segment; wire spheres cost 3 x segments segments, so lower =set_segments()= for thousands of spheres.
- A soft cap of 262144 recorded primitives protects against code that records every frame into a batch nobody flushes: further calls are dropped with one warning.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- *Nobody flushes*: one-frame primitives pile up until the cap. Call =flush()= (or =end_frame()=) every frame for every instance you record into.
- *Tick and duration*: timed primitives only expire through =tick()=; a paused game that stops ticking keeps them on screen (usually what you want while paused).
- *Inside =rlPushMatrix()=*: call =draw_3d()= at the top level of the 3D mode (see above).
- *Line width*: do not call =rlSetLineWidth()= around the batch expecting wide lines; use =set_thickness()=.
- *2D space*: 2D primitives drawn by =flush (camera3d)= are in screen pixels; use a separate =flush (camera2d)= (or another instance) for 2D world-space shapes.
- *Labels before 3D*: =draw_labels()= needs a previous =draw_3d()= for its matrices.
- *Render layers*: debug geometry ignores the camera's cull mask; hide it per viewport with the categories or =enabled=.
- =LrgDebugShape= / =LrgDebugCategory= live in this header, not =lrg-enums.h=.
