** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
LrgAssetManager provides unified asset loading with caching and mod overlay:

#+begin_src C
/* Add search paths */
lrg_asset_manager_add_search_path (manager, "base/assets/");
lrg_asset_manager_add_search_path (manager, "mods/my-mod/");

/* Load asset - searches in reverse priority */
GrlTexture *tex = lrg_asset_manager_load_texture (manager, "sprites/player.png", &error);
#+end_src

Asset types: Textures, Fonts, Sounds, Music, 3D Models and their skeletal animation clips (see [[#models-and-animations][Models and animations]])

#include <libregnum.h>

int main ()
{
    g_autoptr(GError) error = NULL;
    LrgAssetManager *manager = lrg_asset_manager_new ();

    /* Setup search paths */
    lrg_asset_manager_add_search_path (manager, "./assets/base/");

        g_print ("Loaded player texture\n");

    g_object_unref (manager);

}

*** Cache keys
:PROPERTIES:
:CUSTOM_ID: model-cache-keys
:END:
Models and animation sets are cached under the *canonical resolved path*: the name is searched in the search paths (last added first, or used as-is when absolute) and then canonicalized with =g_canonicalize_filename()=. Consequences:

- ="models/bear.glb"=, ="models/./bear.glb"=, ="models//bear.glb"= and the equivalent absolute path share one =GrlModel=.
- The same relative name resolves to a different file (and a different entry) after a higher-priority search path is added, so mods can override models.
- =lrg_asset_manager_unload()= and =lrg_asset_manager_is_cached()= accept any spelling. Unloading drops both the model and its animation set.
- =lrg_asset_manager_load_asset()= dispatches =.glb=, =.gltf=, =.obj=, =.iqm=, =.m3d= and =.vox= to =load_model()=.

Symbolic links are not resolved; two links to one file are two entries.

*** Ownership and unloading
:PROPERTIES:
:CUSTOM_ID: model-ownership
:END:
Both functions return *borrowed* objects: never unref them. The manager unloads a model when it is unloaded explicitly, by =unload_all()= or when the manager is finalized. At load time the manager records every GPU texture the model loader created for the model's material maps and unloads exactly those textures with the model (raylib's =UnloadModel()= leaves textures to the caller). A texture you later assign to a material remains yours, and shaders are never unloaded, so assigning a shared lighting shader to =materials[i].shader= is safe without restoring it first.

Skinned models: raylib 6.0's =UnloadModel()= did not free =Model.currentPose= and =Model.boneMatrices= (raylib 6.2's does). graylib's =GrlModel= finalizer frees them and clears the pointers before calling =UnloadModel()=, so cached skinned models neither leak nor get freed twice with either raylib; code that already frees them manually through =grl_model_get_handle()= and sets them to =NULL= stays safe.

Release the manager (or unload the models) before closing the window: unloading meshes and textures needs the GL context.

*** Errors
:PROPERTIES:
:CUSTOM_ID: model-errors
:END:
| Situation                                    | Error                                                       |
|----------------------------------------------+-------------------------------------------------------------|
| No file matches the name                     | =LRG_ASSET_MANAGER_ERROR= / =LRG_ASSET_MANAGER_ERROR_NOT_FOUND= |
| =load_model()= without a graphics context    | =G_IO_ERROR= / =G_IO_ERROR_NOT_INITIALIZED=                 |
| The loader produced no meshes (corrupt file, Draco-compressed glTF, unsupported format) | =LRG_ASSET_MANAGER_ERROR_LOAD_FAILED= |

Animation loading is CPU-only and works headlessly. A file without a skin or animations yields an *empty* cached array rather than an error (raylib cannot tell "no clips" from "cannot parse"). Clips keep the file's order, are sampled at 60 frames per second, and raylib truncates their names to 31 bytes.

For =.glb= and =.gltf= files the clips are passed through =lrg_gltf_info_fix_animation_roots()= before they are cached. raylib 6.0 posed every root joint except the first without its armature transform, which stretched and twisted rigs with several root joints (Quaternius animals and their IK leg roots, for example); the call corrected that. raylib 6.2, which libregnum now builds with, poses every joint with the transforms of the non-joint nodes above it, so the call only marks the clips. See [[file:../graphics/gltf-info.org::#multi-root-animation-fix][Multi-root animation fix]].

* Definition assets and live reload
:PROPERTIES:
:CUSTOM_ID: definition-assets
:END:

=lrg_asset_manager_load_asset()= dispatches by extension and caches the result.
Since 0.9.0 fonts take the sidecar's size and audio files honour the sidecar's stream/sample mode (see [[#import-settings][Runtime import settings]]); without a sidecar the rules below apply unchanged.
It supports textures (=.png=, =.jpg=, =.bmp=, =.tga=, =.gif=, =.qoi=, =.dds=, =.ktx=, =.pkm=, =.pvr=, =.astc= and =.pep=), fonts (size 32), WAV sounds, streaming OGG/MP3/FLAC/XM/MOD
music, and typed YAML definitions. =.pep= is raylib 6.2's pixel-art palette format; graylib (0.7.1+) decodes it losslessly, since raylib 6.2's own loader is unsafe and stays disabled. Unknown extensions return
=G_IO_ERROR_NOT_SUPPORTED=. Use a specific loader to choose another font size
or to load an OGG file as a sound effect. Graphics loads require a window;
YAML definitions run without a window or audio device.

The engine connects its registered =LrgDataLoader= automatically. For a
standalone manager, configure a loader explicitly:

#+begin_src c
LrgRegistry *registry = lrg_registry_new ();
LrgDataLoader *loader = lrg_data_loader_new ();
LrgAssetManager *assets = lrg_asset_manager_new ();
lrg_registry_register (registry, "item", LRG_TYPE_ITEM_DEF);
lrg_data_loader_set_registry (loader, registry);
lrg_asset_manager_set_data_loader (assets, loader);
lrg_asset_manager_add_search_path (assets, "data");
GObject *item = lrg_asset_manager_load_object (assets, "sword.yaml", &error);
/* item is borrowed from the cache. Ref it if retaining it across reloads. */
g_object_unref (loader);
g_object_unref (registry);
#+end_src

Definitions use =lrg_data_loader_load_file_validated()=. A malformed edit,
unknown type/property, invalid enum, or out-of-range numeric value returns an
error instead of replacing the definition with partially defaulted data.
See [[file:data-loader.org][Data loader]] for the validation contract.

Live reload is opt-in, per asset:

#+begin_src c
if (!lrg_asset_manager_watch_object (assets, "sword.yaml", &error))
    g_printerr ("Cannot watch definition: %s\n", error->message);
#+end_src

The watch monitors the containing directory and coalesces changes for 100ms,
including editor writes made with atomic renames. Invalid edits and deletion
emit =object-reload-failed(name, error)= and retain the last valid object.
Recreation is picked up by the same watch. A valid replacement must keep the
same GType and emits =object-reloaded(name, previous, replacement)= after the
cache has changed. Existing consumers holding a reference to =previous= remain
valid; they should connect to this signal and take a reference to =replacement=
when ready to adopt it. Objects are replaced, not modified in place.

Use =lrg_asset_manager_reload_object()= for an explicit reload without file
monitoring. The resolved file path is fixed when the definition enters the
cache. After modifying search paths or mod priority, unload and reload the
asset to resolve a different file. =unwatch_object()= cancels a watch but keeps
the definition cached. Unloading a definition, unloading all assets, changing
the data loader, or destroying the manager cancels its watches and queued
reloads. Watches do not keep the manager alive.

All calls belong on the manager's owning thread. Iterate the thread-default
=GMainContext= used when establishing each watch; that is where monitor events,
debounced reloads, and signals run. Loading and reloading are synchronous.

** Live definition dependencies

Declare dependencies after loading both YAML objects:

#+begin_src c
lrg_asset_manager_load_object (assets, "weapon.yaml", &error);
lrg_asset_manager_load_object (assets, "enemy.yaml", &error);
/* Check each return value/error in application code. */
lrg_asset_manager_add_object_dependency (assets, "enemy.yaml", "weapon.yaml", &error);
lrg_asset_manager_watch_object (assets, "weapon.yaml", &error);
#+end_src

Explicit and monitored reloads of =weapon.yaml= now also reload =enemy.yaml=
and its transitive dependents. Dependencies are explicit cached-name links;
the manager does not infer references from arbitrary YAML strings. Use the
same names used to load the objects (absolute and relative aliases are distinct).
Both endpoints must be cached. Duplicate links succeed, self-links and cycles
fail, and =remove_object_dependency()= removes a link without unloading assets.
Unloading an endpoint removes its incoming and outgoing links. Clearing the
cache or changing its loader clears the graph. Unwatching retains links.

The manager validates every affected file and enforces unchanged GTypes before
replacing anything. A failure preserves the whole cache and emits one
=object-reload-failed= signal for the requested root, with the failing filename
in the error. Success commits the whole batch, then emits =object-reloaded=
once per affected object in dependency order (lexical order breaks ties).
Thus a shared dependent in a diamond reloads once, and the first observer sees
all new definitions. Unaffected cache entries keep their identities.

Signal arguments retain the old/new objects for the complete notification
batch. Handlers may unload objects, clear the cache, or change links; these
changes affect subsequent reloads. Remaining signals describe the committed
batch, even if an earlier handler unloaded it. Recursive reload attempts fail
with =G_IO_ERROR_PENDING= without emitting another failure signal. Keep all
manager access on its owning thread.

Links propagate definition replacement; applications still use the replacement
signals to reconnect live entities and migrate gameplay state. Validation
constructs standalone definitions before commit; constructors must not mutate
the asset manager or expect staged replacements to be visible. GPU resources,
arbitrary live-object migration, and transactional file writes are outside
this YAML dependency mechanism.


* Projects and guid references
:PROPERTIES:
:CUSTOM_ID: guid-references
:END:
Since 0.9.0 every loader of =LrgAssetManager= (=load_texture=, =load_font=, =load_sound=, =load_music=, =load_audio=, =load_model=, =load_model_animations=, =load_object=, =load_asset=, =resolve_path=, =unload=, =is_cached=) accepts an asset reference by guid, =guid:<uuid>= (=LRG_ASSET_GUID_PREFIX=), wherever it accepts a path. The guid is the one the editor shows for the asset: the =guid:= of its =.meta= sidecar, or for a file without a sidecar its legacy guid (=lrg_asset_meta_compute_legacy_guid()= of its path relative to the asset directory). References by guid survive renames and moves done in the editor, which carries the sidecar along. =.rlevel= files may name visual assets and prefab sources by guid, and the level serializer resolves prefab sources through the index (see [[file:../level/prefabs-runtime.org::#prefabs-runtime-resolution][Prefabs at Runtime]]).

** The guid index
:PROPERTIES:
:CUSTOM_ID: guid-index
:END:
The manager keeps an index from guid to the canonical absolute path of the asset. It is built on first use by scanning the *asset directories* with exactly the rules of the editor's =LrgAssetDatabase= scan, so the editor and the runtime agree on every guid:

- every regular file below each asset directory is an asset, except =.meta= sidecars; =.git=, =.hg= and =.svn= directories are skipped;
- names are visited in sorted order, directories in the order they were added;
- a readable sidecar with a =guid:= gives the guid; a missing, unreadable or guid-less sidecar gives the legacy guid;
- when two files claim the same guid (an asset copied with its sidecar outside the editor) the first one wins. (The editor then gives the second a fresh guid in memory and writes it on its next sidecar save; until then the runtime does not know that guid.)

Asset directories come from =lrg_asset_manager_add_asset_dir()= or from the project (below). With none, the search paths are indexed instead (lowest priority first). A lookup that misses in a cached index, or finds a file that no longer exists, rebuilds the index once from disk; =lrg_asset_manager_rebuild_guid_index()= rebuilds it explicitly (after adding assets while the game runs).

** Projects
:PROPERTIES:
:CUSTOM_ID: projects
:END:
=lrg_asset_manager_set_project_root (manager, root)= (the =project-root= property) makes the manager project-aware:

1. =root= becomes the lowest-priority search path, so the project-relative paths the editor writes into levels resolve; mod search paths added later still override;
2. if =root/project.ryaml= exists, its =asset_dirs= (relative to the root) become the guid index directories, and its =apply_import_settings= key (also =apply-import-settings=, default true) sets the import policy; without a manifest the root itself is the asset directory;
3. the index is rebuilt lazily. Setting another root (or %NULL) first removes the previous root's search path and asset directories.

#+begin_src yaml
project:
  name: my-game
  asset_dirs: [assets, levels]
  apply_import_settings: true     # optional, default true
#+end_src

** Cached index file
:PROPERTIES:
:CUSTOM_ID: guid-index-cache
:END:
A shipped game can skip the scan: =lrg_asset_manager_save_guid_index (manager, path, error)= writes the index (sorted by guid, paths relative to the project root when inside it), and =lrg_asset_manager_load_guid_index (manager, path, error)= replaces the index with it (relative entries resolve against the project root, else the index file's directory). A stale cache heals itself: the first lookup that misses or finds a moved file rebuilds from disk.

#+begin_src yaml
version: 1                        # LRG_ASSET_GUID_INDEX_VERSION
assets:
  11111111-2222-4333-8444-555555555555: assets/textures/crate.png
  9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08: assets/plain.txt   # legacy guid
#+end_src

Errors: an unreadable file is the parser's error; a document that is not a mapping, or has no =assets:= mapping, is =G_IO_ERROR_INVALID_DATA=.

** Materials
:PROPERTIES:
:CUSTOM_ID: materials
:END:
Since 0.9.0 =.rmat= files are an asset type. =lrg_asset_manager_load_material (self, name, error)= resolves =name= (=guid:=, search-path name or absolute path) with =lrg_asset_manager_resolve_reference()=, loads it with =lrg_material_new_from_file()= with the manager as the material's asset manager, and caches it under the canonical path (transfer none): every spelling and the guid share one =LrgMaterial=, and instances naming it as =parent:= share it too. Loading is headless; the material's textures load on first use through =lrg_asset_manager_load_texture()=, so their import settings apply. =lrg_asset_manager_load_asset()= dispatches =.rmat= here; =lrg_asset_manager_unload()=, =lrg_asset_manager_unload_all()= and =lrg_asset_manager_is_cached()= cover the cache; =lrg_asset_manager_get_material_cache_size()= counts it. A missing file fails with =LRG_ASSET_MANAGER_ERROR_NOT_FOUND=, a bad one with the =LRG_MATERIAL_ERROR= of the loader. Materials hold the manager weakly. See [[file:../graphics/material.org][LrgMaterial]].

* Runtime import settings
:PROPERTIES:
:CUSTOM_ID: import-settings
:END:
The editor stores per-asset importer settings in the =.meta= sidecar (see [[file:../../editor/projects-and-assets.org::#import-settings][Import Settings]]). Since 0.9.0 the loaders apply them at load time, so a game shows assets the way the editor's asset inspector configured them. The sidecar reader, =LrgAssetMeta= (=core/lrg-asset-meta.h=), moved from the editor into the core module for this, so it works with =BUILD_EDITOR=0=; =lrg_asset_meta_classify()= is the extension table both sides share.

Settings apply only when the asset has a sidecar and the =apply-import-settings= property is %TRUE (the default; also the project key =apply_import_settings=). Assets without a sidecar load exactly as before. Changing the policy does not touch cached assets; unload them to reload.

| Importer | Setting | Applied at runtime |
|----------+---------+--------------------|
| texture | =max-size= (0 = none) | The image is downscaled on the CPU (aspect kept, longest edge = max-size) before the upload |
| texture | =mipmaps= | =grl_texture_gen_mipmaps()= after the upload (also forced by the =trilinear= filter) |
| texture | =filter= (=point=, =bilinear=, =trilinear=) | =grl_texture_set_filter()=; note that a sidecar defaults to =bilinear= while a texture without one keeps raylib's point filter |
| texture | =wrap= (=repeat=, =clamp=, =mirror=) | =grl_texture_set_wrap()= (=mirror= is =GRL_TEXTURE_WRAP_MIRROR_REPEAT=) |
| texture | =srgb= | Recorded only: the GL 3.3 renderer has no sRGB texture formats; materials read it with =lrg_asset_manager_get_asset_meta()= |
| model | =scale= | Uniform scale folded into the model transform (=grl_model_set_transform()=), after the file's own transform |
| model | =up-axis= (=y=, =z=) | =z= adds a -90 degree rotation about X so the file's +Z becomes +Y |
| model | =generate-normals= | Smooth (indexed meshes) or flat (unindexed) area-weighted normals recomputed on the CPU; the GPU normal buffer is updated or created |
| model | =import-animations= | Not used by the loaders (animation clips load on request with =lrg_asset_manager_load_model_animations()=) |
| model | =lod-levels=, =lod-ratios=, =lod-screen-sizes=, =lod-max-error=, =lod-lock-border=, =lod-hysteresis=, =lod-fade-duration= | Not applied by =lrg_asset_manager_load_model()= (it returns the full model, which level 0 of the chain shares); =LrgLodComponent= with =mesh-asset= + =asset-manager= reads them through =lrg_asset_manager_get_asset_meta()= and builds the chain with =lrg_lod_group_new_from_model_with_meta()= (see [[file:../graphics/lod-group.org::#meta-keys][LOD import keys]]) |
| audio | =mode= (=stream=, =sample=) | =lrg_asset_manager_load_audio()= and =lrg_asset_manager_load_asset()= return a =GrlMusic= for =stream=, a =GrlSound= for =sample=, whatever the extension |
| audio | =volume= | =grl_sound_set_volume()= / =grl_music_set_volume()= |
| audio | =loop= | =grl_music_set_looping()= for streams; raylib sounds cannot loop, so players of samples read it from the sidecar |
| font | =size= | Used when =lrg_asset_manager_load_font()= gets =size <= 0= and by =lrg_asset_manager_load_asset()= (32 without a sidecar) |
| font | =codepoints= | The glyph set rasterised (when the sidecar sets the key; raylib's 32..126 otherwise) |

| Function | Description |
|----------+-------------|

** Performance
:PROPERTIES:
:CUSTOM_ID: import-settings-performance
:END:
- Reading a sidecar costs one small YAML parse per load (not per cache hit).
- =max-size= decodes the image on the CPU and resizes it before the upload; it saves VRAM, not load time. Shrink source art for faster loads.
- =generate-normals= walks every triangle of every mesh once at load.
- The guid index scan reads every sidecar of the asset directories; for large projects ship a cached index (=lrg_asset_manager_save_guid_index()=) and load it at startup.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: import-settings-pitfalls
:END:
- A sidecar without a =filter= key means =bilinear=, not raylib's default point filter: pixel art needs =filter: point=.
- The editor viewport (=lrgeditor=) loads meshes itself; until it uses the manager, model =scale= and =up-axis= show at runtime but not in the editor viewport.
- =lrg_asset_manager_load_font()= used to reject =size <= 0=; it now means "the sidecar's size".
- guid names resolve through the index, which covers only the asset directories: an asset outside them is reachable by path only.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: import-settings-editor
:END:
Edit import settings in the Assets panel's import inspector (it writes the sidecar); copy an asset's guid there to reference it as =guid:<uuid>=. The editor's =LrgAssetDatabase= and this index produce the same guids for the same files, which =tests/test-runtime-import-settings.c= checks.
