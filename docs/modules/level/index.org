* Runtime Level Module
:PROPERTIES:
:CUSTOM_ID: level-module
:END:
=src/level/= holds everything a game needs to load and play the levels and prefabs authored in =lrgeditor=: the =.rlevel= / =.rprefab= data model, its YAML serializer, prefab resolution and linking, and the bridges that turn a level into a runtime =LrgWorld= or =LrgScene=. Since 0.9.0 it is always built: a game linked against a library built with =BUILD_EDITOR=0= can load and instantiate levels. The editor module (=src/editor/=, =BUILD_EDITOR=1=) adds only the authoring layer on top (undo/redo, selection, gizmo, IPC server, project and asset database, settings).

** Overview
:PROPERTIES:
:CUSTOM_ID: level-overview
:END:
| Piece | Header | What it is |
|-------+--------+------------|
| =LrgLevel= | =level/lrg-level.h= | The document: name, default 2D/3D view, an implicit root =LrgNode= and the timelines |
| =LrgNode= | =level/lrg-node.h= | A node: guid, name, flags, Euler TRS, children, visual, components, scripts, prefab link; derivable with the =instantiate= (2D) and =instantiate_3d= vfuncs |
| =LrgNodeVisual= | =level/lrg-node-visual.h= | Tagged visual payload: primitive, mesh, sprite, light, camera, audio emitter, tilemap, prefab instance, CAD part, plus a param bag |
| =LrgNodeTilemap= | =level/lrg-node-tilemap.h= | Layered tile grid carried by a tilemap visual; =lrg_node_tilemap_to_runtime()= builds an =LrgTilemap= |
| =LrgTimeline=, =LrgTimelineTrack= | =level/lrg-timeline.h= | Keyframed node-channel animation stored in the level |
| =LrgComponentDesc= | =level/lrg-component-desc.h= | A serializable component: registry type name + property bag |
| =LrgScriptBinding= | =level/lrg-script-binding.h= | A serializable script reference: language, path, enabled |
| =LrgLevelSerializer= | =level/lrg-level-serializer.h= | =.rlevel= / =.rprefab= YAML load and save |
| =LrgPrefabLink= and =lrg_prefab_*= | =level/lrg-prefab.h= | Prefab load, nested resolution, clone, instantiate (linked or not), overrides, sync |
| =lrg_level_instantiate_3d()=, =lrg_level_load_world3d()=, =lrg_level_instantiate_node_3d()= | =level/lrg-level-instantiate.h= | Level to =LrgWorld3D=: one =LrgEntity3D= per node, same GUID, full TRS, a component per visual (see [[#level-instantiate-3d][3D instantiation]]) |
| =lrg_level_instantiate()=, =lrg_level_to_scene()= | =level/lrg-level-instantiate.h= | Level to the 2D =LrgWorld= (one =LrgGameObject= per node) and level to =LrgScene= (primitive bake) |

The transforms use the shared core math, [[file:../core/math3d.org][lrg-math3d]]: =lrg_node_get_local_matrix()= and =lrg_node_get_world_matrix()= give a node's column-major 4x4 matrix exactly as the editor viewport computes it.

What stays editor-only: =LrgEditor= and its commands, selection, gizmo, view math (=lrg-editor-math.h= picking, rays, =LrgEditorView=), tile painter, timeline editing, settings, actions, IPC/MCP server, validation, =LrgProject=, =LrgAssetDatabase=, asset =.meta= sidecars, thumbnails, VCS, external editor, documents, and the Blender scene importer (=lrg_level_from_scene()= / =lrg_level_import_scene_file()=, an authoring-time conversion).

** Concepts
:PROPERTIES:
:CUSTOM_ID: level-concepts
:END:
*** Authoring model vs runtime model
:PROPERTIES:
:CUSTOM_ID: level-authoring-vs-runtime
:END:
An =LrgLevel= is data: a tree of =LrgNode=s that describes what to create. Playing it means instantiating that data into runtime objects. There are two runtime targets:

- *3D* (=lrg_level_instantiate_3d()=, since 0.9.0): one =LrgEntity3D= per node in an =LrgWorld3D=, with the node's GUID, name, hierarchy and full local transform, a component for the node's visual (mesh renderer, light, camera, audio source, billboard, tilemap), the registry components and the scripts, then the node class's =instantiate_3d= vfunc. This is what a 3D game and the editor's 3D play mode use. See [[#level-instantiate-3d][3D instantiation]].
- *2D* (=lrg_level_instantiate()=): one =LrgGameObject= per node in an =LrgWorld= (position from the node's X/Y), each =LrgComponentDesc= materialised through the engine's =LrgRegistry=, each enabled =LrgScriptBinding= attached as an =LrgScriptComponent=, the object tagged with the node's guid, then the node class's =instantiate= vfunc. Unchanged since 0.8.

*** GUIDs
:PROPERTIES:
:CUSTOM_ID: level-guids
:END:
Every node has a stable guid stored in the file. A 3D entity carries it as its own GUID, so =lrg_world3d_find_by_guid (world, guid)= finds the entity a node produced in O(1); 2D game objects are tagged with it (=lrg_world_find_by_tag (world, guid)=). =lrg_level_find_node (level, guid)= finds the node. Linked prefab instances derive their child guids from the instance root guid, so they stay stable across saves.

*** Prefabs at runtime
:PROPERTIES:
:CUSTOM_ID: level-prefabs-runtime
:END:
A level stores each placed prefab instance expanded (the whole subtree), with an optional =prefab:= block that only the editor uses to keep the instance linked. A game therefore does not need the prefab files to play a level. To spawn prefabs at runtime, load the =.rprefab= with =lrg_prefab_load_resolved()= (nested prefabs refreshed from their own files), make an instance with =lrg_prefab_instantiate()= or =lrg_prefab_instantiate_linked()=, add it to a level and instantiate that level (or a scratch level holding just the instance).

** File formats
:PROPERTIES:
:CUSTOM_ID: level-formats
:END:
Both formats are the same YAML document; a =.rprefab= is a level whose first top-level node is the prefab root. The full schema is [[file:../../editor/yaml-format.org][.rlevel YAML Format Reference]]; the annotated summary:

#+begin_src yaml
type: level                 # always "level" (also in a .rprefab)
name: room                  # LrgLevel:name
default_view: 3d            # 2d | 3d (editor preference)
nodes:                      # top-level nodes (children of the implicit root)
  - name: Room
    guid: bbbbbbbb-0000-0000-0000-000000000001   # stable id, runtime tag
    is_2d: false            # optional flags: is_2d, visible, locked
    transform:
      location: [10.0, 0.0, 0.0]
      rotation: [0.0, 1.5707963, 0.0]   # Euler radians, R = Rz * Ry * Rx
      scale: [2.0, 2.0, 2.0]
    visual:                 # optional LrgNodeVisual
      kind: primitive       # LrgNodeVisualKind nick
      primitive: primitive_cube
    components:             # LrgComponentDesc list, materialised via LrgRegistry
      - type: test-health   # registry name
        props:
          hp: 100           # GObject property values (enums as nicks)
    scripts:                # LrgScriptBinding list -> LrgScriptComponent
      - language: lua
        script: scripts/door.lua
        enabled: true
    prefab:                 # editor-only link metadata of a prefab instance
      source: prefabs/crate.rprefab
      map: { <instance guid>: <source guid> }
    children: []            # nested nodes, same schema
environment:                # optional (0.9.0) LrgEnvironment block, see below
  sky: { source: equirect, path: skies/noon.hdr, exposure: 0.0, rotation: 0.0 }
  ambient: { color: [0.2, 0.2, 0.2], intensity: 1.0 }
  post_stack: post/day.rpost
timelines:                  # optional LrgTimeline list
  - name: DoorOpen
    length: 1.0
    tracks:
      - node: bbbbbbbb-0000-0000-0000-000000000002
        channel: rotation.y
        keys: [ { time: 0.0, value: 0.0 }, { time: 1.0, value: 1.5 } ]
#+end_src

The =environment:= block (sky source, image-based lighting, ambient, fog, volumetrics and the =.rpost= post stack) is read into an [[file:../lighting/environment.org][LrgEnvironment]] held by the level (=lrg_level_get_environment=, =lrg_level_set_environment=, =lrg_level_ensure_environment=, property =LrgLevel:environment=); levels without the block (every 0.8 file) load with no environment and are written back without it. Its full schema is [[file:../../editor/yaml-format.org::#environment][.rlevel: environment]].

Tilemap visuals store their layers inline (see [[file:../../editor/editor-tools.org::#tilemap-yaml][tilemap saved format]]); timeline channels and easing are in [[file:../../editor/editor-tools.org::#timeline-yaml][timeline saved format]].

** 3D instantiation
:PROPERTIES:
:CUSTOM_ID: level-instantiate-3d
:END:
=lrg_level_instantiate_3d (level, world, engine, &error)= turns the node tree into an entity tree, appended under =lrg_world3d_get_root (world)= in the level's order. The level's implicit root node is not an entity; its children are the world's top-level entities. The level is not modified and the world is not cleared first.

*** What each node becomes
:PROPERTIES:
:CUSTOM_ID: level-instantiate-3d-node
:END:
| Node | Entity |
|------+--------|
| GUID | =lrg_entity3d_set_guid()= with the same string. A GUID already in the world (the level instantiated twice) or used twice inside the level gets a fresh GUID instead (the second case with a warning), so the world's GUID map stays 1:1. |
| name | =LrgEntity3D:name= |
| children | child entities in the same order (=lrg_entity3d_get_child()=) |
| location / rotation / scale | local position, rotation and scale. The rotation goes in through =lrg_entity3d_set_rotation_euler()=, so the entity keeps the authored Euler angles (=lrg_entity3d_has_authored_euler()=) and =lrg_entity3d_get_world_matrix()= equals =lrg_node_get_world_matrix()= |
| =visible= | =LrgEntity3D:visible= (not collected for rendering); the entity is always active |
| =locked=, =is_2d= | nothing (editor-only flags) |
| visual | one component, see the map below; group nodes (no visual, =none=) and prefab instance roots get none |
| =components= | each =LrgComponentDesc= whose type name is registered: =lrg_registry_create()=, then the props applied exactly as in 2D (enum and flags props from nicks or numbers, other types through =g_value_transform()=); unregistered types are skipped (a =g_debug()=) |
| =scripts= | each enabled binding as an =LrgScriptComponent= |
| node class | =LrgNodeClass.instantiate_3d (node, entity, world)= last, before the children |

Components attach in this order: the visual's component, the registry components in description order, the scripts. The entity joins the world (its parent is already in it) before any component attaches, so =attached_entity()= and =world_entered()= see the world. Prefab instances are stored expanded in the level, so their nodes instantiate like any other; the =prefab:= link block is editor metadata and ignored.

*** Visual to component property map
:PROPERTIES:
:CUSTOM_ID: level-visual-map
:END:
=lrg_level_visual_create_component (visual)= builds the component for one visual; =lrg_level_visual_get_component_type (kind)= says which type. The visual's parts map onto the component's GObject properties:

| Visual kind | Component | Explicit mappings | Params (by name, =_= becomes =-=) |
|-------------+-----------+-------------------+-----------------------------------|
| =primitive= | =LrgMeshRendererComponent= | =primitive= to =primitive=; material colour to =color-r= .. =color-a=, =roughness=, =metallic= (no material: the editor's grey 0.75, 0.75, 0.78) | =size_x= .. =size_z=, =radius=, =height=, =major_radius=, =minor_radius=, =emission_r= .. =emission_strength=, =cast_shadows=, =receive_shadows=, =transparent=, =double_sided=, =unlit=, =layer= |
| =mesh-asset= | =LrgMeshRendererComponent= | =asset= to =mesh-asset=; material as above | as above, plus =mesh_index= |
| =light= | =LrgLightComponent= | param =light_type= (=directional= / =point= / =spot=) to =kind=; param =spot_angle= (the full cone, degrees) to =outer-angle= (a half-angle: =spot_angle= / 2); material colour to =color-r= .. =color-b= | =intensity=, =range=, =inner_angle=, =cast_shadows=, =layer_mask= |
| =camera= | =LrgCameraComponent= | none | =fov=, =near=, =far=, =aspect=, =orthographic=, =ortho_size=, =priority=, =active=, =cull_mask= |
| =audio-emitter= | =LrgAudioSourceComponent= | =asset= to =sound-path=; param =radius= to =max-distance= | =bank=, =sound=, =volume=, =pitch=, =min_distance=, =max_distance=, =rolloff=, =spatial_blend=, =loop=, =autoplay= |
| =sprite= | =LrgBillboardComponent= | =asset= to =texture-path=; material colour to =color-r= .. =color-a=; =facing= defaults to =fixed= and =preserve-aspect= to on (the editor's aspect-fit 1 x 1 quad in the node's XY plane); param =pixels_per_unit= is ignored, as the editor ignores it | =width=, =height=, =facing=, =preserve_aspect=, =cutout=, =cast_shadows= |
| =tilemap= | =LrgTilemapComponent= | =asset= to =tileset-path=; the painted grid (=visual.tilemap=) is copied into =lrg_tilemap_component_set_node_tilemap()=, which builds the runtime =LrgTilemap= with =lrg_node_tilemap_to_runtime()= once the tileset loads | =tile_size=, =cast_shadows= |
| =mesh-asset= whose =.meta= has =lod-levels= > 1 | =LrgLodComponent= | the resolved (absolute) asset to =mesh-asset= and the engine's asset manager to =asset-manager=; material as above (needs a started engine and =apply-import-settings= on) | =cast_shadows=, =receive_shadows=, =layer=, =force_level=, =bias= |
| =decal= (0.9.0) | =LrgDecalComponent= | =asset= to =albedo-path=; param =normal= to =normal-path=, =orm= to =orm-path= (each stored absolute when it resolves, else as written for the renderer's resolver); material colour to =color-r= .. =color-a= | =size_x=, =size_y= (projection depth, local Y), =size_z=, =opacity=, =fade_angle=, =fade_width=, =depth_fade=, =sort_order=, =layer_mask=, =blend=, =channels=, =normal_strength=, =roughness=, =metallic= |
| =reflection-probe= (0.9.0) | =LrgReflectionProbeComponent= | none | =extents_x= .. =extents_z= (half sizes), =blend_distance=, =intensity=, =box_projection=, =resolution=, =near_clip=, =far_clip=, =auto_recapture= |
| =none=, =prefab-instance=, =cad-part= | none | | |

Game and editor draw the same sizes and colours: a sprite is the editor's aspect-fit quad whatever =pixels_per_unit= says (0.8 levels may carry it; set =width= / =height= params for another size), a mesh without a material is the editor's grey rather than the renderer's white, and a spot light's =spot_angle= keeps the editor's full-cone meaning. A light without =light_type= follows the editor viewport's rule: a positive =spot_angle= makes a spot light, anything else a point light. Params whose component has no such property are skipped (a =g_debug()=), so editor-only params never fail a load. The light, camera and audio defaults are the components' own (a light of intensity 1, a 60 degree camera, ...).

=lrg_level_visual_store_property (visual, property, value)= walks the same map backwards: it stores a component property value into the visual (param, material, asset or primitive). Play-in-editor's "Apply to Level" uses it for visual components. A param keeps the type it already has; a new one is stored as the type a level file round-trips (double for floating point, int64 for integers, boolean, string; enums and flags as their nick string).

#+begin_src yaml
# A light node and what it becomes
- name: Sun
  guid: 7a000000-0000-4000-8000-000000000001
  transform:
    rotation: [-0.95, 0.65, 0.0]   # the light shines down the entity's local -Z
  visual:
    kind: light                    # -> LrgLightComponent
    material:
      color: [1.0, 0.93, 0.8, 1.0] # -> color-r / color-g / color-b
    params:
      light_type: directional      # -> kind = LRG_LIGHT3D_DIRECTIONAL
      intensity: 1.6               # -> intensity
      cast_shadows: true           # -> cast-shadows
#+end_src

*** The level's look
:PROPERTIES:
:CUSTOM_ID: level-look
:END:
Before any node is instantiated, the level's =environment:= block (=lrg_level_get_environment()=) becomes the world's environment and its =post_stack:= the world's post stack (see [[file:../world3d/world3d.org::#look][The world's look]]):

1. The environment is copied (its YAML block is written and read back into a new =LrgEnvironment=), so the runtime (reflection probes registering, a game changing the exposure) never changes the authored level.
2. Sky images the level's environment already holds (the editor loaded them for its viewport, or the game called =lrg_environment_load_sources()= on the level) are shared with the copy. Otherwise the copy's sky references are resolved and loaded with =lrg_environment_load_sources()=.
3. The =post_stack:= reference is resolved and loaded with =lrg_post_stack_new_from_file()=, then set with =lrg_world3d_set_post_stack()=.

References are resolved, in order: =guid:= through the asset manager's GUID index; absolute paths as they are; relative paths against the base directory (=lrg_level_instantiate_3d_with_base_dir()=, which =lrg_level_load_world3d()= calls with the level file's directory and play-in-editor with the open level's directory), then the asset manager's search paths, its project root, and the working directory. The same order resolves the =.meta= of mesh assets (the LOD decision) and decal textures. A sky or post stack that does not load is a =g_warning()= and is left out; it never fails the instantiation. A level without an =environment:= block leaves the world's environment and post stack as they are.

Reflection probe components register with the world's environment as they enter the world, so after instantiation =lrg_environment_get_n_probes (lrg_world3d_get_environment (world))= counts them; they reflect nothing until captured (=lrg_world3d_renderer_capture_probes()=).

#+begin_src yaml
# The environment block and the two node kinds that make a level's look
environment:
  sky: { source: equirect, path: skies/noon.hdr, exposure: 0.0 }  # -> world environment (copy)
  post_stack: post/day.rpost                                       # -> world post stack
nodes:
  - name: Splat
    transform: { location: [0.0, 0.0, 0.0] }   # local -Y is the projection direction
    visual:
      kind: decal                   # -> LrgDecalComponent
      asset: textures/splat.png     # -> albedo-path (absolute when it resolves)
      material: { color: [1.0, 1.0, 1.0, 0.9] }  # -> color-r .. color-a
      params: { size_x: 2.0, size_y: 0.5, size_z: 2.0, fade_angle: 60.0 }
  - name: Room probe
    transform: { location: [0.0, 2.0, 0.0] }
    visual:
      kind: reflection-probe        # -> LrgReflectionProbeComponent on the world environment
      params: { extents_x: 6.0, extents_y: 2.0, extents_z: 4.0, resolution: 128 }
#+end_src

*** The level's baked lighting
:PROPERTIES:
:CUSTOM_ID: level-lighting
:END:
After the look, the level's =lighting:= block (0.9.0 M3, see [[file:../../editor/yaml-format.org::#lighting][the format]]) loads onto the world: the =lightmap:= reference becomes =lrg_world3d_set_lightmap()= (=lrg_lightmap3d_new_from_file()=) and every =probes:= reference a grid added with =lrg_world3d_add_probe_grid()= (=lrg_probe_grid_new_from_file()=). References resolve exactly like the look's; one that does not resolve or load is a =g_warning()= and is skipped. A level without the block leaves the world's lightmap and grids as they are. The block's settings are not used at runtime: they are the baker's input (the editor's bake panel).

Node GUIDs key the lightmap entries, and =assign_guid= keeps the node's GUID on its entity unless it is already taken in the world (an instance spawned twice), in which case that copy is not lightmapped.

#+begin_src C
/* the LrgLevel side of the block */
lrg_level_set_lightmap_ref (level, "maps/town.rlightmap");
lrg_level_add_probe_ref (level, "maps/town-0.rprobes");
lrg_level_set_bake_setting (level, "texels_per_unit", 8.0);
if (lrg_level_has_lighting (level))
	g_print ("%u grids\n", lrg_level_get_probe_refs (level)->len);
#+end_src

*** Custom node kinds
:PROPERTIES:
:CUSTOM_ID: level-instantiate-3d-vfunc
:END:
A subclass of =LrgNode= adds its own runtime pieces in =instantiate_3d=. The hook runs once per node after the entity has its identity, transform, flags and the visual, registry and script components, after it joined the world, and before the node's children are instantiated. The default is =NULL=, so there is nothing to chain up to. =lrg_node_instantiate_3d()= is the dispatcher.

#+begin_src C
static void
spawn_node_instantiate_3d (LrgNode     *node,
                           LrgEntity3D *entity,
                           LrgWorld3D  *world)
{
	MySpawnNode *self = MY_SPAWN_NODE (node);

	/* A runtime component that knows the node's authored data */
	g_autoptr(MySpawner) spawner = my_spawner_new (self->prefab_path, self->interval);

	lrg_entity3d_add_component (entity, LRG_COMPONENT (spawner));
	lrg_entity3d_add_tag (entity, "spawner");
}

static void
my_spawn_node_class_init (MySpawnNodeClass *klass)
{
	LRG_NODE_CLASS (klass)->instantiate_3d = spawn_node_instantiate_3d;
}
#+end_src

*** Loading a 3D level in a game
:PROPERTIES:
:CUSTOM_ID: level-game-loading-3d
:END:
The guide [[file:../../guides/load-a-level-in-your-game.org][Load a level in your game]] walks through a whole game loop; =examples/level-3d-runtime.c= ([[file:../../examples/level-3d-runtime.org][example page]]) is the complete program. The core is three calls:

#+begin_src C
g_autoptr(LrgWorld3D) world = lrg_world3d_new ();
g_autoptr(LrgLevel)   level = NULL;

lrg_registry_register (lrg_engine_get_registry (lrg_engine_get_default ()), "spinner", GAME_TYPE_SPINNER);
level = lrg_level_load_world3d ("levels/main.rlevel", world, &error);   /* load + instantiate */
/* every frame */
lrg_world3d_step (world, GetFrameTime ());
lrg_world3d_renderer_render (renderer, world, NULL, NULL, 0, 0);
#+end_src

=lrg_level_load_world3d()= returns the loaded level (keep it to look nodes up, or drop it: the world does not reference it). =lrg_level_instantiate_node_3d (node, parent, world, engine, &error)= instantiates one subtree under =parent= (or the world root), which is how a game spawns a prefab at runtime:

#+begin_src C
static LrgEntity3D *
spawn_crate (LrgWorld3D   *world,
             const gfloat *position,
             GError      **error)
{
	g_autoptr(LrgNode) prefab = lrg_prefab_load_resolved ("prefabs/crate.rprefab", NULL, error);
	g_autoptr(LrgNode) crate = NULL;

	if (prefab == NULL)
		return NULL;
	crate = lrg_prefab_instantiate (prefab);   /* fresh GUIDs */
	lrg_node_set_location_xyz (crate, position[0], position[1], position[2]);
	return lrg_level_instantiate_node_3d (crate, NULL, world, NULL, error);
}
#+end_src

** Loading a level in a 2D game (no editor)
:PROPERTIES:
:CUSTOM_ID: level-game-loading
:END:
This 2D program links against a =BUILD_EDITOR=0= library; =tests/test-level-runtime.c= is the same flow as a test.

#+begin_src C
#include <libregnum.h>

static gboolean
load_and_play (const gchar  *level_path,
               LrgWorld     *world,
               GError      **error)
{
	g_autoptr(LrgLevelSerializer) ser = lrg_level_serializer_new ();
	g_autoptr(LrgLevel)           level = NULL;
	LrgEngine                    *engine = lrg_engine_get_default ();
	LrgGameObject                *door;

	/* the registry must know every component type the level names */
	if (!lrg_engine_startup (engine, error))
		return FALSE;
	lrg_registry_register (lrg_engine_get_registry (engine),
	                       "health", MY_TYPE_HEALTH);

	level = lrg_level_serializer_load_from_file (ser, level_path, error);
	if (level == NULL)
		return FALSE;

	/* one LrgGameObject per node, tagged with the node guid */
	if (!lrg_level_instantiate (level, world, engine, error))
		return FALSE;

	door = lrg_world_find_by_tag (world, "bbbbbbbb-0000-0000-0000-000000000002");
	if (door != NULL)
	{
		LrgNode *node = lrg_level_find_node (level, "bbbbbbbb-0000-0000-0000-000000000002");
		gfloat   world_m[16];

		/* full 3D world transform of the authored node */
		lrg_node_get_world_matrix (node, world_m);
		g_message ("door at %.2f %.2f %.2f", world_m[12], world_m[13], world_m[14]);
	}

	return TRUE;
}
#+end_src

*** Spawning a prefab at runtime
:PROPERTIES:
:CUSTOM_ID: level-game-prefab
:END:
#+begin_src C
static gboolean
spawn_crate (LrgWorld    *world,
             gfloat       x,
             gfloat       y,
             GError     **error)
{
	g_autoptr(LrgNode)  prefab = NULL;
	g_autoptr(LrgNode)  crate = NULL;
	g_autoptr(LrgLevel) scratch = lrg_level_new ("spawn");

	prefab = lrg_prefab_load_resolved ("prefabs/crate.rprefab", NULL, error);
	if (prefab == NULL)
		return FALSE;

	crate = lrg_prefab_instantiate (prefab);   /* fresh guids, unlinked */
	lrg_node_set_location_xyz (crate, x, y, 0.0f);
	lrg_level_add_node (scratch, crate, NULL);

	return lrg_level_instantiate (scratch, world, NULL, error);
}
#+end_src

Cache the loaded =prefab= root if you spawn it often: =lrg_prefab_load_resolved()= parses YAML and re-reads every nested prefab each call.

*** Tilemaps and timelines
:PROPERTIES:
:CUSTOM_ID: level-game-tilemaps
:END:
=lrg_level_instantiate_3d()= gives each tilemap node an =LrgTilemapComponent= holding a copy of its grid; the component builds the runtime =LrgTilemap= with =lrg_node_tilemap_to_runtime()= once the tileset loads (=lrg_tilemap_component_get_tilemap()=). The 2D =lrg_level_instantiate()= does not create tilemaps: walk the nodes and call =lrg_node_tilemap_to_runtime()= on each tilemap visual's =LrgNodeTilemap=. Timelines can be sampled with =lrg_timeline_apply()= against the level's nodes, then read back with =lrg_node_get_world_matrix()=. To play a timeline on the instantiated =LrgWorld3D= entities, convert it with =lrg_sequence_new_from_timeline()= and play the result with an =LrgSequencePlayer= ([[file:../animation/sequence.org::#sequence-example-timeline][Sequences]]); since 0.9.0 timelines also have Bézier keys and bone channels ([[file:../../editor/editor-tools.org::#timeline-bezier][Bézier tangents]]).

** Compatibility (0.8 include paths)
:PROPERTIES:
:CUSTOM_ID: level-compat
:END:
The headers moved from =src/editor/= to =src/level/= with identical content. The old =src/editor/lrg-level.h= (and the other nine) are now one-line forwarding headers (=#include "../level/lrg-level.h"=), so in-tree code and installed =<libregnum/editor/...>= includes keep compiling. ** Performance
:PROPERTIES:
:CUSTOM_ID: level-performance
:END:
- Loading is a YAML parse plus one GObject per node, component description and script binding; load levels behind a loading screen, not mid-frame.
- =lrg_level_instantiate()= and =lrg_level_instantiate_3d()= are linear in the node count and create components through the registry (one =g_object_new= each). The 3D path also creates one component per visual and walks each visual's param bag once; a level of a few thousand nodes instantiates in milliseconds.
- Instantiating 3D does no GPU work: meshes, textures and tilesets load on the first render (the renderer's caches) or through an =LrgAssetManager= set on the components.
- =lrg_node_get_world_matrix()= recomposes every ancestor per call (O(depth)); cache world matrices of static nodes.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: level-pitfalls
:END:
- *Unregistered component types are skipped silently.* Register every type name the level uses before =lrg_level_instantiate()=; =lrgeditor --validate= reports unknown types at authoring time.
- *2D instantiation is X/Y only.* Only X/Y reach an =LrgGameObject=; use =lrg_level_instantiate_3d()= for the full transform.
- *The look is a copy.* Changing =lrg_level_get_environment()= after instantiation does not change the world; change =lrg_world3d_get_environment()= (or instantiate again).
- *Relative asset paths.* A visual's =asset= is stored as written (usually relative to the project root). =LrgWorld3DRenderer= resolves meshes and textures against =lrg_world3d_renderer_set_base_dir()= (or the working directory); audio files are opened by path, so make =sound-path= absolute or run from the project root.
- *Autoplay audio fires on world entry*, i.e. during =lrg_level_instantiate_3d()=; if you fix up =sound-path= afterwards, start the emitter again (=lrg_audio_source_component_play()=).
- *Instantiating the same level twice* into one world gives the second copy fresh GUIDs; look entities of the second copy up by name or path (=lrg_world3d_find_by_path()=), not by the node GUID.
- *Relative prefab paths* in =prefab: source:= (and nested prefab sources inside a =.rprefab=) are canonicalised against the process working directory (=g_canonicalize_filename()=); run the game from the project root or load prefabs with absolute paths.
- *Do not include =src/level/*.h= directly* from applications; =<libregnum.h>= is the only supported entry point.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: level-from-editor
:END:
Everything the editor saves is this module's data: =LrgEditor= owns an =LrgLevel=, prefab panels call the =lrg_prefab_*= functions, and play-in-editor instantiates the level the way a game does: =lrg_level_instantiate_3d()= when the level's default view is 3D (the inspector's level section, /2D view/ off; =default_view: 3d= in the file), =lrg_level_instantiate()= when it is 2D. While a 3D level plays the viewport draws the runtime =LrgWorld3D= through =LrgWorld3DRenderer=, the hierarchy's Live tab shows the entity tree, and the inspector shows the picked entity's transform and components, with "Apply to Level" writing component values back into the node (registry components into their description, visual components into the visual). See [[file:../../editor/view-model.org::#play-3d][Play session: 2D or 3D]]. =lrgeditorctl play start= / =play.state= work as before.
