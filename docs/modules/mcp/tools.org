*** lrg_input_get_state
:PROPERTIES:
:CUSTOM_ID: lrg_input_get_state
:END:
Report the full input state the game sees this frame. Keyboard, mouse and gamepad state come from =LrgInputManager= (hardware sources merged with MCP-injected input); the mouse wheel is read from the hardware path (=grl_input_get_mouse_wheel_move_v()=); the =injected= block shows only what this tool group has injected.

No parameters.

Key, mouse-button, gamepad-button and axis names are the same names the press/release/set tools accept, so any reported name can be passed straight back.

- =keyboard.keys_down=: every held key (=GrlKey= nicks).
- =mouse=: position, per-frame delta, =wheel= (=x=, =y=) and held buttons.
- =gamepads=: one entry per pad that is physically connected (a non-software source reports it, =connected= true, with the controller =name=) or has non-neutral state (a held button, a stick off 0, a trigger off its -1 rest). Each entry lists held buttons and all six axes.
- =actions=: the input map attached with =lrg_mcp_server_set_input_map()= (=null= when none is attached). Each action reports =down=, =pressed=, =released=, =value=, =axis= and =binding_count=.
- =sources=: the manager's input sources in priority order, and =enabled= for the manager itself.

Attach the game's input map once, after creating the server:

#+begin_src c
lrg_mcp_server_set_input_map (lrg_mcp_server_get_default (),
                              lrg_game_template_get_input_map (template));
#+end_src

*Returns:*

#+begin_src json
{
  "keyboard": {"keys_down": ["w", "left_shift"]},
  "mouse": {
    "x": 640.0, "y": 480.0, "dx": 0.0, "dy": 0.0,
    "wheel": {"x": 0.0, "y": -1.0},
    "buttons_down": ["left"]
  },
  "gamepads": [
    {
      "index": 0,
      "connected": true,
      "name": "Xbox Controller",
      "buttons_down": ["a"],
      "axes": {"left_x": 0.5, "left_y": -0.3, "right_x": 0.0,
               "right_y": 0.0, "left_trigger": -1.0, "right_trigger": -1.0}
    }
  ],
  "actions": [
    {"name": "jump", "down": true, "pressed": true, "released": false,
     "value": 1.0, "axis": 1.0, "binding_count": 2}
  ],
  "enabled": true,
  "sources": [
    {"name": "software", "type": "LrgInputSoftware", "enabled": true, "priority": 0}
  ],
  "injected": {
    "keys_down": ["w"], "mouse_buttons_down": [],
    "mouse_x": 0.0, "mouse_y": 0.0, "registered": true

}

** ECS Tools (=LrgMcpEcsTools=)
:PROPERTIES:
:CUSTOM_ID: ecs-tools-lrgmcpecstools
:END:
ECS tools query and manipulate the Entity-Component-System.

Applications expose worlds explicitly on the engine thread:

#+begin_src c
lrg_engine_register_world (lrg_engine_get_default (), "main", world);
/* When this world should no longer be inspected: */
lrg_engine_unregister_world (lrg_engine_get_default (), "main");
#+end_src

The engine retains registered worlds; registration does not update or draw them.
The default world is the first active world in lexicographic name order. Object
IDs are UUIDs returned by listing/spawning, stable for the object's lifetime,
and shared by tools and resources. Tags need not be unique. A missing world or
object produces an error, and an engine with no registrations lists no worlds.

Transform tools edit local values when an =LrgTransformComponent= is attached,
then synchronize its world transform to the entity. Otherwise they edit entity
values and require uniform scale: pass both =scale_x= and =scale_y= equally.
Partial updates preserve omitted fields. Numeric arguments must be finite and
representable as floats. Invalid requests do not partially apply transforms.

Component inspection reports scalar properties plus =unsupported_properties=
for boxed/object-valued properties. Property editing supports booleans, strings
(including null), integer, float, enum and flags properties. Enum values accept
registered names/nicks or numeric values. Read-only, construct-only, unknown,
wrong-type and out-of-range properties return errors; boxed/object values are
unsupported. Unsigned values beyond signed 64-bit range are reported as decimal
strings and cannot be edited through JSON integers.

** Save Tools (=LrgMcpSaveTools=)
:PROPERTIES:
:CUSTOM_ID: save-tools-lrgmcpsavetools
:END:
Save tools use the default =LrgSaveManager= and its registered =LrgSaveable=
objects. Configure its save directory before use. Slot names are basenames;
empty names, path separators, =.=, =..= and drive/path prefixes are rejected.
Create saves the description as the display-name metadata in the same write as
game state. Quick save/load use the =quicksave= slot. Missing, corrupt or
unwritable saves return errors; list returns only readable existing saves,
so a new game can legitimately have an empty slot list.

*** lrg_debug_inspect
:PROPERTIES:
:CUSTOM_ID: lrg_debug_inspect
:END:
Point the default inspector at a world and optionally select a game object, then return the inspector's views. An =object_id= (from the ECS tools) picks its own world; otherwise =world= names one, defaulting to the first active registered world. The selection is left in place, so the in-game inspector shows the same object.

| Parameter | Type   | Required | Description                                    |
|-----------+--------+----------+------------------------------------------------|
| world     | string | No       | World name (default: first active world)       |
| object_id | string | No       | Game object id to select                       |

*Returns:*

#+begin_src json
{
  "visible": false,
  "object_count": 12,
  "world_info": "World: 12 objects ...",
  "selected": {
    "id": "6f1c...",
    "info": "LrgGameObject at (8, 9) ...",
    "components": ["LrgTransformComponent"],
    "component_properties": [
      {"type": "LrgTransformComponent", "properties": {"local-x": 8.0}}
    ]
  }
}
#+end_src

=selected= is =null= when no object is selected.


** UI Inspector Tools (=LrgMcpDebugTools=)
:PROPERTIES:
:CUSTOM_ID: mcp-ui-inspector-tools
:END:
Six debug tools inspect and tweak the retained-mode UI through the default =LrgUIInspector=. The app makes its canvas visible to them with =lrg_ui_inspector_register_canvas (canvas)=; without a registered canvas every tool fails with a clear error. The tools exist only in builds made with =MCP=1=. Parameters, return shapes and examples are documented in [[file:../ui/inspector.org::#mcp-tools][the inspector page]].

| Tool | Purpose |
|------+---------|
| [[file:../ui/inspector.org::#mcp-ui-tree][=lrg_ui_tree=]] | Snapshot the widget tree as JSON: paths, geometry, state, classes and the resolved look |
| [[file:../ui/inspector.org::#mcp-ui-pick][=lrg_ui_pick=]] | Topmost widget at a canvas point, hit-tested the way clicks are (popups and overlays first) |
| [[file:../ui/inspector.org::#mcp-ui-get-widget][=lrg_ui_get_widget=]] | One widget by path with every readable property |
| [[file:../ui/inspector.org::#mcp-ui-set-property][=lrg_ui_set_property=]] | Set a widget property by name for live tweaking (strings convert to bools, numbers, enum nicks, flags and colours) |
| [[file:../ui/inspector.org::#mcp-ui-highlight][=lrg_ui_highlight=]] | Select and highlight a widget by path, or toggle pick mode |
| [[file:../ui/inspector.org::#mcp-ui-timings][=lrg_ui_timings=]] | Frame timings (step, layout, record) and paint instance, command and draw-call counts |
