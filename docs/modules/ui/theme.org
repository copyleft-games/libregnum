=LrgTheme= (=src/ui/lrg-theme.h=, final =GObject=) holds everything widgets need to look consistent: 27 colour roles, 18 metrics, a motion preset, a dark flag, a name, a UI font and a list of style rules. Every widget draws with an effective theme (its own, an ancestor's, or the process-wide default), reading roles and metrics instead of hard-coded values. This page is the API reference; [[file:../../guides/theming.org][the theming guide]] explains how to write theme files and use themes in a game, and [[file:styling.org][UI styling]] covers style rules.

** Overview
:PROPERTIES:
:CUSTOM_ID: theme-overview
:END:
#+begin_src c
LrgTheme       *theme = lrg_widget_get_theme (widget);       /* effective theme */
const GrlColor *panel = lrg_theme_get_color (theme, LRG_THEME_COLOR_PANEL);
gfloat          pad = lrg_theme_get_metric (theme, LRG_THEME_METRIC_PADDING_X);
GrlFont        *font = lrg_theme_get_ui_font (theme);         /* NULL headless */

A new theme (=lrg_theme_new()=) and the lazily created default theme start as the =midnight= preset.

** Colour roles
:PROPERTIES:
:CUSTOM_ID: theme-colors
:END:
| Function | Purpose | Notes |
|----------+---------+-------|
| =lrg_theme_get_color (self, role)= | Colour of an =LrgThemeColor= role | (transfer none); valid until the role changes |
| =lrg_theme_set_color (self, role, color)= | Set one role | Emits =::changed=; notifies the matching legacy property |
| =lrg_theme_set_accent (self, accent)= | Set =ACCENT= and derive =ACCENT_HOVER=, =ACCENT_PRESSED=, =LINK=, =FOCUS=, =SELECTION= and =TEXT_ON_ACCENT= | Derivation depends on =dark=; see [[file:../../guides/theming.org::#theming-accent][deriving from an accent]] |

The roles (=WINDOW=, =PANEL=, =SURFACE=, =BORDER=, =TEXT=, =TEXT_MUTED=, =TEXT_ON_ACCENT=, =ACCENT=, =ACCENT_HOVER=, =ACCENT_PRESSED=, =CONTROL=, =CONTROL_HOVER=, =CONTROL_PRESSED=, =INPUT=, =FOCUS=, =SELECTION=, =TRACK=, =HANDLE=, =POPUP=, =TOOLTIP=, =SHADOW=, =VEIL=, =SUCCESS=, =WARNING=, =DANGER=, =LINK=, =DISABLED=; =LRG_THEME_COLOR_COUNT= = 27) and what they are used for are tabled in [[file:../../guides/theming.org::#theming-roles][the theming guide]], with every preset's values.

** Metrics
:PROPERTIES:
:CUSTOM_ID: theme-metrics
:END:
| Function | Purpose | Notes |

Metrics (=LRG_THEME_METRIC_COUNT= = 18) and defaults: =FONT_SIZE= 16, =FONT_SIZE_SMALL= 12, =FONT_SIZE_LARGE= 24, =FONT_SIZE_TITLE= 32, =CORNER_RADIUS= 8, =BORDER_WIDTH= 1, =CONTROL_HEIGHT= 36, =PADDING_X= 14, =PADDING_Y= 8, =SPACING= 8, =ROW_HEIGHT= 32, =POPUP_RADIUS= 12, =SHADOW_BLUR= 18, =SHADOW_OFFSET_Y= 6, =FOCUS_RING_WIDTH= 2, =SCROLLBAR_SIZE= 8, =CHECK_SIZE= 20, =HANDLE_SIZE= 18 (presets override some; see [[file:../../guides/theming.org::#theming-metrics][metrics]]).

** Legacy API
:PROPERTIES:
:CUSTOM_ID: theme-legacy
:END:
The original per-colour and per-size accessors still work. They are thin aliases of colour roles and metrics, so older code and saved settings keep functioning and a legacy setter is indistinguishable from the modern call it forwards to (it emits =::changed= and notifies both the legacy property and the role).

*** Legacy colours
:PROPERTIES:
:CUSTOM_ID: theme-legacy-colors
:END:
Every getter returns (transfer none) a pointer into the theme, valid until that role changes; =lrg_theme_get_<name> (self)= is exactly =lrg_theme_get_color (self, LRG_THEME_COLOR_<ROLE>)= and the setter is =lrg_theme_set_color()=, which copies =color=.

*** Legacy sizes
:PROPERTIES:
:CUSTOM_ID: theme-legacy-sizes
:END:
The font sizes, border width and corner radius forward to =lrg_theme_get_metric()= / =lrg_theme_set_metric()= (which does not queue layout: call =lrg_widget_queue_layout()= on affected trees, or rely on the canvas noticing the theme generation change). static const GrlColor red = { 230, 70, 70, 255 };
g_autoptr(GError) error = NULL;
g_autoptr(LrgTheme) theme = lrg_theme_new_from_file ("themes/arcade.yaml", &error);

if (theme == NULL)
{
	if (g_error_matches (error, LRG_THEME_ERROR, LRG_THEME_ERROR_FONT))
		g_warning ("theme font missing, using the system UI font: %s", error->message);
	else
		g_warning ("bad theme file: %s", error->message);
	return;
}

** Example: a theme built in code
:PROPERTIES:
:CUSTOM_ID: theme-example
:END:
#+begin_src c
static LrgTheme *
make_arcade_theme (void)
{
	static const GrlColor magenta = { 255, 64, 160, 255 };
	static const GrlColor bg = { 8, 6, 20, 255 };
	LrgTheme             *theme = lrg_theme_new_preset ("midnight");
	g_autoptr(LrgStyleRule) pill = lrg_style_rule_new ("LrgButton", NULL,
	                                                   LRG_UI_PART_BOX, LRG_WIDGET_STATE_NONE);

	lrg_theme_set_name (theme, "arcade");
	lrg_theme_set_motion (theme, LRG_MOTION_WOBBLY);
	lrg_theme_set_accent (theme, &magenta);
	lrg_theme_set_color (theme, LRG_THEME_COLOR_WINDOW, &bg);
	lrg_theme_set_metric (theme, LRG_THEME_METRIC_FONT_SIZE, 20.0f);
	lrg_theme_set_metric (theme, LRG_THEME_METRIC_CONTROL_HEIGHT, 44.0f);

	lrg_part_look_set_radius (lrg_style_rule_get_look (pill), G_MAXFLOAT);
	lrg_theme_add_style_rule (theme, pill);

	g_warn_if_fail (lrg_theme_get_contrast (theme, LRG_THEME_COLOR_TEXT,
	                                        LRG_THEME_COLOR_PANEL) >= 4.5f);
	return theme;
}
#+end_src

** Notes
:PROPERTIES:
:CUSTOM_ID: theme-notes
:END:
- Widgets read the theme every frame; colour changes show immediately. Size metric changes need a re-layout (see [[file:../../guides/theming.org::#theming-runtime][switching at runtime]]).
- Every mutation invalidates the style-rule cache; editing a rule's look after adding it does not.
- The legacy default font is initialised from the font manager once per process, by the first theme asked for it; themes created later have no legacy default font unless one is set (=lrg_theme_set_default()= carries it over).
