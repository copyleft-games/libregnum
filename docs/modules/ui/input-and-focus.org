* UI Input, Focus and Popups
:PROPERTIES:
:CUSTOM_ID: input
:END:
#+begin_quote
*[[file:../../index.org][Home]]* > *[[file:../index.org][Modules]]* > *[[file:index.org][UI]]* > Input and focus
#+end_quote

=LrgCanvas= turns one frame of device input into UI events and delivers them through the widget tree: pointer events go to the widget under the pointer (or the one holding the pointer capture) and bubble up its ancestors; keys go to the focused widget; Tab, arrow keys and the gamepad move focus between widgets; Enter, Space and gamepad A activate; Escape and gamepad B cancel. A popup layer above the tree hosts menus, combo lists, dialogs and tooltips, with placement, flipping, modality and light dismiss. This page documents the whole path; the event struct itself is in [[file:ui-event.org][LrgUIEvent]].

** Input frames: LrgCanvasInput
:PROPERTIES:
:CUSTOM_ID: input-frames
:END:
Input is split into two steps so that anything can drive a canvas:

#+begin_example
 graylib devices ──► lrg_canvas_input_poll (&input, dt) ──┐
 your input layer  ──────────────────────────────────────►├──► lrg_canvas_process_input (canvas, &input)
 a replay file / network ────────────────────────────────►│        dispatch, focus, popups,
 a unit test (hand-built frames) ─────────────────────────┘        then lrg_canvas_update (canvas, dt)

 lrg_canvas_handle_input (canvas) == poll (GetFrameTime ()) + process_input
#+end_example

=LrgCanvasInput= (=src/ui/lrg-canvas-input.h=) is a plain value struct describing everything that happened during one frame:

| Field | Meaning |
|-------+---------|
| =pointer_x=, =pointer_y= | Pointer position in *canvas* coordinates |
| =buttons_down= | Mask of buttons held this frame (=LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT)= ...) |
| =buttons_pressed= | Buttons that went down this frame |
| =buttons_released= | Buttons that went up this frame |
| =wheel_x=, =wheel_y= | Wheel movement this frame |
| =keys[]=, =n_keys= | Key presses this frame, oldest first (at most =LRG_CANVAS_INPUT_MAX_KEYS=, 16) |
| =chars[]=, =n_chars= | Composed characters typed this frame (layout, Shift and dead keys applied), oldest first (at most 16) |
| =modifiers= | =LrgInputModifiers= held (=SHIFT=, =CTRL=, =ALT=) |
| =nav= | A focus-navigation request (=LrgNavDirection=) |
| =activate= | Activate the focused widget |
| =cancel= | Back / cancel |
| =delta_time= | Seconds since the previous frame; drives every spring |

| Function | Purpose | Notes |
|----------+---------+-------|
| =lrg_canvas_input_init (self)= | Reset to "nothing happened" (pointer at 0,0, no buttons, keys or navigation, =dt= 0) | Always init before filling by hand |
| =lrg_canvas_input_add_key (self, key)= | Append a key press | Ignored once full |
| =lrg_canvas_input_add_char (self, codepoint)= | Append a typed character | Ignored once full |
| =lrg_canvas_input_add_text (self, utf8)= | Append every character of a string | Tests, on-screen keyboards |
| =lrg_canvas_input_poll (self, delta_time)= | Fill from graylib (needs a window) | See below |
| =lrg_canvas_input_new ()= / =_copy ()= / =_free ()= | Boxed allocation for bindings | =g_autoptr (LrgCanvasInput)= |

What =lrg_canvas_input_poll()= reads:

- the mouse position, mapped through the process-wide pointer transform (=lrg_canvas_set_default_pointer_transform()=, installed by whatever presents a scaled render target, e.g. the 2D game template's virtual resolution);
- left, right and middle button down / pressed / released;
- both wheel axes;
- Shift, Ctrl and Alt (left or right);
- raylib's key-press queue; *Tab is not queued as a key*: it becomes =nav = NEXT= (=PREVIOUS= with Shift);
- raylib's character queue (composed codepoints);
- gamepad 0: D-pad up/down/left/right become =nav=, the bottom face button (A / Cross) =activate=, the right face button (B / Circle) =cancel=; when the D-pad gave nothing, the left stick becomes =nav= once it passes 0.6 on an axis (dominant axis wins), and it must return below 0.3 before it can navigate again (latched, so holding the stick moves one step).

** What process_input does, in order
:PROPERTIES:
:CUSTOM_ID: input-process-order
:END:
1. Ends the previous frame's activation flash (see [[#input-activate][ACTIVATE]]).
2. *Hit test*: =lrg_canvas_widget_at_point()= at the pointer (popups first, see [[#input-hit-testing][hit testing]]). The *target* for pointer events is the capture widget while a button is held, else the hit widget.
3. *Hover*: updates the hover path to the hit widget (=POINTER_LEAVE= / =POINTER_ENTER=, =HOVERED= flags).
4. *Move*: if the pointer moved since the last frame, dispatches =MOUSE_MOVE= to the target; a capture widget gets =PRESSED= while the pointer is over it and loses it while outside.
5. *Presses*: closes non-modal popups above the one clicked into (light dismiss); on a left press, focuses the nearest focusable ancestor of the hit widget (or clears focus when clicking empty space with no modal open) and starts a capture on the hit widget (with =PRESSED=); then dispatches one =MOUSE_BUTTON_DOWN= per pressed button to the target.
6. *Releases*: dispatches one =MOUSE_BUTTON_UP= per released button to the capture widget (or the hit widget); a left release ends the capture and clears =PRESSED=.
7. *Wheel*: =SCROLL= to the hit widget (not the capture).
8. *Keys*: each key as =KEY_DOWN= to the focused widget (or, with nothing focused, the top popup), bubbling. If nobody handled it: an arrow key moves focus spatially (when navigation is enabled), Enter / keypad Enter / Space activate the focus, Escape cancels.
9. *Characters*: each as =TEXT_INPUT= to the focused widget, bubbling.
10. *Navigation*: =nav= moves focus (when navigation is enabled), =activate= activates, =cancel= cancels.
11. *Animation*: =lrg_canvas_update (canvas, delta_time)= steps every spring.

Key presses are dispatched before =nav=, so a widget that wants arrow keys must handle (return =TRUE= for) them; unhandled arrows navigate.

** Dispatch and bubbling
:PROPERTIES:
:CUSTOM_ID: input-bubbling
:END:
Most events are delivered to a target and then *bubble*: the canvas calls =lrg_widget_handle_event()= on the target, then on its parent, then the grandparent, stopping as soon as a handler returns =TRUE= or the canvas itself is reached (the canvas never handles bubbled events). Before delivery the canvas stamps the event with =lrg_ui_event_set_target()= (the original target, readable while bubbling) and =lrg_ui_event_set_bubbling()= (=FALSE= for the target, =TRUE= for ancestors).

#+begin_example
 click on the Label inside a Button inside a Panel

   LrgCanvas             (never receives it)
     └─ LrgPanel         3. handle_event (bubbling = TRUE)   only if 1 and 2 returned FALSE
          └─ LrgButton   2. handle_event (bubbling = TRUE)   returns TRUE: "clicked", stop
               └─ LrgLabel   1. handle_event (bubbling = FALSE, target = label)
#+end_example

=lrg_widget_handle_event()= skips invisible and disabled widgets (returns =FALSE=), so a disabled ancestor is passed over and bubbling continues above it.

Containers do *not* forward bubbling events back down to their children: =LrgContainer='s default =handle_event= returns =FALSE= when =lrg_ui_event_get_bubbling()= is =TRUE=, which prevents the old double delivery. When a non-bubbling event is delivered directly to a container (a legacy call path), the default still offers it to the children front to back.

| Event | Target | Bubbles |
|-------+--------+---------|
| =MOUSE_MOVE= | capture, else widget under the pointer | yes |
| =MOUSE_BUTTON_DOWN= / =UP= | capture, else widget under the pointer | yes |
| =SCROLL= | widget under the pointer | yes |
| =KEY_DOWN= | focused widget, else top popup | yes |
| =TEXT_INPUT= | focused widget | yes |
| =ACTIVATE= | focused widget | yes |
| =CANCEL= | focused widget, else top popup | yes |
| =POINTER_ENTER= / =POINTER_LEAVE= | each widget entering / leaving the hover path | no (sent directly) |
| =FOCUS_IN= / =FOCUS_OUT= | the widget gaining / losing focus | no (sent directly) |
| =KEY_UP= | not generated by the canvas | - |

Only the return value stops bubbling; the event's =consumed= flag (=lrg_ui_event_consume()=) is not consulted by the canvas.

** Pointer capture
:PROPERTIES:
:CUSTOM_ID: input-capture
:END:
The widget hit by a *left* press captures the pointer until the left button is released: it receives every =MOUSE_MOVE= and the =MOUSE_BUTTON_UP= even when the pointer has left its bounds (or the window area of other widgets). This is what makes slider drags, scrollbar drags and "press, slide off, release to cancel" buttons work without each widget tracking global state. While captured, the widget carries =PRESSED= only while the pointer is over it, so a button visibly un-presses when dragged off. Right and middle presses do not capture or focus; their events go to the hit widget.

A widget that implements "click" should therefore treat =MOUSE_BUTTON_UP= with button 0 *inside its bounds* (=lrg_widget_contains_point()= with the event's x/y) as the click; outside means the user cancelled.

Capture is released when the popup containing the captured widget is dismissed.

** Hover
:PROPERTIES:
:CUSTOM_ID: input-hover
:END:
The *hover path* is the hit widget and all its ancestors (below the canvas). Each frame the canvas diffs the old path against the new one:

- widgets that left the path lose =LRG_WIDGET_STATE_HOVERED= and get =POINTER_LEAVE= (innermost first);
- widgets that joined gain =HOVERED= and get =POINTER_ENTER= (outermost first).

So a panel stays hovered while the pointer is over one of its buttons, and moving between two buttons in the same panel sends no events to the panel. =HOVERED= drives the hover spring (=lrg_widget_get_hover_progress()=), which in turn blends the hovered look in (see [[file:styling.org][styling]]). =lrg_canvas_get_hovered_widget()= / the =hovered-widget= property is the innermost hovered widget. Hiding a widget clears its =HOVERED= and =PRESSED= flags.

*Hovering no longer sends =FOCUS_IN= / =FOCUS_OUT=*: those are reserved for keyboard focus. Use =POINTER_ENTER= / =POINTER_LEAVE= or the =HOVERED= state.

** Hit testing
:PROPERTIES:
:CUSTOM_ID: input-hit-testing
:END:
=lrg_canvas_widget_at_point (canvas, x, y)= returns the deepest visible, enabled widget containing the point:

1. Open popups are tested first, newest first. If a popup contains a hit, that is the result. A *modal* popup that does not contain the point stops the search there: its veil swallows the rest of the canvas (=NULL=).
2. Then the canvas tree, depth first, children in reverse order (the last painted is on top).
3. Invisible or disabled widgets and their subtrees are skipped; the canvas itself is never returned.

*** Pointer-transparent widgets
:PROPERTIES:
:CUSTOM_ID: input-pointer-transparent
:END:
=lrg_widget_set_pointer_transparent (widget, TRUE)= makes hit-testing pass through the widget *itself* while its children can still be hit: a click on an empty area of the widget reaches whatever is underneath. Full-screen layers use it: an =LrgOverlay= or a toast queue covering the whole canvas must not block clicks on the game UI beneath except where a toast actually is. =lrg_widget_get_pointer_transparent()= reads it.

** Focus
:PROPERTIES:
:CUSTOM_ID: input-focus
:END:
One widget per canvas has keyboard / gamepad focus (=lrg_canvas_get_focused_widget()=, the =focused-widget= property). It receives =KEY_DOWN=, =TEXT_INPUT=, =ACTIVATE= and =CANCEL= first.

- *Focusable widgets*: only widgets with =lrg_widget_set_focusable (self, TRUE)= take focus by click or navigation; interactive widgets set it in their =init=. Navigation additionally requires the widget to be enabled, have a non-zero size and be visible along with every ancestor.
- *Focus change*: the old widget loses =FOCUSED= and =FOCUS_VISIBLE= and gets =FOCUS_OUT=; the new one gains =FOCUSED= (and =FOCUS_VISIBLE= when focus came from the keyboard or gamepad) and gets =FOCUS_IN=. Both are sent directly (no bubbling).
- *Click focus*: a left press focuses the nearest focusable, enabled ancestor-or-self of the hit widget (clicking a button's label focuses the button). Clicking something with no focusable ancestor *clears* focus; clicking empty canvas clears it too unless a modal popup is open. Click focus never shows the focus ring.
- *Programmatic focus*: =lrg_canvas_set_focused_widget (canvas, widget)= focuses any widget (or =NULL=), without the ring and without checking focusability.

*** Tab order
:PROPERTIES:
:CUSTOM_ID: input-tab-order
:END:
=lrg_canvas_move_focus (canvas, LRG_NAV_DIRECTION_NEXT / PREVIOUS)= walks the *focus scope* in depth-first tree order (children in insertion order), wrapping at both ends. With nothing focused, NEXT starts at the first widget and PREVIOUS at the last. The scope is every navigable widget in the canvas tree followed by those in open popups; while a modal popup is open the scope is *only that popup* (focus trap).

*** Spatial navigation
:PROPERTIES:
:CUSTOM_ID: input-spatial-nav
:END:
Arrow keys (when unhandled) and the gamepad D-pad / stick pick the best widget in a direction, measured between widget centres:

#+begin_example
 primary  = distance along the direction        (must be >= 1 unit, i.e. really ahead)
 sideways = |offset across the direction|
 score    = primary + 2 * sideways               lowest score wins
#+end_example

Sideways distance costs double, so a widget straight ahead beats a slightly closer one off to the side: moving down a column of buttons stays in the column. With nothing focused, any direction focuses the first widget of the scope. When there is nothing in that direction, focus stays and the current widget gets =FOCUS_VISIBLE= so the player sees where they are. =lrg_canvas_move_focus()= returns =TRUE= when focus moved.

*** Focus-visible
:PROPERTIES:
:CUSTOM_ID: input-focus-visible
:END:
=LRG_WIDGET_STATE_FOCUS_VISIBLE= marks focus that the user reached by keyboard or gamepad. =lrg_widget_paint()= draws the focus ring (the =FOCUS= part look: a border =FOCUS_RING_WIDTH= wide, 2 units outside the widget) only in that state, which is the familiar ":focus-visible" behaviour: mouse users never see rings, keyboard and controller users always do. A later click on the focused widget removes the flag.

*** ACTIVATE
:PROPERTIES:
:CUSTOM_ID: input-activate
:END:
Enter, keypad Enter, Space (each only when the focused widget did not handle the key itself) and gamepad A call =lrg_canvas_activate_focus()=. It sets =PRESSED= and =FOCUS_VISIBLE= on the focused widget for one frame (so the press spring gives the activation a visible "squash" and colour change) and dispatches =LRG_UI_EVENT_ACTIVATE= to it, bubbling. Buttons click on it, check boxes toggle, combo boxes open. Implement =ACTIVATE= in every interactive widget so it is usable without a mouse.

*** CANCEL and the ::cancel signal
:PROPERTIES:
:CUSTOM_ID: input-cancel
:END:
Escape (unhandled) and gamepad B:

1. dispatch =LRG_UI_EVENT_CANCEL= to the focused widget (or the top popup when nothing is focused), bubbling; a handler returning =TRUE= ends it (a text field reverting an edit, a dialog closing itself);
2. otherwise, if any popup is open, the top popup is dismissed;
3. otherwise the canvas emits =LrgCanvas::cancel=.

Games connect to =::cancel= for "back" and pause menus:

#+begin_src c
static void
on_ui_cancel (LrgCanvas *canvas,
              gpointer   user_data)
{
	GameState *game = user_data;

	game_toggle_pause_menu (game);
}

g_signal_connect (canvas, "cancel", G_CALLBACK (on_ui_cancel), game);
#+end_src

*** Turning navigation off
:PROPERTIES:
:CUSTOM_ID: input-navigation-enabled
:END:
=lrg_canvas_set_navigation_enabled (canvas, FALSE)= (property =navigation-enabled=, default =TRUE=) stops unhandled arrows and =nav= requests from moving focus, for games that drive focus themselves or use arrows for gameplay while a HUD is up. Activate and cancel still work. =lrg_canvas_move_focus()= can always be called directly.

** Popups
:PROPERTIES:
:CUSTOM_ID: input-popups
:END:
The canvas has a popup layer above its children for menus, combo lists, dialogs, tooltips and context menus. A popup is an ordinary widget (usually a container) that is *not* added as a child: the canvas parents it for coordinates and theme inheritance, paints it after the tree, hit-tests it first and steps its springs.

#+begin_src c
/* a context menu at the pointer, light-dismissed */
lrg_canvas_show_popup (canvas, LRG_WIDGET (menu), NULL,
                       LRG_POPUP_PLACEMENT_AT_POINTER, FALSE);

/* a combo list under its combo box */
lrg_canvas_show_popup (canvas, LRG_WIDGET (list), LRG_WIDGET (combo),
                       LRG_POPUP_PLACEMENT_BELOW, FALSE);

/* a modal dialog centred on the canvas */
lrg_canvas_show_popup (canvas, LRG_WIDGET (dialog), NULL,
                       LRG_POPUP_PLACEMENT_CENTER, TRUE);
#+end_src

| Function | Purpose | Notes |
|----------+---------+-------|
| =lrg_canvas_show_popup (self, popup, anchor, placement, modal)= | Opens a popup | The canvas refs =popup= (and =anchor=) until dismissed; =popup= must have no parent; =anchor= nullable |
| =lrg_canvas_dismiss_popup (self, popup)= | Closes it and every popup opened after it | Emits =::popup-dismissed= per popup; unknown popups are ignored |
| =lrg_canvas_get_top_popup (self)= | Most recent open popup | (transfer none) (nullable) |
| =lrg_canvas_get_popup_count (self)= | Open popups (closing ghosts excluded) | |
| =lrg_canvas_place_popup (...)= | The placement maths, as a pure function | For custom placement and tests |

Signal =LrgCanvas::popup-dismissed (canvas, popup)= fires when a popup is dismissed by any route (API, Escape, light dismiss).

*** Showing: size, placement and flipping
:PROPERTIES:
:CUSTOM_ID: input-popup-placement
:END:
1. *Size*: an explicit width/height on the popup is kept; a zero dimension takes the popup's preferred size.
2. *Anchor*: the anchor's rectangle relative to the canvas. Without an anchor the last pointer position is the anchor point and any placement other than =AT_POINTER= becomes =CENTER=.
3. *Placement* (=lrg_canvas_place_popup()=), with a 6-unit gap and a 4-unit edge margin:

| Placement | Position | Flips when |
|-----------+----------+------------|
| =BELOW= | left edges aligned, top = anchor bottom + gap | it does not fit below *and* it fits above |
| =ABOVE= | left edges aligned, bottom = anchor top - gap | it does not fit above *and* it fits below |
| =RIGHT= | tops aligned, left = anchor right + gap | it does not fit right *and* fits left |
| =LEFT= | tops aligned, right = anchor left - gap | it does not fit left *and* fits right |
| =CENTER= | =x = (canvas_w - w) / 2=, =y = (canvas_h - h) * 0.45= (slightly above centre) | never |
| =AT_POINTER= | top-left at the pointer / anchor point | never (clamped) |

"Fits below" means =anchor_y + anchor_h + gap + popup_h <= canvas_h - edge=; the other sides are analogous. If neither side fits, the requested side is kept. Finally the position is clamped inside the canvas (=edge= .. =canvas - size - edge=) and rounded. =lrg_canvas_place_popup()= returns the placement actually used, so a widget can point an arrow the right way.

4. The popup is allocated at that rectangle (laid out), gets a =POP= appear animation if it has none, and plays it.
5. The anchor gets =LRG_WIDGET_STATE_OPEN= until the popup closes (combo boxes rotate their arrow on it).
6. A *modal* popup takes focus: its first focusable widget is focused, keeping the focus ring if focus was keyboard-visible before.

*** Modal popups
:PROPERTIES:
:CUSTOM_ID: input-popup-modal
:END:
A modal popup:

- dims everything under it with a full-canvas *veil* of =LRG_THEME_COLOR_VEIL= whose alpha fades in with a smooth spring (and out with the popup);
- *swallows pointer input* outside it (hit-testing stops at the modal, see [[#input-hit-testing][hit testing]]), so clicks outside do nothing and do not close it;
- *traps focus*: Tab and spatial navigation only reach widgets inside the top modal popup, and clicking empty space does not clear focus;
- is closed by its own buttons (=lrg_canvas_dismiss_popup()=), or by Escape / gamepad B when no widget handled =CANCEL=.

*** Non-modal popups and light dismiss
:PROPERTIES:
:CUSTOM_ID: input-popup-light-dismiss
:END:
A press outside a non-modal popup closes it ("light dismiss"), and the press still reaches whatever is underneath, so clicking another button while a menu is open both closes the menu and clicks the button. Precisely: on any button press, every non-modal popup stacked above the popup that contains the hit widget is dismissed (all of them when the press is outside every popup), stopping at the first modal one. Nested menus therefore stay open while you click inside a submenu's parent. Escape closes the top popup.

*** Dismissing and ghosts
:PROPERTIES:
:CUSTOM_ID: input-popup-dismiss
:END:
=lrg_canvas_dismiss_popup()= removes the popup and everything above it, newest first. For each one it clears the anchor's =OPEN= state, moves focus back to the anchor when focus was inside the popup (if the anchor is focusable; otherwise clears it), releases a capture inside it, resets the hover path and emits =::popup-dismissed=.

The popup then lingers as a *ghost* for its closing animation: it is painted (no longer hit-tested or focusable) while a snappy spring runs from 1 to 0, scaled from 100 % to 92 % around the anchor's centre (or its own centre without an anchor) and faded out, with a modal veil fading too. When the spring falls below 0.01 the canvas drops its references and unparents the widget. A dismissed popup should not be shown again until its ghost is gone (its parent is still set during the fade, and =show_popup= requires a parentless popup); create a new popup or wait a few frames.

** Driving the canvas yourself: replays and tests
:PROPERTIES:
:CUSTOM_ID: input-testing
:END:
=lrg_canvas_process_input()= is the only entry point the canvas needs, and it takes canvas coordinates (no pointer transform is applied). Games with their own input mapping build frames from their actions; replays serialise frames; tests construct them by hand. Everything is headless: =lrg_canvas_record()= lays out and records without a window.

#+begin_src c
/* frame_at: a frame with the pointer at (x, y) and nothing else */
static void
frame_at (LrgCanvasInput *input,
          gfloat          x,
          gfloat          y)
{
	lrg_canvas_input_init (input);
	input->pointer_x = x;
	input->pointer_y = y;
	input->delta_time = 1.0f / 60.0f;
}

/* click_at: move there, press, release: three frames */
static void
click_at (LrgCanvas *canvas,
          gfloat     x,
          gfloat     y)
{
	LrgCanvasInput input;

	frame_at (&input, x, y);
	lrg_canvas_process_input (canvas, &input);

	frame_at (&input, x, y);
	input.buttons_down = LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);
	input.buttons_pressed = LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);
	lrg_canvas_process_input (canvas, &input);

	frame_at (&input, x, y);
	input.buttons_released = LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);
	lrg_canvas_process_input (canvas, &input);
}

/* increment: "clicked" handler connected swapped, so @count comes first */
static void
increment (gint *count)
{
	(*count)++;
}

static void
test_tab_then_activate (void)
{
	g_autoptr(LrgCanvas) canvas = lrg_canvas_new ();
	LrgButton           *ok = lrg_button_new ("OK");
	LrgCanvasInput       input;
	gint                 clicks = 0;

	lrg_widget_set_size (LRG_WIDGET (canvas), 800.0f, 600.0f);
	lrg_widget_set_position (LRG_WIDGET (ok), 100.0f, 100.0f);
	lrg_widget_set_size (LRG_WIDGET (ok), 120.0f, 36.0f);
	lrg_container_add_child (LRG_CONTAINER (canvas), LRG_WIDGET (ok));
	g_object_unref (ok);                  /* the canvas holds it */
	g_signal_connect_swapped (ok, "clicked", G_CALLBACK (increment), &clicks);

	/* Tab focuses the first focusable widget, with a ring */
	frame_at (&input, 0.0f, 0.0f);
	input.nav = LRG_NAV_DIRECTION_NEXT;
	lrg_canvas_process_input (canvas, &input);
	g_assert_true (lrg_canvas_get_focused_widget (canvas) == LRG_WIDGET (ok));
	g_assert_true (lrg_widget_get_state_flags (LRG_WIDGET (ok)) &
	               LRG_WIDGET_STATE_FOCUS_VISIBLE);

	/* gamepad A activates it */
	frame_at (&input, 0.0f, 0.0f);
	input.activate = TRUE;
	lrg_canvas_process_input (canvas, &input);
	g_assert_cmpint (clicks, ==, 1);

	/* the ring is painted: record headless and look at the list */
	lrg_canvas_record (canvas);
	g_assert_cmpuint (lrg_paint_list_get_n_instances (lrg_canvas_get_paint_list (canvas)), >, 0);
}
#+end_src

=tests/test-ui-input.c= in the source tree uses the same helpers. Typing into a focused text field: =lrg_canvas_input_add_text (&input, "héllo")= and for editing keys =lrg_canvas_input_add_key (&input, GRL_KEY_BACKSPACE)=.

*** Bridging your own input layer
:PROPERTIES:
:CUSTOM_ID: input-own-layer
:END:
#+begin_src c
static void
ui_frame_from_actions (GameInput      *in,
                       LrgCanvasInput *out,
                       gfloat          dt)
{
	lrg_canvas_input_init (out);
	out->delta_time = dt;

	/* virtual cursor driven by the right stick, already in canvas units */
	out->pointer_x = in->cursor_x;
	out->pointer_y = in->cursor_y;
	if (game_input_action_pressed (in, "ui-click"))
	{
		out->buttons_pressed |= LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);
		out->buttons_down |= LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);
	}
	if (game_input_action_released (in, "ui-click"))
		out->buttons_released |= LRG_CANVAS_BUTTON_MASK (GRL_MOUSE_BUTTON_LEFT);

	/* rebindable menu navigation */
	if (game_input_action_pressed (in, "menu-up"))
		out->nav = LRG_NAV_DIRECTION_UP;
	else if (game_input_action_pressed (in, "menu-down"))
		out->nav = LRG_NAV_DIRECTION_DOWN;
	out->activate = game_input_action_pressed (in, "menu-confirm");
	out->cancel = game_input_action_pressed (in, "menu-back");
}
#+end_src

** Typical frame
:PROPERTIES:
:CUSTOM_ID: input-frame-loop
:END:
#+begin_src c
/* update */
lrg_canvas_handle_input (canvas);         /* poll + dispatch + step springs */

/* draw */
BeginDrawing ();
game_draw_world (game);
lrg_canvas_render (canvas);               /* layout + record + one SDF render */
EndDrawing ();
#+end_src

If you skip input for a frame (a cutscene), still call =lrg_canvas_update (canvas, dt)= so animations keep running; =lrg_canvas_update()= returns =TRUE= while anything animates, which a power-saving loop can use to decide whether to redraw.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: input-pitfalls
:END:
- *Handle arrows you use.* A widget that consumes arrow keys (sliders, spin boxes, text cursors) must return =TRUE= for them, otherwise focus moves away as well.
- *Do not rely on hover for focus.* =FOCUS_IN= / =FOCUS_OUT= are keyboard focus only.
- *Containers must not re-dispatch bubbling events* to children in custom =handle_event= implementations; check =lrg_ui_event_get_bubbling()= and chain up.
- *Clicks are on release, inside.* Using =MOUSE_BUTTON_DOWN= to trigger actions breaks drag-off cancellation and fires on the press that also light-dismisses popups.
- *Buttons index from 0*: =lrg_ui_event_get_button()= returns a =GrlMouseButton= (=GRL_MOUSE_BUTTON_LEFT= is 0).
- *Coordinates*: =process_input= wants canvas coordinates; only =poll= applies the pointer transform.
- *Calling both =handle_input= and =update=* steps springs twice per frame.
- *Re-showing a popup* while its ghost is still fading fails the parent precondition (see [[#input-popup-dismiss][ghosts]]).
- *Hidden focus*: hiding the focused widget does not move focus; its key events are skipped (invisible widgets do not handle events) and bubble to visible ancestors. Move focus yourself (=lrg_canvas_move_focus (canvas, LRG_NAV_DIRECTION_NEXT)=) when hiding a focused widget.
