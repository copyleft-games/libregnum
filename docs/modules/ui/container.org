=LrgContainer= (=src/ui/lrg-container.h=, derivable, subclass of =LrgWidget=) is the base of every widget that owns children: the canvas, panels, boxes, grids, scroll boxes, list views, tab views, dialogs and overlays. It owns the child list, spacing and padding, and the =layout_children()= virtual method. Everything else children need (painting, stepping springs, hit-testing, focus traversal, layout recursion) works on any container automatically.

** Overview
:PROPERTIES:
:CUSTOM_ID: container-overview
:END:
What =LrgContainer= provides on top of =LrgWidget=:

| Widget vfunc | Container implementation |
|--------------+--------------------------|
| =paint= | Paints every child with =lrg_widget_paint()= in list order (later children on top) |
| =arrange= | Calls =layout_children()= |
| =measure= | Bounding box of the visible children's measured sizes at their current positions, plus padding on both sides (absolute layout); layout containers override it |
| =handle_event= | Returns =FALSE= for bubbling events; non-bubbling events delivered directly to the container are offered to the children front to back (legacy path) |
| =draw= (legacy) | Draws the children with =lrg_widget_draw()= |

The default =layout_children()= does nothing: children keep the positions and sizes you gave them (absolute layout, as in =LrgCanvas= and =LrgPanel=). Layout containers (=LrgVBox=, =LrgHBox=, =LrgGrid= ...) override it.

** Child management
:PROPERTIES:
:CUSTOM_ID: container-children
:END:
| Function | Purpose | Notes |
|----------+---------+-------|
| =lrg_container_add_child (self, child)= | Append a child | The container takes a reference (drop yours, or use =g_autoptr=); =child= must have no parent; lays out immediately and queues layout |
| =lrg_container_remove_child (self, child)= | Remove a child | Releases the reference; warns if not a child; lays out immediately and queues layout |
| =lrg_container_remove_all (self)= | Remove every child | Releases references; does *not* queue layout (call =lrg_widget_queue_layout()= yourself) |
| =lrg_container_get_child_count (self)= | Number of children | O(n) |
| =lrg_container_get_child (self, index)= | Child by index | (transfer none) (nullable) |
| =lrg_container_get_children (self)= | The child list | (transfer none) (element-type LrgWidget); do not modify |

Children are disposed with the container (=dispose= removes them all).

#+begin_src c
g_autoptr(LrgVBox)  list = lrg_vbox_new ();
g_autoptr(LrgLabel) title = lrg_label_new ("Settings");

lrg_container_add_child (LRG_CONTAINER (list), LRG_WIDGET (title));
/* title is now owned twice: by g_autoptr and by the box; the
 * g_autoptr ref is dropped at scope end, the box keeps its own */
#+end_src

** Spacing and padding
:PROPERTIES:
:CUSTOM_ID: container-spacing
:END:
| Function | Purpose | Notes |
|----------+---------+-------|
| =lrg_container_get_spacing= / =set_spacing= | Gap between children (box and flow layouts) | >= 0; re-lays out and queues layout on change |
| =lrg_container_get_padding= / =set_padding= | Space inside the container's edges | >= 0; uniform on all sides |

Theme-aware containers read =LRG_THEME_METRIC_SPACING= and =PADDING_X= / =PADDING_Y= in their own code; these properties are explicit values in canvas units.

** Layout
:PROPERTIES:
:CUSTOM_ID: container-layout
:END:
| Function / vfunc | Purpose |
|------------------+---------|
| =LrgContainerClass.layout_children (self)= | Place every visible child, normally with =lrg_widget_place_in_slot()= in the container's coordinates |
| =lrg_container_layout_children (self)= | Run it now |

Layout is driven by the canvas: =lrg_widget_queue_layout()= marks dirty widgets, and before each paint =lrg_widget_layout()= arranges marked containers (which calls =layout_children()=) and recurses into marked children. Writing a =layout_children()=:

#+begin_src c
static void
game_two_columns_layout_children (LrgContainer *container)
{
	gfloat pad = lrg_container_get_padding (container);
	gfloat gap = lrg_container_get_spacing (container);
	gfloat w = lrg_widget_get_width (LRG_WIDGET (container)) - pad * 2.0f;
	gfloat h = lrg_widget_get_height (LRG_WIDGET (container)) - pad * 2.0f;
	gfloat col = (w - gap) * 0.5f;
	LrgWidget *left = lrg_container_get_child (container, 0);
	LrgWidget *right = lrg_container_get_child (container, 1);

	/* slots in the container's coordinates; margins, alignment and
	 * min/max of each child are applied by place_in_slot */
	if (left != NULL)
		lrg_widget_place_in_slot (left, pad, pad, col, h);
	if (right != NULL)
		lrg_widget_place_in_slot (right, pad + col + gap, pad, col, h);
}
#+end_src

Measurement, slots, box and grid algorithms, dirty propagation and a full custom-container example (a wrapping flow box) are in [[file:layout.org][UI layout]].

** Notes
:PROPERTIES:
:CUSTOM_ID: container-notes
:END:
- A custom =handle_event= on a container must ignore bubbling events for its children (check =lrg_ui_event_get_bubbling()=, or chain up first): the canvas already delivered the event to the child before it bubbled to you. Forwarding it down again delivers it twice.
- =add_child= and =remove_child= still run =layout_children()= immediately for code that reads child positions right after adding them; the canvas lays out again before painting anyway.
- Overriding =paint= in a container replaces child painting; call =lrg_widget_paint()= on each child yourself (or chain up) after drawing your own background.
- Children of an invisible container are neither painted, stepped nor hit-tested.
