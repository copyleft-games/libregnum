* Menu Widget
:PROPERTIES:
:CUSTOM_ID: menu-widget
:END:

** Overview
:PROPERTIES:
:CUSTOM_ID: menu-overview
:END:
=LrgMenu= is a popup menu: a floating surface with rows of commands, built from a =GMenuModel= (=GMenu=), the GLib-standard description of menus that GTK and GApplication also use. It opens on the canvas popup layer, anchored to a widget (a button, a menu bar title) or at a point (a context menu), with a soft shadow, the theme's popup radius and the canvas's appear / ghost-close animations.

What it does:
- Rows come from the model: items (label, GIO action and target, accelerator, icon), sections (fenced by separators, optionally with a muted header), and submenus (nested =LrgMenu= popups beside their item).
- Choosing an item closes the whole menu chain, runs the item's action through =lrg_widget_activate_action()= on the widget the menu was opened for (its /owner/), and emits =activated= with the action name.
- Rows reflect their action live: a boolean-state action draws a check mark, a string-state action draws a radio dot on the item whose target matches, and items whose action is missing or disabled are greyed out and skipped by the keyboard.
- The highlight is one rounded shape that glides from row to row on springs (Raven-style sliding highlight) and fades in and out.
- Submenus open after the pointer rests on their item for a short delay (=submenu-delay=, 0.2 s), or at once with Right / Enter. A /safe triangle/ keeps the submenu open while the pointer travels diagonally towards it across other rows.
- Full keyboard support: Up / Down (wrapping, skipping separators, headers and disabled rows), Right / Left open and close submenus, Enter / Space activate, Escape closes one level, and type-ahead by first letter (or mnemonic).
- Right-to-left layouts mirror everything: submenus open to the left, chevrons point left, labels and accelerators swap sides, and Left becomes the "open submenu" key.

All timing (hover delay, the safe-triangle grace period, type-ahead reset, the highlight glide) runs in the widget's =step()= on the canvas clock, so tests drive it deterministically with =lrg_canvas_update()=.

** Creation
:PROPERTIES:
:CUSTOM_ID: menu-creation
:END:
#+begin_src c
g_autoptr(GMenu)     model = g_menu_new ();
g_autoptr(GMenu)     edit = g_menu_new ();
g_autoptr(GMenu)     view = g_menu_new ();
g_autoptr(GMenuItem) undo = g_menu_item_new ("_Undo", "doc.undo");
g_autoptr(LrgMenu)   menu = NULL;

/* Items carry an action, an optional target, an accel and an icon */
g_menu_item_set_attribute (undo, "accel", "s", "<Ctrl>z");
g_menu_item_set_attribute (undo, "icon", "s", "refresh");
g_menu_append_item (edit, undo);
g_menu_append (edit, "_Redo", "doc.redo");
g_menu_append_section (model, NULL, G_MENU_MODEL (edit));

/* A labelled section: a separator, a muted header, then its items */
g_menu_append (view, "Show _grid", "doc.grid");          /* boolean state: check mark */
g_menu_append (view, "Light", "doc.theme::light");        /* string state: radio */
g_menu_append (view, "Dark", "doc.theme::dark");
g_menu_append_section (model, "View", G_MENU_MODEL (view));

menu = lrg_menu_new_from_model (G_MENU_MODEL (model));
#+end_src

The menu resolves =doc.undo= from its owner up through the owner's ancestors to the canvas (see [[file:../actions.org][actions]]), so insert the action group on the canvas or on a container around the owner:

#+begin_src c
lrg_widget_insert_action_group (LRG_WIDGET (canvas), "doc", G_ACTION_GROUP (doc_actions));
#+end_src

** Model attributes
:PROPERTIES:
:CUSTOM_ID: menu-model-attributes
:END:
| Attribute / link | Type | Meaning |
|------------------+------+---------|
| =label= | =s= | Row text. =_x= marks the mnemonic =x=, =__= is a literal underscore. |
| =action= | =s= | Action name, "prefix.name". =g_menu_item_new()= splits detailed names ("doc.theme::dark") into action and target. |
| =target= | any | Parameter passed to the action; for string-state actions, the radio value. |
| =accel= | =s= | Accelerator ("<Ctrl><Shift>s"), shown right-aligned as =lrg_accel_to_label()= formats it. Display only: register the shortcut itself with =lrg_canvas_add_shortcut()=. Without this attribute the row shows the shortcut bound to its action and target on the canvas (=lrg_canvas_get_accel_for_action()=), so usually you only register the shortcut. |
| =icon= | =s= | An =LrgIcon= nick ("folder", "gear", "trash"), drawn in the leading gutter when the row has no check or radio mark. |
| section link | model | Separator before and after, plus a header row when the section has a label. Empty sections add nothing; separators are never leading, trailing or doubled. |
| submenu link | model | The row opens a nested menu; a chevron is drawn at its trailing edge. |

An item is enabled when its action is found and enabled (GTK's rule: an item whose action cannot be found is insensitive). Submenu rows are always enabled. Separators and headers are never highlighted.

The menu follows =items-changed= on its top-level model and rebuilds its rows (closing an open submenu). Edits inside a section or submenu model are picked up at the next rebuild; edit through the top-level model, or call =lrg_menu_set_model()= again.

** Opening and closing
:PROPERTIES:
:CUSTOM_ID: menu-opening
:END:
| Function | Use |
|----------+-----|
| =lrg_menu_popup_at_widget (menu, widget, placement)= | Open next to a widget (=LRG_POPUP_PLACEMENT_BELOW=, =ABOVE=, =LEFT=, =RIGHT=); flips when it does not fit. The widget becomes the owner and gets =LRG_WIDGET_STATE_OPEN=. |
| =lrg_menu_popup_at_point (menu, owner, x, y)= | Context menu with its corner at a canvas point; flips horizontally and vertically near the edges. |
| =lrg_menu_popup_at_rect (menu, owner, x, y, w, h, placement)= | Open next to an arbitrary rectangle in canvas coordinates (a menu bar title, a cell of a custom widget). |
| =lrg_menu_close (menu)= | Close the menu and its submenus; they fade out as ghosts. |

Opening gives the menu keyboard focus. Re-opening an open menu moves it. Closing (by any path: item chosen, Escape, click outside, code) emits =closed= and returns focus to the owner when it is focusable. A click outside the menu stack closes it (the click still reaches what is underneath).

Below / above placements align the menu's leading edge with the anchor: its left edge, or its right edge in right-to-left layouts.

** Context menus
:PROPERTIES:
:CUSTOM_ID: menu-context
:END:
The easy way: set a model on the widget and let the canvas do the rest (GTK style):

#+begin_src c
g_autoptr(GMenu) menu = g_menu_new ();

g_menu_append (menu, "_Rename", "item.rename");
g_menu_append (menu, "_Delete", "item.delete");
lrg_widget_set_context_menu (row, G_MENU_MODEL (menu));
#+end_src

An unhandled right press on =row= or any descendant opens an =LrgMenu= from the model at the pointer, owned by =row= (actions resolve from it); Shift+F10 or the Menu key opens it below the focused widget with the first row highlighted. The property is =context-menu=. See [[file:../input-and-focus.org::#input-context-menus][context menus]] in the input page.

Opening a menu yourself from a press works without boilerplate too. When the widget that holds the pointer capture opens a popup during the press, the canvas hands the gesture to the popup: moves and the release over the menu (or a submenu) reach it, elsewhere they still reach the widget. So press-drag-release picks a row in one gesture:

#+begin_src c
static gboolean
my_item_handle_event (LrgWidget        *widget,
                      const LrgUIEvent *event)
{
	MyItem *self = MY_ITEM (widget);

	if (lrg_ui_event_get_event_type (event) == LRG_UI_EVENT_MOUSE_BUTTON_DOWN &&
	    lrg_ui_event_get_button (event) == 1)
	{
		LrgWidget *canvas = lrg_widget_get_root (widget);

		/* Canvas coordinates: world minus the canvas origin */
		lrg_menu_popup_at_point (self->context_menu, widget,
		                         lrg_ui_event_get_x (event) - lrg_widget_get_world_x (canvas),
		                         lrg_ui_event_get_y (event) - lrg_widget_get_world_y (canvas));
		return TRUE;
	}
	return MY_ITEM_CLASS (my_item_parent_class)->handle_event (widget, event);
}
#+end_src

*Advanced*: =lrg_menu_forward_pointer_event (menu, event)= delivers a pointer event the widget received to the open menu chain under the pointer. It is no longer needed for the gestures above; use it only when a widget routes pointer events to a menu itself (for example events it synthesises, or a menu opened outside the press that started the capture).

The release of the press that opened the menu does not activate anything: a release only activates once the pointer has moved inside the menu or a button was pressed in it. Dragging onto a row and releasing (either button) picks that row. =LrgMenuBar= relies on the same hand-over for its titles.

** Pointer, keyboard and gamepad
:PROPERTIES:
:CUSTOM_ID: menu-input
:END:
| Input | Effect |
|-------+--------|
| Pointer over a row | Highlight glides to it. Over a separator, header, disabled row or the padding the highlight fades out (an open submenu's item stays lit). |
| Pointer rests on a submenu row | Its submenu opens after =submenu-delay=. Resting on another row closes an open submenu after the same delay. |
| Pointer heading into an open submenu | Rows crossed inside the safe triangle (from the last pointer position to the submenu's near edge) do not take the highlight; if the pointer stops on one, it takes over after 1.5 × =submenu-delay=. |
| Pointer enters a submenu | Keyboard focus follows it. |
| Click / release on an item | Close the chain, run the action, emit =activated=. On a submenu row: open it at once. |
| Up / Down | Previous / next enabled row, wrapping, skipping separators and headers. |
| Home / End | First / last enabled row. |
| Right (Left in RTL) | On a submenu row: open it, focus it, highlight its first row. Otherwise: emit =move-out= (a menu bar switches to the next title). |
| Left (Right in RTL) | In a submenu: close it, focus back on the parent. In a top-level menu: emit =move-out=. |
| Enter / Space / gamepad A | Activate the highlighted row (opens a submenu row). |
| Escape / gamepad B | Close this level only; focus returns to the parent menu (or the owner). |
| Typing a letter | Highlight the next row whose mnemonic (or first letter) matches, cycling through repeats; letters typed within a second extend the prefix and match whole labels. |
| Tab | Swallowed: focus stays in the menu. |
| Mouse wheel | Swallowed. |

Mnemonic underlines are drawn while the menu is driven by the keyboard (opened with keys, or after a key press).

:PROPERTIES:
:CUSTOM_ID: menu-parts
:END:
| Part | Default look | Notes |
|------+--------------+-------|
| =popup= | =POPUP= fill, =BORDER= hairline, =POPUP_RADIUS=, =SHADOW= with =SHADOW_BLUR= / =SHADOW_OFFSET_Y= | The menu surface |
| =item= | =CONTROL_HOVER= fill, =CORNER_RADIUS=, =TEXT= foreground | The gliding highlight is the =hovered= look; the =disabled= look's foreground (=DISABLED=) greys disabled rows; =pressed= → =CONTROL_PRESSED= |

| =mark= | =ACCENT= foreground | Check marks and radio dots |
| =arrow= | =TEXT_MUTED= foreground | Submenu chevrons (the open submenu's chevron uses the row text colour) |
| =track= | =BORDER= background | Separator lines |
| =focus= | no ring | The highlight shows keyboard position |

Submenus copy their parent's style classes when they are created, so a rule aimed at a class reaches the whole chain.

** YAML
:PROPERTIES:
:CUSTOM_ID: menu-yaml
:END:
Supported by =LrgUILoader= as =LrgMenu= (=type: menu=). =model:= takes a menu: a list of entries or the name of a menu declared under the document's top-level =menus:= (see [[file:../declarative-ui.org::#menus][Declarative UI]]). =submenu-delay= is a plain property. The same menu syntax works for =LrgWidget:context-menu= on any widget, which is the usual way to get a popup without code.

#+begin_src yaml
menus:
  clipboard:
    - {label: Cu_t, action: app.cut, accel: "<Ctrl>x"}
    - {label: _Copy, action: app.copy, accel: "<Ctrl>c", icon: file}
    - separator                                   # starts a new section
    - {label: _Paste, action: app.paste, accel: "<Ctrl>v"}
root:
  type: vbox
  children:
    - {type: menu, id: popup, model: clipboard, submenu-delay: 0.2}
    - type: text-input
      context-menu:                               # inline, no LrgMenu needed
        - {section: clipboard, label: Edit}
        - label: Insert
          submenu: [{label: Date, action: app.insert, target: date}]
#+end_src

Entry keys: =label= (=_= marks the mnemonic), =action= (="prefix.action"=), =target= / =target-type= (the parameter), =accel= (shown as the shortcut label), =icon= (an =LrgIcon= nick), =submenu= / =section= (a nested menu or a menu name), =separator=, =if=. Pop the menu from code after loading: =lrg_menu_popup_at_widget (LRG_MENU (lrg_ui_loader_get_widget (loader, "popup")), anchor, LRG_POPUP_PLACEMENT_BELOW)=. A hot reload sets =model= again only when the menu's content changed.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: menu-pitfalls
:END:
- An item without an action, or whose action is not reachable from the owner, is disabled. Insert the action group on the canvas or on an ancestor of the owner before opening the menu.
- The =accel= attribute only labels the row; register the shortcut with =lrg_canvas_add_shortcut()= so it works while the menu is closed (and then the attribute is unnecessary).
- A menu opened from a press receives the captured pointer only while the pointer is over the menu chain; a release elsewhere still goes to the pressed widget (and leaves the menu open), so do not close the menu on every =MOUSE_BUTTON_UP= the widget sees.
- Held Enter / Space (auto-repeat) never activate a row: only a fresh press does.
- A stateful boolean action used as a check item must have no parameter type; =GSimpleAction= then toggles it on activation by itself.
- Context menus need the owner on a canvas; =lrg_menu_popup_at_point()= takes canvas coordinates, not world coordinates (they differ when the canvas is not at the origin).
- Hover delays and the highlight glide only advance when the canvas is updated; a paused game loop that stops calling =lrg_canvas_update()= freezes them.
