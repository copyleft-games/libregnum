* UI Module
:PROPERTIES:
:CUSTOM_ID: ui-module
:END:
#+begin_quote
*[[file:../../index.org][Home]]* > *[[file:../index.org][Modules]]* > UI
#+end_quote

The UI module (=src/ui/=) is a retained-mode widget toolkit for game menus, HUDs, inventories, dialogs and settings screens. Widgets form a tree under an =LrgCanvas=; the canvas turns input into events, keeps keyboard and gamepad focus, lays out what changed, animates state changes with springs, and records the whole tree into one paint list that the [[file:../paint/index.org][SDF paint renderer]] draws, usually in a single draw call, with anti-aliased rounded shapes, soft shadows, gradients and crisp text.

It is distinct from the immediate-mode [[file:../gui/index.org][GUI module]] used by the editor, although both share the paint renderer and can share a theme.

** Quick start
:PROPERTIES:
:CUSTOM_ID: ui-quick-start
:END:
#+begin_src c
#include <libregnum.h>

static void
on_play (LrgButton *button,
         gpointer   user_data)
{
	g_message ("play!");
}

static LrgCanvas *
build_menu (gfloat width,
            gfloat height)
{
	LrgCanvas *canvas = lrg_canvas_new ();
	LrgVBox   *menu = lrg_vbox_new ();
	LrgLabel  *title = lrg_label_new ("Ember Keep");
	LrgButton *play = lrg_button_new ("Play");
	LrgButton *quit = lrg_button_new ("Quit");

	lrg_widget_set_size (LRG_WIDGET (canvas), width, height);

	/* a centred column, 280 units wide */
	lrg_widget_set_size (LRG_WIDGET (menu), 280.0f, 220.0f);
	lrg_widget_set_position (LRG_WIDGET (menu), (width - 280.0f) * 0.5f, height * 0.3f);
	lrg_container_set_spacing (LRG_CONTAINER (menu), 10.0f);

	lrg_widget_set_halign (LRG_WIDGET (title), LRG_ALIGN_CENTER);
	lrg_widget_add_class (LRG_WIDGET (play), "primary");
	lrg_widget_set_appear (LRG_WIDGET (play), LRG_APPEAR_FLY_UP, 0.00f);
	lrg_widget_set_appear (LRG_WIDGET (quit), LRG_APPEAR_FLY_UP, 0.06f);
	g_signal_connect (play, "clicked", G_CALLBACK (on_play), NULL);

	/* containers take their own reference */
	lrg_container_add_child (LRG_CONTAINER (menu), LRG_WIDGET (title));
	lrg_container_add_child (LRG_CONTAINER (menu), LRG_WIDGET (play));
	lrg_container_add_child (LRG_CONTAINER (menu), LRG_WIDGET (quit));
	lrg_container_add_child (LRG_CONTAINER (canvas), LRG_WIDGET (menu));
	g_object_unref (title);
	g_object_unref (play);
	g_object_unref (quit);
	g_object_unref (menu);

	return canvas;
}

/* in the game loop */
static void
frame (LrgCanvas *canvas)
{
	lrg_canvas_handle_input (canvas);      /* events, focus, springs */

	BeginDrawing ();
	ClearBackground (BLACK);
	/* ... the game scene ... */
	lrg_canvas_render (canvas);            /* layout + paint + one SDF draw */
	EndDrawing ();
}
#+end_src

Set a look for the whole UI with a preset (=lrg_theme_set_default()= takes its own reference, so drop yours):

#+begin_src c
g_autoptr(LrgTheme) theme = lrg_theme_new_preset ("catppuccin-mocha");

lrg_theme_set_default (theme);
#+end_src

or load a theme file ([[file:../../guides/theming.org][theming guide]]).

** Core concepts
:PROPERTIES:
:CUSTOM_ID: ui-concepts
:END:
*** The tree
:PROPERTIES:
:CUSTOM_ID: ui-tree
:END:
Every element derives from =LrgWidget=; elements with children derive from =LrgContainer=. Containers own references to their children. Positions are relative to the parent; =lrg_widget_get_world_x/y()= give absolute positions. =lrg_widget_find (root, "name")= finds a named widget.

*** Painting, not drawing
:PROPERTIES:
:CUSTOM_ID: ui-painting
:END:
Widgets implement =paint (self, LrgPaintList *list)= and record shapes at world coordinates; they never touch the GPU. The canvas records the whole tree each frame (=lrg_canvas_record()=) and renders it once. This is what allows post-layout appear animations, per-pixel clipping without batch breaks, headless tests (record and inspect without a window) and one draw call per frame. Older widgets implementing =draw()= still work through a paint callback. See [[file:../paint/index.org][the paint module]].

*** Looks, parts and themes
:PROPERTIES:
:CUSTOM_ID: ui-looks
:END:
A widget is drawn from looks (=LrgPartLook=) of named parts (box, label, thumb, track ...). Its =style_defaults()= fills each look from theme colour roles and metrics; theme style rules override fields by widget type, style class, part and state, CSS-style. Themes come from presets or YAML files and can be scoped to subtrees. See [[file:styling.org][styling]] and [[file:theme.org][LrgTheme]].

*** State and motion
:PROPERTIES:
:CUSTOM_ID: ui-state
:END:
Widgets carry state flags (=HOVERED=, =PRESSED=, =FOCUSED=, =FOCUS_VISIBLE=, =DISABLED=, =CHECKED=, =SELECTED=, =OPEN=). Hover and press drive springs that blend the looks continuously; entrance animations scale, slide and fade widgets in after layout. All motion follows the theme's preset and the global reduced-motion switch. See [[file:animation.org][animation]].

*** Input and focus
:PROPERTIES:
:CUSTOM_ID: ui-input
:END:
Events bubble from the target widget to its ancestors until handled; a pressed widget captures the pointer; the canvas manages hover enter/leave, click focus, Tab order, spatial arrow and gamepad navigation, activation and cancel, and a popup layer with placement, flipping, modality and light dismiss. Input frames (=LrgCanvasInput=) can come from graylib, your own input mapping, a replay or a test. See [[file:input-and-focus.org][input and focus]].

*** Layout
:PROPERTIES:
:CUSTOM_ID: ui-layout
:END:
Widgets report preferred sizes (=measure=) and declare margin, alignment, fill weight and min/max hints; containers place children in slots (=lrg_widget_place_in_slot()=). Only subtrees marked with =lrg_widget_queue_layout()= are laid out each frame. See [[file:layout.org][layout]].

** What changed in the paint rework
:PROPERTIES:
:CUSTOM_ID: ui-changes
:END:
For code written before the rework (see [[file:../../guides/ui-migration.org][the migration guide]] for details):

- Rendering goes through =paint()= and the SDF renderer; =draw()= still works for old widgets.
- Hover no longer sends =FOCUS_IN= / =FOCUS_OUT=; events bubble; containers do not re-broadcast bubbling events; clicks focus the nearest focusable widget (or clear focus).
- The theme has roles, metrics, presets, YAML and style rules; the default corner radius is now 8 (was 4).
- =lrg_canvas_handle_input()= is now poll + =lrg_canvas_process_input()=, and also steps animations.
