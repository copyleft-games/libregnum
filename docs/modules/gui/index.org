* GUI Module Reference

#+begin_quote

The GUI module (=src/gui/=) is a small immediate-mode UI toolkit in the spirit of Dear ImGui, written for libregnum's own tools. The editor application (=lrg-editor=, see [[file:../../editor/editor-app.org][The libregnum Editor Application]]) is built entirely from it, and it is equally usable for in-game debug overlays, consoles and tool windows. It is always built (no build flag) and its headers are pulled in by =<libregnum.h>=.

It is a different thing from the retained-mode widget tree in [[file:../ui/index.org][the UI module]] (=LrgWidget= and friends): there are no widget objects here. Each frame the program calls widget functions in the order they appear; each call lays itself out, reacts to the input snapshot, records drawing commands and returns what happened ("clicked", "value changed").

*** The immediate-mode model
:PROPERTIES:
:CUSTOM_ID: immediate-mode-model
:END:
The UI is a function of the application state, re-run every frame. There is no "create a button, connect a signal, destroy the button": the code that describes the UI is also the code that handles it.

#+begin_src c
lrg_gui_context_begin_frame (ctx, &input, width, height);
lrg_gui_begin_region (ctx, "panel", &rect, LRG_GUI_REGION_SCROLL_Y);
if (lrg_gui_button (ctx, "Save"))
	save ();
lrg_gui_drag_float3 (ctx, "Position", pos, 0.05f, "%.2f");
lrg_gui_end_region (ctx);
lrg_gui_context_end_frame (ctx);
lrg_gui_raylib_render (backend, lrg_gui_context_get_draw_list (ctx));
#+end_src

State that must survive between frames (tree open flags, scroll offsets, the text being edited, open popups, the selected tab, the widget being dragged) lives inside the context in a hash table keyed by widget identity (see [[#identity][Identity and the ID stack]]). Application data (the float being edited, the boolean behind a checkbox) stays in the application and is passed by pointer.

*** Backend-agnostic split
:PROPERTIES:
:CUSTOM_ID: backend-split
:END:
The toolkit never touches a window, a GPU or a font file. Work flows in one direction:

#+begin_example
platform ──> LrgGuiInput ──> LrgGuiContext widgets ──> LrgGuiDrawList ──> backend renders
             (snapshot)       (layout + logic)          (plain structs)
#+end_example

- *Input* is a plain struct (=LrgGuiInput=) that a backend fills (=lrg_gui_raylib_poll_input()=) or a test constructs by hand.
- *Output* is a list of plain command structs (=LrgGuiCommand=) that a backend replays (=lrg_gui_raylib_render()=) or a test inspects (=lrg_gui_draw_list_find_text()=).
- *Text measurement* and the *clipboard* are callbacks. Without them the context uses a fixed 0.55 em per character and an internal clipboard buffer, so layout is deterministic headless.

*** Why it exists
:PROPERTIES:
:CUSTOM_ID: why
:END:
- *The editor.* An editor needs docking, trees, inspectors, drag and drop, menus, modals and a 3D viewport composited under overlays; the toolkit was shaped by those needs.
- *In-game tools.* Debug panels, consoles and cheat menus can be dropped into any game loop with a handful of calls, sharing the engine's raylib window.
- *Headless tests.* Because input and output are plain data, every widget is exercised by =tests/test-gui.c= without a display: inject synthetic frames, assert on return values and recorded draw commands.

** Frame loop
:PROPERTIES:
:CUSTOM_ID: frame-loop
:END:
#+begin_src c
LrgGuiContext * lrg_gui_context_new            (void);
void            lrg_gui_context_begin_frame    (LrgGuiContext     *self,
                                                const LrgGuiInput *input,
                                                gfloat             width,
                                                gfloat             height);
void            lrg_gui_context_end_frame      (LrgGuiContext     *self);
LrgGuiDrawList *lrg_gui_context_get_draw_list  (LrgGuiContext     *self);
guint64         lrg_gui_context_get_frame      (LrgGuiContext     *self);
LrgGuiCursor    lrg_gui_context_get_cursor     (LrgGuiContext     *self);
gboolean        lrg_gui_context_wants_mouse    (LrgGuiContext     *self);
gboolean        lrg_gui_context_wants_keyboard (LrgGuiContext     *self);
gboolean        lrg_gui_context_needs_redraw   (LrgGuiContext     *self);
#+end_src

=lrg_gui_context_begin_frame()= copies the input, derives per-button click/release/double-click transitions (double-click: second press within 0.30 s and 6 px), clears the draw layers, resets the ID stack and region stack, and processes popup dismissal: a mouse press outside the top-most popups closes them (modals are never closed this way), and Escape closes the top popup unless a text field has focus. It then opens an implicit root region covering the whole window (=LRG_GUI_REGION_NO_PADDING=), so widgets can be called without any explicit region.

=lrg_gui_context_end_frame()= closes any regions left open, drops popups that were not built this frame, releases the active/focused widget if it was not submitted this frame (a widget that vanished cannot keep the pointer captured), emits the tooltip or drag preview, ends a drag when the left button is up, and merges the internal layers (base, popup, overlay) into the final draw list in that order. The returned list stays valid until the next =begin_frame=.

The queries after =end_frame= are what a host uses to route input and schedule frames:

| Function | Meaning |
|----------+---------|
| =lrg_gui_context_wants_mouse()= | Pointer is over UI or a widget is active: the 3D scene should ignore the mouse |
| =lrg_gui_context_wants_keyboard()= | A text field has keyboard focus: game/editor hotkeys should not fire |
| =lrg_gui_context_needs_redraw()= | Something animates (caret blink, drags): an event-driven host should schedule another frame |
| =lrg_gui_context_get_cursor()= | Pointer shape requested this frame (pass to =lrg_gui_raylib_apply_cursor()=) |
| =lrg_gui_context_get_frame()= | Number of frames begun |

Coordinates everywhere are window pixels with the origin at the top left.

** Input snapshot
:PROPERTIES:
:CUSTOM_ID: input-snapshot
:END:
#+begin_src c
#define LRG_GUI_MAX_INPUT_EVENTS (64)

typedef struct
{
	LrgGuiKey       key;
	LrgGuiModifiers mods;
	gboolean        repeat;
} LrgGuiKeyEvent;

typedef struct
{
	gfloat          mouse_x;
	gfloat          mouse_y;
	gboolean        mouse_down[LRG_GUI_MOUSE_BUTTON_COUNT];
	gfloat          wheel_x;
	gfloat          wheel_y;
	LrgGuiModifiers mods;
	LrgGuiKeyEvent  keys[LRG_GUI_MAX_INPUT_EVENTS];
	guint           n_keys;
	gunichar        chars[LRG_GUI_MAX_INPUT_EVENTS];
	guint           n_chars;
	gboolean        key_down[LRG_GUI_KEY_COUNT];
	gdouble         time;
	gfloat          delta;
} LrgGuiInput;

void lrg_gui_input_init      (LrgGuiInput     *input);
void lrg_gui_input_new_frame (LrgGuiInput     *input,
                              gfloat           delta);
void lrg_gui_input_add_key   (LrgGuiInput     *input,
                              LrgGuiKey        key,
                              LrgGuiModifiers  mods);
void lrg_gui_input_add_text  (LrgGuiInput     *input,
                              const gchar     *text);
#+end_src

The snapshot mixes *held state* (=mouse_down=, =key_down=, =mods=, pointer position) with *per-frame events* (=keys=, =chars=, wheel deltas). =lrg_gui_input_init()= zeroes the struct and parks the pointer far outside any window. =lrg_gui_input_new_frame()= clears only the per-frame events and advances =time= by =delta=, keeping held state, so a host (or test) calls it once at the top of each frame and then updates what changed. =lrg_gui_input_add_key()= appends a press and also marks the key held; =lrg_gui_input_add_text()= appends the UTF-8 text as typed characters. Clicks are not events: the context detects them from =mouse_down= changing between consecutive frames, so a click takes two frames (down, then up).

=wheel_y= is positive when the wheel moves away from the user. Keys are backend-independent =LrgGuiKey= values (=LRG_GUI_KEY_TAB= ... =LRG_GUI_KEY_A= .. =LRG_GUI_KEY_Z=, =LRG_GUI_KEY_0= .. =LRG_GUI_KEY_9=, =LRG_GUI_KEY_F1= .. =LRG_GUI_KEY_F12=, punctuation, keypad, with =LRG_GUI_KEY_COUNT= as the array size); keypad Enter maps to =LRG_GUI_KEY_ENTER=. Modifiers are the bits =LRG_GUI_MOD_CTRL=, =LRG_GUI_MOD_SHIFT=, =LRG_GUI_MOD_ALT=, =LRG_GUI_MOD_SUPER=. Mouse buttons are =LRG_GUI_MOUSE_LEFT=, =LRG_GUI_MOUSE_RIGHT=, =LRG_GUI_MOUSE_MIDDLE= (=LRG_GUI_MOUSE_BUTTON_COUNT= = 3).

** Identity and the ID stack
:PROPERTIES:
:CUSTOM_ID: identity
:END:
#+begin_src c
LrgGuiId lrg_gui_get_id      (LrgGuiContext *self,
                              const gchar   *str);
void     lrg_gui_push_id     (LrgGuiContext *self,
                              const gchar   *str);
void     lrg_gui_push_id_int (LrgGuiContext *self,
                              gint64         value);
void     lrg_gui_push_id_ptr (LrgGuiContext *self,
                              gconstpointer  ptr);
void     lrg_gui_pop_id      (LrgGuiContext *self);
#+end_src

Every interactive widget has an =LrgGuiId=: an FNV-1a hash of its label seeded with the hash on top of the ID stack. Two widgets with the same label in the same scope share state (and fight over the pointer), so repeated rows push a scope first:

#+begin_src c
for (i = 0; i < n_nodes; i++)
{
	lrg_gui_push_id_ptr (ctx, nodes[i]);
	if (lrg_gui_button (ctx, "Delete"))
		delete_node (nodes[i]);
	lrg_gui_pop_id (ctx);
}
#+end_src

Label rules:

| Label | Displayed | Identity hashed |
|-------+-----------+-----------------|
| ="Save"= | =Save= | ="Save"= |
| ="Delete##node42"= | =Delete= | ="Delete##node42"= (whole string) |
| ="##rename"= | nothing | ="##rename"= |
| ="Inspector (3)###inspector"= | =Inspector (3)= | ="inspector"= only |

- *"##"*: everything from =##= on is hidden but stays part of the identity. Use it to give identical visible labels distinct identities, or to make a label-less field.
- *"###"*: only the part after =###= is hashed, so the visible text can change frame to frame (counts, dirty markers, dynamic tab titles) while the widget keeps its state.
- =lrg_gui_text()= and friends are not parsed for =##=; =lrg_gui_calc_text_width()= ignores the hidden part.
- The ID stack is reset at every =begin_frame=; =lrg_gui_tree_node()= and =lrg_gui_dock_begin_panel()= push their own scope.

A region is a clipped layout area with its own cursor. Scroll offsets are kept per =str_id=.

| Flag | Effect |
|------+--------|
| =LRG_GUI_REGION_NONE= | Plain clipped area with padding |
| =LRG_GUI_REGION_SCROLL_Y= | Vertical scrolling via wheel and scrollbar |
| =LRG_GUI_REGION_SCROLL_X= | Horizontal scrolling via Shift+wheel and scrollbar |
| =LRG_GUI_REGION_BORDER= | Draw a border |
| =LRG_GUI_REGION_BACKGROUND= | Fill with =LRG_GUI_COL_PANEL_BG= |
| =LRG_GUI_REGION_NO_PADDING= | Content starts at the edge (no =region_padding=) |
| =LRG_GUI_REGION_HORIZONTAL= | Items flow left to right on one line (toolbars, menu bars) |

=lrg_gui_begin_region()= with an explicit =rect= places the region absolutely; with =rect= = =NULL= it takes the rest of the current region as a child. =lrg_gui_begin_child()= lays out a child region as an item of the current region: a =width= or =height= =<= 0 means "available size plus that value", so =lrg_gui_begin_child (ctx, "log", 0, -lrg_gui_get_frame_height (ctx) - 6, LRG_GUI_REGION_SCROLL_Y)= leaves room for one input row below. Both are closed with =lrg_gui_end_region()=. The wheel delta consumed by a scrolling region is not reported by =lrg_gui_get_mouse_wheel()=.

By default items stack vertically, one per row, separated by =item_spacing_y=.

- =lrg_gui_same_line()= puts the next item to the right of the previous one, =spacing= pixels away (=< 0= = style =item_spacing_x=).
- =lrg_gui_set_cursor()= places the *next item exactly at (x, y)* in window pixels, in any region, including the x coordinate in an ordinary vertical region; layout then continues on the row below that item. This is how the editor overlays controls on a panel: the viewport sets the cursor to the panel's top-left and submits a full-size =lrg_gui_invisible_button()=, and the hierarchy places the visibility and lock toggles at the right edge of each row.
- =lrg_gui_get_cursor()= returns where the next item would go.
- =lrg_gui_indent()= / =lrg_gui_unindent()= shift the left edge (=<= 0 = style =indent=); pass the same value to both.
- =lrg_gui_set_next_item_width()= sets the next widget's width; =<= 0 means available width plus that value.
- =lrg_gui_property_label()= draws a label in the left column of a two-column grid (=label_ratio= of the width) and positions the next widget in the right column with its width set to fill it. Inspector rows are =property_label= followed by a value editor with a =##= label.
- =lrg_gui_scroll_to_item()= scrolls the current region from the next frame so the last item is visible: =align= 0 top, 0.5 centre, 1 bottom, =< 0= only if it is not already fully visible.
- =lrg_gui_dummy()= reserves empty space; =lrg_gui_separator()= draws a rule; =lrg_gui_separator_text()= draws a rule with a heading in it.
- =lrg_gui_get_frame_height()= is the height of a button or field (font size plus vertical frame padding), useful for sizing custom rows.

** Trees and collapsing headers
:PROPERTIES:
:CUSTOM_ID: trees
:END:
#+begin_src c
gboolean lrg_gui_tree_node          (LrgGuiContext   *self,
                                     const gchar     *label,
                                     LrgGuiTreeFlags  flags);
void     lrg_gui_tree_pop           (LrgGuiContext   *self);
void     lrg_gui_set_next_item_open (LrgGuiContext   *self,
                                     gboolean         open);
gboolean lrg_gui_collapsing_header  (LrgGuiContext   *self,
                                     const gchar     *label,
                                     gboolean         default_open);
#+end_src

=lrg_gui_tree_node()= draws a collapsible row and returns =TRUE= if it is open; the children follow and *must* be closed with =lrg_gui_tree_pop()=, which undoes the indentation and ID scope the node pushed. The open flag is stored in the context per identity. Without =OPEN_ON_ARROW= a click anywhere on the row toggles it, and Right / Left arrow open / close the hovered row when no text field has focus. Item queries (left and right clicks) after the node report clicks on the label, which is how outliners implement selection.

| Flag | Effect |
|------+--------|
| =LRG_GUI_TREE_LEAF= | No children and no arrow; never opens, so it returns =FALSE= and needs no =tree_pop()= |
| =LRG_GUI_TREE_SELECTED= | Highlight as selected |
| =LRG_GUI_TREE_DEFAULT_OPEN= | Open the first time it appears |
| =LRG_GUI_TREE_OPEN_ON_ARROW= | Only the arrow (or a double-click on the label) toggles; a single click on the label selects (outliner rows) |
| =LRG_GUI_TREE_FRAMED= | Draw as a header bar |
| =LRG_GUI_TREE_DIMMED= | Label in the disabled colour (hidden nodes) |

=lrg_gui_set_next_item_open()= forces the open state of the next tree node or header (the hierarchy uses it to expand ancestors of a node selected in the viewport). =lrg_gui_collapsing_header()= is a framed section header that needs no =tree_pop()=; the inspector uses one per component.

#+begin_src c
open = lrg_gui_tree_node (ctx, name, LRG_GUI_TREE_OPEN_ON_ARROW |
                                     (selected ? LRG_GUI_TREE_SELECTED : 0) |
                                     (has_kids ? 0 : LRG_GUI_TREE_LEAF));
if (lrg_gui_is_item_clicked (ctx, LRG_GUI_MOUSE_LEFT))
	select_node (node);
if (open)
{
	draw_children (node);
	lrg_gui_tree_pop (ctx);
}
#+end_src

** Value editors
:PROPERTIES:
:CUSTOM_ID: value-editors
:END:
All value editors edit application data in place and return =TRUE= on the frame the value changed. Pair them with [[#item-queries][item queries]] for undo: begin an undo step on =lrg_gui_is_item_activated()= and commit it on =lrg_gui_is_item_deactivated()=, so a whole drag becomes one step.

*** Drag fields and sliders
:PROPERTIES:
:CUSTOM_ID: drag-and-slider

*** How popups work
:PROPERTIES:
:CUSTOM_ID: popup-model
:END:
- Open popups form a stack by nesting level. =lrg_gui_open_popup()= opens one at the pointer (or at =lrg_gui_set_next_popup_pos()=) at the current nesting level, closing any deeper popups; reopening an already-open popup is a no-op.
- A popup is *rebuilt every frame* by calling its =begin_*= function. When it returns =TRUE= build the contents and call =lrg_gui_end_popup()=. A popup that is not built during a frame is closed at =end_frame=.
- =open_popup= and =begin_popup= must use the same =str_id= in the same ID scope.
- Popups are drawn on their own layer above the base UI; hover queries for widgets underneath are blocked.
- Dismissal: a press outside the top-most popups closes them; Escape closes the top one (unless a text field has focus); activating a =lrg_gui_menu_item()= or a =lrg_gui_selectable()= (without =DONT_CLOSE_POPUP=) closes the menu; =lrg_gui_close_current_popup()= closes the popup being built and its children; =lrg_gui_close_all_popups()= closes everything.
- Size: popups fit their content (default minimum width 180 px) unless =lrg_gui_set_next_popup_size()= requests a size (0 = fit); a requested height makes the popup scroll. The background is recorded first and patched to the measured size at =end_popup= (=lrg_gui_draw_list_set_rect()=).
- Placement is clamped to the window.

#+begin_src c

Payloads are a *type* string plus a *data* string (both copied), so they survive any frame without lifetime concerns. The editor uses type ="node"= with a node GUID, ="asset"= with an asset path, and the dock uses its own internal type for tabs.

- *Source*: right after a widget, =lrg_gui_begin_drag_source()= returns =TRUE= once the left button has been held on that item and the pointer moved more than 4 px, and on every frame of the drag after that. - *Target*: right after the target widget, =lrg_gui_accept_drop (ctx, type)= highlights the item (=LRG_GUI_COL_DROP_TARGET= outline) while a matching payload hovers it, and returns the payload data on the frame the button is released over it, otherwise =NULL=. - *Anywhere*: =lrg_gui_get_drag_payload()= returns the payload (and its type) while a drag is active, for custom feedback such as insertion lines; =lrg_gui_was_payload_dropped()= is =TRUE= on the frame a payload was released anywhere, accepted or not.

*** Callbacks and the 3D viewport
:PROPERTIES:
:CUSTOM_ID: draw-callbacks
:END:
#+begin_src c

                                    gpointer          user_data);
#+end_src

A callback command lets arbitrary rendering happen at a precise point in the UI's paint order, so UI drawn later in the same layer (overlay toolbars, the gizmo, hints) composites on top of it and popups still cover it. The raylib backend ends its scissor mode before calling the hook (the hook manages its own GPU state) and restores the GUI clip afterwards. =user_data= must outlive the replay.

The editor viewport renders the 3D scene into a render texture before the UI pass, then inside its dock panel records a callback that blits that texture into the panel rectangle, and finally covers the panel with an invisible button for input:

#+begin_src c
static void
viewport_blit (const LrgGuiRect *rect,
               gpointer          user_data)
{
	Viewport *vp = user_data;

	/* Render textures are stored upside down. */
	DrawTextureRec (vp->target.texture,
	                (Rectangle) { 0.0f, 0.0f, (gfloat) vp->tw, -(gfloat) vp->th },
	                (Vector2) { rect->x, rect->y }, WHITE);
}

static void
viewport_panel (Viewport      *vp,
                LrgGuiContext *ctx)
{
	LrgGuiRect rect;

	lrg_gui_get_region_rect (ctx, &rect);
	lrg_gui_draw_callback (ctx, &rect, viewport_blit, vp);

	/* One interactive surface covering the panel. */
	lrg_gui_set_cursor (ctx, rect.x, rect.y);
	lrg_gui_invisible_button (ctx, "##viewport", rect.w, rect.h);

		viewport_handle_camera (vp, ctx);
}

** Docking
:PROPERTIES:
:CUSTOM_ID: docking
:END:
=LrgGuiDock= arranges named panels in a binary tree of resizable splits whose leaves are tab stacks, the layout model of the Godot, Unreal and Unity editors. Users drag a splitter to resize, click a tab to show that panel, drag a tab onto another stack's centre to join it or onto one of its edges to split it, and close a tab with its "x" or a middle-click. Removing the last tab of a stack collapses it into its sibling, so the tree never holds empty stacks (except an empty root).

*** Layout string grammar
:PROPERTIES:
:CUSTOM_ID: dock-grammar
:END:
=lrg_gui_dock_to_string()= serializes the tree to a compact string the application stores in its settings; =lrg_gui_dock_load_string()= parses one back. The editor's default layout serializes to:

#+begin_example
split(v,0.180,tabs(0,hierarchy),split(v,0.730,split(h,0.700,tabs(0,viewport),tabs(0,assets,console,problems)),tabs(0,inspector,history)))
#+end_example

Grammar (whitespace between tokens is ignored):

#+begin_example
node      := split | tabs
split     := "split(" dir "," ratio "," node "," node ")"
dir       := "v" | "h"
ratio     := decimal number             ; share of the FIRST child, clamped to [0.05, 0.95]
tabs      := "tabs(" active { "," panel-id } ")"
active    := integer                    ; index of the shown tab, clamped to the tab count
panel-id  := 1*( ALNUM | "_" | "-" | "." )
#+end_example

- =v= means the children sit side by side (left, right) separated by a vertical bar; =h= means they are stacked (top, bottom).
- The ratio is written with =%.3f= in the C locale; a missing ratio defaults to 0.5. On screen the first child gets =ratio= of the size minus the 4 px splitter, and each pane is kept at least 48 px where possible.
- =tabs(0)= is an empty stack (only meaningful as the root).
- Panel ids should therefore be restricted to letters, digits, =_=, =-= and =.=.
- Nesting deeper than 64 levels, an unknown direction, an empty panel id, an unexpected token or trailing data is a =G_IO_ERROR_INVALID_DATA= error, and on any error the current layout is kept unchanged.

*** Fonts
:PROPERTIES:
:CUSTOM_ID: raylib-fonts
:END:
=lrg_gui_raylib_load_fonts()= (re)loads a proportional UI font and a monospace font rasterized at =size= pixels (pass =style->font_size=; reload when the scale changes). An explicit path wins; a =NULL= or empty path calls =lrg_gui_raylib_find_system_font()=, which probes a fixed list of common TrueType locations across distributions: DejaVu Sans, Noto Sans, Liberation Sans, Adwaita Sans and Open Sans for the UI font, and DejaVu Sans Mono, Noto Sans Mono, Liberation Mono and Source Code Pro for monospace (=/usr/share/fonts/...= paths as laid out by Fedora, Debian and Arch packages). It does not run =fc-match=; fontconfig-based fallback lookup lives in =LrgFontAtlas= ([[file:../text/font-atlas.org][Rich Text: LrgFontAtlas]]). The glyph set covers ASCII, Latin-1, Latin Extended-A and the symbols the editor draws (arrows, bullets, check marks, triangles, gear, warning sign, x, degree). A file that is missing or fails to load falls back to raylib's built-in font (for monospace, to the UI font first). =lrg_gui_raylib_get_font_path()= returns the UI font file actually in use, or =NULL= when the built-in font is used.

On Fedora, =dejavu-sans-fonts= and =dejavu-sans-mono-fonts= satisfy the first candidates.

*** Input, rendering and cursor
:PROPERTIES:
:CUSTOM_ID: raylib-frame
:END:
- =lrg_gui_raylib_poll_input()= calls =lrg_gui_input_new_frame()= with =GetFrameTime()=, sets =time= from =GetTime()=, reads modifiers (left or right Ctrl/Shift/Alt/Super), fresh key presses, auto-repeats of the editing keys (Backspace, Delete, arrows, Page Up/Down, Enter, Tab), typed characters, held state of every mapped key, pointer position, the three buttons and both wheel axes.
- =lrg_gui_raylib_render()= replays a draw list; call it between =BeginDrawing()= and =EndDrawing()=. Clip push/pop become nested scissor rectangles; images draw a =GrlTexture='s raylib handle; callbacks run with scissoring suspended and the clip restored afterwards.

		/* The game only sees the mouse when the UI does not want it. */
		if (!lrg_gui_context_wants_mouse (ctx))
			game_handle_mouse ();

		BeginDrawing ();
		ClearBackground (BLACK);
		game_draw ();
		lrg_gui_raylib_render (backend, lrg_gui_context_get_draw_list (ctx));
		EndDrawing ();
	}

	g_clear_object (&backend);
	CloseWindow ();
	return 0;
}
#+end_src

The backend is cleared before =CloseWindow()= so its fonts are unloaded while the GL context still exists.

** Headless testing
:PROPERTIES:
:CUSTOM_ID: headless-testing
:END:
Without a backend, a context measures text at 0.55 em per character and uses an internal clipboard, so the whole toolkit runs in a plain GTest binary. The pattern used by =tests/test-gui.c=:

1. Keep one =LrgGuiInput= across frames; at the top of each frame call =lrg_gui_input_new_frame()= and set the pointer and button state.
2. Run a frame that builds the UI, then inspect return values, item queries, =lrg_gui_context_wants_*()= and the draw list.
3. Locate widgets in a first frame with the pointer parked away (=lrg_gui_get_item_rect()=), then drive them in later frames. A click is two frames: one with the button down over the item, one with it up.
4. Inject keys with =lrg_gui_input_add_key()= and typing with =lrg_gui_input_add_text()=; clear =key_down= and =mods= yourself to model a release.
5. Assert on visuals with =lrg_gui_draw_list_find_text()= or by walking =lrg_gui_draw_list_get_command()=.

#+begin_src c
#include <glib.h>
#include <libregnum.h>

static const LrgGuiRect panel = { 10.0f, 10.0f, 400.0f, 300.0f };

/* One frame with the pointer at (x, y); returns whether "Save" was clicked. */
static gboolean
save_frame (LrgGuiContext *ctx,
            LrgGuiInput   *input,
            gfloat         x,
            gfloat         y,
            gboolean       down,
            LrgGuiRect    *rect)
{
	gboolean clicked;

	lrg_gui_input_new_frame (input, 1.0f / 60.0f);
	input->mouse_x = x;
	input->mouse_y = y;
	input->mouse_down[LRG_GUI_MOUSE_LEFT] = down;

	lrg_gui_context_begin_frame (ctx, input, 800.0f, 600.0f);
	lrg_gui_begin_region (ctx, "p", &panel, LRG_GUI_REGION_NONE);
	clicked = lrg_gui_button (ctx, "Save##btn");
	if (rect != NULL)
		lrg_gui_get_item_rect (ctx, rect);
	lrg_gui_end_region (ctx);
	lrg_gui_context_end_frame (ctx);

	return clicked;
}

static void
test_save_button (void)
{
	g_autoptr(LrgGuiContext) ctx = lrg_gui_context_new ();
	LrgGuiDrawList          *dl;
	LrgGuiInput              input;
	LrgGuiRect               r;
	gfloat                   cx, cy;

	lrg_gui_input_init (&input);

	/* Frame 1: lay out with the pointer away, check what was drawn. */
	g_assert_false (save_frame (ctx, &input, -1.0f, -1.0f, FALSE, &r));
	dl = lrg_gui_context_get_draw_list (ctx);
	g_assert_nonnull (lrg_gui_draw_list_find_text (dl, "Save"));
	g_assert_null (lrg_gui_draw_list_find_text (dl, "Save##btn"));
	cx = r.x + r.w * 0.5f;
	cy = r.y + r.h * 0.5f;

	/* Frame 2: press; frame 3: release over it = click. */
	g_assert_false (save_frame (ctx, &input, cx, cy, TRUE, NULL));
	g_assert_true (lrg_gui_context_wants_mouse (ctx));
	g_assert_true (save_frame (ctx, &input, cx, cy, FALSE, NULL));
}

int
main (int    argc,
      char **argv)
{
	g_test_init (&argc, &argv, NULL);
	g_test_add_func ("/gui/save-button", test_save_button);
	return g_test_run ();
}
#+end_src
