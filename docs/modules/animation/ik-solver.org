** Solver Types
:PROPERTIES:
:CUSTOM_ID: solver-types
:END:
*** FABRIK (Any Length)
:PROPERTIES:
:CUSTOM_ID: fabrik-any-length
:END:
Forward And Backward Reaching Inverse Kinematics. Works with any chain length.

#+begin_src C
#define LRG_TYPE_IK_SOLVER_FABRIK (lrg_ik_solver_fabrik_get_type ())
LrgIKSolverFABRIK *lrg_ik_solver_fabrik_new (void);
#+end_src

*Algorithm*: Iteratively adjusts bone positions from tip to root (backward) then root to tip (forward) until convergence.

*Best for*: Tentacles, tails, spines, any multi-bone chain.

*** CCD (Any Length)
:PROPERTIES:
:CUSTOM_ID: ccd-any-length
:END:
Cyclic Coordinate Descent. Works with any chain length.

#+begin_src C
#define LRG_TYPE_IK_SOLVER_CCD (lrg_ik_solver_ccd_get_type ())
LrgIKSolverCCD *lrg_ik_solver_ccd_new (void);
#+end_src

*Algorithm*: Rotates each bone from tip to root to minimize distance to target.

*Best for*: Robot arms, mechanical joints.

*** Two-Bone (Exactly 2 Bones)
:PROPERTIES:
:CUSTOM_ID: two-bone-exactly-2-bones
:END:
Analytical solution for exactly two bones.

#+begin_src C
#define LRG_TYPE_IK_SOLVER_TWO_BONE (lrg_ik_solver_two_bone_get_type ())

*Algorithm*: Uses law of cosines for exact, single-frame solution.

*Best for*: Arms (upper arm + forearm), legs (thigh + shin).

** Example: Arm IK
:PROPERTIES:
:CUSTOM_ID: example-arm-ik
:END:
#+begin_src C
/* Build IK chain for arm */
g_autoptr(LrgIKChain) arm_chain = lrg_ik_chain_new (skeleton);
lrg_ik_chain_add_bone (arm_chain, "upper_arm");
lrg_ik_chain_add_bone (arm_chain, "forearm");
lrg_ik_chain_set_effector_bone (arm_chain, "hand");   /* the hand reaches the target */

/* Create two-bone solver */
g_autoptr(LrgIKSolverTwoBone) solver = lrg_ik_solver_two_bone_new ();

/* In game loop */
void
update_arm_ik (gfloat target_x, gfloat target_y, gfloat target_z)
{
    /* Set target (e.g., weapon aim point) */
    lrg_ik_chain_set_target_position (arm_chain, target_x, target_y, target_z);

    /* Set pole (elbow direction) */
    lrg_ik_chain_set_pole_position (arm_chain, shoulder_x, shoulder_y - 1.0f, shoulder_z);  /* a point below: the elbow bends down */

    /* Solve */
    if (lrg_ik_solver_solve (LRG_IK_SOLVER (solver), arm_chain, 1, 0.001f))
    {
        /* Solution found - bone poses updated */
    }

    /* the solver already recomputed the world poses */
}
#+end_src

** 0.9.0: correct solvers and the IK post-pass
:PROPERTIES:
:CUSTOM_ID: v090
:END:
The solvers were rewritten. They used to write world-space orientations into local poses with the translation reset, which collapsed any real skeleton; they now move a chain only by rotating bones about their joints (=lrg_ik_chain_aim_bone()=: the shortest arc between two model-space directions, converted into a local rotation under the parent; translations, scales and therefore bone lengths never change) and work on the current animated pose.

*Conventions.* Positions are model space (the space of the skeleton's world poses). The chain lists the bones a solver turns; the end effector is the =effector= bone (a child of the last chain bone, e.g. the hand of an upper-arm/forearm chain) or, without one, the tip of the last bone (its position plus its length along the bone axis, default +Y as glTF and Blender export bones; a zero-length bone counts as length 1 so look-at still has a direction). Two-bone needs 2 chain bones, look-at 1, FABRIK and CCD any number.

| solver | method | result |
|-+-+-|
| =LrgIKSolverTwoBone= | law of cosines: the knee on the circle at len0 from the root and len1 from the (clamped) target, picked by the pole (else the current bend plane) | exact in reach (the tests check < 1e-3), fully stretched toward an unreachable target |
| =LrgIKSolverFABRIK= | backward/forward passes on joint positions (Aristidou and Lasenby 2011), then each bone aimed at its solved child | converges within tolerance in a few iterations; stretched line when out of reach |
| =LrgIKSolverCCD= | from the last bone to the first, turn the bone so the effector lies on the line to the target | converges for reachable targets, tends to curl the tip first |
| =LrgIKSolverLookAt= | turn the single bone so its bone axis points at the target (shortest arc; the animated roll is kept, the up vector is not used) | exact |

=lrg_ik_solver_solve()= now refuses chains the solver does not support (=supports_chain_length=).

*** LrgIKGoal
:PROPERTIES:
:CUSTOM_ID: ik-goal
:END:
=LrgIKGoal= is one entry of the [[file:anim-graph.org::#ik][animation graph's IK post-pass]] (=ik:= in .ranim) and can be used on its own: a chain, a solver kind (=LrgIKGoalKind=, =lrg_ik_goal_kind_get_type()=: =TWO_BONE=, =CCD=, =FABRIK=, =LOOK_AT=, =FOOT=), a world-space target, a pole, a weight.

| function | |
|-+-|
| =lrg_ik_goal_new (name, kind)= / =lrg_ik_goal_get_name()= / =lrg_ik_goal_get_kind()= | |
| =lrg_ik_goal_set_bones()= / =lrg_ik_goal_get_bones()= | the chain, root first |
| =lrg_ik_goal_set_effector()= / =lrg_ik_goal_get_effector()= | the effector bone |
| =lrg_ik_goal_set_pole()= / =lrg_ik_goal_get_pole()= / =lrg_ik_goal_clear_pole()= | model-space bend point |
| =lrg_ik_goal_set_target()= / =lrg_ik_goal_get_target()= / =lrg_ik_goal_clear_target()= | world-space target (no target: the goal does nothing, except foot goals) |
| =lrg_ik_goal_set_weight()= / =lrg_ik_goal_get_weight()= | 0 = animation, 1 = solved (slerped per bone) |
| =lrg_ik_goal_set_iterations()= / =lrg_ik_goal_get_iterations()= / =lrg_ik_goal_set_tolerance()= / =lrg_ik_goal_get_tolerance()= | CCD/FABRIK budget |
| =lrg_ik_goal_set_enabled()= / =lrg_ik_goal_get_enabled()= | |
| =lrg_ik_goal_set_bone_axis()= / =lrg_ik_goal_get_bone_axis()= | look-at forward / tip direction |
| =lrg_ik_goal_set_foot (self, ray_up, ray_down, align)= / =lrg_ik_goal_get_foot()= | foot probe |
| =lrg_ik_goal_apply (self, skeleton, model_matrix, raycast, user_data)= | solve on a posed skeleton; =model_matrix= is the character's model-to-world matrix (column-major), =raycast= an =LrgIKRaycastFunc= |
| =lrg_ik_goal_get_last_target()= | the model-space point the last apply aimed at (gizmos) |

*Foot placement.* A foot goal casts a ray (your =LrgIKRaycastFunc=, world space) from =ray_up= above the animated foot down =ray_up + ray_down=. On a hit the foot moves by the ground's height relative to the character's ground plane (model y = 0 under the foot), so planted feet land on slopes and steps while lifted feet stay lifted; the leg is solved as two-bone; with =align= the effector is turned so its model-space up matches the ground normal. No hit (or no raycast): nothing changes. Pelvis lowering for steps below the plane is left to gameplay (move the entity or add an additive crouch layer).

#+begin_src c
static gboolean
ground_ray (const gfloat *origin, const gfloat *dir, gfloat max_distance,
            gfloat *hit, gfloat *normal, gpointer user_data)
{
	return my_physics_raycast (user_data, origin, dir, max_distance, hit, normal);
}

g_autoptr(LrgIKGoal) foot = lrg_ik_goal_new ("l_foot", LRG_IK_GOAL_FOOT);
const gchar *bones[] = { "l_thigh", "l_shin", NULL };

lrg_ik_goal_set_bones (foot, bones);
lrg_ik_goal_set_effector (foot, "l_foot");
lrg_ik_goal_set_pole (foot, -0.15f, 0.5f, 1.0f);   /* knee forward */
lrg_ik_goal_set_foot (foot, 0.5f, 0.5f, TRUE);

/* after posing the skeleton for this frame */
lrg_ik_goal_apply (foot, skeleton, entity_world_matrix, ground_ray, physics);
#+end_src

Measured: a two-bone goal adds about 5 µs to an animator step (16-bone character, see [[file:anim-graph.org::#performance][performance]]); FABRIK and CCD cost one world pose recomputation per bone turned per iteration.
