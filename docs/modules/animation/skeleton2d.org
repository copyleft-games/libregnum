:PROPERTIES:

#+begin_quote
*[[file:../../index.org][Home]]* > [[file:index.org][Animation]] > LrgSkeleton2D
#+end_quote

=LrgSkeleton2D= animates 2D characters made of image pieces that bend: a hierarchy of 2D bones moves deformable sprite meshes (=LrgSkinnedSprite=), named blend shapes morph those meshes (blinks, mouth shapes, squash), clips (=LrgSkeleton2DClip=) key bone transforms, attachment swaps, draw order, colours, shape weights and events, and the whole rig is stored in libregnum's own =.rskel2d= YAML format. =LrgSkeleton2DComponent= plays it on an =LrgGameObject= in an =LrgWorld= with crossfades.

- *Header*: =animation/lrg-skeleton2d.h= (plus =graphics/lrg-skinned-sprite.h=, =ecs/components/lrg-skeleton2d-component.h=)
- *Types*: =LrgSkeleton2D= and =LrgSkeleton2DClip= (final GObjects, =LRG_TYPE_SKELETON2D=, =LRG_TYPE_SKELETON2D_CLIP=, GIR =Libregnum.Skeleton2D=, =Libregnum.Skeleton2DClip=); enums =LrgSkeleton2DError=, =LrgSkeleton2DCurve=, =LrgSkeleton2DChannel=
- *Since*: 0.9.0; blend shapes, shape weight keys, format version 2 and CPU drawing since 0.14
- *Headless*: everything except GPU drawing (=lrg_skeleton2d_draw()=, =lrg_skeleton2d_draw_bones()=, =lrg_skeleton2d_load_textures()=) runs without a window, including drawing on the CPU with =lrg_skeleton2d_draw_to_canvas()= (0.14, see [[#cpu-drawing][Drawing on the CPU]]), which shows blend shapes exactly as the GPU path does
- *Format*: =.rskel2d= (versions 1 and 2), our own design. Spine and DragonBones files are not read or written: their formats are proprietary or restrictively licensed. Rigs are authored in code, by hand in YAML, or with the editor's [[file:../../editor/skeleton2d-editor.org][2D Rig Editor]].

** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

A frame of a 2D skeletal character goes through four steps:

1. *Pose*: reset to the setup pose (=lrg_skeleton2d_reset_pose()=), then apply one or more clips at a time and weight (=lrg_skeleton2d_clip_apply()=). Procedural changes (look at the mouse, IK) set bones directly with =lrg_skeleton2d_set_bone_local()=; procedural face layers (blink, breathe) mix into the shape weights with [[file:procedural.org][LrgSkeleton2DProcedural]].
2. *World transforms*: =lrg_skeleton2d_update_world()= turns local poses into world matrices and the skinning palette.
3. *Deform*: every visible attachment gets its slot's blend-shape weights, is morphed by them and skinned on the CPU with the palette (=lrg_skeleton2d_deform()=, done by draw).
4. *Draw*: slots are drawn back to front in the current draw order, each attachment tinted by its slot colour (=lrg_skeleton2d_draw()=).

=LrgSkeleton2DComponent= runs steps 1 and 2 in its update and 3 and 4 in its draw, at the owning game object's position, rotation and scale.

#+begin_example
LrgSkeleton2D
 +-- bones      root > hip > torso > head ...        (hierarchy, setup + current pose)
 +-- slots      arm_r, leg_r, torso, head, ...       (draw order, bone, attachment, colour, shape weights)
 +-- skins      default, big-head ...                (slot + name -> LrgSkinnedSprite)
 +-- clips      walk, wave ...                       (LrgSkeleton2DClip: keys by bone/slot name)
#+end_example

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:

*** Coordinates
:PROPERTIES:
:CUSTOM_ID: coordinates
:END:
- Screen space: x right, *y down* (raylib's 2D convention). Units are pixels at scale 1.
- Rotations are in *degrees*; positive turns *clockwise* on screen (the same sense as =DrawTexturePro()= and =GrlEntity= rotation). A bone rotated 90 points down.
- A bone's length lies along its local +X axis. Length is only used for drawing, picking and automatic weights; it does not move children (place children with their own =x=).
- 2D affine matrices are six floats =(a, b, c, d, tx, ty)=: =x' = a*x + c*y + tx=, =y' = b*x + d*y + ty=. A bone's local matrix is =T(x, y) * R(rotation) * S(scale_x, scale_y)=; its world matrix is =parent_world * local= (the root transform for root bones).

*** Bones, setup pose and current pose
:PROPERTIES:
:CUSTOM_ID: bones
:END:
Bones are stored in an array where every parent precedes its children, so world transforms are a single pass in index order. Each bone has two poses relative to its parent:
- the *setup pose* (rest pose; =lrg_skeleton2d_get_bone_setup()= / =lrg_skeleton2d_set_bone_setup()=), which is what the file stores and what meshes are bound to;
- the *current pose* (=lrg_skeleton2d_get_bone_local()= / =lrg_skeleton2d_set_bone_local()=), which clips and code change every frame.

The *root transform* (=lrg_skeleton2d_set_root_transform()=) places the whole skeleton; the component sets it from its game object. Negative scales mirror the character.

*** Slots and draw order
:PROPERTIES:
:CUSTOM_ID: slots
:END:
A slot is a drawing layer bound to one bone. It shows one attachment at a time (by name, or none) tinted by a colour (RGBA 0 .. 1, multiplied into the texture). The order in which slots were added is the *setup draw order*, back to front; clips can reorder slots for a while (an arm swinging in front of the body) with draw-order keys. =lrg_skeleton2d_get_draw_order()= / =lrg_skeleton2d_set_draw_order()= read and set the current order.

*** Skins and attachments
:PROPERTIES:
:CUSTOM_ID: skins
:END:
An attachment is an =LrgSkinnedSprite= stored in a skin under (slot, name). Every skeleton has the skin named =default= (=LRG_SKELETON2D_DEFAULT_SKIN=); further skins hold variants (armour, a big-head mode). Lookups go to the active skin first (=lrg_skeleton2d_set_skin()=), then to the default skin, so a variant skin only holds what differs.

Attachment meshes are authored in *setup space*: the coordinates of the skeleton in its setup pose with an identity root transform. A vertex is weighted to up to four bones (=LRG_SKINNED_SPRITE_MAX_WEIGHTS=); a vertex without weights moves rigidly with its slot's bone. A "region attachment" (a rigid image on one bone) is a four-vertex quad, made with =lrg_skinned_sprite_new_quad()=.

*** Skinning
:PROPERTIES:
:CUSTOM_ID: skinning
:END:
The palette entry of a bone is =world(bone) * inverse(bind(bone))=, where =bind(bone)= is the bone's setup-pose world matrix without the root transform (=lrg_skeleton2d_get_palette()=). Linear blend skinning gives each vertex =sum(weight_k * palette[bone_k] * bind_position)=. In the setup pose with an identity root every palette entry is the identity, so meshes draw exactly where they were authored. Changing a bone's setup pose recomputes the bind matrices on the next update.

*** Blend shapes
:PROPERTIES:
:CUSTOM_ID: blend-shapes
:END:
An attachment can carry *blend shapes* (morph targets): named sets of per-vertex offsets in setup space (=lrg_skinned_sprite_add_shape()=, see [[file:../graphics/skinned-sprite.org::#blend-shapes][LrgSkinnedSprite: blend shapes]]). A shape with weight =w= moves every vertex by =w * offset=; shapes add up. The morph happens *before* skinning, on the bind position, so a shape follows its bones: a "blink" authored on an upright head still closes the eyelid when the head is tilted.

Weights belong to the *slot*, not to the mesh: =lrg_skeleton2d_set_shape_weight (skel, slot, shape, w)= sets them (clamped to 0 .. 1) and clips key them. =lrg_skeleton2d_deform()= and =lrg_skeleton2d_draw()= hand each slot's weights to whatever attachment the slot shows at that moment, so swapping the head attachment keeps the expression, and an attachment without a shape simply ignores its weight. That is what lets one clip or one lip-sync track drive a whole cast: every character implements the names of the [[file:shape-sheet.org][standard shape sheet]] it needs and nothing else. =lrg_skeleton2d_reset_pose()= returns every slot weight to 0.

*** Clips
:PROPERTIES:
:CUSTOM_ID: clips
:END:
An =LrgSkeleton2DClip= has a name, a duration in seconds and a default loop flag, and timelines keyed by bone or slot *name* (so a clip plays on any skeleton with those names):

| Channel | Target | Values | Meaning |
|---------+--------+--------+---------|
| =LRG_SKELETON2D_CHANNEL_TRANSLATE= | bone | x, y | offset added to the setup translation |
| =LRG_SKELETON2D_CHANNEL_ROTATE= | bone | degrees | offset added to the setup rotation |
| =LRG_SKELETON2D_CHANNEL_SCALE= | bone | x, y | factors multiplied into the setup scale |
| =LRG_SKELETON2D_CHANNEL_COLOR= | slot | r, g, b, a | absolute slot colour |
| =LRG_SKELETON2D_CHANNEL_ATTACHMENT= | slot | name or none | attachment swap (always stepped) |
| =LRG_SKELETON2D_CHANNEL_SHAPE= | slot + shape name | weight 0 .. 1 | blend-shape weight (since 0.14) |

A shape timeline is named by a slot *and* a shape, so it has its own functions (=lrg_skeleton2d_clip_add_shape_key()=, =lrg_skeleton2d_clip_sample_shape()=, ...); the functions taking a =(target, channel)= pair report no keys for =LRG_SKELETON2D_CHANNEL_SHAPE=. Shape keys use the same curves as the numeric channels (Bézier control points with =lrg_skeleton2d_clip_set_shape_key_bezier()=).

Bone values are *relative to the setup pose*, so re-rigging (moving a bone's rest position) keeps clips valid. Clips also hold draw-order keys (the full slot order back to front, or none for the setup order) and events (a name at a time, several may share a time).

Each numeric key carries the curve of the span to the next key (=LrgSkeleton2DCurve=): =LRG_SKELETON2D_CURVE_LINEAR=, =LRG_SKELETON2D_CURVE_STEPPED= (hold until the next key) or =LRG_SKELETON2D_CURVE_BEZIER= (a cubic Bézier timing curve like CSS =cubic-bezier(x1, y1, x2, y2)=, set with =lrg_skeleton2d_clip_set_key_bezier()=). Before the first key a timeline holds the first value, after the last key the last value. Rotation keys interpolate the stored numbers, so =0 -> 360= is a full turn.

Adding a key later than the duration extends the duration; a key at the time of an existing key (within 1 µs) replaces it.

*** Mixing and crossfades
:PROPERTIES:
:CUSTOM_ID: mixing
:END:
=lrg_skeleton2d_clip_apply (clip, skeleton, time, alpha)= moves every keyed channel of the current pose toward the clip's value by =alpha=:
- translation, scale and colour lerp; rotation turns along the shorter arc (=alpha= 1 sets the exact value, even beyond ±180);
- attachment and draw-order keys apply when =alpha >= 0.5=;
- slot shape weights lerp like colours, from the slot's current weight (0 for a shape the slot has not been given yet), and stay in 0 .. 1;
- channels the clip does not key are left alone.

So a crossfade from A to B at weight =w= is: reset, apply A at 1, apply B at =w=. Layering (an upper-body wave on top of a walk) is: reset, apply walk at 1, apply wave at 1 (wave only keys the arm). =LrgSkeleton2DComponent= does the crossfade for you with two tracks.

** The =.rskel2d= format
:PROPERTIES:
:CUSTOM_ID: format
:END:
A YAML document. Loading is strict: unknown keys, wrong types, unknown bone or slot names, duplicates and out-of-range indices are errors whose message names the source and the node path (=figure.rskel2d: /bones/3/parent: unknown bone "hip" (a parent must come before its children)=). Saving is deterministic and leaves out defaults; loading a saved file and saving it again gives the same bytes. Floats are written in their shortest exact form.

*** Versions
:PROPERTIES:
:CUSTOM_ID: format-versions
:END:
| Version | Since | Adds |
|---------+-------+------|
| 1 | 0.9.0 | bones, slots, skins, attachments, clips with bone, slot, draw-order and event keys |
| 2 | 0.14 | blend shapes on attachments (=shapes:=) and shape weight timelines on slot tracks (=shapes:=) |

The reader accepts every version from 1 to =LRG_SKELETON2D_FORMAT_VERSION= (2). The version gates the content: a version 1 document that uses =shapes:= is an error (=a blend shape needs "rskel2d: 2"=). The writer emits the *lowest* version that can hold the document, so a rig without shapes is still written as version 1, byte for byte as before; adding one shape or one shape key makes it version 2.

*** Annotated example
:PROPERTIES:
:CUSTOM_ID: format-example
:END:
A version 1 document; the version 2 additions follow in [[#format-v2][the next section]].
#+begin_src yaml
rskel2d: 1                    # required; format version (integer, 1 or 2; see Versions)
name: arm                     # optional; informational name (string)
bones:                        # optional; list, parents before children
  - name: upper               # required; unique string
    length: 50                # optional; >= 0, default 0 (drawing, picking, auto weights)
  - name: fore
    parent: upper             # optional; an earlier bone's name; omitted = root bone
    x: 50                     # optional; setup translation relative to the parent, default 0
    y: 0                      # optional; default 0
    rotation: -12.5           # optional; degrees, clockwise on screen, default 0
    scale: [1.5, 1]           # optional; [x, y], default [1, 1]
    length: 50
slots:                        # optional; list, setup draw order back to front
  - name: arm                 # required; unique string
    bone: upper               # required; a bone name
    attachment: arm           # optional; attachment shown in the setup pose (null or omitted = none)
    color: [1, 0.5, 0.25, 1]  # optional; RGBA 0..1, default [1, 1, 1, 1]
  - name: hand
    bone: fore
skins:                        # optional; list; "default" is implicit and written only when non-empty
  - name: default             # required; unique (other than "default", which may appear once)
    attachments:              # optional; list
      - slot: arm             # required; a slot name
        name: arm             # required; unique per skin and slot
        image: limbs/arm.png  # optional; image path relative to this file (lrg_skeleton2d_load_textures)
        region: [0, 16, 64, 16]  # optional; [x, y, w, h] pixels in the image, default [0, 0, 0, 0] = whole image
        vertices:             # optional; one row per vertex: [x, y, u, v]
          - [0, -5, 0, 0]     #   x, y in setup space; u, v 0..1 across the region
          - [100, -5, 1, 0]
          - [0, 5, 0, 1]
          - [100, 5, 1, 1]
        weights:              # optional; one row per vertex, up to 4 [bone, weight] pairs
          - [upper, 1]        #   bone names; weights >= 0, normalised on load
          - [fore, 0.7, upper, 0.3]
          - []                #   no influences: the vertex follows the slot's bone
          - [fore, 1]
        triangles:            # optional; rows of three vertex indices (any winding)
          - [0, 1, 2]
          - [1, 3, 2]
  - name: "gold skin"         # strings that are not plain identifiers are double-quoted
    attachments:
      - slot: hand
        name: fist
        vertices:             # no weights: rigid on the slot's bone ("fore")
          - [95, -4, 0, 0]
          - [105, -4, 1, 0]
          - [100, 4, 0.5, 1]
        triangles:
          - [0, 1, 2]
animations:                   # optional; list of clips
  - name: wave                # required; unique
    duration: 1.5             # optional; seconds >= 0, default 0 (keys extend it)
    loop: true                # optional; default false (the component's "clip" property honours it)
    bones:                    # optional; one entry per animated bone
      - bone: fore            # required; a bone name
        translate:            # optional; keys {time, x, y[, curve]}; offsets from setup (x, y default 0)
          - {time: 0, x: 0, y: 0}
          - {time: 1, x: 2, y: -1.25, curve: stepped}
        rotate:               # optional; keys {time, angle[, curve]}; degrees offset from setup
          - {time: 0, angle: 0, curve: [0.42, 0, 0.58, 1]}   # Bézier ease to the next key
          - {time: 0.5, angle: 45}
        scale:                # optional; keys {time, x, y[, curve]}; factors (x, y default 1)
          - {time: 0.25, x: 1, y: 1.1}
    slots:                    # optional; one entry per animated slot
      - slot: hand            # required; a slot name
        attachment:           # optional; keys {time, name}; name null hides the slot
          - {time: 0, name: fist}
          - {time: 1, name: null}
        color:                # optional; keys {time, color: [r, g, b, a][, curve]}; absolute
          - {time: 0.5, color: [1, 1, 1, 0.5]}
    draw_order:               # optional; keys {time, order}; order = every slot once, back to front
      - {time: 0.5, order: [hand, arm]}
      - {time: 1.5, order: null}  # null = back to the setup order
    events:                   # optional; {time, name}
      - {time: 0.5, name: "wave hello"}
  - name: idle
#+end_src

Key rules common to every timeline: =time= is required and >= 0; =curve= is optional: =linear= (default, omitted when saving), =stepped=, or =[x1, y1, x2, y2]= with =x1=, =x2= in 0 .. 1.

*** Version 2: blend shapes and weight keys
:PROPERTIES:
:CUSTOM_ID: format-v2
:END:
Two keys are added, both named =shapes:=, one on an attachment and one on a clip's slot track. Everything else is exactly version 1.
#+begin_src yaml
rskel2d: 2                    # required to use shapes:
name: face
bones:
  - name: head
    length: 40
slots:
  - name: face
    bone: head
    attachment: face
skins:
  - name: default
    attachments:
      - slot: face
        name: face
        vertices:
          - [0, 0, 0, 0]
          - [10, 0, 1, 0]
          - [0, 10, 0, 1]
        weights:
          - [head, 1]
          - [head, 1]
          - [head, 1]
        triangles:
          - [0, 1, 2]
        shapes:               # optional (v2); list of blend shapes, in this order
          - name: blink_l     # required; unique per attachment (any string; see the shape sheet)
            offsets:          # optional; sparse rows [vertex, dx, dy] in setup space
              - [0, 0, 2.5]   #   vertex 0 moves 2.5 down at weight 1
              - [2, -1, 0.5]  #   vertices not listed do not move
          - name: A
            offsets: []       # a shape that moves nothing yet (written as [])
animations:
  - name: talk
    duration: 1
    slots:
      - slot: face
        shapes:               # optional (v2); one entry per shape timeline of this slot
          - shape: A          # required; the shape name (attachments without it ignore it)
            keys:             # optional; keys {time, w[, curve]}; w is the weight, 0 .. 1
              - {time: 0, w: 0}
              - {time: 0.25, w: 1, curve: [0.42, 0, 0.58, 1]}
              - {time: 1, w: 0, curve: stepped}
          - shape: blink_l
            keys:
              - {time: 0.5, w: 0.75}
#+end_src

Rules: a shape's =name= is required and unique within its attachment; =offsets= rows have exactly three numbers, the first a vertex index of that attachment, each vertex at most once; the writer lists only the vertices a shape moves, in vertex order. A slot track's =shapes= names each shape at most once; =w= is required and must be from 0 to 1. Shape timelines without keys are not written.

*** Migration from version 1
:PROPERTIES:
:CUSTOM_ID: format-migration
:END:
Nothing to do: version 1 files load unchanged and save back byte for byte as version 1. A file becomes version 2 only when shapes or shape keys are added to it (by code, the lip-sync helper or hand editing); an older libregnum (0.13 and earlier) refuses such a file with =unsupported version 2=. To keep a rig readable by an older engine, remove its shapes and shape keys before saving.

*** Errors
:PROPERTIES:
:CUSTOM_ID: format-errors
:END:
| Code | When |
|------+------|
| =LRG_SKELETON2D_ERROR_PARSE= | not YAML, or a value of the wrong type or shape (=expected a number, got "left"=, =expected a list of 2 numbers=, =expected true or false=, =expected [vertex, dx, dy]=) |
| =LRG_SKELETON2D_ERROR_INVALID= | unknown key, missing required key, unknown bone/slot, duplicate name (also a duplicate shape on an attachment or a slot track), negative time/length/size, out-of-range vertex index, a weights list whose length is not the vertex count, a draw order that does not name every slot once, a shape vertex listed twice, a shape weight outside 0 .. 1 |
| =LRG_SKELETON2D_ERROR_VERSION= | =rskel2d:= missing, not a whole number, or outside 1 .. 2 (=unsupported version 3 (this library reads 1 to 2)=); =shapes:= in a version 1 document (=a blend shape needs "rskel2d: 2"=, =a shape weight timeline needs "rskel2d: 2"=) |
| =LRG_SKELETON2D_ERROR_IO= | the file cannot be read or written |

The error domain is =LRG_SKELETON2D_ERROR= (=lrg_skeleton2d_error_quark()=); the enum's GType is =lrg_skeleton2d_error_get_type()=. Examples of the version 2 messages:

*** A bending arm in code
:PROPERTIES:
:CUSTOM_ID: example-arm
:END:
#+begin_src C
g_autoptr(LrgSkeleton2D)     skel = lrg_skeleton2d_new ();
g_autoptr(LrgSkinnedSprite)  strip = lrg_skinned_sprite_new_grid (0, -8, 100, 16, 10, 1);
g_autoptr(LrgSkeleton2DClip) bend = lrg_skeleton2d_clip_new ("bend");
gint upper, fore, slot;

upper = lrg_skeleton2d_add_bone (skel, "upper", -1, 0, 0, 0, 1, 1, 50);
fore  = lrg_skeleton2d_add_bone (skel, "fore", upper, 50, 0, 0, 1, 1, 50);
slot  = lrg_skeleton2d_add_slot (skel, "arm", upper, "arm");

/* weights from the bones' setup segments: 2 influences, one smoothing pass */
lrg_skeleton2d_compute_auto_weights (skel, strip, NULL, 0, 4.0f, 2, 1);
lrg_skinned_sprite_set_texture (strip, arm_texture);  /* or set_image + load_textures */
lrg_skeleton2d_set_attachment (skel, NULL, slot, "arm", strip);

lrg_skeleton2d_clip_add_rotate_key (bend, "fore", 0.0f, 0.0f, LRG_SKELETON2D_CURVE_BEZIER);
lrg_skeleton2d_clip_set_key_bezier (bend, "fore", LRG_SKELETON2D_CHANNEL_ROTATE, 0, 0.42f, 0, 0.58f, 1);
lrg_skeleton2d_clip_add_rotate_key (bend, "fore", 1.0f, 90.0f, LRG_SKELETON2D_CURVE_LINEAR);
lrg_skeleton2d_add_clip (skel, bend);

/* every frame */
lrg_skeleton2d_reset_pose (skel);
lrg_skeleton2d_clip_apply (bend, skel, t, 1.0f);
lrg_skeleton2d_set_root_transform (skel, 200, 150, 0, 1, 1);
lrg_skeleton2d_update_world (skel);
BeginDrawing ();
ClearBackground (BLACK);
lrg_skeleton2d_draw (skel, NULL);
EndDrawing ();
#+end_src

** Drawing on the CPU
:PROPERTIES:
:CUSTOM_ID: cpu-drawing
:END:
=lrg_skeleton2d_draw_to_canvas (skel, canvas, tint)= draws a skeleton into an =LrgImageCanvas= on the CPU, so a character renders headless: to frames in CI, in a reel, on a server, into a thumbnail. It walks the slots exactly as =lrg_skeleton2d_draw()= does: current draw order, the attachment each slot shows (active skin, then default), slots at alpha 0 skipped, slot colour times =tint= as the tint, each attachment deformed with the palette of the last =lrg_skeleton2d_update_world()=. Only the last step differs: each mesh is drawn with [[file:../graphics/skinned-sprite.org::#cpu-drawing][lrg_skinned_sprite_draw_to_canvas()]] instead of through rlgl. It deforms through the same per-slot path as =lrg_skeleton2d_deform()= and =lrg_skeleton2d_draw()=: each slot's blend-shape weights (=lrg_skeleton2d_set_shape_weight()=, clip shape keys, procedural layers) are handed to the attachment it shows before skinning, so expressions, blinks and visemes look the same on the CPU as on the GPU (=tests/test-skeleton2d.c= checks the CPU pixels against the =lrg_skeleton2d_deform()= positions). The [[file:../../examples/skeleton2d-talking-head.org][talking head]] and [[file:../../examples/skeleton2d-shape-sheet.org][shape sheet]] examples render a character with the whole shape sheet this way.

*Placement* mirrors the GPU path: the root transform (=lrg_skeleton2d_set_root_transform()=) places the skeleton in canvas pixels, as =LrgSkeleton2DComponent= does from its game object, and the canvas transform stack (=lrg_image_canvas_translate()=, =lrg_image_canvas_scale()=, =lrg_image_canvas_rotate()=) stands in for the 2D camera of =BeginMode2D()=.

*Images*: each attachment samples its CPU source image (=lrg_skinned_sprite_set_source_image()=). An attachment with an =image= path and no source image loads it on first draw, relative to the skeleton's =base-dir= (set by =lrg_skeleton2d_new_from_file()=); =lrg_skeleton2d_load_source_images()= does it for every attachment up front, decoding each distinct file once and reporting a missing file as =G_IO_ERROR_NOT_FOUND=. A mesh without any image is filled with its slot colour, as on the GPU.

#+begin_src C
/* render the "walk" clip of a rig to a PNG sequence, headless */
g_autoptr(GError)         error = NULL;
g_autoptr(LrgSkeleton2D)  skel = lrg_skeleton2d_new_from_file ("hero.rskel2d", &error);
LrgSkeleton2DClip        *walk = lrg_skeleton2d_get_clip (skel, "walk");
GrlColor                  sky = { 40, 50, 70, 255 };
guint                     f;

lrg_skeleton2d_load_source_images (skel, &error);       /* or let the first draw load them */
for (f = 0; f < 24; f++)
{
	g_autoptr(LrgImageCanvas) canvas = lrg_image_canvas_new (256, 256, &sky);
	g_autofree gchar         *path = g_strdup_printf ("walk-%02u.png", f);

	lrg_skeleton2d_reset_pose (skel);
	lrg_skeleton2d_clip_apply (walk, skel, (gfloat)f / 24.0f, 1.0f);
	lrg_skeleton2d_set_root_transform (skel, 128.0f, 200.0f, 0.0f, 1.0f, 1.0f);
	lrg_skeleton2d_update_world (skel);
	lrg_skeleton2d_draw_to_canvas (skel, canvas, NULL);
	grl_image_export (lrg_image_canvas_get_image (canvas), path);
}
#+end_src

For video, use the reel clip [[file:../reel/clips.org::#skeleton2d-clip][LrgReelSkeleton2DClip]], which does the per-frame posing for you and exports through any reel exporter.

*Threads*: the pose, the world matrices and every attachment's deformed buffer are mutable state, so one skeleton must not be posed or drawn from two threads at once. =LrgReelSkeleton2DClip= takes a lock around posing and drawing for =lrg_reel_renderer_render_parallel()=.

*Differences from the GPU*: the CPU path samples bilinearly (the GPU uses the texture's filter mode, point by default) and always blends source-over in 8-bit gamma space. The deformed geometry is identical. =tests/test-skeleton2d.c= (=/skeleton2d/cpu/*=) draws the arm and figure fixtures and checks pixels: the bending forearm moves, slot colours and the draw tint multiply, draw order decides overlaps, the canvas transform moves the skeleton, atlas regions sample only their cell, and image paths load relative to the base directory.

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:
Measured by =tests/test-skeleton2d.c= (=/skeleton2d/perf=, release build, x86_64, one core; run it with =--verbose= to see the numbers on your machine):

| Work | Time |
|------+------|
| Pose a 12-bone figure: reset + apply the 13-timeline walk clip + =update_world= | 1.8 .. 2.5 µs |
| Skin a 1024-vertex grid with 4 influences per vertex | 24 .. 39 µs (24 .. 38 ns per vertex) |
| Deform the 6-slot, 112-vertex figure | 1.7 .. 2.8 µs |

So a hundred animated 100-vertex characters cost well under a millisecond of CPU per frame. Skinning runs on the CPU; drawing goes through rlgl's batch (one batch per texture change; triangles are submitted in chunks of 1024). A GPU skinning path was not added: at these sizes the CPU cost is small next to the draw submission, and the CPU path keeps exact deformed positions available for picking and bounds. Clip lookups resolve names through hash tables each apply; keep clips small (tens of timelines).

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- *Reset before applying.* =lrg_skeleton2d_clip_apply()= leaves unkeyed channels alone and mixes from the current pose; without =lrg_skeleton2d_reset_pose()= poses accumulate.
- *Update before reading or drawing.* World transforms and the palette are only computed by =lrg_skeleton2d_update_world()=.
- *Meshes live in setup space*, not in bone space: author vertices where the image sits in the setup pose. Moving a bone's setup pose afterwards moves its bind, so meshes keep their place in the setup pose but deform from the new joint.
- *One skeleton per character.* A skeleton holds its current pose; two components sharing one fight over it. Load the file once per character (or save to data and load copies).
- *Attachments are shared by reference*, also across copies made with =lrg_skinned_sprite_copy()= for textures; changing a sprite's geometry changes it everywhere it is attached.
- *Rotation keys are not wrapped*: =350 -> 10= turns 340 degrees backwards. Key =350 -> 370= for the short way.
- *Draw-order keys must name every slot*; a key written for an older version of the rig with fewer slots is skipped when applied.
- *Attachment swaps and draw order switch at mix weight 0.5* during crossfades; bones, colours and shape weights blend smoothly.
- *Shape weights live on the slot.* Setting a weight on the sprite directly (=lrg_skinned_sprite_set_shape_weight()=) is overwritten on the next skeleton deform for every shape the slot has a weight for; drive faces through the slot.
- *Your own deform path must push the weights.* Code that skins attachments itself (=lrg_skinned_sprite_deform()= on =lrg_skeleton2d_get_attachment()=) sees the weights last pushed by =lrg_skeleton2d_deform()= or =lrg_skeleton2d_draw()=; call one of those first.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: editor
:END:
The editor's 2D rig editor ([[file:../../editor/skeleton2d-editor.org][2D Rig Editor]]) is built on these hooks:
- *Bone tool*: create bones by dragging (=lrg_skeleton2d_add_bone()=), select with =lrg_skeleton2d_pick_bone()=, edit the rest pose with =lrg_skeleton2d_set_bone_setup()= and =lrg_skeleton2d_set_bone_length()=; the overlay is =lrg_skeleton2d_draw_bones()=.
- *Mesh tool*: cut a sprite into a grid (=lrg_skinned_sprite_new_grid()=) or place vertices (=lrg_skinned_sprite_add_vertex()=, =lrg_skinned_sprite_set_vertex()=, =lrg_skinned_sprite_add_triangle()=), wireframe with =lrg_skinned_sprite_draw_wireframe()=.
- *Weights*: an "automatic weights" button calls =lrg_skeleton2d_compute_auto_weights()=; weight painting edits =lrg_skinned_sprite_set_weights()=.
- *Slots, skins, attachments panel*: =lrg_skeleton2d_list_attachments()=, =lrg_skeleton2d_set_attachment()=, =lrg_skeleton2d_set_skin()=; the =changed= signal refreshes the inspector.
- *Dopesheet / clip preview*: rows from =lrg_skeleton2d_clip_get_targets()=, keys from =lrg_skeleton2d_clip_get_key()= and friends, scrubbing with =lrg_skeleton2d_component_set_time()=. Shape weight timelines are not shown or edited there yet; the editor keeps them intact on save, and mesh edits keep each shape's offsets on the surviving vertices.
- *Validation*: the document editor runs =lrg_skeleton2d_new_from_data()= on the =.rskel2d= text; messages carry the node path.
