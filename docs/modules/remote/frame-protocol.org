** Transport
:PROPERTIES:
:CUSTOM_ID: frame-protocol-transport
:END:
One connected =AF_UNIX=, =SOCK_STREAM= socket carries both directions: frames from the /application/ (which renders, =LrgFrameExport=) to the /host/ (which shows them: a GTK widget, a web page, another process), and input from the host back (=LrgInputInject= reads it). Get one from =socketpair()= when the host starts the application, or from =accept()= on a listening socket. A stream socket was chosen over =SOCK_SEQPACKET= because messages can be larger than a datagram (an inline 1920x1080 frame is 8 MiB) and every message carries its own length.

Both ends use =MSG_DONTWAIT= (and =MSG_NOSIGNAL= when writing), so the socket's own blocking mode does not matter and neither side ever blocks on the other. =SIGPIPE= is never raised; a closed peer is the error =LRG_FRAME_ERROR_CLOSED=.

** Messages
:PROPERTIES:
:CUSTOM_ID: frame-protocol-messages
:END:
Every message is a 16-byte header followed by =body_size= bytes. All integers are little-endian; floats are IEEE-754 binary32, little-endian.

| Offset | Size | Field       | Value                                              |
|--------+------+-------------+----------------------------------------------------|
|      0 |    4 | =magic=     | =LRG_FRAME_PROTOCOL_MAGIC=, the bytes "LFRM" (0x4D52464C) |
|      4 |    2 | =version=   | =LRG_FRAME_PROTOCOL_VERSION= (1)                   |
|      6 |    2 | =type=      | an =LrgFrameMessageType=                           |
|      8 |    4 | =body_size= | bytes after the header (at most =LRG_FRAME_MAX_BODY_SIZE=, 256 MiB) |
|     12 |    4 | =reserved=  | 0; readers ignore it                               |

=LRG_FRAME_HEADER_SIZE= is 16. Readers refuse a wrong magic, a different version and an oversized body (=LRG_FRAME_ERROR_PROTOCOL=; the stream cannot be resynchronised, so the connection is over). They skip whole messages of types they do not know, and ignore body bytes beyond the sizes below, so a later version can add messages and grow existing ones.

*** Application to host
:PROPERTIES:
:CUSTOM_ID: frame-protocol-app-to-host
:END:
=LRG_FRAME_MSG_HELLO= (1) is the first message, =LRG_FRAME_HELLO_BODY_SIZE= (16) bytes:

| Offset | Size | Field          | Meaning                                                    |
|--------+------+----------------+------------------------------------------------------------|
|      0 |    4 | =capabilities= | bit 0 =LRG_FRAME_CAPABILITY_MEMFD=: frames may come in memfds |
|      4 |    4 | =width=        | initial frame width                                        |
|      8 |    4 | =height=       | initial frame height                                       |
|     12 |    4 | =reserved=     | 0                                                          |

=LRG_FRAME_MSG_FRAME= (2) is one frame. Its fixed part is =LRG_FRAME_FRAME_BODY_SIZE= (48) bytes:

| Offset | Size | Field          | Meaning                                                       |
|--------+------+----------------+---------------------------------------------------------------|
|      0 |    4 | =width=        | pixels, 1 to =LRG_FRAME_MAX_DIMENSION= (16384)                 |
|      4 |    4 | =height=       | pixels, 1 to 16384                                            |
|      8 |    4 | =stride=       | bytes from one row to the next, at least =width= x 4          |
|     12 |    4 | =format=       | =LRG_FRAME_FORMAT_RGBA8= (1): R, G, B, A bytes, straight alpha, rows top to bottom |
|     16 |    8 | =frame_number= | counts from 0 for every frame rendered, sent or dropped, so gaps show drops |
|     24 |    8 | =timestamp=    | microseconds on the sender's monotonic clock (=g_get_monotonic_time()=) |
|     32 |    4 | =flags=        | bit 0 =LRG_FRAME_FLAG_PIXELS_IN_FD=                            |
|     36 |    4 | =pixel_bytes=  | =stride= x =height=                                            |
|     40 |    8 | reserved       | 0                                                             |

With =LRG_FRAME_FLAG_PIXELS_IN_FD= clear the =pixel_bytes= of pixels follow in the body (=body_size= = 48 + =pixel_bytes=). With it set the body is only the 48 bytes and the pixels are in a *memfd* passed with =SCM_RIGHTS= on the message's first byte: offset 0, at least =pixel_bytes= long, sealed with =F_SEAL_SHRINK=, =F_SEAL_GROW=, =F_SEAL_WRITE= and =F_SEAL_SEAL=, so the host can =mmap()= it read-only and nothing can change or truncate it underneath. The host owns the received descriptor and closes it. Descriptors are paired with frames in arrival order; a memfd frame with no descriptor waiting is a protocol error.

*** Host to application
:PROPERTIES:
:CUSTOM_ID: frame-protocol-host-to-app
:END:
| Type                                | Body bytes | Fields                                                              |
|-------------------------------------+------------+---------------------------------------------------------------------|
| =LRG_FRAME_MSG_POINTER_MOVE= (16)   |          8 | f32 =x=, f32 =y= in frame pixels                                    |
| =LRG_FRAME_MSG_POINTER_BUTTON= (17) |         16 | u32 =button= (0 left, 1 right, 2 middle, as =GrlMouseButton=), u32 =pressed= (1/0), f32 =x=, f32 =y= |
| =LRG_FRAME_MSG_SCROLL= (18)         |          8 | f32 =dx=, f32 =dy= in wheel steps, positive =dy= away from the user |
| =LRG_FRAME_MSG_KEY= (19)            |         16 | u32 =key= (a =GrlKey=, raylib's key code; 0 for text only), u32 =pressed=, u32 =modifiers= (=LrgFrameModifier=: shift 1, control 2, alt 4, super 8), u32 =codepoint= (the character typed, 0 for none) |
| =LRG_FRAME_MSG_RESIZE= (20)         |          8 | u32 =width=, u32 =height= the host wants frames at                  |

Coordinates are in frame pixels, origin top-left, whatever size the host displays the frame at: the host scales its pointer position. A resize to 0 or past 16384 is ignored.

** Delivery: memfd or inline, and back-pressure
:PROPERTIES:
:CUSTOM_ID: frame-protocol-delivery
:END:
The application chooses (=lrg_frame_export_set_use_memfd()=): memfds on Linux by default, inline elsewhere. A memfd frame is a 64-byte message, so a host that falls behind costs a dropped frame and nothing else; inline frames are simpler for a host that cannot receive descriptors (a WebSocket bridge, another machine through a relay).

Frames are never queued behind a busy socket, because a late frame is worse than a missing one: when the socket takes none of a frame it is dropped; when it takes part of one the rest is kept and written first by the next send or =lrg_frame_export_flush()=, and every frame until then is dropped. =lrg_frame_export_get_sent_frames()= and =lrg_frame_export_get_dropped_frames()= count them; frame numbers keep counting, so the host sees the gaps. Input in the other direction is small and is never dropped: what the socket cannot take is queued.

** Errors
:PROPERTIES:
:CUSTOM_ID: frame-protocol-errors
:END:
=LRG_FRAME_ERROR= (=lrg_frame_error_quark()=, =LrgFrameError=, =lrg_frame_error_get_type()=):

| Code                       | When                                                                  |
|----------------------------+-----------------------------------------------------------------------|
| =LRG_FRAME_ERROR_IO=       | a system call failed                                                  |
| =LRG_FRAME_ERROR_PROTOCOL= | bad magic or version, an oversized body, a frame that does not add up, a memfd frame without a descriptor; the connection stays broken |
| =LRG_FRAME_ERROR_CLOSED=   | the peer closed the connection                                        |
| =LRG_FRAME_ERROR_INVALID=  | the caller passed a frame that cannot be sent                         |

=lrg_frame_message_type_get_type()= and =lrg_frame_modifier_get_type()= register the message type and modifier enums.

** Writing a host without libregnum
:PROPERTIES:
:CUSTOM_ID: frame-protocol-foreign-host
:END:
A host reads with =recvmsg()= (collecting =SCM_RIGHTS= descriptors in order into a queue), buffers bytes until a whole header and body are there, checks the magic and version, and for each frame either copies the inline pixels or pops the next descriptor, =mmap()=s =pixel_bytes= read-only and closes it. It writes the five input messages above. =src/remote/lrg-frame-receiver.c= is a complete host in about 300 lines; =src/remote/lrg-frame-protocol.h= has every constant.
