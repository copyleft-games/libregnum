** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
Since 0.9.0 an =LrgTileset= is more than a texture cut into a grid. It carries everything a tile needs at runtime and in the editor, and it is saved as an =.rtileset= YAML file:

- *Flip and rotation per cell.* A layer cell keeps three transform bits next to the tile id (Tiled's encoding), so one tile image can be drawn in all eight orientations.
- *Collision shapes per tile.* Polygons in tile pixels; a solid tile without polygons collides over its whole cell.
- *Custom data per tile.* Ordered key/value text (terrain kind, footstep sound, damage).
- *Animated tiles.* A list of frames with durations in milliseconds; every cell of the tile plays it.
- *Rule tiles.* Autotiling brushes (see [[file:rule-tile.org][Rule tiles]]) stored in the same file.
- *Layout.* Margin and spacing in the image, and a draw offset for tall isometric tiles.

The format follows the [[file:../../guides/writing-a-data-format.org][data format rules]]: strict errors with the key path, unknown keys kept and written back, byte-stable round trips.

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:

*** Tile ids and tile indices
:PROPERTIES:
:CUSTOM_ID: ids
:END:
There are two numberings and they differ by one:

| Where | Numbering | Example |
|-------+-----------+---------|
| =LrgTileset= API (=tile_id= parameters), every tile reference inside an =.rtileset= | 0-based *tile index* into the image grid | =lrg_tileset_set_tile_data (ts, 4, ...)= |
| =LrgTilemapLayer= cells, rule tile outputs (=lrg_tile_rule_add_output()=), =LrgRuleTile= API | 1-based *tile id* plus transform bits; 0 is an empty cell | =lrg_tilemap_layer_set_tile (layer, x, y, 5)= draws tile index 4 |

=lrg_tile_get_id()= strips the transform bits from a cell value; the tile index is that id minus one.

*** Transform bits
:PROPERTIES:
:CUSTOM_ID: transform-bits
:END:
The top three bits of a 32-bit cell value transform the tile when it is drawn, exactly like Tiled's GID flags:

| Bit | Macro | Meaning |
|-----+-------+---------|
| 31 | =LRG_TILE_FLIP_HORIZONTAL= | mirror left to right |
| 30 | =LRG_TILE_FLIP_VERTICAL= | mirror top to bottom |
| 29 | =LRG_TILE_FLIP_DIAGONAL= | swap x and y (applied first) |
| | =LRG_TILE_FLAGS_MASK= | the three bits |
| | =LRG_TILE_ID_MASK= | the id bits (29 bits) |

Working with the raw bits is error-prone, so the API speaks in a canonical form: *mirror left to right (optional), then rotate clockwise by 0-3 quarter turns*. Every one of the eight orientations of a square has exactly one such pair:

| mirrored | rotation | bits |
|----------+----------+------|
| no | 0 | none |
| no | 1 (90 degrees clockwise) | diagonal + horizontal |
| no | 2 | horizontal + vertical |
| no | 3 | diagonal + vertical |
| yes | 0 | horizontal |
| yes | 1 | all three |
| yes | 2 | vertical |
| yes | 3 | diagonal |

=lrg_tile_make()= builds a cell value from an id and a transform, =lrg_tile_get_rotation()= and =lrg_tile_get_mirrored()= read it back, =lrg_tile_rotate()=, =lrg_tile_flip_horizontally()= and =lrg_tile_flip_vertically()= compose a transform on top of the current one (what a painter's rotate/flip keys do). =lrg_tile_transform_point()= maps a point of the tile image through the transform; collision polygons use it.

The renderer draws a mirrored tile with a negative source width and rotates it about its centre. Rotating a non-square tile by a quarter turn swaps its extents; keep rotated tiles square.

*** Collision
:PROPERTIES:
:CUSTOM_ID: collision
:END:
A tile collides when it has the =LRG_TILE_PROPERTY_SOLID= flag or at least one collision polygon (=lrg_tileset_tile_has_collision()=). Polygons are in tile-image pixels, origin top-left, either winding, at least three points. Consumers place them like the renderer places the image: the image's bottom-left corner on the cell's bottom-left corner plus the tileset's draw offset, transformed with the cell's flip/rotation. =lrg_shadow_occluder2d_add_tilemap()= is the first consumer (2D shadows); physics colliders can be built the same way.

*** Animated tiles
:PROPERTIES:
:CUSTOM_ID: animation
:END:
=lrg_tileset_set_tile_animation()= gives a tile a frame list. Cells keep the animated tile's own id; at draw time =lrg_tileset_get_animated_tile()= maps it to the frame for the map's clock (=lrg_tilemap_update()=). The flag =LRG_TILE_PROPERTY_ANIMATED= follows the frame list.

** The .rtileset format
:PROPERTIES:
:CUSTOM_ID: format
:END:

*** Annotated example
:PROPERTIES:
:CUSTOM_ID: format-example
:END:
#+begin_src yaml
version: 1                 # optional; only 1 is accepted
name: dungeon              # optional, LrgTileset name
image: dungeon.png         # optional, relative to this file's directory
tile_size: [16, 16]        # required: tile width and height in pixels (1..65536)
columns: 8                 # required: tiles per image row (1..65536)
tile_count: 64             # required: number of tiles (0..16777216)
margin: 0                  # optional, default 0: pixels before the first tile
spacing: 1                 # optional, default 0: pixels between tiles
offset: [0, -8]            # optional, default [0, 0]: draw offset of every tile
tiles:                     # optional: only tiles with something to say, ascending ids
- id: 3                    # required: tile index 0..tile_count-1, each id once
  flags: [solid]           # optional: solid, animated, hazard
- id: 5
  flags: [hazard]
  collision:               # optional: polygons, x0, y0, x1, y1, ... (>= 3 points)
  - [0, 8, 16, 8, 16, 16, 0, 16]
  data:                    # optional: scalar values, kept in order, read as text
    kind: water
    damage: 2
  animation:               # optional: frames (tile index, milliseconds >= 1)
  - {tile: 5, duration: 200}
  - {tile: 6, duration: 100}
  note: keep me            # unknown keys of a tile entry are kept
rule_tiles:                # optional, see rule-tile.org
- name: grass
  default: 20              # tile index, or {tile, rotate, flip}
  seed: 7
  match_tiles: [3]
  rules:
  - pattern: [".#.", "-@-", "..."]
    transform: rotated
    tiles: [21, {tile: 22, weight: 0.5, rotate: 1, flip: true}]
  - tiles: [20]
editor: {zoom: 2}          # unknown top-level keys are kept and written back
#+end_src

The writer emits the keys in the order above, block style, omits defaults (=margin=, =spacing=, =offset= and empty tile entries) and writes =animated= in =flags= only for tiles without frames (frames imply it). Data values are written as plain scalars; they always read back as text, so =damage: 2= and =damage: "2"= load the same.

*** Errors
:PROPERTIES:
:CUSTOM_ID: format-errors
:END:
Load errors use =LRG_TILESET_ERROR= (=LrgTilesetError=, registered as =lrg_tileset_error_get_type()=, quark =lrg_tileset_error_quark()=):

| Code | When |
|------+------|
| =LRG_TILESET_ERROR_IO= | the file or the image cannot be read or written; texture load without a GL context |
| =LRG_TILESET_ERROR_PARSE= | the text is not YAML |
| =LRG_TILESET_ERROR_INVALID= | a schema error; the message is =source: /key/path: what is wrong= |

Examples of messages: =dungeon.rtileset: /tiles/0/id: expected a whole number from 0 to 15=, =/tiles/0/flags/1: expected solid, animated or hazard=, =/tiles/1: tile 2 is listed twice=, =/rule_tiles/0/rules/0/pattern/1: the centre character must be '@'=, =/rule_tiles/1: rule tile "a" is defined twice=.

*** Loading a tileset and reading tile data
:PROPERTIES:
:CUSTOM_ID: example-load
:END:
#+begin_src C
g_autoptr(GError) error = NULL;
g_autoptr(LrgTileset) tiles = NULL;
guint tile_x, tile_y;
guint cell;

/* after InitWindow(): load the description and the image */
tiles = lrg_tileset_new_from_asset_file ("assets/dungeon.rtileset", TRUE, &error);
if (tiles == NULL)
	g_error ("%s", error->message);   /* e.g. "dungeon.rtileset: /tiles/2/id: ..." */

/* footstep sound of the tile under the player */
lrg_tilemap_world_to_tile (map, player_x, player_y, &tile_x, &tile_y);
cell = lrg_tilemap_layer_get_tile (ground, tile_x, tile_y);
if (lrg_tile_get_id (cell) != 0)
{
	const gchar *sound = lrg_tileset_get_tile_data (tiles, lrg_tile_get_id (cell) - 1, "sound");

	if (sound != NULL)
		play_footstep (sound);
}
#+end_src

*** Authoring a tileset in code and saving it
:PROPERTIES:
:CUSTOM_ID: example-save
:END:
#+begin_src C
g_autoptr(LrgTileset) ts = lrg_tileset_new_empty (16, 16, 8, 64);
gfloat ramp[6] = { 0, 16, 16, 0, 16, 16 };   /* a slope: bottom-left, top-right, bottom-right */
guint water[3] = { 40, 41, 42 };
guint ms[3] = { 150, 150, 150 };

lrg_tileset_set_name (ts, "overworld");
lrg_tileset_set_image_path (ts, "overworld.png");
lrg_tileset_set_tile_properties (ts, 1, LRG_TILE_PROPERTY_SOLID);
lrg_tileset_add_tile_collision_polygon (ts, 2, ramp, 6);
lrg_tileset_set_tile_data (ts, 40, "kind", "water");
lrg_tileset_set_tile_animation (ts, 40, water, ms, 3);
lrg_tileset_save_to_file (ts, "assets/overworld.rtileset", NULL);
#+end_src

*** Rotating a painted tile
:PROPERTIES:
:CUSTOM_ID: example-rotate
:END:
#+begin_src C
guint cell = lrg_tilemap_layer_get_tile (layer, x, y);

/* R key: turn clockwise; F key: mirror */

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:
Per-tile data lives in a sparse array of tile slots; a tile without data costs one NULL pointer. Lookups are O(1) (=lrg_tileset_get_tile_data()= is a hash lookup, collision polygons an array index). Animated tiles are resolved per drawn cell with a walk over the tile's frames (a handful of comparisons). Loading and saving are linear in the file size. The transform bits cost nothing at draw time beyond a negative source width and a rotation argument to the same draw call.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- *Off by one.* Tileset functions and the file take 0-based tile indices; cells and rule tile outputs hold 1-based ids. =lrg_tile_get_id (cell) - 1= is the index.
- *Strip the bits before comparing ids.* =lrg_tilemap_layer_get_tile()= returns the raw cell; code that did arithmetic on raw values (=tile - 1=) breaks on flipped cells. Use =lrg_tilemap_layer_get_tile_id()= or =lrg_tile_get_id()=.
- *=columns= and =tile_count= are required in the file* even when an image is present, so tools can work without decoding it; keep them in step with the image.
- *Rotated non-square tiles* swap extents and will not fit their cell.
- *Data values are text.* =lrg_tileset_get_tile_data_double()= parses; a value written as =2= reads back as ="2"=.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: editor
:END:
The 0.9.0 editor wave (tile properties panel, rule tile editor) builds on these hooks; until then the tile painter writes the transform bits through the layer API.
- *Tile properties panel*: select a tile in the palette; flags via =lrg_tileset_set_tile_properties()=, a polygon editor over the tile image with =lrg_tileset_add_tile_collision_polygon()= / =lrg_tileset_clear_tile_collision()=, a key/value table on =lrg_tileset_get_tile_data_keys()= / =lrg_tileset_set_tile_data()=, a frame strip on =lrg_tileset_set_tile_animation()=. Refresh on =LrgTileset::changed=.
- *Painter flips/rotation*: rotate and flip keys compose with =lrg_tile_rotate()= / =lrg_tile_flip_horizontally()= / =lrg_tile_flip_vertically()= on the brush value; previews draw through the normal tilemap path, which honours the bits.
- *Validation*: the document editor runs =lrg_tileset_new_from_asset_data()= (=load_texture= FALSE) on the =.rtileset= text; messages carry the key path.
- *Saving*: =lrg_tileset_save_to_data()= gives the text the document model diffs and writes.
