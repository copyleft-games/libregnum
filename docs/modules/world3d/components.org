* 3D Components

** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

libregnum 0.9 adds a runtime 3D world: an [[file:world3d.org][LrgWorld3D]] owning a tree of [[file:entity3d.org][LrgEntity3D]] entities. An entity is only a transform with a name, tags, a layer and flags; everything it does comes from its components, the same #LrgComponent base class the 2D ECS uses, with the 0.9 3D hooks (=attached_entity=, =fixed_update=, =late_update=, =collect_render=, =get_bounds=, =world_entered=, =world_exited=).

=LrgParticleComponent= (=.rparticles= effects on an entity, drawn in the transparent pass) has its own page: [[file:particle-component.org][LrgParticleComponent]].

This page documents the built-in 3D components, which live in =src/world3d/components/=:

| Component                    | What it is                                              | Editor visual it comes from |
|------------------------------+---------------------------------------------------------+-----------------------------|
| =LrgMeshRendererComponent=   | a built-in primitive or a mesh asset with a material    | PRIMITIVE, MESH_ASSET       |
| =LrgLightComponent=          | a directional, point or spot light                      | LIGHT                       |
| =LrgCameraComponent=         | a camera with priority-based selection                  | CAMERA                      |
| =LrgAudioSourceComponent=    | a positional sound emitter                              | AUDIO_EMITTER               |
| =LrgAudioListenerComponent=  | the ears of the world                                   | (none: add it to the player or camera) |
| =LrgBillboardComponent=      | a textured quad, camera facing or fixed                 | SPRITE                      |
| =LrgTilemapComponent=        | a tile grid in the entity's XY plane                    | TILEMAP                     |
| =LrgSpawnComponent=          | a spawn point with type, team and tags                  | (none: gameplay data)       |
| =LrgTriggerComponent=        | a box or sphere volume with enter/exit signals          | (none: gameplay data)       |
| =LrgSkinnedModelComponent=   | an animated glTF model driven by an #LrgModelAnimator   | (none in 0.9 M1)            |
| =LrgRigidBodyComponent=      | a physics body (0.9.0 M5)                                | the node's =physics:= block |
| =LrgColliderComponent3D=     | one collision shape, or a trigger volume                 | =physics: shapes:=          |
| =LrgJointComponent=          | a joint to another body or the world                     | =physics: joints:=          |
| =LrgNavAgentComponent=       | a navigation agent of the world's crowd (0.9.0 M6)       | (none: add it in the components list) |
| =LrgTerrainComponent=        | a .rterrain with foliage and a heightfield body (0.9.0 M7, [[file:../graphics/terrain-asset.org][terrain-asset]]) | TERRAIN |
| =LrgFoliageComponent=        | standalone foliage layers (0.9.0 M7, [[file:../graphics/foliage.org][foliage]])       | (none: add it in the components list) |
| =LrgWaterComponent=          | a .rwater plane, lake or river (0.9.0 M7, [[file:../graphics/water-body.org][water-body]]) | WATER |
| =LrgParticleComponent=       | a .rparticles effect (0.9.0 M7, [[file:particle-component.org][particle-component]]) | (none: =type: particles=) |
| =LrgAiComponent=             | a .rbt tree and/or .rfsm machine over a blackboard (0.9.0 M6, [[file:../ai/ai-component.org][ai-component]]) | (none: =type: ai=) |

Three rules hold for all of them:

1. *Everything is a GObject property.* Level instantiation (=lrg_level_instantiate_3d()=), the inspector and play-in-editor set components only through properties, so every tunable is one (scalars, enums, strings and objects; colours are split into =color-r= .. =color-a= floats so the inspector and the =.rlevel= param bags can edit them). Every property is =G_PARAM_EXPLICIT_NOTIFY=: =notify= fires only on real changes.
2. *Nothing draws directly.* Drawing components implement =collect_render()= and submit #LrgRenderItem records into the #LrgRenderList that =lrg_world3d_collect_render()= builds per camera; a renderer ([[file:renderer.org][LrgWorld3DRenderer]], the editor viewport) replays the list for every pass. Lights register an #LrgLight3DDesc with the world instead.
3. *Headless first.* No component needs a window or an audio device to be created, configured, simulated or collected. GPU resources (models, textures, tilesets) load lazily through an optional #LrgAssetManager and fail quietly (once, with a =g_debug=) without a graphics context; the renderer can resolve unresolved assets itself.

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:

*** The frame
:PROPERTIES:
:CUSTOM_ID: concepts-frame
:END:

=lrg_world3d_step()= runs =fixed_update= (0..n times), =update=, then =late_update=; rendering calls =collect_render= per camera afterwards. The components use the phases like this:

| Phase            | Components that use it                                                                 |
|------------------+----------------------------------------------------------------------------------------|
| =world_entered=  | light (registers), camera (registers by priority), listener (becomes the world's listener), audio source (autoplay) |
| =fixed_update=   | trigger (overlap test, enter/exit signals); the physics components run in the world's physics hooks right after it (build and sync bodies, step, write back, trigger / collision / broken signals) |
| =update=         | skinned model (clip switch, time advance), animator (graph, IK, palette, root motion) |
| =late_update=    | light (re-registers from the moved entity), camera (follows the entity), listener (feeds pose and velocity to the audio manager), audio source (re-spatialises its voice: rolloff, cone, doppler, occlusion; restarts device loops) |
| =collect_render= | mesh renderer, billboard, tilemap, skinned model                                       |
| =world_exited=   | light, camera, listener, audio source, trigger (unregister / stop / forget)            |

A component added to an entity that is already in a world gets =world_entered= at once; one added before the entity joins gets it when the entity joins. Removing the component or the entity runs =world_exited=.

*** Render items
:PROPERTIES:
:CUSTOM_ID: concepts-render-items
:END:

Each drawing component starts from =lrg_render_item_init_for_entity()= (the entity's world matrix and layer), fills the kind, parameters, material, colour and flags, sets world bounds with =lrg_render_item_set_local_bounds()= when it knows its local bounds, and adds the item when =lrg_render_list_accepts()= keeps it (layer in the camera's cull mask, inside the frustum or a shadow caster). The list files the item under OPAQUE, CUTOUT or TRANSPARENT from its flags, and also under SHADOW_CASTER with =LRG_RENDER_ITEM_FLAG_CAST_SHADOW=.

Every component with a =layer= property uses -1 for "the entity's layer" and 0 .. 31 to override it.

*** Lazy assets
:PROPERTIES:
:CUSTOM_ID: concepts-assets
:END:

Mesh assets, billboard textures, tileset images and skinned models are referenced by path or GUID. When the component has an =asset-manager=, it loads the asset on first use (the model or texture needs a graphics context; a failed load is not retried until the path or manager changes). Without one, the render item goes out with a =NULL= handle and the renderer resolves the path from the component: [[file:renderer.org][LrgWorld3DRenderer]] does this for mesh renderers through =lrg_world3d_renderer_get_model()= and its asset resolver. An explicit handle (=lrg_mesh_renderer_component_set_model()=, =lrg_billboard_component_set_texture()=, =lrg_tilemap_component_set_tileset()=, =lrg_skinned_model_component_set_animator()=) always wins.

*** A lit scene
:PROPERTIES:
:CUSTOM_ID: example-lit-scene
:END:

#+begin_src c
g_autoptr(LrgWorld3D)         world = lrg_world3d_new ();
g_autoptr(LrgWorld3DRenderer) renderer = lrg_world3d_renderer_new ();
g_autoptr(LrgEntity3D)        crate = lrg_entity3d_new_with_name ("crate");
g_autoptr(LrgEntity3D)        lamp = lrg_entity3d_new_with_name ("lamp");
g_autoptr(LrgEntity3D)        eye = lrg_entity3d_new_with_name ("camera");
LrgMeshRendererComponent     *mesh;
LrgLightComponent            *light;
LrgCameraComponent           *cam;

/* A red 2 x 2 x 2 cube at the origin. */
mesh = lrg_mesh_renderer_component_new_primitive (LRG_PRIMITIVE_CUBE);
lrg_mesh_renderer_component_set_size (mesh, 2.0f, 2.0f, 2.0f);
lrg_mesh_renderer_component_set_color (mesh, 1.0f, 0.1f, 0.1f, 1.0f);
g_object_set (mesh, "roughness", 0.3f, "metallic", 0.0f, NULL);
lrg_entity3d_add_component (crate, LRG_COMPONENT (mesh));
g_object_unref (mesh);
lrg_world3d_add_entity (world, crate);

/* A warm point light above it. */
light = lrg_light_component_new_with_kind (LRG_LIGHT3D_POINT);
lrg_light_component_set_color (light, 1.0f, 0.9f, 0.7f);
g_object_set (light, "intensity", 2.0f, "range", 15.0f, NULL);
lrg_entity3d_set_position_xyz (lamp, 0.0f, 4.0f, 2.0f);
lrg_entity3d_add_component (lamp, LRG_COMPONENT (light));
g_object_unref (light);
lrg_world3d_add_entity (world, lamp);

/* The camera looks down its local -Z. */
cam = lrg_camera_component_new ();
lrg_camera_component_set_priority (cam, 10);
lrg_entity3d_set_position_xyz (eye, 0.0f, 1.0f, 8.0f);
lrg_entity3d_add_component (eye, LRG_COMPONENT (cam));
g_object_unref (cam);
lrg_world3d_add_entity (world, eye);

while (!WindowShouldClose ())
{
	lrg_world3d_step (world, GetFrameTime ());
	BeginDrawing ();
	lrg_world3d_renderer_render (renderer, world, NULL, NULL, 0, 0);
	EndDrawing ();
}
lrg_world3d_renderer_release (renderer);
#+end_src

*** Triggers and spawn points
:PROPERTIES:
:CUSTOM_ID: example-gameplay
:END:

#+begin_src c
static void
on_entered (LrgTriggerComponent *trigger,
            LrgEntity3D         *who,
            gpointer             user_data)
{
	g_message ("%s reached the exit", lrg_entity3d_get_name (who));
}

/* An exit zone: 4 x 3 x 4 box, only entities tagged "player" count. */
LrgTriggerComponent *exit_zone = lrg_trigger_component_new_box (4.0f, 3.0f, 4.0f);

lrg_trigger_component_set_filter_tag (exit_zone, "player");
g_signal_connect (exit_zone, "entered", G_CALLBACK (on_entered), NULL);
lrg_entity3d_add_component (zone_entity, LRG_COMPONENT (exit_zone));
g_object_unref (exit_zone);

/* Pick a start for team 1. */
g_autoptr(GPtrArray) starts = lrg_spawn_component_find (world, "start", 1);

if (starts->len > 0)
{
	g_autoptr(LrgSpawnPoint3D) sp =
		lrg_spawn_component_to_spawn_point (g_ptr_array_index (starts, 0));
	g_autoptr(GrlVector3) at = lrg_spawn_point3d_get_position (sp);

	lrg_entity3d_set_position_xyz (player, at->x, at->y, at->z);
	lrg_entity3d_add_tag (player, "player");
}
#+end_src

** LrgMeshRendererComponent
:PROPERTIES:
:CUSTOM_ID: mesh-renderer
:END:

Draws a built-in primitive (the #LrgPrimitiveType set the editor uses) or a mesh asset at the entity's world transform. Primitives are centred on the entity and sized like the editor viewport's unit meshes, so a level looks the same in the editor and in the game.

*** Render items
:PROPERTIES:
:CUSTOM_ID: mesh-renderer-items
:END:

One item per frame:

| Case                 | kind      | Fields                                                                                  |
|----------------------+-----------+-----------------------------------------------------------------------------------------|
| primitive            | PRIMITIVE | =primitive=; =params=: cube (x, y, z), sphere/circle (radius), cylinder/cone (radius, height), torus (major, minor), plane/grid (x, z), rectangle (x, y) |
| mesh asset or model  | MODEL     | =model= (resolved, or NULL for the renderer to resolve from =mesh-asset=), =mesh_index= |

Both carry =material= (=lrg_mesh_renderer_component_get_effective_material()=: the slot, or an internal #LrgMaterial3D mirroring colour, roughness, metallic and emission), =color=, the flags of =lrg_mesh_renderer_component_get_flags()=, the layer, world bounds from the local bounds (unknown for an unresolved model) and a =sort_key= grouping equal shapes and models.

With an =LrgMaterial= in the slot (see [[file:../graphics/material.org::#binding][Material binding]]) the item's =color= is the material's base colour and its flags follow the material: the resolved render queue adds =LRG_RENDER_ITEM_FLAG_TRANSPARENT= or =LRG_RENDER_ITEM_FLAG_CUTOUT= (the scalar alpha is no longer consulted; =transparent= still forces it), cull =none= adds =LRG_RENDER_ITEM_FLAG_DOUBLE_SIDED=, the unlit model =LRG_RENDER_ITEM_FLAG_UNLIT=.

*Submesh materials.* =lrg_mesh_renderer_component_set_submesh_material (self, index, material)= gives one mesh of a mesh asset its own =LrgMaterial= (%NULL falls back to the slot); =lrg_mesh_renderer_component_get_submesh_material()=, =lrg_mesh_renderer_component_get_n_submesh_materials()= (one past the highest set index) and =lrg_mesh_renderer_component_clear_submesh_materials()= complete the set. With any submesh material and a resolved model (and =mesh-index= -1) the component submits one MODEL item per mesh (=mesh_index= = i), each with its submesh material or the slot's. Primitives ignore them.

** LrgLightComponent
:PROPERTIES:
:CUSTOM_ID: light
:END:

A light registered with the world as an #LrgLight3DDesc: at =world_entered=, after every property change (including enabling and disabling), and every =late_update= so it follows a moving entity. The position is the entity's world position and the direction its forward (local -Z), like the editor's light gizmo. It is unregistered at =world_exited= and on dispose.

** LrgCameraComponent
:PROPERTIES:
:CUSTOM_ID: camera
:END:

Owns an #LrgCamera3D that renderers draw with. The camera's eye is the entity's world position, it looks down the entity's local -Z with the entity's local +Y up (written at =world_entered= and every =late_update=); projection, field of view and cull mask are written whenever a property changes. While =active= and enabled, the camera is registered with =lrg_world3d_register_camera()= at its =priority=, so =lrg_world3d_get_active_camera()= returns the highest-priority camera (earliest registered on ties) unless one is forced with =lrg_camera_component_make_current()=.

#LrgCamera3D has no clip planes: renderers that need them find the component with =lrg_camera_component_from_camera()= and read =near= and =far=.

:PROPERTIES:
:CUSTOM_ID: camera-properties
:END:

| Property       | Type        | Default | Meaning                                                    |

** LrgAudioSourceComponent
:PROPERTIES:
:CUSTOM_ID: audio-source
:END:

A positional emitter. =lrg_audio_source_component_play()= starts a voice at the entity's world position and every =late_update= keeps it spatialised: distance rolloff, a directional cone, doppler from the measured movement and optional physics occlusion, mixed with flat playback by =spatial-blend=. =autoplay= plays on world entry; leaving the world stops the voice.

Two backends share that spatialisation:

- *Mixer voice* (routed to a bus): when the component has an explicit =mixer=, or a =bus= and the audio manager has a mixer (=lrg_audio_manager_set_mixer()=, normally the project's [[file:../audio/mixer-asset.org][=.rmixer=]]). The sound plays through =lrg_audio_mixer_play()= on =bus= (master when unset); gain and pan are ramped per frame over the update interval, pitch and the occlusion low-pass are set directly (=lrg_audio_mixer_set_voice_gain()= and friends). The samples are the explicit =wave=, else the =sound-path= file, else the bank entry's manifest file, loaded once as =LrgWaveData=. Works headless: render the mixer offline.
- *Device voice*: otherwise, an #LrgAudioManager voice (=lrg_audio_manager_play_sound_at()=) whose gain and pan the component sets itself (=lrg_audio_manager_set_voice_mix()=) along with the doppler pitch (=lrg_audio_manager_set_voice_pitch()=). The sound is a bank entry (=bank= + =sound=) or the =sound-path= file loaded once into the =LRG_AUDIO_SOURCE_FILE_BANK= bank. Without an audio device, an unknown bank or a missing file, =play()= returns 0 and nothing else happens.

*** Attenuation
:PROPERTIES:
:CUSTOM_ID: audio-attenuation
:END:
The gain a source is heard at is

#+begin_example
gain = 1 + spatial_blend * (rolloff(d) * cone(angle) * occlusion - 1)
#+end_example

times =volume= (and, for device voices, the manager's master and SFX volumes). =lrg_audio_source_component_evaluate()= computes gain, pan and pitch for a given listener; =lrg_audio_source_component_get_distance_gain()= is the rolloff alone (what an attenuation gizmo plots).

*Rolloff* (=rolloff-mode=, #LrgAudioRolloff, pure function =lrg_audio_rolloff_evaluate()=), with =d= the distance to the listener, every built-in curve 1 within =min-distance= and 0 beyond =max-distance=:

| Mode | Gain between min and max |
|------+--------------------------|
| =LRG_AUDIO_ROLLOFF_LINEAR= | =(max - d) / (max - min)= |
| =LRG_AUDIO_ROLLOFF_INVERSE= (default) | =min / (min + rolloff (d - min))= rescaled to reach 0 at max (=rolloff= 1 resembles Unity's logarithmic rolloff; 0 is linear); the same curve as #LrgAudioAttenuation |
| =LRG_AUDIO_ROLLOFF_LOGARITHMIC= | =1 - ln (d / min) / ln (max / min)=: linear in log distance |
| =LRG_AUDIO_ROLLOFF_CUSTOM= | the custom #LrgKeyframeCurve sampled at =t = (d - min) / (max - min)= clamped to 0 .. 1 (so it also decides the gain inside min and beyond max), output clamped to 0 .. 1; linear without a curve |

The custom curve is set as an object (=lrg_audio_source_component_set_rolloff_curve()=, which also selects the mode) or as text in =rolloff-curve-keys=: =t:gain= pairs, linear between keys, the form level visual params use (=rolloff_curve_keys: "0:1, 0.25:0.4, 1:0"=).

*Cone* (=lrg_audio_cone_gain()=): the angle between the entity's forward (local -Z) and the direction to the listener. Within half =cone-inner-angle= the gain is 1, beyond half =cone-outer-angle= it is =cone-outer-gain=, linear in angle between. An inner angle of 360 (the default) makes the source omnidirectional.

*Doppler* (=lrg_audio_doppler_pitch()=, OpenAL 1.1): with =u= the unit vector from source to listener, =vl= and =vs= the listener's and the source's velocity along it, =pitch = (c - f vl) / (c - f vs)= with =c= = =speed-of-sound= and =f= = =doppler-factor= (scaled by =spatial-blend=; 0 turns it off). The source's velocity is measured from its movement between late updates (=lrg_audio_source_component_get_velocity()=), the listener's by #LrgAudioListenerComponent (=lrg_audio_manager_set_listener_velocity()=). The result multiplies =pitch=.

*Occlusion* (=occlusion=): every late update a ray from the listener to the source is cast through the world's physics (=lrg_world3d_get_physics()=, =lrg_dynamics_world_raycast_all()= on =occlusion-mask= layers); hits in the last 2% of the ray belong to the source and are ignored. Each body hit multiplies the gain by =occlusion-gain= (up to four count), faded with the =occlusion-fade= time constant; a mixer voice also gets a =occlusion-cutoff= low-pass while occluded. =lrg_audio_source_component_get_occlusion()= and =lrg_audio_source_component_get_occluders()= report it. Without a physics world nothing is occluded.

*Pan* comes from the listener's basis as in =lrg_audio_compute_spatial()=: the direction projected on the listener's right, shrunk inside =min-distance=, scaled by =spatial-blend=.

** LrgLodComponent
:PROPERTIES:
:CUSTOM_ID: lod
:END:

Draws an [[file:../graphics/lod-group.org][LrgLodGroup]] (a level-of-detail chain) at the entity (0.9.0). Every =collect_render= measures the entity's screen size from the render list's camera, picks the level (thresholds, hysteresis, biases, forced level) and submits the models of that level; during a cross-fade it also submits the level fading out. The group is set directly (=group=) or generated from a model asset and its =.meta= LOD keys (=mesh-asset= + =asset-manager=; components with the same model and sidecar settings share one generated group).

*Screen size:* the group's bounding sphere (local bounds, centre and half diagonal) moved by the entity's world matrix, the radius scaled by the largest axis scale, measured with =lrg_lod_screen_size_from_view_projection()= on the list's view-projection, or, when the list has none (frustum culling off), by distance to the eye with the world's active camera fovy (45° without one). It is then multiplied by the component's =bias=.

*Per view state:* selection is stateful (hysteresis, fade), so the component keeps one #LrgLodState per #LrgRenderList (=lrg_lod_component_get_state_for_list()=). The fade advances with the world time the component receives in =update=; before the world ever steps (an editor viewport in edit mode) it uses wall-clock time. Fade steps are clamped to 0.25 s per draw.

*Render items:* one MODEL item per model of the level (=mesh_index= -1, the =material= override, =color=, the layer, world bounds from the group bounds, a =sort_key= by model). Only the incoming level gets =LRG_RENDER_ITEM_FLAG_CAST_SHADOW= (when =cast-shadows=), so a cross-fade does not double the shadow. The item's =lodFade= value is packed into =user_data= (float bits, no destroy notify); renderers read it with =lrg_lod_component_get_item_fade()= and bind it with =lrg_lod_bind_fade()= (see [[file:../graphics/lod-group.org::#renderer][Renderer integration]]).

** LrgReflectionProbeComponent
:PROPERTIES:
:CUSTOM_ID: reflection-probe
:END:

A box-projected local reflection probe ([[file:../lighting/reflection-probe.org][LrgReflectionProbe]]) placed by the entity (0.9.0). The component owns the probe, keeps it at the entity's world position with an axis-aligned box of the authored half sizes (=extents-x/-y/-z=) times the entity's world scale (the entity's rotation does not turn the box), and registers it with the environment of the world it is in (=lrg_world3d_get_environment()=). The lit shader then blends the two probes with the largest influence around each draw (see [[file:../lighting/environment.org][LrgEnvironment]]). Probes are not render items: =collect_render= submits nothing, =get_bounds= reports the local box for picking and the octree.

*Registration.* =world_entered= and every =late_update= (=lrg_reflection_probe_component_sync()=) move the probe into the world's current environment: replacing the world's environment moves the probe on the next frame, a world without an environment leaves it unregistered (unused until the world gets one), a disabled component or an inactive entity takes it out, =world_exited= removes it. =lrg_level_instantiate_3d()= gives the world the level's environment before any entity enters it.

*Captures.* A probe has to be rendered (six faces, then GGX prefiltered) before it reflects anything, which is GPU work done outside =BeginDrawing()=. The component only tracks when it is due: a capture is pending after the probe enters a world, after a resolution or clip change, after =lrg_reflection_probe_component_request_capture()=, and (with =auto-recapture=, the default) after the entity moved or the box changed. Any successful capture of the probe after the request clears it, whoever makes it: =lrg_world3d_renderer_capture_probes()= (the usual call, it captures every probe of the environment in effect with the renderer's own lit passes), =lrg_reflection_probe_component_capture_world()= with your own draw callback, or a direct =lrg_reflection_probe_capture()=.

#+begin_src C
/* after loading the level and opening the window, once: */
lrg_world3d_renderer_capture_probes (renderer, world);

/* every frame: recapture the probes whose capture is pending (moved,
 * requested); cheap when there are none */
if (lrg_reflection_probe_component_count_pending (world) > 0)
	lrg_world3d_renderer_capture_probes (renderer, world);

** Physics components (0.9.0 M5)
:PROPERTIES:
:CUSTOM_ID: physics-components
:END:
Three components put an entity into the world's [[file:../physics/dynamics.org][LrgDynamicsWorld]]: #LrgRigidBodyComponent (the body: kind, mass, material, damping, layer), #LrgColliderComponent3D (one shape each: primitive, convex hull or triangle mesh, offset, trigger flag) and #LrgJointComponent (a joint to another entity or the world). They do nothing until the world has a physics world: =lrg_world3d_set_physics()= or =lrg_world3d_ensure_physics()= (=lrg_level_instantiate_3d()= calls the latter for any level with a =physics:= block). The world steps it from =lrg_world3d_fixed_update()= and keeps entities and bodies in step (see [[file:world3d.org::#physics][LrgWorld3D physics]]).

*** Who owns which body
:PROPERTIES:
:CUSTOM_ID: physics-ownership
:END:
| Entity has                              | Body                                                                                  |
|-----------------------------------------+---------------------------------------------------------------------------------------|
| rigid body + solid colliders            | one body of the rigid body's kind; its shape is the collider's, or a compound of all of them (attach order, each at its offset and rotation) |
| solid colliders, no rigid body          | one *static* body made of all of them, owned by the first one (a wall, a floor, a level mesh) |
| a trigger collider (with or without a rigid body) | its own *kinematic sensor* body following the entity; never part of the rigid body |
| a rigid body without colliders          | no body (nothing to collide with) until a collider is added                           |
| a joint component                       | an #LrgJoint between the entity's body and the target's body (or the world), built when both exist |

Bodies are built lazily in the first fixed update after a change (a collider added, removed or edited, a setting changed, the entity's world scale changed) and rebuilt the same way, keeping the velocity. The entity's world scale is baked into the shape dimensions (non-uniform scale on spheres and capsules uses the largest radial axis). Disabling a component or deactivating its entity removes the body; re-enabling builds it again.

g_autoptr(LrgWorld3D) world = lrg_world3d_new ();
LrgEntity3D *floor, *crate, *zone, *door;

lrg_world3d_ensure_physics (world);   /* gravity -9.81 Y, default layers */

/* a static floor: colliders without a rigid body */

{
	g_autoptr(LrgColliderComponent3D) slab = lrg_collider_component3d_new_box (20.0f, 0.5f, 20.0f);

	lrg_entity3d_add_component (floor, LRG_COMPONENT (slab));
}

/* a dynamic crate */
crate = lrg_entity3d_new_with_name ("crate");
lrg_entity3d_set_position_xyz (crate, 0.0f, 4.0f, 0.0f);
{
	g_autoptr(LrgRigidBodyComponent) body = lrg_rigid_body_component_new (LRG_DYNAMICS_BODY_DYNAMIC);
	g_autoptr(LrgColliderComponent3D) box = lrg_collider_component3d_new_box (0.5f, 0.5f, 0.5f);

	lrg_rigid_body_component_set_mass (body, 20.0f);
	lrg_rigid_body_component_set_layer (body, "debris");
	lrg_entity3d_add_component (crate, LRG_COMPONENT (body));
	lrg_entity3d_add_component (crate, LRG_COMPONENT (box));
}
lrg_world3d_add_entity (world, crate);

/* a trigger volume */
zone = lrg_entity3d_new_with_name ("zone");
{
	g_autoptr(LrgColliderComponent3D) volume = lrg_collider_component3d_new_box (2.0f, 1.0f, 2.0f);

	lrg_collider_component3d_set_trigger (volume, TRUE);
	g_signal_connect (volume, "trigger-entered", G_CALLBACK (on_zone_entered), game);
	lrg_entity3d_add_component (zone, LRG_COMPONENT (volume));
}
lrg_world3d_add_entity (world, zone);

/* a door hinged to the floor at its left edge, limited to +-90 degrees */

lrg_entity3d_set_position_xyz (door, 3.0f, 1.0f, 0.0f);
{
	g_autoptr(LrgRigidBodyComponent) body = lrg_rigid_body_component_new (LRG_DYNAMICS_BODY_DYNAMIC);
	g_autoptr(LrgColliderComponent3D) panel = lrg_collider_component3d_new_box (0.5f, 1.0f, 0.05f);

	lrg_joint_component_set_anchor (hinge, -0.5f, 0.0f, 0.0f);

	lrg_entity3d_add_component (door, LRG_COMPONENT (body));
	lrg_entity3d_add_component (door, LRG_COMPONENT (panel));
	lrg_entity3d_add_component (door, LRG_COMPONENT (hinge));
}
lrg_world3d_add_entity (world, door);

lrg_world3d_step (world, frame_time);

** LrgClothComponent
:PROPERTIES:
:CUSTOM_ID: cloth-component
:END:
A cloth grid hanging from its entity (=src/world3d/components/lrg-cloth-component.h=): a flag, a banner, a curtain, a cape. It owns an [[file:../physics/cloth.org][LrgCloth]]. The grid lies in the entity's local XY plane with its top left corner at the entity origin, columns along local +X and rows down local -Y; =pin-edges= chooses which vertices follow the entity.

*Phases:* =fixed_update= rebuilds the grid after a property change, pushes the parameters, sets the cloth transform to the entity's world matrix (the first time also resets the cloth there), feeds the skeleton's bone matrices (=lrg_cloth_component_set_skeleton()=), attaches the world's physics (=collide-physics=, =collision-mask=) and steps the cloth by the fixed step. =collect_render= streams the particles into the mesh once per simulation step and submits one =LRG_RENDER_ITEM_MESH= item with an identity world matrix (particles are in world space), the colour, =DOUBLE_SIDED | RECEIVE_SHADOW= (plus =CAST_SHADOW=, =TRANSPARENT= for alpha below 1) and world bounds from the particles. The mesh is created on the first draw with a graphics context; headless the item goes out with a =NULL= mesh. =get_bounds= reports the rest grid. =world_exited= detaches the physics world.

#+end_src

*Pitfalls:* the grid hangs from the entity origin (put the entity at the top of the pole, not its base); teleporting the entity drags the cloth along through its pins, call =lrg_cloth_component_reset()= to snap it; physics collision is one way (bodies do not feel the cloth).

** LrgDestructibleComponent
:PROPERTIES:
:CUSTOM_ID: destructible-component
:END:
Makes an entity breakable (=src/world3d/components/lrg-destructible-component.h=). Its shape is pre-fractured into Voronoi chunks ([[file:../physics/fracture.org][LrgFracture]]): by default the box of the entity's cube #LrgMeshRendererComponent (its size times the entity's world scale), or any fracture given with =lrg_destructible_component_set_fracture()=. A hit swaps the intact object for one dynamic body per chunk in the world's physics.

*Lifecycle:* /intact/ - with =auto-break= the component listens to the physics world's =contact-added= signal; a contact on the entity's #LrgRigidBodyComponent body whose =normal_impulse= reaches =impulse-threshold= is reported (=lrg_destructible_component_report_impact()=, the strongest of a step is kept). /queued/ - the next =fixed_update= breaks (never inside the physics emission). /broken/ - =lrg_fracture_swap_in()= added the chunk bodies (layer =debris-layer=, mass =density= x volume, the break-up velocity), the mesh renderer and rigid body components are disabled (the rigid body drops its body on its next sync), =fractured= is emitted, and =collect_render= draws every chunk as a MESH item at its body's (interpolated) pose with the mesh renderer's colour, material and flags. With =chunk-lifetime= the chunk bodies are removed that many seconds later. =lrg_destructible_component_restore()= undoes it all.

*Signals:* =fractured (LrgDestructibleComponent *self, guint n_chunks)=, =G_SIGNAL_RUN_LAST=.

*** Properties
:PROPERTIES:
:CUSTOM_ID: destructible-component-properties
:END:
| Property | Type | Default | Meaning |
|----------+------+---------+---------|
| =fracture= | =LrgFracture= | NULL | the fracture in use (explicit or derived) |
| =fracture-path= | string | NULL | =.rfracture= cache of the derived fracture |
| =chunk-count=, =seed=, =seed-mode=, =interior-material= | | 12, 1, random, 1 | derived fracture parameters |
| =impulse-threshold= | float (N·s) | 50 | break impulse |
| =density= | float (kg/m³) | 1000 | chunk density |
| =debris-layer= | uint | =LRG_PHYSICS_LAYER_DEBRIS= | chunk object layer |
| =auto-break= | boolean | TRUE | watch contacts |
| =chunk-lifetime= | float (s) | 0 | remove debris after (0: keep) |
| =broken= | boolean, read only | FALSE | state |

*** API
:PROPERTIES:
:CUSTOM_ID: destructible-component-api
:END:
| Function | Description |
|----------+-------------|
| =lrg_destructible_component_new()= | defaults above |
| =lrg_destructible_component_get_fracture()= / =lrg_destructible_component_set_fracture()= | explicit fracture (local frame, scale baked) |
| =lrg_destructible_component_prepare (self, error)= | derive and build (or load the cache) now, at load time |
| =lrg_destructible_component_fracture (self, impact_point, impulse, error)= | break now (needs a world with physics) |
| =lrg_destructible_component_report_impact (self, point, impulse)= | queue a hit; TRUE when it will break |
| =lrg_destructible_component_restore()= | undo the break |
| =lrg_destructible_component_is_broken()=, =lrg_destructible_component_get_chunk_count()=, =lrg_destructible_component_get_chunk_body()= | state and chunk body ids |

#+begin_src c
/* A breakable 2 x 1 x 0.2 m wall: cube visual, static body, box collider, destructible. */
LrgMeshRendererComponent *cube = lrg_mesh_renderer_component_new_primitive (LRG_PRIMITIVE_CUBE);
LrgDestructibleComponent *breakable = lrg_destructible_component_new ();

lrg_mesh_renderer_component_set_size (cube, 2.0f, 1.0f, 0.2f);
g_object_set (breakable, "chunk-count", 16, "impulse-threshold", 80.0f, "density", 2400.0f,
              "fracture-path", "cache/wall.rfracture", "chunk-lifetime", 20.0f, NULL);
/* ... add cube, an LrgRigidBodyComponent (static) with a box collider, then: */
lrg_entity3d_add_component (wall, LRG_COMPONENT (breakable));
lrg_destructible_component_prepare (breakable, NULL);   /* at load time */
#+end_src

*Pitfalls:* derived fractures need a cube primitive (use =set_fracture= for anything else, convex only); a queued break happens in the destructible's =fixed_update=, before the entity-to-body sync of the same fixed update drops the intact body, so the chunks never meet it in a step; a direct =lrg_destructible_component_fracture()= call from game code outside the fixed update leaves the intact body in place until the next sync; a hit must start a new contact to be seen (a resting heavy object never breaks its support); without a rigid body, call =report_impact()= or =fracture()= yourself.

** LrgNavAgentComponent
:PROPERTIES:
:CUSTOM_ID: nav-agent-component
:END:
Makes its entity a navigation agent (0.9.0 M6). While the entity is in a world the component's #LrgNavAgent is in the world's crowd (=lrg_world3d_get_nav_crowd()=) and walks the world's mesh (=lrg_world3d_set_navigation()=): =lrg_nav_agent_component_set_destination()= plans a path, the crowd steers it around other agents and walls with ORCA every fixed substep, and the component writes the agent back to the entity (position = feet + =base-offset=, yaw towards the velocity at =angular-speed=) or, with a dynamic #LrgRigidBodyComponent on the entity, sets the body's horizontal velocity. A kinematic body follows the entity. Game code that moves the entity teleports the agent.

| =radius= | 0.3 | avoidance radius |

| =avoidance-priority= | 0.5 | 0 .. 1, higher gives way less |
| =avoidance-enabled= | =TRUE= | |
| =stopping-distance= | 0.1 | |
| =base-offset= | 0 | pivot height above the feet |
| =update-rotation= | =TRUE= | face the velocity (+Z forward) |

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: editor
:END:

You do not add these components by hand in the editor (0.9 M1): each node visual becomes one component when a level is instantiated with =lrg_level_instantiate_3d()= (also what play-in-editor runs), and the visual's material and param bag map onto the component's properties. Params map by name with underscores turned into dashes (=cast_shadows= → =cast-shadows=), so any property above can be authored as a node param in the inspector or in the =.rlevel= file.

| Visual        | Component                  | Mapping                                                                  |
|---------------+----------------------------+--------------------------------------------------------------------------|
| PRIMITIVE     | mesh renderer              | primitive, material colour → =color-*=, roughness, metallic             |
| MESH_ASSET    | mesh renderer              | asset → =mesh-asset=, material as above                                  |
| LIGHT         | light                      | =light_type= → =kind=, =spot_angle= → =outer-angle=, =intensity=, =range=, material colour → =color-*= |
| CAMERA        | camera                     | =fov=, =near=, =far=                                                     |
| AUDIO_EMITTER | audio source               | asset → =sound-path=, =volume=                                           |
| SPRITE        | billboard                  | asset → =texture-path=, material colour → =color-*=, =pixels_per_unit=  |
| TILEMAP       | tilemap                    | the painted grid (copied) → =node-tilemap=, asset → =tileset-path=, =tile_size= |
| MESH_ASSET with =lod-levels= > 1 in its =.meta= | LOD | resolved asset (absolute) → =mesh-asset=, the engine's asset manager, material as above |
| DECAL         | decal                      | asset → =albedo-path= (absolute when it resolves), =normal= → =normal-path=, =orm= → =orm-path=, material colour → =color-*=, =size_x= .. =size_z=, =opacity=, =fade_angle=, =fade_width=, =sort_order=, =normal_strength=, =blend= by name |
| REFLECTION_PROBE | reflection probe        | =extents_x= .. =extents_z=, =blend_distance=, =intensity=, =box_projection=, =resolution= by name |

Physics components come from the node's =physics:= block instead of the visual (0.9.0 M5): one #LrgRigidBodyComponent with the body settings, one #LrgColliderComponent3D per =shapes:= entry and one #LrgJointComponent per =joints:= entry, added after the visual component (see [[file:../../editor/yaml-format.org::#physics][the format]] and [[file:../../guides/physics.org::#levels][the physics guide]]). The collider gizmos, the body / shape / joint inspector and the layer matrix editor arrive in the next 0.9.0 wave; until then edit the block in the =.rlevel= or through #LrgNodePhysics.

Because the map is shared with =lrg_level_visual_store_property()=, a component property changed while playing can be written back to the node visual it came from.

Example =.rlevel= node (annotated):

#+begin_src yaml
nodes:
  - name: Lamp                  # -> entity name
    transform:
      location: [0.0, 4.0, 2.0] # entity position
      rotation: [-0.8, 0.0, 0.0]  # Euler radians; local -Z is where the light points
    visual:
      kind: light               # -> LrgLightComponent
      material:
        color: [1.0, 0.9, 0.7, 1.0]  # -> color-r/g/b
      params:
        light_type: spot        # -> kind (enum nick)
        intensity: 2.0          # -> intensity
        range: 15.0             # -> range
        spot_angle: 40.0        # -> outer-angle
        cast_shadows: true      # -> cast-shadows (by name)
#+end_src

** Performance notes
:PROPERTIES:
:CUSTOM_ID: performance
:END:

- =collect_render= is per camera per frame: each drawing component builds one item on the stack (tilemaps one per visible layer) and copies it in; there is no per-frame allocation except the tilemap's small callback record.
- Lights re-register every =late_update= (a hash lookup and a struct copy). Hundreds are fine; with thousands, prefer fewer, larger lights (the 0.9 light set holds a limited number of point lights anyway).
- Trigger tests are O(candidates) per fixed step. Filter by tag or component on busy worlds; the unfiltered case uses the octree (=lrg_world3d_query_box()=), so keep entity bounds meaningful.
- Tilemaps emit every non-empty cell each frame through the rlgl batch (4 vertices per tile per layer). Very large maps should be split across several entities so frustum culling drops off-screen chunks.
- LOD components measure one sphere and run a few comparisons per view; generating a chain from =mesh-asset= simplifies the model once per level on the first draw (about 3 µs per source triangle per level, see [[file:../graphics/mesh-simplify.org::#performance][simplifier performance]]) and the result is shared by every component with the same model and sidecar.
- Decal components cost nothing per camera (no render items); =sync_world()= is one matrix multiply per decal per frame, and the decal set's selection and upload are described in [[file:../graphics/decal.org::#performance][decal performance]].
- Physics components cost one hook call each per fixed substep (a world-version compare for static bodies, a kinematic move, a pose read and two entity writes for dynamic bodies) plus the dynamics step itself; interpolation writes every dynamic entity once per frame. Contact signals build a body-to-contacts index once per substep, only when some body listens.
- Cloth components cost a cloth step per fixed update (about 2-3 ms for a 32 x 32 grid at 8 substeps, see [[file:../physics/cloth.org::#performance][cloth performance]]) and one mesh upload per step when drawn; destructibles cost nothing until they break, then one MESH item and a pose read per chunk per camera.
- Skinned models sharing one animator re-pose the shared model per component only when the pose key changes (=lrg_model_animator_apply()=).

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:

- *Forward is -Z.* Lights, cameras and listeners point down the entity's local -Z; rotate the entity, not the component.
- *Spot angles are half-angles in degrees.* =inner-angle= / =outer-angle= are measured from the axis; the #LrgLight3DDesc gets radians.
- *A light on an entity made inactive* keeps its last registration until the next property change or a =late_update= (inactive entities get no updates); disable the component instead when switching lights off.
- *Triggers test positions, not volumes.* A large entity whose origin is outside the trigger is outside. Give the entity a child marker or test bounds yourself.
- *Pitch is stored, not applied* by the 0.9 audio manager's voices; volume changes apply on the next play.
- *Asset loads need a graphics context.* With an asset manager but no window, the first load fails and is not retried until the path or manager changes; set the manager after the window opens (or let the renderer resolve assets).
- *Tilemap custom items transform themselves.* A renderer must not push the item's world matrix before calling the =draw_func=.
- *LOD state is per render list.* A renderer that reuses one list for several cameras makes them share the hysteresis and fade state; give each view its own list (the editor's viewports do).
- *LOD at instantiation needs the engine's asset manager.* A MESH_ASSET visual becomes an #LrgLodComponent only when the engine is started (=lrg_engine_startup()= creates the asset manager), import settings apply, the asset resolves to a file and its =.meta= says =lod-levels= > 1; otherwise it stays a mesh renderer.
- *Decals need a renderer to drive the world's set.* #LrgWorld3DRenderer calls =lrg_decal_component_sync_world()=, =lrg_decal_set_select()= and =lrg_light_set_set_decals()= every frame; a custom renderer must do the same or nothing paints. A decal projects along the entity's local -Y, not -Z.
- *Reflection probes reflect nothing until captured.* Call =lrg_world3d_renderer_capture_probes()= once after the window opens and the level is loaded (and again when =lrg_reflection_probe_component_count_pending()= says so); a probe whose world has no environment is not used at all.
- *A probe is bound by where the camera is.* #LrgWorld3DRenderer selects probes once per view at the camera position, so make the box contain the places the camera goes (the blend distance fades it in at the edges); a box tightly around an object reflects nothing while the camera is outside.
- *Probe boxes do not rotate.* The box is axis aligned in world space; rotating the probe's entity changes nothing.
- *Dynamic bodies want top-level entities* (or static parents): the world writes their world pose every step; a moving parent changes the child's world transform, which reads as a teleport.
- *Body ids are not 0-based sentinels:* the first body of a world has id 0; "no body" is =LRG_PHYSICS_NO_BODY= (which equals =LRG_DYNAMICS_WORLD_BODY=).
- *Edit shapes through the components,* not through =lrg_dynamics_world_set_shape()=: the next rebuild replaces anything changed behind their back.
- *Mesh colliders on dynamic bodies* become kinematic (a warning says so); use =convex= for moving rocks.
- *Fixed billboards* are plane primitives: a renderer's plane must be the editor's unit XZ plane for the Rx(90°) turn to land in XY.
