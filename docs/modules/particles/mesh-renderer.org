** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
=LrgParticleMeshRenderer= (=particles/lrg-particle-mesh-renderer.h=, 0.9.0) draws each live particle of a system as an instance of one mesh: debris, rocks, leaves, shell casings, gibs, confetti. All instances go out in one instanced draw call (GL 3.3 core instancing, no extension). The mesh is a model's first mesh, an uploaded =GrlMesh=, or a generated primitive; particles are oriented by their rotation (about Y, about their velocity, or tumbling about a per-particle axis), scaled by their size and tinted by their colour. =build()= produces the per-instance data headless; =draw()= uploads and draws it. The =mesh= renderer kind of a [[file:particle-asset.org][.rparticles]] emitter creates and configures one.

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:
- *Instance data*: 20 floats per particle (=LRG_PARTICLE_MESH_FLOATS_PER_INSTANCE=): a column-major world matrix (translation = position; rotation by the align mode; column scale = renderer scale x particle size) and the RGBA colour.
- *Align modes* (=LrgParticleMeshAlign=): =NONE= turns the mesh by =rotation= about world Y; =VELOCITY= points the mesh's +Y along the velocity and spins it by =rotation= about that axis (shards, arrows); =TUMBLE= turns it by =rotation= about an axis derived from the particle's random number (stable per particle), which with an =angular-velocity= range makes convincing debris.
- *Drawing*: the instance buffer (a dynamic VBO that grows to the largest count seen) is attached to the mesh's vertex array at attribute locations 10 .. 13 (matrix columns) and 14 (colour) with divisor 1, the mesh is drawn instanced with a small GLSL 330 program reading rlgl's current view and projection matrices, then the attributes are disabled again so other users of the mesh are unaffected. The program multiplies the albedo texture (white without one) by the instance colour and, when =lit=, by =0.3 + 0.7 h^2= with =h= the half-Lambert term of the light direction (default slanted downward). Additive systems draw without depth writes; others write depth (mesh particles are usually solid).
- *Primitives* (=LrgParticleMeshPrimitive=): raylib's generators: a unit cube, a sphere of diameter 1, a cylinder and a cone of diameter and height 1 (base on the origin), a unit XZ plane.

** Example
:PROPERTIES:
:CUSTOM_ID: example
:END:
#+begin_src C
g_autoptr(LrgParticleMeshRenderer) debris = lrg_particle_mesh_renderer_new ();
GrlModel                          *rock = lrg_asset_manager_load_model (manager, "props/rock.glb", NULL);

lrg_particle_mesh_renderer_set_model (debris, rock);
lrg_particle_mesh_renderer_set_scale (debris, 1.0f, 0.6f, 0.8f);
lrg_particle_mesh_renderer_set_align (debris, LRG_PARTICLE_MESH_ALIGN_TUMBLE);

BeginMode3D (camera);
lrg_particle_mesh_renderer_draw (debris, system);
EndMode3D ();
#+end_src

As an emitter's =renderer:= block: ={kind: mesh, mesh: props/rock.glb, mesh-scale: [1, 0.6, 0.8], align: tumble}=.

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:
Building instance data for 19 800 particles takes 2.3 ms on one i7-1280P core (=taskset -c 2=); the draw is a single call whatever the count, so the GPU cost is the mesh's triangles times the instances. Keep debris meshes low-poly (a few dozen triangles).

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- Mesh particles are not lit by the scene's light set or shadowed: the simple shading only suggests form. For a handful of hero objects, spawn entities with mesh components instead.
- The model must stay loaded while the renderer uses it (the asset manager keeps it).
- Cylinder and cone primitives sit on their base; give a =shape= offset if they should be centred.
