* LrgSkinnedSprite - Deformable 2D Sprite Meshes
:PROPERTIES:
:CUSTOM_ID: lrgskinnedsprite
:END:
#+begin_quote
*[[file:../../index.org][Home]]* > [[file:index.org][Graphics]] > LrgSkinnedSprite
#+end_quote

=LrgSkinnedSprite= is a small 2D triangle mesh cut out of a texture (or an atlas region) whose vertices are weighted to bones. Given a palette of bone matrices it deforms on the CPU (linear blend skinning) and draws through rlgl. It is the attachment type of [[file:../animation/skeleton2d.org][LrgSkeleton2D]], and usable on its own with any palette.

- *Header*: =graphics/lrg-skinned-sprite.h=
- *Type*: =LrgSkinnedSprite=, final GObject, =LRG_TYPE_SKINNED_SPRITE=, GIR =Libregnum.SkinnedSprite=
- *Since*: 0.9.0
- *Headless*: everything except =lrg_skinned_sprite_draw()=, =lrg_skinned_sprite_draw_wireframe()= and =lrg_skinned_sprite_load_texture()=; =lrg_skinned_sprite_draw_to_canvas()= draws without a window (0.14)

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:
- *Vertices* have a bind position =(x, y)= in skeleton setup space, a texture coordinate =(u, v)= in 0 .. 1 across the region, and up to =LRG_SKINNED_SPRITE_MAX_WEIGHTS= (4) =(bone, weight)= influences kept heaviest first and normalised to sum to 1. A mesh holds at most =LRG_SKINNED_SPRITE_MAX_VERTICES= (65535) vertices (16-bit indices).
- *Triangles* index vertices; their winding does not matter: draw emits every triangle front-facing (raylib culls back faces), also after a deformation or mirror flips it.
- *Region*: a pixel rectangle of the texture (=lrg_skinned_sprite_set_region()=); 0 width or height means the whole texture. The final texture coordinate is =region.xy + uv * region.wh=, normalised by the texture size.
- *Palette*: six floats per bone =(a, b, c, d, tx, ty)= with =x' = a*x + c*y + tx=, =y' = b*x + d*y + ty=, normally =world(bone) * inverse_bind(bone)= from =lrg_skeleton2d_get_palette()=. Influences naming a bone outside the palette are skipped and the rest renormalised. Vertices with no usable influence take the *default bone*'s matrix (the slot's bone under a skeleton), or stay at their bind position when the default bone is -1.
- *Deformed positions* are cached in the sprite after =lrg_skinned_sprite_deform()=; =lrg_skinned_sprite_get_deformed()= and =lrg_skinned_sprite_get_deformed_bounds()= read them for picking and culling.
- *Texture*: set a =GrlTexture= directly, or set an =image= path and call =lrg_skinned_sprite_load_texture()= (the skeleton loads all of its images with =lrg_skeleton2d_load_textures()=). Untextured meshes draw in the tint colour.

** CPU drawing
:PROPERTIES:
:CUSTOM_ID: cpu-drawing
:END:
Since 0.14 a sprite can also be drawn on the CPU into an =LrgImageCanvas=, with no window or GL context: headless renders, reels, thumbnails and tests in CI. The geometry is exactly the GPU path's: =lrg_skinned_sprite_draw_to_canvas()= reads the same deformed positions =lrg_skinned_sprite_draw()= does (so anything that changes the deformation, such as blend shapes applied inside =lrg_skinned_sprite_deform()=, shows up in both), and draws each triangle with [[file:image-raster.org][lrg_image_draw_triangle_textured()]].

*** The source image
The GPU path samples a =GrlTexture=, which lives on the GPU and cannot be read back cheaply. The CPU path samples a =GrlImage=, the *source image*:
- =lrg_skinned_sprite_set_source_image (sprite, image)= sets it. The sprite keeps a reference and never modifies the image; one that is not RGBA8 is copied and converted first. Set the same image on many sprites freely: they share it.
- =lrg_skinned_sprite_get_source_image (sprite)= returns it. When none is set and the sprite has an =image= path, the first call loads that file with =grl_image_new_from_file()=, relative to the current directory (a sprite does not know which =.rskel2d= file it came from). A failed lazy load logs one warning and is not retried until the path changes.
- =lrg_skinned_sprite_load_source_image (sprite, base_dir, &error)= loads the =image= path explicitly, resolved against =base_dir= exactly as =lrg_skinned_sprite_load_texture()= resolves it, and reports errors as =G_IO_ERROR=. It does nothing when a source image is already set. No window is needed.
- Under a skeleton you rarely call these: =lrg_skeleton2d_draw_to_canvas()= loads missing sources lazily relative to the skeleton's =base-dir=, and =lrg_skeleton2d_load_source_images()= loads them all up front, decoding each distinct file once (the CPU counterparts of =lrg_skeleton2d_load_textures()=).
- =lrg_skinned_sprite_copy()= shares the source image with the copy.

*** Regions
The region (=lrg_skinned_sprite_set_region()=) means the same as on the GPU: the vertices' U, V coordinates span that pixel rectangle of the image. The CPU path crops the region out of the source image once, when the image or the region changes, and samples the crop. Bilinear filtering therefore clamps at the region's own border and never bleeds the neighbouring atlas cell in. The region is rounded to whole pixels and clamped to the image; a region of 0 width or height means the whole image.

*** Drawing
=lrg_skinned_sprite_draw_to_canvas (sprite, canvas, tint)=:
1. Transforms every deformed position by the canvas's current transform (=lrg_image_canvas_translate()=, =lrg_image_canvas_scale()=, =lrg_image_canvas_rotate()=, its 2D affine part), the CPU counterpart of a 2D camera.
2. Draws each triangle with bilinear, premultiplied sampling of the source region, multiplied by =tint= (=NULL= for white). Without a source image the mesh is filled with =tint=, like an untextured GPU draw.
3. Blends source-over, whatever the canvas blend mode, and honours the canvas clip rectangle.

Shared edges are drawn exactly once (the rasteriser's top-left rule), so a translucent tint shows no seams along the mesh's inner edges, and the winding of the triangles does not matter.

#+begin_src C
/* a bending tail drawn headless into a PNG */
GrlColor                  clear = { 0, 0, 0, 0 };
g_autoptr(LrgImageCanvas) canvas = lrg_image_canvas_new (256, 128, &clear);
g_autoptr(GrlImage)       scales = grl_image_new_from_file ("tail.png");

lrg_skinned_sprite_set_source_image (tail, scales);
lrg_skinned_sprite_deform (tail, palette, 18, 0);
lrg_image_canvas_translate (canvas, 40.0f, 64.0f);   /* like a camera offset */
lrg_skinned_sprite_draw_to_canvas (tail, canvas, NULL);
grl_image_export (lrg_image_canvas_get_image (canvas), "tail-frame.png");
#+end_src

*** Differences from the GPU path
- Filtering: the CPU path always samples bilinearly; the GPU samples with the texture's filter mode (raylib's default is point sampling).
- Edges: the CPU path does not anti-alias triangle edges (neither does the GPU without MSAA); soft outlines come from the texture's alpha.
- Blending is always source-over in 8-bit gamma space.

*** Threads
Like the GPU draw, CPU drawing reads the sprite's deformed buffer, and the lazy load writes the sprite, so one sprite must not be deformed or drawn from two threads at once. Source images are immutable once set, so several sprites drawn on different threads may share one. The reel's [[file:../reel/clips.org::#skeleton2d-clip][LrgReelSkeleton2DClip]] serialises its renders for this reason.

** Automatic weights
:PROPERTIES:
:CUSTOM_ID: auto-weights
:END:
=lrg_skinned_sprite_compute_auto_weights()= weights the mesh to bone *segments* (origin to tip in setup space):
1. Each vertex gets =1 / (d + e)^falloff= per segment, where =d= is the distance to the segment and =e= is 1% of the mesh size (so a vertex on a bone does not divide by zero), normalised per vertex.
2. Optional smoothing: =smooth_iterations= passes blend each vertex's weights halfway toward the mean of its triangle neighbours. This is a few explicit steps of heat diffusion over the mesh graph: weights spread along the surface instead of jumping across gaps.
3. The heaviest =max_influences= are kept and normalised.

The nearest bone always dominates a vertex lying on it. =falloff= 2 .. 4 gives soft elbows, 6 .. 8 sharp ones; =max_influences= 2 is right for limbs. =lrg_skeleton2d_compute_auto_weights()= builds the segments from a skeleton's setup pose.

** Example
:PROPERTIES:
:CUSTOM_ID: example
:END:
#+begin_src C
/* a tail: a 12-cell strip over three bones, weighted automatically */
gfloat segs[] = { 0, 0, 30, 0,   30, 0, 60, 0,   60, 0, 90, 0 };
g_autoptr(LrgSkinnedSprite) tail = lrg_skinned_sprite_new_grid (0, -6, 90, 12, 12, 1);

lrg_skinned_sprite_compute_auto_weights (tail, segs, G_N_ELEMENTS (segs), NULL, 0, 3.0f, 2, 2);
lrg_skinned_sprite_set_texture (tail, tail_texture);
lrg_skinned_sprite_set_region (tail, 0, 64, 128, 16);

/* each frame, with a palette of 3 bones (18 floats) */
lrg_skinned_sprite_deform (tail, palette, 18, 0);
lrg_skinned_sprite_draw (tail, NULL);
#+end_src

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:
CPU skinning costs about 24 .. 38 ns per vertex with four influences (1024 vertices in 24 .. 39 µs; =tests/test-skeleton2d.c= =/skeleton2d/perf=). Drawing submits triangles to rlgl's batch in chunks of 1024 with one texture bind per chunk, so many small meshes sharing an atlas batch together. There is no GPU skinning path in 0.9.0 (see the skeleton page).

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- Call =lrg_skinned_sprite_deform()= before =lrg_skinned_sprite_draw()=; draw uses the last deformed positions (the bind positions before the first deform).
- Weights are skeleton bone *indices*; a palette shorter than the largest index (=lrg_skinned_sprite_get_max_bone()=) skips those influences.
- =new_grid= vertices have no weights; without weights or a default bone the mesh never moves.
- A region needs a texture to mean anything; untextured meshes ignore UVs and draw flat.
