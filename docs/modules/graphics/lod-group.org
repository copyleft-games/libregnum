* LrgLodGroup - Level of Detail
:PROPERTIES:
:CUSTOM_ID: lrglodgroup
:END:

=LrgLodGroup= holds a level-of-detail (LOD) chain for one object: level 0 is the full-detail model, every further level is a cheaper version used once the object is small enough on screen. Selection uses the object's /screen size/, a per-level threshold, a hysteresis band, group, instance and global biases and an optional forced level; =LrgLodState= carries one view's selection and the dithered cross-fade between two levels. Chains are authored by hand or generated with [[file:mesh-simplify.org][LrgMeshSimplify]], optionally driven by the model's =.meta= LOD keys. [[file:../world3d/components.org::#lod][LrgLodComponent]] draws a chain in an =LrgWorld3D=.

- *Header*: =graphics/lrg-lod-group.h=
- *Types*: =LrgLodGroup= (final GObject, =LRG_TYPE_LOD_GROUP=, GIR =Libregnum.LodGroup=), =LrgLodState= (boxed struct, =LRG_TYPE_LOD_STATE=)
- *Since*: 0.9.0
- *Headless*: selection, states, screen-size maths and hand-made groups need no GPU; generating levels and binding the fade uniform do

** Concepts
:PROPERTIES:
:CUSTOM_ID: concepts
:END:

*** Screen size
:PROPERTIES:
:CUSTOM_ID: screen-size
:END:

The /screen size/ is the fraction of the screen height covered by the object's bounding sphere diameter: 1 means as tall as the screen, 0.1 a tenth of it. For a perspective camera it is =radius / (distance * tan (fovy / 2))=; for an orthographic camera =2 * radius / view_height=. It is independent of the resolution, so the same thresholds work on a phone and a 4K monitor.

- =lrg_lod_compute_screen_size (radius, distance, fovy)= is the perspective formula (fovy in degrees).
- =lrg_lod_screen_size_from_view_projection (vp, center, radius)= reads both cases from a view-projection matrix: the projection's vertical scale is the length of the matrix's second row (P[1][1] times a unit camera axis) and the clip =w= of the centre is the view depth (perspective) or 1 (orthographic). This is what =LrgLodComponent= uses with =lrg_render_list_get_view_projection()=.

The group's sphere comes from its local bounds (=lrg_lod_group_get_bounding_sphere()=: box centre, half diagonal), taken from the level-0 model's meshes (all eight corners of each mesh box transformed by the model transform, so a Z-up import is right) or set with =lrg_lod_group_set_bounds()=.

*** Thresholds
:PROPERTIES:
:CUSTOM_ID: thresholds
:END:

Each level has a threshold: the /smallest/ screen size at which the level is still used. Thresholds decrease with the level. A size picks the first level whose threshold it reaches; below the last level's threshold the object is culled (=LRG_LOD_LEVEL_CULLED=). A last threshold of 0 never culls.

#+begin_example
screen size  1.0 ─────── 0.5 ─────── 0.25 ───── 0.1 ──── 0.0
level            0      │     1      │    2     │   3 (last threshold 0: never culled)
thresholds:  0.5, 0.25, 0.1, 0
#+end_example

*** Hysteresis
:PROPERTIES:
:CUSTOM_ID: hysteresis
:END:

An object hovering at a threshold would flip between two levels every frame. With hysteresis h (default 0.1) the level gets coarser only once the size drops below =threshold * (1 - h)= and finer only once it rises above =threshold * (1 + h)=. A large jump (a teleport, a camera cut) still lands on the right level at once. =lrg_lod_group_select_level()= takes the current level for this reason; pass =LRG_LOD_LEVEL_NONE= for a selection without history.

*** Bias and forced level
:PROPERTIES:
:CUSTOM_ID: bias
:END:

The measured size is multiplied by the group's =bias=, the component's =bias= (per instance) and the process-wide =lrg_lod_set_global_bias()= before the thresholds are applied. Above 1 keeps detailed levels longer (a "high quality" setting, or a hero object), below 1 switches earlier (low-end hardware). =force-level= pins a level regardless of size (debugging, the editor's LOD preview); a forced level past the end is clamped to the last level.

*** Cross-fade
:PROPERTIES:
:CUSTOM_ID: cross-fade
:END:

When the level changes and =fade-duration= (default 0.25 s) is positive, both levels are drawn for that time with complementary /dither/ masks instead of popping. Each fragment computes a stable pseudo-random value d in [0, 1) from its screen position (interleaved gradient noise); the incoming level keeps the fragments with d < fade, the outgoing one those with d >= fade, so every pixel is drawn exactly once and the image dissolves from one level to the other as =fade= goes 0 → 1. Because it is a discard (alpha test), not blending, it needs no sorting and works with opaque materials and the depth buffer.

The per-draw value is the =lodFade= uniform:

| =lodFade= | Meaning |
|-----------+---------|
| 0 | fully visible (every non-LOD draw, and LOD levels not fading) |
| 0 < f < 1 | fading in: draw fragments whose dither value is below f |
| -1 < f < 0 | fading out: draw fragments whose dither value is at least -f |

=lrg_lod_state_get_level_fade()= returns the value for a level (and whether it is drawn at all); for a cross-fade at progress p the two values are p and -p.

** LOD import keys (=.meta=)
:PROPERTIES:
:CUSTOM_ID: meta-keys
:END:

A model's sidecar (=rock.glb.meta=, importer =model=) can describe a generated chain. The keys are ordinary import settings (=LrgAssetMeta=), so they show in the editor's asset inspector, round-trip through IPC (=lrg_asset_meta_set_setting_variant()= validates them) and feed the thumbnail cache's settings hash.

| Key | Type | Default | Meaning |
|-----+------+---------+---------|
| =lod-levels= | integer 1..8 | 1 | levels including the original; 1 = no chain |
| =lod-ratios= | list of numbers | empty | triangle ratio of levels 1, 2, ... relative to the original; missing entries are 0.5^level |
| =lod-screen-sizes= | list of numbers | empty | thresholds of levels 0, 1, ...; missing entries are 0.5^(level+1), except the last level which is 0 (never culled); a positive last value culls below it |
| =lod-max-error= | number 0..1 | 0.05 | largest simplification error of any level, relative to the model size; a level stops short of its ratio rather than exceed it |
| =lod-lock-border= | boolean | true | pin open mesh borders while simplifying |
| =lod-hysteresis= | number 0..0.9 | 0.1 | the group's hysteresis |
| =lod-fade-duration= | seconds 0..10 | 0.25 | the group's cross-fade time (0 = pop) |

Lists are strings of numbers separated by commas, spaces or semicolons, or YAML flow sequences; both read the same (=lrg_asset_meta_parse_float_list()=).

Annotated example:

#+begin_src yaml
version: 1
guid: 7d3c2a9e-1f4b-4c8e-9a51-0b6e2f8d4c13
importer: model
settings:
  scale: 0.01                 # import settings applied by the asset manager
  up-axis: z
  lod-levels: 4               # level 0 (the model) + 3 generated levels
  lod-ratios: [0.5, 0.2, 0.05]          # 50%, 20%, 5% of the triangles
  lod-screen-sizes: "0.4, 0.15, 0.05, 0.01"
                              # level 0 down to 40% of the screen height,
                              # level 1 to 15%, level 2 to 5%, level 3 to 1%,
                              # culled below 1%
  lod-max-error: 0.03         # never deviate more than 3% of the model size
  lod-lock-border: true       # open edges (e.g. a cut-off trunk) stay put
  lod-hysteresis: 0.1         # +-10% band around each threshold
  lod-fade-duration: 0.3      # 0.3 s dithered cross-fade
#+end_src

The asset manager does not apply these keys when it loads the model (=lrg_asset_manager_load_model()= returns the full model, which becomes level 0); =lrg_lod_group_new_from_model_with_meta()= and =LrgLodComponent= read them. =lrg_lod_group_apply_meta()= re-applies only the selection keys (thresholds, hysteresis, fade) to an existing group, for live tuning without regenerating.

** Generated levels
:PROPERTIES:
:CUSTOM_ID: generated-levels
:END:

=lrg_lod_group_new_from_model()= keeps the model itself as level 0 and simplifies every mesh of it from the original for each further level (errors never stack). A generated level is one single-mesh =GrlModel= per source mesh (=lrg_lod_group_get_level_models()=), each carrying a copy of its source material's maps, shader and parameters and the source model's transform: textures and shaders are shared with the source model, which the group keeps referenced. Every generated mesh keeps all of its attributes (see [[file:mesh-simplify.org][LrgMeshSimplify]]) and is uploaded, so generation needs a graphics context. =lrg_lod_group_get_level_triangle_count()= and =lrg_lod_group_get_level_error()= report what each level achieved. Skinned models (with bones) are refused.

** Renderer integration
:PROPERTIES:
:CUSTOM_ID: renderer
:END:

What a renderer (the 0.9 =LrgWorld3DRenderer= and the editor viewport, wired in wave 2b) does with LOD items:

1. *Shader.* Every program that draws LOD items (the lit shader, user shaders, the depth prepass and shadow-map programs) pastes =lrg_lod_get_glsl()= before =main= and calls =lrg_lod_fade_discard ();= first thing in =main=. Written out, the three lines are:

   #+begin_src glsl
   uniform float lodFade;   /* top level, next to the other uniforms */
   /* first thing in main(): */
   float lrg_lod_d = fract (52.9829189 * fract (dot (gl_FragCoord.xy, vec2 (0.06711056, 0.00583715))));
   if (lodFade != 0.0 && (lodFade > 0.0 ? lrg_lod_d >= lodFade : lrg_lod_d < -lodFade)) discard;
   #+end_src

   An unset =lodFade= is 0, so programs that never see a LOD item are unaffected.
2. *Per item.* Before drawing an item: =lrg_lod_bind_fade (shader_id, lrg_lod_component_get_item_fade (item, NULL))=. It returns 0 for items of other components, which also resets a value left by the previous item.
3. *Depth.* A depth prepass must discard the same fragments as the colour pass (same =lodFade=), or the discarded fragments' depth hides the other level.
4. *Shadows.* Only the incoming level carries =LRG_RENDER_ITEM_FLAG_CAST_SHADOW=; the fading-out level does not cast, so shadows do not double during a fade.

Without step 1 a cross-fade simply shows both levels overlapped for =fade-duration=; set =fade-duration= to 0 on renderers that do not support it.

*** Generate a chain from a model and its sidecar
:PROPERTIES:
:CUSTOM_ID: example-generate

#+begin_src C
g_autoptr(GError)       error = NULL;
g_autoptr(LrgAssetMeta) meta = lrg_asset_manager_get_asset_meta (assets, "models/rock.glb");

chain = lrg_lod_group_new_from_model_with_meta (rock, meta, &error);
if (chain == NULL)
	g_error ("LOD: %s", error->message);
for (i = 0; i < lrg_lod_group_get_n_levels (chain); i++)
	g_message ("level %u: %d triangles, error %.2f%%, down to %.0f%% of the screen", i,
	           lrg_lod_group_get_level_triangle_count (chain, i),
	           100.0 * lrg_lod_group_get_level_error (chain, i),
	           100.0 * lrg_lod_group_get_level_screen_size (chain, i));
#+end_src

*** Drive selection yourself (a custom renderer)
:PROPERTIES:
:CUSTOM_ID: example-select
:END:

#+begin_src C
/* One state per object and camera. */
LrgLodState state;
gfloat      center[3];
gfloat      radius;
gfloat      size;
gfloat      fade;
gint        level;

lrg_lod_state_init (&state);

/* every frame */
lrg_lod_group_get_bounding_sphere (chain, center, &radius);   /* then to world space */
size = lrg_lod_compute_screen_size (radius, distance_to_camera, camera_fovy);
lrg_lod_group_update_state (chain, &state, size, frame_delta);

for (level = 0; level < (gint) lrg_lod_group_get_n_levels (chain); level++)
	if (lrg_lod_state_get_level_fade (&state, level, &fade))
	{
		lrg_lod_bind_fade (my_shader_id, fade);
		draw_models (lrg_lod_group_get_level_models (chain, (guint) level));
	}
lrg_lod_bind_fade (my_shader_id, 0.0f);
#+end_src

** Performance
:PROPERTIES:
:CUSTOM_ID: performance
:END:

- Selection is a handful of float operations per object and view (one sphere transform, one dot product, up to 8 threshold compares); thousands of LOD objects cost well under a millisecond.
- The win is in vertex and triangle throughput and in shadow passes: at 25% of the triangles an object far away costs a quarter of its vertex work in every pass.
- A cross-fade draws two levels with discards (no early-z rejection inside the dithered fragments) for =fade-duration=; keep it short (0.2-0.4 s) on scenes with many objects crossing thresholds at once (fast flyovers).
- Generation cost is the simplifier's, once per level: see [[file:mesh-simplify.org::#performance][LrgMeshSimplify performance]] (about 3 µs per source triangle per level). Generated groups are shared between components with the same model and sidecar.
- Memory: a generated level stores compacted copies of the used vertices (with all attributes) and a 16-bit index buffer, so a 25% level costs roughly a quarter of the original's vertex memory.

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:

- *Thresholds must decrease with the level.* Selection takes the first level whose threshold the size reaches; an increasing threshold makes later levels unreachable.
- *The last threshold culls.* Leave it at 0 unless you want the object to disappear when tiny.
- *One state per view.* =LrgLodState= carries history; sharing one between cameras (or the shadow-map camera) makes them fight. The component keeps one per render list.
- *Fade needs shader support.* Programs that do not run =lrg_lod_fade_discard()= draw both levels fully during a fade (and a depth prepass without it writes depth for both).
- *Generated levels borrow textures.* Keep the group (it references the source model) alive as long as its level models are drawn; do not hand a generated part model to something that outlives the group.
- *Skinned models are not supported* by the generator; author their levels by hand.
- *Bounds come from CPU vertex data.* A level-0 model whose CPU arrays were freed has no bounds; call =lrg_lod_group_set_bounds()=.

** Using it from the editor
:PROPERTIES:
:CUSTOM_ID: editor
:END:

- *Import settings.* The =lod-*= keys appear today as rows of the model import settings in the asset inspector (they are known settings of the =model= importer) and are editable over IPC with =asset.meta.set= (which validates the lists).
- *LOD preview.* The viewport draws mesh-asset nodes through the LOD group of their asset (=lrg_editor_scene_renderer_get_lod_group()=, built from the model and its =.meta=). Selecting such a node shows a "LOD" section in the inspector: a meter of the node's screen size in the active viewport against every level's threshold, one row per level with =lrg_lod_group_get_level_triangle_count()=, the threshold and =lrg_lod_group_get_level_error()=, the level drawn now highlighted, and a *Force level* picker (=lrg_lod_group_set_force_level()=, a preview shared by every instance of the asset, reset when the node is deselected). With the Bounds overlay on, the viewport draws the bounding sphere and a chip with the level, triangles and screen size. Over IPC: =lod.get= and =lod.force= (=lrgeditorctl lod get|force=). See [[file:../../editor/environment.org::#inspector-additions][Inspector additions]].
