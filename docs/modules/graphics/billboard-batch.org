* LrgBillboardBatch - Batched Billboards
:PROPERTIES:
:CUSTOM_ID: lrgbillboardbatch---batched-billboards
:END:
Draws many camera-facing textured quads ("billboards", the /flats/ of sprite-based 3D games: trees, NPCs, monsters, signs) with one texture bind per material. Billboards are plain records (position, size, pivot, UV rectangle, tint, visibility, material); every =draw()= rebuilds their quads from the camera position, so they turn as the camera moves, and emits them through rlgl's immediate batch grouped by material.

Orientation and corner math run headlessly (=get_corners()=), so picking and tests see exactly what is drawn. Only =draw()= needs a GL context.

** Semantics
:PROPERTIES:
:CUSTOM_ID: semantics
:END:
- *Axis-locked facing*: the quad's right vector is perpendicular to the horizontal direction from the billboard to the camera, =(f.z, 0, -f.x)= for that direction =f=, so it faces the eye regardless of camera height. With the camera exactly overhead the basis falls back to world +X/+Y.
- *Corners* are bottom-left, bottom-right, top-right, top-left, counter-clockwise as seen from the camera (front-facing under raylib's default culling). The pivot is the point of the quad placed at =position= (0,0 = bottom-left, 1,1 = top-right).
- *UVs* are normalized with =y= at the top of the texture; a negative width mirrors the image (e.g. for the opposite facing of a directional sprite).
- *Cutout*: with a cutoff above 0 an alpha-test shader discards texels below it, so transparent pixels never write depth and overlapping billboards need no sorting. If the shader cannot be built (GLES2) the batch falls back to raylib's default shader and plain blending. =set_alpha_cutoff (0)= forces plain blending.
- *Materials* without a texture are skipped. The batch keeps a reference to each texture.
- Call =draw()= inside =BeginMode3D()= / =grl_camera3d_begin()=.
- *Lighting*: a batch is lit by its own [[file:light-set.org][LrgLightSet]] (=set_light_set()=), else by the bound one (=lrg_light_set_bind()=), unless =set_lit (FALSE)=. The quads are immediate-mode geometry the light set's shader cannot light correctly (rlgl transforms their vertices on the CPU), so the batch lights them on the CPU instead: per quad, the centre (the pivot moved to mid-height along world up) is put through the current rlgl transform (=rlGetMatrixTransform()=, the space the static-geometry shader lights) and =lrg_light_set_sample()= is evaluated there without a normal (the quad faces the camera, so every light counts in full). The vertex colour becomes =tint × light=, clamped to 255 per channel; alpha is the tint's. Emissive billboards (flames, lamps) keep their plain tint. Lights come from the light set's last selection, so call =lrg_light_set_apply()= (or =select()=) first, as for the shader. =get_lit_tint()= returns the colour a draw would use with an identity transform (tests, tools).

** Example
:PROPERTIES:
:CUSTOM_ID: example
:END:
#+begin_src C
g_autoptr(LrgBillboardBatch) flats = lrg_billboard_batch_new ();
GrlVector3 tree = { 12.0f, 0.0f, -4.0f };
guint index;

lrg_billboard_batch_set_material_texture (flats, 0, tree_texture);
index = lrg_billboard_batch_add (flats, 0, &tree, 3.2f, 6.4f);

/* animate by switching material (one texture per frame) or UV rect */
lrg_billboard_batch_set_material (flats, index, 1);

grl_camera3d_begin (camera);
lrg_billboard_batch_draw (flats, &camera_position);
grl_camera3d_end (camera);
#+end_src
