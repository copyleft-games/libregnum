* Null-only thread lifetime evidence and remaining native leaks
The temporary stress fixture is retained locally as =build/merge-verification/test-audio-null-threads.c=. It is linked with an independently ASan/UBSan-instrumented build of the merged Graylib and the unchanged =completion/tests/audio-null-helper.c= adapter. The helper asserts Landlock/seccomp filesystem/socket barriers before device startup, forces exactly miniaudio's null backend, and verifies it. This is the only audio-device exception, never a global default; no hardware backend is exercised.

Across 30 simultaneous music/alias/callback-stream lifetimes and three device open/close cycles, real background decoder progress, pull callbacks and per-music processors run. Replacing callbacks and removing processors must deliver destroy notifications only after callbacks stop. Music is dropped while playing; weak references confirm finalization, then further pump time is allowed before the next cycle. Sound aliases are destroyed before their source. No UAF, invalid access, callback-after-destroy or UBSan failure was observed. This finite stress run is not a proof of all interleavings or a TSAN result.

LSan nevertheless fails with 14,160 bytes in 60 allocations: 30 allocations/12,240 bytes resolve to =LoadMusicStreamFromMemory=, and 30 allocations/1,920 bytes to =LoadAudioBuffer=. In the unchanged pinned raylib =src/raudio.c=, WAV unload calls =drwav_uninit()= but does not free the separately allocated decoder struct (line 1773); =LoadAudioBuffer()= allocates =converterResidual= (line 606), while =UnloadSoundAlias()= omits that residual buffer's free (lines 1043..1050). These correspond to the 408-byte WAV contexts and 64-byte alias residuals in each stress iteration. No suppression, direct opaque-layout workaround, vendor source patch or passing relabel was applied. This native cleanup failure remains for the reviewer/upstream; it does not invalidate the separately clean rendering-profile LSan run.
