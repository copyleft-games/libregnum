* Exporters — Output sinks
:PROPERTIES:
:CUSTOM_ID: exporters-output-sinks
:END:
An exporter consumes a stream of =GrlImage= frames and writes them to a file or
process.  The abstract base class =LrgReelExporter= defines the protocol; three
concrete subclasses handle animated GIF, numbered image sequences, and
ffmpeg-backed video.

** LrgReelExporter contract
:PROPERTIES:
:CUSTOM_ID: lrgreelexporter-contract
:END:
All exporters follow the same lifecycle:

1. =lrg_reel_exporter_begin()= — called once before any frames; opens the output.
2. =lrg_reel_exporter_add_frame()= — called once per frame in order.
3. =lrg_reel_exporter_finish()= — called once after the last frame; flushes and closes.

=lrg_reel_renderer_render_to_exporter()= handles this lifecycle automatically.
You only need to call these functions manually when building a custom pipeline.

Error handling follows the standard =GError= pattern; all three functions return
=gboolean= and populate =**error= on failure.  The error domain is
=LRG_REEL_EXPORTER_ERROR=.

| Error code                               | Meaning                             |
|------------------------------------------+-------------------------------------|
| =LRG_REEL_EXPORTER_ERROR_FAILED=         | Generic failure                     |
| =LRG_REEL_EXPORTER_ERROR_OPEN=           | Could not create or open the output |
| =LRG_REEL_EXPORTER_ERROR_WRITE=          | Write failed mid-stream             |
| =LRG_REEL_EXPORTER_ERROR_FFMPEG_NOT_FOUND= | ffmpeg not on PATH                 |
| =LRG_REEL_EXPORTER_ERROR_SPAWN=          | Could not launch encoder            |
| =LRG_REEL_EXPORTER_ERROR_UNSUPPORTED=    | Operation not implemented           |

** LrgReelGifExporter — animated GIF
:PROPERTIES:
:CUSTOM_ID: lrgreelgifexporter
:END:
Writes a multi-frame animated GIF.  No external tools required; the encoder
runs in-process.

#+begin_src c
g_autoptr(GError)             error = NULL;
g_autoptr(LrgReelGifExporter) gif   =
    lrg_reel_gif_exporter_new ("output.gif", &error);

if (gif == NULL)
{
    g_printerr ("Could not open output: %s\n", error->message);
    return 1;
}

/* Optional: better palette quality at the cost of file size.
 * Must be called before begin() / render_to_exporter(). */
lrg_reel_gif_exporter_set_quality (gif,
                                    TRUE,   /* adaptive_palette */
                                    TRUE);  /* dither */

lrg_reel_renderer_render_to_exporter (renderer, LRG_REEL_EXPORTER (gif), &error);
#+end_src

Quality defaults (both =FALSE=) use the fixed web-safe palette, producing the
smallest files with widest viewer compatibility.  Enable =adaptive_palette= for
natural-looking gradients; add =dither= on top for the best quality at a modest
size increase.  =dither= has no effect when =adaptive_palette= is =FALSE=.

** LrgReelSeqExporter — image sequence
:PROPERTIES:
:CUSTOM_ID: lrgreelseqexporter
:END:
Writes each frame as a separate numbered image file in a directory.

#+begin_src c
g_autoptr(LrgReelSeqExporter) seq =
    lrg_reel_seq_exporter_new ("frames/",      /* output directory */
                                "frame_%05d",  /* printf pattern (no extension) */
                                LRG_REEL_IMAGE_FORMAT_PNG);

lrg_reel_renderer_render_to_exporter (renderer, LRG_REEL_EXPORTER (seq), &error);

g_print ("Wrote %u frames\n",
         lrg_reel_seq_exporter_get_frame_count (seq));
#+end_src

The directory is created with =g_mkdir_with_parents()= on the first call to
=begin()=.  The frame index substituted into the pattern is 0-based and
matches the absolute frame number passed to =add_frame()=.

| Format                       | Extension | Notes                    |
|------------------------------+-----------+--------------------------|
| =LRG_REEL_IMAGE_FORMAT_PNG=  | .png      | Lossless; larger files   |
| =LRG_REEL_IMAGE_FORMAT_JPEG= | .jpg      | Lossy; smaller files     |

** LrgReelVideoExporter — MP4 / WebM via ffmpeg
:PROPERTIES:
:CUSTOM_ID: lrgreelvideoexporter
:END:
Streams frames to an ffmpeg subprocess and produces a muxed video file.
ffmpeg must be installed and discoverable on =PATH= (or explicitly configured).

*** Availability check

Always check for ffmpeg before attempting a video export:

#+begin_src c
if (!lrg_reel_video_exporter_is_ffmpeg_available ())
{
    g_print ("ffmpeg not found; falling back to GIF.\n");
    /* ... fall back to LrgReelGifExporter ... */
}
#+end_src

If =begin()= is called without ffmpeg available, it fails with
=LRG_REEL_EXPORTER_ERROR_FFMPEG_NOT_FOUND=.

*** Basic usage

#+begin_src c
g_autoptr(LrgReelVideoExporter) vid =
    lrg_reel_video_exporter_new ("output.mp4", LRG_REEL_VIDEO_CODEC_H264);

/* Quality: lower CRF = higher quality. Default is 23. */
lrg_reel_video_exporter_set_crf (vid, 18);

lrg_reel_renderer_render_to_exporter (renderer, LRG_REEL_EXPORTER (vid), &error);
#+end_src

| Codec                               | Container | Encoder (first usable)                                     |
|-------------------------------------+-----------+------------------------------------------------------------|
| =LRG_REEL_VIDEO_CODEC_H264=         | .mp4      | libx264, libopenh264, h264_nvenc, h264_qsv, h264_vaapi     |
| =LRG_REEL_VIDEO_CODEC_H265=         | .mp4      | libx265                                                    |
| =LRG_REEL_VIDEO_CODEC_VP9=          | .webm     | libvpx-vp9                                                 |
| =LRG_REEL_VIDEO_CODEC_VP9_ALPHA=    | .webm     | libvpx-vp9                                                 |
| =LRG_REEL_VIDEO_CODEC_AV1=          | .mp4      | libsvtav1                                                  |
| =LRG_REEL_VIDEO_CODEC_PRORES=       | .mov      | prores_ks                                                  |
| =LRG_REEL_VIDEO_CODEC_PRORES_ALPHA= | .mov      | prores_ks                                                  |

*** Choosing the encoder
:PROPERTIES:
:CUSTOM_ID: video-encoder
:END:
A codec names a format; ffmpeg needs an encoder, and which encoders an ffmpeg has depends on how it was built. Fedora's packaged ffmpeg, for example, has no =libx264=. So when an export begins, the exporter:

1. asks the ffmpeg it is about to run for its video encoders (=ffmpeg -hide_banner -encoders=);
2. walks the codec's candidate list (the table above) in order and skips every encoder that ffmpeg does not list;
3. runs a one-frame trial encode with each listed candidate and takes the first that succeeds.

The trial is needed because listed is not the same as usable. Hardware encoders (=h264_nvenc=, =h264_qsv=, =h264_vaapi=) are listed whenever ffmpeg was built with them, whether or not the machine has the GPU. Fedora's ffmpeg also lists =libopenh264=, but the library installed by default is =noopenh264=, a stub that refuses to create an encoder. The real OpenH264 is the =openh264= package from the =fedora-cisco-openh264= repository.

The listing and the trial results are cached per ffmpeg path for the life of the process, so the cost (a few tens of milliseconds per candidate) is paid once.

When no candidate works, =begin()= fails with =LRG_REEL_EXPORTER_ERROR_ENCODER_NOT_FOUND=, and the message names every candidate it tried. If the listing itself cannot be read (an ffmpeg wrapper script, a very old ffmpeg), the exporter skips discovery and passes the codec's first encoder to ffmpeg, as before 0.13.7.

After =begin()=, =lrg_reel_video_exporter_get_encoder()= returns the encoder that was chosen.

To pick the encoder yourself, name it with =lrg_reel_video_exporter_set_encoder()=. The name must be in the ffmpeg's listing (otherwise =ENCODER_NOT_FOUND=); it gets no trial encode. =NULL= or an empty string returns to automatic choice. =reel render --encoder NAME= does the same from the CLI.

#+begin_src c
/* Use VA-API even when libx264 is available. */
lrg_reel_video_exporter_set_encoder (vid, "h264_vaapi");
#+end_src

Each encoder family gets its own quality flags. =set_crf()= is translated as follows (when =set_bitrate()= is non-zero, every encoder except ProRes gets =-b:v= instead):

| Encoder                 | Quality flags from =set_crf (N)=                       | Input pixel format              |
|-------------------------+--------------------------------------------------------+---------------------------------|
| libx264, libx265        | =-preset= (=set_preset()=, default veryfast) =-crf N=  | yuv420p                         |
| libopenh264             | =-b:v= derived from N (see below)                      | yuv420p                         |
| h264_nvenc              | =-preset p4 -rc vbr -cq N -b:v 0=                      | yuv420p                         |
| h264_qsv                | =-global_quality N=                                    | nv12                            |
| h264_vaapi              | =-rc_mode CQP -qp N=; device =/dev/dri/renderD128=     | nv12 uploaded (=hwupload=)      |
| libvpx-vp9              | =-b:v 0 -crf N=                                        | yuv420p / yuva420p              |
| libsvtav1               | =-preset 8 -crf N=                                     | yuv420p                         |
| prores_ks               | =-profile:v= 3 or 4 (CRF ignored)                      | yuv422p10le / yuva444p10le      |
| anything else (by name) | none: the encoder's own defaults                       | the codec's                     |

OpenH264 has no constant-quality mode, so N becomes a bitrate: 0.1 bit per pixel per frame at N = 23, doubling for every 6 steps down and halving for every 6 up (the slope of x264's CRF scale), with a floor of 100 kbit/s. 1280x720 at 24 fps comes to about 2200 kbit/s at the default CRF and 4400 kbit/s at CRF 17.

*** Adding audio

Pass a mixed =LrgWaveData= (from =lrg_reel_audio_track_mix()=) before calling
=begin()= / =render_to_exporter()=:

#+begin_src c
lrg_reel_video_exporter_set_audio (vid, mixed_wave);
/* Now render_to_exporter() will mux audio into the output. */
#+end_src

See [[file:audio.org][audio.org]] for how to produce =mixed_wave=.

*** Custom ffmpeg path

#+begin_src c
/* Override auto-discovery if ffmpeg lives in a non-standard location. */
lrg_reel_video_exporter_set_ffmpeg_path (vid, "/opt/ffmpeg/bin/ffmpeg");

/* Pass NULL to restore auto-discovery. */
lrg_reel_video_exporter_set_ffmpeg_path (vid, NULL);
#+end_src

** New codecs — H.265, ProRes, and VP9 alpha
:PROPERTIES:
:CUSTOM_ID: new-codecs
:END:
The =LrgReelVideoCodec= enum gained four new entries that cover professional
and alpha-channel workflows:

| Codec                                | Container | Encoder        | Notes                                      |
|--------------------------------------+-----------+----------------+--------------------------------------------|
| =LRG_REEL_VIDEO_CODEC_H265=          | .mp4      | libx265        | Smaller files than H.264 at equivalent quality |
| =LRG_REEL_VIDEO_CODEC_PRORES=        | .mov      | prores_ks      | Apple ProRes 422 for edit-ready delivery   |
| =LRG_REEL_VIDEO_CODEC_PRORES_ALPHA=  | .mov      | prores_ks      | ProRes 4444 — preserves the alpha channel  |
| =LRG_REEL_VIDEO_CODEC_VP9_ALPHA=     | .webm     | libvpx-vp9     | VP9 with yuva420p — alpha for the web      |

The =*_ALPHA= codecs transmit the composition's transparency as a real alpha
channel.  The renderer always produces RGBA8 internally; you only need to
choose a codec that preserves it.

#+begin_src c
/* Export with alpha for compositing in a video editor. */
g_autoptr(LrgReelVideoExporter) vid =
    lrg_reel_video_exporter_new ("output.mov",
                                  LRG_REEL_VIDEO_CODEC_PRORES_ALPHA);

lrg_reel_renderer_render_to_exporter (renderer,
                                       LRG_REEL_EXPORTER (vid),
                                       &error);
#+end_src

** Bitrate control
:PROPERTIES:
:CUSTOM_ID: bitrate-control
:END:
In addition to CRF quality control, a target bitrate (in kbit/s) can be set.
Setting bitrate takes precedence over CRF for codecs that support it.

#+begin_src c
/* Target 8 Mbit/s — useful for streaming delivery. */
lrg_reel_video_exporter_set_bitrate (vid, 8000);
#+end_src

** Render a single still with LrgReelRenderer
:PROPERTIES:
:CUSTOM_ID: render-still
:END:
=lrg_reel_renderer_render_still()= renders a single frame and writes it
directly to an image file.  It is a convenience wrapper around
=render_frame()= + =grl_image_export_to_file()=, but keeps the exporter
abstraction out of the way for quick single-frame use.

#+begin_src c
g_autoptr(LrgReelRenderer) renderer = lrg_reel_renderer_new (reel);
g_autoptr(GError) error = NULL;

if (!lrg_reel_renderer_render_still (renderer, 30, "preview.png", &error))
{
    g_printerr ("Still render failed: %s\n", error->message);
    return 1;
}
#+end_src

The output format is inferred from the file extension (=.png= → PNG, =.jpg=/=.jpeg= → JPEG).

** LrgReelAudioExporter — audio-only output
:PROPERTIES:
:CUSTOM_ID: lrgreelaudioxporter
:END:
Write a mixed =LrgWaveData= to an audio file without rendering any video
frames.  WAV is written in-process; since 0.10.0 every other format goes
through =lrg_audio_encode_wave()= ([[file:../audio/encoder.org][audio files]]): in-process libav when libregnum
is built with =FFMPEG=1=, otherwise the =ffmpeg= program fed through a pipe.

#+begin_src c
g_autoptr(LrgWaveData) mix = lrg_reel_audio_track_mix (audio_track, &error);
if (mix == NULL) { /* handle error */ }

g_autoptr(LrgReelAudioExporter) ae =
    lrg_reel_audio_exporter_new ("soundtrack.mp3", LRG_REEL_AUDIO_FORMAT_MP3);
lrg_reel_audio_exporter_set_bitrate (ae, 256);  /* kbit/s */

if (!lrg_reel_audio_exporter_export (ae, mix, &error))
{
    g_printerr ("Audio export failed: %s\n", error->message);
}
#+end_src

| =LrgReelAudioFormat=            | File | Encoder        |
|---------------------------------+------+----------------|
| =LRG_REEL_AUDIO_FORMAT_WAV=     | .wav | in-process PCM |
| =LRG_REEL_AUDIO_FORMAT_MP3=     | .mp3 | libmp3lame     |
| =LRG_REEL_AUDIO_FORMAT_AAC=     | .m4a | AAC            |
| =LRG_REEL_AUDIO_FORMAT_FLAC=    | .flac| FLAC lossless  |
| =LRG_REEL_AUDIO_FORMAT_OGG=     | .ogg | Vorbis (0.10.0) |
| =LRG_REEL_AUDIO_FORMAT_OPUS=    | .opus| Opus, 48 kHz (0.10.0) |

** Pitfalls
:PROPERTIES:
:CUSTOM_ID: pitfalls
:END:
- =lrg_reel_gif_exporter_set_quality()= must be called *before*
  =lrg_reel_exporter_begin()= (or before =render_to_exporter()=, which calls
  =begin()= internally).  Calling it after the first frame is written has no
  effect.
- =lrg_reel_video_exporter_set_audio()= must also be called before =begin()=.
  Setting it after =begin()= is called will not mux audio into the current run.
- The video exporter spawns an ffmpeg subprocess and pipes frames via stdin.
  If the ffmpeg process exits unexpectedly, subsequent =add_frame()= calls will
  fail with =LRG_REEL_EXPORTER_ERROR_WRITE= or =LRG_REEL_EXPORTER_ERROR_SPAWN=.
- The image sequence exporter does not clean up partial output on failure.
  If =add_frame()= fails mid-run, previously written frames remain on disk.
- =LrgReelExporter= is derivable; you can implement a custom sink by subclassing
  it and overriding the =begin= / =add_frame= / =finish= vfuncs.
- Every codec needs its encoder in the ffmpeg that runs: =LRG_REEL_VIDEO_CODEC_H265= needs =libx265=, ProRes needs =prores_ks=, VP9 needs =libvpx-vp9=, AV1 needs =libsvtav1=. A missing one fails =begin()= up front with =LRG_REEL_EXPORTER_ERROR_ENCODER_NOT_FOUND= (since 0.13.7), before any frame is rendered. H.264 has a list of fallbacks ([[#video-encoder][Choosing the encoder]]).
- =lrg_reel_renderer_render_still()= infers the image format from the file
  extension.  An unknown extension falls back to PNG.
