** 0.13.7
:PROPERTIES:
:CUSTOM_ID: changelog-0-13-7
:END:
H.264 export works with an ffmpeg that has no =libx264= (issue #3). The video exporter used to ask ffmpeg for =libx264= unconditionally, so =reel render= failed out of the box on Fedora's ffmpeg. It now asks the ffmpeg it runs which encoders it has, and uses the first of =libx264=, =libopenh264=, =h264_nvenc=, =h264_qsv= and =h264_vaapi= that is listed and passes a one-frame trial encode. The trial matters: Fedora's ffmpeg lists =libopenh264=, but the library installed by default is the =noopenh264= stub, which refuses to encode. The real OpenH264 is the =openh264= package from the =fedora-cisco-openh264= repository.

- Reel: =lrg_reel_video_exporter_set_encoder()= and =lrg_reel_video_exporter_get_encoder()= name or report the ffmpeg encoder. Rate control follows the encoder: libopenh264 gets a bitrate derived from the CRF, NVENC =-cq=, QSV =-global_quality=, VA-API =-qp= with its device and upload filter ([[file:modules/reel/exporters.org::#video-encoder][Choosing the encoder]]).
- Reel: a codec whose encoder ffmpeg lacks (=libx265=, =libsvtav1=, ...) now fails =begin()= up front with the new =LRG_REEL_EXPORTER_ERROR_ENCODER_NOT_FOUND=, which names every encoder tried, instead of failing later with an ffmpeg exit code.
- CLI: =reel render --encoder NAME=, and =--codec av1=. MCP: =reel_render= takes an optional =encoder= and reports the one used; the MCP tools page now documents the reel tools.
- Tests: a fake ffmpeg (=tests/data/fake-ffmpeg.sh=) drives the fallback chain, failed trials, the override, a failed probe, the probe cache and every encoder's argv; =/reel/video-encoder/h264-real= exports with whatever this machine's ffmpeg can run.

** 0.13.4
:PROPERTIES:
:CUSTOM_ID: changelog-0-13-4
:END:
The android-arm64 build image no longer fails at random. Its smoke tests piped =llvm-readelf -h= into =grep -q= under =pipefail=; when grep exited on the match, readelf died of SIGPIPE and the check reported "not AArch64" (about one build in 15 over the two checks).

- Build: the image's ELF checks, =lrg_dnf_install_optional()= and the sysroot's archive listing read their command's output whole instead of piping into an early-exit reader.
- Tests: =tests/test-pipefail-pipes.sh= (in =make test-build-system=) fails on that pattern in any build-system script ([[file:cross-compile.org::#testing-build-system][The build system itself]]).

** 0.12.0
:PROPERTIES:
:CUSTOM_ID: changelog-0-12-0
:END:
Cross-target builds: Windows (x86_64), Linux (aarch64) and Android (arm64-v8a) from one checkout, each in its own build directory, with the native build unchanged. See [[file:cross-compile.org][Cross-Compilation Guide]].

- Build: a target model (=build-aux/mk/target.mk=). =LRG_TARGET=<os>-<arch>= or the =WINDOWS=1=, =ARM64=1=, =ANDROID=1= switches pick a target; asking for the host's own target is a native build. One profile per cross target in =build-aux/mk/targets/=. Cross builds go to =build/<release|debug>-<target>= (=-windows-amd64=, =-arm64=, =-android-arm64=); =build/release= and =build/debug= stay native-only, so a =WINDOWS=1= build no longer wipes the native objects. New goals =print-target=, =targets= and =clean-targets=; =make clean= keeps the cross targets' directories, =make WINDOWS=1 clean= removes only Windows'. Conflicting switches, unknown targets and =SANITIZE=1= with a cross target stop with an error, and a missing cross toolchain is one clear message.
- Build: cross targets build graylib, raylib, yaml-glib and crispy into their own =$(BUILDDIR)/deps/= (graylib's new =BUILDDIR= and =RAYLIB_BUILD_DIR=, yaml-glib's and crispy's overridable =BUILDDIR=); the native build keeps the in-tree paths cmacs links against. =make WINDOWS=1 DEBUG=1= now forwards =DEBUG= to the dependencies, so the debug yaml-glib archive it links exists. =examples/Makefile= takes the dependency archives from =config.mk= instead of hard-coding them.
- Build: cross builds run in a podman build container by default (=GNUmakefile= dispatches; =build-aux/mk/container.mk=). All goals become one =make= in the container, with the checkout mounted at the same path, files owned by the caller and =MAKEFLAGS= (=-j=, every =VAR=value=) forwarded minus the jobserver. Images are built from =build-aux/containers/<target>/= on top of =registry.fedoraproject.org/fedora:45= (=BUILD_CONTAINER_BASE=), tagged with a hash of their recipe (an edited recipe means a new image, an unchanged one is reused), and every image ends with a toolchain smoke test. =BUILD_CONTAINER_IMAGE= runs a prebuilt image, =BUILD_CONTAINER_ARGS= adds run arguments, =NO_BUILD_CONTAINER=1= builds on the host. New goals =container-image=, =container-shell=, =container-prune= and =print-container=. A cross build entered from =tests/= or with =-f Makefile= is refused instead of silently using host tools.
- Targets: =linux-arm64= is a true gcc cross build against a Fedora aarch64 sysroot (=build-aux/cross/= wrappers; tests under qemu-aarch64). =windows-amd64= builds the DLL and every tool and runs the tests under Wine. =android-arm64= builds static and shared libraries with the NDK's clang against a static GLib stack and packages games as APKs (=make ANDROID=1 apk APK_GAME=<game.c>=, =apk-install=, =apk-run=; =build-aux/android/mkapk.sh=: no Gradle, no Java code, 16 KB aligned, signed). Pages: [[file:platforms/windows.org][Windows]], [[file:platforms/linux-arm64.org][Linux aarch64]], [[file:platforms/android.org][Android]].
- Core: =lrg_platform_prepare()=, =lrg_platform_set_data_root()= and =lrg_platform_extract_assets()= (=core/lrg-platform.h=): on Android, logcat logging, XDG directories in internal storage and the APK's assets extracted (stamped, atomic, path-checked); a no-op elsewhere. Called by =LRG_DEFINE_GAME_MODULE='s =main()=, =lrg_game_run_standalone()= and =lrg_engine_startup()=.
- Graphics: every built-in shader starts with =LRG_GLSL_HEADER= (=#version 330=, or =#version 300 es= with precisions on Android) and is written in the GLSL 3.30 / ES 3.00 common subset; =make test-shaders= compiles all 70 both ways with glslang.
- Build: =SOUP=0= and =LIBPQ=0= build the HTTP analytics backend and the MMO PostgreSQL store as documented stubs (both stay required by default); =BUILD_TOOLS=0= leaves the tools out of =make all=.
- Fixes found by the new targets: =%ld= used for =gint64= (wrong wherever =long= is 32-bit); a G_TYPE_LONG/ULONG range check that let 2^63 through to an overflowing cast; translated printf formats now checked against the fallback string (types by position, no =%n=) before use; builds without GObject Introspection failed (vscript, editor script API); =static volatile gsize= with =g_once_init_*= (226 sites); POSIX-only calls (=realpath=, =S_ISLNK=, =sigaction=, =dladdr=, Unix credentials) given Windows equivalents; =backtrace()= and =memfd_create()= on bionic; dead helpers, missing printf attributes and a misleading indentation.
- Known aarch64 bugs, found by the new test runs and listed at the end of every =make ARM64=1 test=: =/replay/golden/physics-timers-rng=, =/collide/random-consistency= and =/foley-patch/pinned-bytes= are not bit-identical to x86-64. See [[file:platforms/linux-arm64.org::#known-bugs][Known aarch64 bugs]].
- Windows fixes found by running the tests under Wine: project-relative paths written into data (asset database entries and their legacy guids, the runtime guid index, level references from the editor, sound-bank, material and rig paths) used =\= on Windows, so a project saved there did not open elsewhere; they are =/=-separated everywhere now (=lrg_portable_relative_path()=, =lrg_portable_relative_to()= in =src/lrg-portable-private.h=). The editor opened a second editor on a file reached by two spellings (=editor_app_project_path()= canonicalizes; the terrain/water store compares canonical paths). Renaming an asset while its thumbnail was being read failed with "Permission denied" (Windows cannot move an open file; =lrg_portable_rename()= waits up to 2 s). =rename()= of an asset accepted =a/b.png= on Windows. Theme files were not found by an uninstalled or installed Windows editor (=/proc/self/exe=; now =lrg_portable_exe_path()=, plus a relocatable =<prefix>/share= lookup).
- Editor: 23 =LrgSpinBox::value-changed= handlers (sequencer key and section fields, timeline and sequence length, tile, brush and grid sizes, snap, sprite and tileset fields) were declared with a =gdouble= the signal never passes. On x86-64 Linux the =user_data= still arrived, so most worked by accident, but the sequencer's key and section fields applied whatever was in a floating-point register; on Windows x64, which assigns argument registers by position, the handlers read a bad =user_data= and the editor crashed. They take =(spin, user_data)= now and read the value from the spin box; =test-editor-app-sequencer= sets a key's value through its field.
- Tests under Wine run on a pseudo-terminal (=build-aux/cross/lrg-wine-run=), as a Windows console program always has a console; tests no longer assume =/= in paths, paste paths into JSON unescaped, spawn POSIX =true=, call a =stepped= handler with the wrong signature (it read the wrong argument under the Windows x64 calling convention), or read =n= in the same call that sets it (=test-terrain-asset=: the argument order is unspecified, and MinGW gcc read it first); the notification tests skip where there is no =dbus-daemon= for their private bus.
- Tests: =make test-minimal-features= (the library without libsoup and libpq in =build/minimal=, =tests/test-optional-features.c=); =make test-cross-arm64=, =test-cross-windows=, =test-cross-android= and =test-cross= (each target's whole gate); =make <target> test-cross-artifacts= (architecture, 16 KB alignment, DLL exports and imports: =tests/test-cross-artifacts.sh=); =make ANDROID=1 test-device= (the APK on an adb device: =tests/test-apk-device.sh=, skips without one). =/ui/label/ellipsize= skips where no font can be drawn with (headless, no system font): it was not an aarch64 bug.
- Tests: =make test-build-system= (target resolution for every spelling and host, the clean goals, the container dispatch through a stub engine, ShellCheck) and =make test-native-unchanged [BASE=ref] [EXCLUDE_ADDED=1]=, which diffs the native =make -Bn= output against a base ref rebuilt in a hard-linked copy of the tree and, on the host that recorded it, against the stored baseline in =tests/golden/native-make-n/= (=make update-native-golden=); =tests/test-platform.c=, =tests/test-apk-layout.sh=, =tests/test-shader-glsl.sh=, format-check cases in =test-i18n=.
