* Editor Runtime
:PROPERTIES:
:CUSTOM_ID: editor-runtime
:END:
This document covers =LrgEditor= (the host-agnostic editor runtime), the undo/redo
command system (=LrgEditorCommand=), the selection model (=LrgEditorSelection=), and
the host embedding contract (=LrgEditorHost= / =LrgEditorSoftwareHost=). It also covers the headless building blocks every editor frontend shares: viewport math and the =LrgEditorView= camera, ray picking and box selection, the =LrgEditorGizmo= transform controller, the =LrgEditorActions= command registry and level validation (=LrgEditorProblem=).

The full editor application (=lrgeditor=, =LrgEditorApp=) is built on top of this runtime and drawn with libregnum's own immediate-mode GUI (=LrgGuiContext=); it is documented in [[file:editor-app.org][Editor Application]]. Everything in this document is window-less and unit-testable, so an IDE such as cmacs can reuse it without the application.

** LrgEditor
:PROPERTIES:
:CUSTOM_ID: lrgeditor
:END:
=LrgEditor= is a final GObject that owns the level document, the selection, and
the undo/redo stacks. All mutations go through reversible commands so the full
history participates in undo/redo. The editor emits a =changed= signal whenever
any mutation is applied or undone.

*** Creation and Document
:PROPERTIES:
:CUSTOM_ID: creation-and-document
:END:
#+begin_src C
g_autoptr(LrgEditor) editor = lrg_editor_new ();

/* Replace the active level (clears history and selection) */
lrg_editor_set_level (editor, my_level);

/* Load from disk (equivalent to set_level after deserializing) */
g_autoptr(GError) error = NULL;
lrg_editor_load_level (editor, "dungeon.rlevel", &error);

/* Save */
lrg_editor_save_level (editor, "dungeon.rlevel", &error);

LrgLevel *level = lrg_editor_get_level (editor);  /* (transfer none) */
#+end_src

The editor also tracks the document's own file path, so a frontend can offer plain Save / Reload without carrying the path around:

#+begin_src C
/* Fresh empty level; clears path, selection and history */
lrg_editor_new_level (editor, "untitled");

/* Path-based save / reload */
lrg_editor_set_path (editor, "levels/dungeon.rlevel");
if (!lrg_editor_save (editor, &error))      /* G_IO_ERROR_INVALID_FILENAME if no path */
	g_warning ("save failed: %s", error->message);

/* Re-read from disk (file edited in Emacs); selection is restored by GUID */
lrg_editor_reload (editor, &error);

const gchar *path = lrg_editor_get_path (editor);   /* (transfer none) (nullable) */

/* The whole document as .rlevel YAML, without touching disk */
g_autofree gchar *yaml = lrg_editor_serialize (editor);
#+end_src

*** Dirty Tracking and Save Signals
:PROPERTIES:
:CUSTOM_ID: dirty-tracking
:END:
Dirty state is derived from the undo history rather than a free-standing flag. Every =LrgEditorCommand= carries a process-unique modification serial (=lrg_editor_command_get_serial()=), refreshed whenever another command is merged into it. =lrg_editor_mark_clean()= records the serial at the top of the undo stack as the saved state; the document is dirty whenever the current top differs. Undoing back to the saved point therefore makes the document clean again, and redoing past it makes it dirty.

#+begin_src C
gboolean dirty = lrg_editor_is_dirty (editor);

/* Declare the current history position as "saved" (save/load do this) */
lrg_editor_mark_clean (editor);

/* Force dirty without a history entry, e.g. after restoring an autosave
   over the file it belongs to */
lrg_editor_mark_modified (editor);
#+end_src

| Function | Signature |
|----------+-----------|
| =lrg_editor_is_dirty= | =gboolean (LrgEditor *self)= |
| =lrg_editor_mark_clean= | =void (LrgEditor *self)= |
| =lrg_editor_mark_modified= | =void (LrgEditor *self)= |

Note that =lrg_editor_clear_history()= keeps the dirty state: clearing history does not make unsaved changes disappear.

*** Mutating Operations
:PROPERTIES:
:CUSTOM_ID: mutating-operations
:END:
Each operation below pushes an undoable =LrgEditorCommand= onto the undo stack and
emits the =changed= signal.

#+begin_src C
/* Add a node (also selects it) */
g_autoptr(LrgNode) node = lrg_node_new ("crate");
lrg_editor_add_node (editor, node, NULL);   /* NULL = under root */

/* Delete a node */
lrg_editor_delete_node (editor, node);

/* Reparent */
lrg_editor_reparent_node (editor, node, new_parent);

/* Set full local transform in one command */
const gfloat loc[3] = { 1.0f, 0.0f, 0.0f };
const gfloat rot[3] = { 0.0f, 0.0f, 0.0f };
const gfloat scl[3] = { 1.0f, 1.0f, 1.0f };
lrg_editor_set_node_transform (editor, node, loc, rot, scl);

/* Set a GObject property on a node (e.g. "name", "visible") */
GValue name_val = G_VALUE_INIT;
g_value_init (&name_val, G_TYPE_STRING);
g_value_set_string (&name_val, "crate_01");
lrg_editor_set_node_property (editor, node, "name", &name_val);
g_value_unset (&name_val);
#+end_src

Further operations added for the editor application. Every one records exactly one undo step; functions taking a =merge= flag coalesce with the previous command when it targets the same thing, so a whole slider or gizmo drag is a single undo.

#+begin_src C
/* Insert at a child index (-1 appends) and select */
lrg_editor_insert_node (editor, node, parent, 0);

lrg_editor_move_node (editor, node, new_parent, -1, TRUE);

/* Rename */
lrg_editor_rename_node (editor, node, "crate_02");

/* Any subset of TRS channels; NULL keeps a channel. merge=TRUE while dragging */

*** Undo Groups and Custom Commands
:PROPERTIES:
:CUSTOM_ID: undo-groups
:END:
=lrg_editor_begin_group()= opens a compound undo step. Every command executed until the matching =lrg_editor_end_group()= is applied immediately and recorded as a child of one =LRG_EDITOR_CMD_GROUP= command, which undoes back-to-front. Groups nest; only the outermost one reaches the history. An empty group is discarded.

#+begin_src C
/* Align every selected node to y = 0 as one undo step */
g_autoptr(GPtrArray) roots = NULL;
guint i;

roots = lrg_editor_get_selected_roots (editor);
lrg_editor_begin_group (editor, "Drop to Floor");
for (i = 0; i < roots->len; i++)
{
	LrgNode *n;
	GrlVector3 *p;
	gfloat loc[3];

	n = (LrgNode *)g_ptr_array_index (roots, i);
	p = lrg_node_get_location (n);
	loc[0] = p->x;
	loc[1] = 0.0f;
	loc[2] = p->z;
	lrg_editor_transform_node (editor, n, loc, NULL, NULL, FALSE);
}
lrg_editor_end_group (editor);
#+end_src

=lrg_editor_execute()= runs a command you built yourself: it applies the command and records it in the history, or in the open group if one is open. Ownership of the command is transferred.

#+begin_src C
LrgEditorCommand *cmd;

cmd = lrg_editor_command_new_move (node, new_parent, 0);   /* NULL if it would create a cycle */
if (cmd != NULL)
{
	lrg_editor_command_set_label (cmd, "Move to Top");
	lrg_editor_execute (editor, cmd);                       /* (transfer full) */
}
#+end_src

*** Node-State Snapshots (Making Any Edit Undoable)
:PROPERTIES:
:CUSTOM_ID: node-state-snapshots
:END:
Not every edit has a dedicated command. The catch-all path is snapshot / mutate / commit: capture the node's own state, change the node directly with the plain =lrg_node_*= setters, then commit. The editor compares the snapshot with the live node (=lrg_node_state_equal()=) and, if anything changed, records an =LRG_EDITOR_CMD_NODE_STATE= command whose undo and redo restore the before/after state with =lrg_node_copy_state()=.

A node's "own state" is its name, flags (visible, locked, 2D), local transform, and deep copies of its visual payload, component descriptions and script bindings. The GUID, parent and children are never part of it, so snapshots are only for edits of a single node, not structural changes.

#+begin_src C
g_autoptr(LrgNode) before = NULL;
g_autoptr(LrgComponentDesc) desc = NULL;

before = lrg_editor_snapshot_node (node);      /* (transfer full), detached copy */

/* mutate in place with any combination of plain setters */
lrg_node_set_locked (node, TRUE);
desc = lrg_component_desc_new ("RigidBody");
lrg_node_add_component (node, desc);

/* records one undo step named "Make Physical"; FALSE if nothing changed */
lrg_editor_commit_node_state (editor, node, before, "Make Physical", FALSE);
#+end_src

Pass =merge= = =TRUE= to coalesce with the previous commit of the same node and label, e.g. while a colour picker or text field is being dragged/typed. The command can also be built directly with =lrg_editor_command_new_node_state()=, which copies both snapshots.

*** Clipboard
:PROPERTIES:
:CUSTOM_ID: clipboard
:END:
Copy and cut serialize the selected subtrees as =.rlevel= YAML and store it as the editor clipboard; the text is also returned so a host can put it on the system clipboard (and pasting it into a =.rlevel= in a text editor works). Paste and duplicate insert copies with fresh GUIDs and unique sibling names, as one undo step, and select the result. All of them act on =lrg_editor_get_selected_roots()=, so a selected child of a selected parent is not copied twice.

#+begin_src C
g_autofree gchar *text = lrg_editor_copy_selection (editor);  /* NULL if nothing selected */
g_autofree gchar *cut  = lrg_editor_cut_selection (editor);   /* copy then delete */

/* NULL data pastes the editor clipboard; NULL parent pastes under the root */
g_autoptr(GPtrArray) pasted = lrg_editor_paste (editor, NULL, NULL, &error);

/* Paste YAML from elsewhere (system clipboard, a file) */
g_autoptr(GPtrArray) more = lrg_editor_paste (editor, system_text, target_parent, &error);

/* Duplicate next to the originals */
g_autoptr(GPtrArray) copies = lrg_editor_duplicate_selection (editor);

/* Delete the selection with subtrees */
guint n_deleted = lrg_editor_delete_selection (editor);

/* Direct clipboard access */
const gchar *clip = lrg_editor_get_clipboard (editor);
lrg_editor_set_clipboard (editor, system_text);
#+end_src

*** History API
:PROPERTIES:
:CUSTOM_ID: history-api
:END:
The undo and redo stacks are inspectable, which is what the History panel and the IPC =edit.history= / =edit.jump= methods are built on. Undo index 0 is the oldest step; redo index 0 is the step =lrg_editor_redo()= would apply next.

#+begin_src C
guint n_undo;
guint n_redo;
guint i;

n_undo = lrg_editor_get_undo_count (editor);
n_redo = lrg_editor_get_redo_count (editor);

for (i = 0; i < n_undo; i++)
{
	LrgEditorCommand *cmd;
	g_autofree gchar *desc = NULL;

	cmd = lrg_editor_get_undo_command (editor, i);   /* (transfer none) */
	desc = lrg_editor_command_describe (cmd);
	g_print ("%2u  %s\n", i + 1, desc);
}

/* Click-to-jump: undo/redo until exactly 3 steps are applied
   (0 = the initial document) */
lrg_editor_jump_to_history (editor, 3);

/* Drop all steps (the dirty state is kept) */
lrg_editor_clear_history (editor);

/* Bound memory use; 0 = unlimited */
lrg_editor_set_history_limit (editor, 500);
#+end_src

*** Tool, Space and Snap
:PROPERTIES:
:CUSTOM_ID: tool-and-snap
:END:
The active tool determines which gizmo is drawn and which drag operations are
sent to the editor. Snap increments of 0 disable snapping for that channel; on top of that, =snap-enabled= switches snapping on and off as a whole while keeping the increments (the gizmo's Ctrl modifier inverts it per drag update). The space selects whether the translate/rotate gizmo axes are world axes or the node's own rotated axes; the scale gizmo always uses local axes.

#+begin_src C
lrg_editor_set_tool (editor, LRG_EDITOR_TOOL_TRANSLATE);
LrgEditorTool tool = lrg_editor_get_tool (editor);

/* Translation snap of 0.5 units, rotation snap of 15 degrees, no scale snap */
lrg_editor_set_snap (editor, 0.5, G_PI / 12.0, 0.0);
lrg_editor_set_snap_enabled (editor, TRUE);

gdouble snap_t, snap_r, snap_s;
lrg_editor_get_snap (editor, &snap_t, &snap_r, &snap_s);

lrg_editor_set_space (editor, LRG_EDITOR_SPACE_LOCAL);
LrgEditorSpace space = lrg_editor_get_space (editor);
#+end_src

** LrgEditorCommand
:PROPERTIES:
:CUSTOM_ID: lrgeditorcommand
:END:
=LrgEditorCommand= is the discriminated undo record. =LrgEditor= creates commands
internally; direct use is only needed when building a custom editor, running a
custom command through =lrg_editor_execute()=, or inspecting the history.

** Viewport Math and LrgEditorView
:PROPERTIES:
:CUSTOM_ID: viewport-math
:END:
=lrg-editor-math.h= is the headless 3D math every viewport, the gizmo and the picker use. Nothing in it needs a window or GL context.

*** Conventions
:PROPERTIES:
:CUSTOM_ID: math-conventions
:END:
- Matrices are 4x4, column-major, stored as 16 floats (=m[col * 4 + row]=), matching raylib / graylib.
- Points are column vectors: =world = M * local=.
- Euler rotations are radians applied X, then Y, then Z (=R = Rz * Ry * Rx=), like raylib's =MatrixRotateXYZ=; =lrg_editor_math_compose()= builds =T * Rz * Ry * Rx * S=.
- Y is up; the camera looks down its local -Z.
- Screen coordinates are viewport pixels with the origin at the top-left.

** LrgEditorGizmo
:PROPERTIES:
:CUSTOM_ID: lrgeditorgizmo
:END:
=LrgEditorGizmo= is the headless interaction model of the translate, rotate and scale gizmos for an =LrgEditor='s selection. It reads the editor's tool, space and snap settings, computes the gizmo frame (pivot, axes, on-screen size), hit-tests the mouse against the handles in viewport pixels, and turns a drag into node transforms. Nodes are updated live while dragging; ending the drag records a single undo step for the whole selection, and cancelling restores the original transforms without touching the history. Rendering is left to the host.

*** Drag Model
:PROPERTIES:
:CUSTOM_ID: gizmo-drag-model
:END:
- The gizmo is visible (=lrg_editor_gizmo_is_visible()=) when a manipulation tool is active and an unlocked node is selected.
- The pivot (=get_origin=) is the primary selection's world origin. Axes (=get_axis=) are world axes in world space and the primary node's rotated axes in local space; the scale tool always uses local axes.
- =get_size= returns the world-space arm length that makes the gizmo =LRG_EDITOR_GIZMO_SIZE_PIXELS= (96) pixels long on screen; a handle counts as hovered within =LRG_EDITOR_GIZMO_PICK_PIXELS= (8) pixels.
- Per frame: when not dragging, =update_hover= stores the handle under the mouse (unchanged while dragging). On press, =begin_drag= grabs the handle under the mouse and returns =FALSE= if there is none, in which case the click falls through to picking / box selection. While the button is held, =drag= updates the transforms; =invert_snap= (Ctrl held) toggles the editor's snap setting for that update. On release, =end_drag= records the undo step. Escape or a right click calls =cancel_drag=.
- =begin_drag_handle= starts a drag on a specific handle regardless of the mouse position (keyboard modal transforms such as G then X).
- =get_drag_delta= gives the current amount for an on-screen readout: translation in world units, rotation in radians (x only), or scale factors.

	gboolean             down,
	gboolean             cancel,
	gboolean             ctrl
){
	/* idle: track the hovered handle for highlighting */
	if (!lrg_editor_gizmo_is_dragging (gizmo))
		lrg_editor_gizmo_update_hover (gizmo, view, x, y);

	/* press: grab the handle under the mouse; FALSE lets the click
	 * fall through to lrg_editor_pick() / box selection */
	if (pressed && !lrg_editor_gizmo_begin_drag (gizmo, view, x, y))
		return FALSE;

	if (!lrg_editor_gizmo_is_dragging (gizmo))
		return FALSE;

	/* dragging: cancel restores the originals, release commits one
	 * undo step for the whole selection, otherwise update live */
	if (cancel)
		lrg_editor_gizmo_cancel_drag (gizmo);
	else if (down)
		lrg_editor_gizmo_drag (gizmo, view, x, y, ctrl);
	else
		lrg_editor_gizmo_end_drag (gizmo);

	return TRUE;
}
#+end_src

** LrgEditorActions
:PROPERTIES:
:CUSTOM_ID: lrgeditoractions
:END:
=LrgEditorActions= is the registry of named editor commands. Every user-facing operation ("file.save", "edit.duplicate", "view.focus", "play.start", ...) is registered once with a label, a category and a default shortcut; menus, the command palette, keyboard handling and the IPC =action.run= method all go through it, so a rebinding or a new action shows up everywhere. User overrides come from the =keybindings= mapping of =LrgEditorSettings= (=editor.yaml=).

*** Shortcuts
:PROPERTIES:
:CUSTOM_ID: shortcuts
:END:
Shortcuts are text such as ="Ctrl+Shift+S"=, ="F2"=, ="Delete"=, ="Alt+Up"=, ="Ctrl+="=, ="Shift+Num7"=. Modifier names: Ctrl/Control, Shift, Alt/Meta, Super/Win/Logo. Key names: letters, digits, F1-F12, Num0-Num9, Up/Down/Left/Right, Home, End, PageUp, PageDown, Insert, Delete/Del, Backspace, Enter/Return, Escape/Esc, Tab, Space and the punctuation characters =- = [ ] / \ , . ; ' `=. Case is ignored. Several alternatives are separated by =|= (="Ctrl+Shift+Z|Ctrl+Y"=); menus show the first. In settings, an empty string unbinds an action and a missing entry restores the default.

#+begin_src C
LrgGuiModifiers mods;
LrgGuiKey key;

if (lrg_editor_shortcut_parse ("ctrl+shift+s", &mods, &key))
{
	g_autofree gchar *canon = lrg_editor_shortcut_format (mods, key);   /* "Ctrl+Shift+S" */
}

/* Fuzzy subsequence score used by the palette and quick open; 0 = no match */
gint score = lrg_editor_fuzzy_score ("dupsel", "Edit: Duplicate Selection");
#+end_src

** Level Validation
:PROPERTIES:
:CUSTOM_ID: level-validation
:END:
=lrg_editor_validate_level()= checks a level for mistakes that would make it misbehave at runtime or in other tools. The Problems panel, =lrgeditor --validate= and the =level.validate= IPC method all use it. Results are sorted errors first, then in tree order.

#+begin_src C
g_autoptr(GPtrArray) problems = NULL;
guint i;

/* base_dir NULL skips file checks; registry NULL skips component-type checks */
problems = lrg_editor_validate_level (level, project_root,
                                      lrg_engine_get_registry (engine));
for (i = 0; i < problems->len; i++)
{
	LrgEditorProblem *p;

	p = (LrgEditorProblem *)g_ptr_array_index (problems, i);
	g_printerr ("%s: [%s] %s: %s\n",
	            lrg_editor_problem_severity_to_string (p->severity),
	            p->code,
	            p->node_path != NULL ? p->node_path : "(level)",
	            p->message);
}
#+end_src

=LrgEditorProblem= is a boxed struct (=lrg_editor_problem_copy()= / =lrg_editor_problem_free()=, =g_autoptr= supported) with the fields =severity=, =code= (stable, machine-readable), =node_guid=, =node_path=, =message= and =file= (the related asset or script, if any).
