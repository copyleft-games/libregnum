* lrgeditorctl and the Editor MCP Server
:PROPERTIES:
:CUSTOM_ID: lrgeditorctl

#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > lrgeditorctl and MCP
#+end_quote

=lrgeditorctl= is to =lrgeditor= what kubectl is to a cluster: verbs (=get=, =describe=, =create=, =delete=, =set=, =edit=, =apply=, ...) acting on resources (=nodes=, =selection=, =actions=, =problems=, =assets=, ...) of a running editor session, with =-o yaml|json|table|wide|name= output. It speaks the editor's JSON-lines IPC socket ([[file:ipc-protocol.org][IPC protocol]]), opens one connection per call (so editor restarts are harmless), starts instantly and needs no display or GL. It also serves the editor's tools over MCP so AI agents can drive the editor, and the same tools are available from inside the editor with =lrgeditor --mcp=.

Sources: =src/editorctl/= (=lrgeditorctl.c= commands, =lrgeditorctl-client.c= sessions and calls, =lrgeditorctl-format.c= YAML/JSON/tables, =lrgeditorctl-mcp.c= the MCP tool table shared with =src/launcher/lrgeditor.c=). An agent skill covering all of this lives in =skills/skill-libregnum/= (=make install-skills=).

** Building
:PROPERTIES:
:CUSTOM_ID: building
:END:
Built by default with the editor (=BUILD_EDITOR=1=). It links GLib, GIO, json-glib and the bundled yaml-glib; MCP support (the bundled mcp-glib) is enabled when =libsoup-3.0= and =libdex-1= are installed, or forced off with =EDITOR_MCP=0=.

| Fedora package     | Why                                      |
|--------------------+------------------------------------------|
| =json-glib-devel=  | IPC messages                              |
| =libyaml-devel=    | yaml-glib (YAML output, =edit=, =apply=) |
| =libsoup3-devel=, =libdex-devel= | mcp-glib (MCP support)     |
| =bash-completion=  | (runtime) =lrgeditorctl completion bash= |

#+begin_src sh
make lrgeditorctl            # build/release/lrgeditorctl
make test-editorctl          # every verb and both MCP servers against a headless editor
make install                 # bin/lrgeditorctl + share/bash-completion/completions/lrgeditorctl
#+end_src

** Sessions and global flags
:PROPERTIES:
:CUSTOM_ID: sessions
:END:
Editors listen on =$XDG_RUNTIME_DIR/libregnum/editor-PID.sock= (or =--socket=, =$LRG_EDITOR_SOCKET=). =lrgeditorctl sessions= lists the live ones (stale sockets are skipped, the current one is starred); without =-s= the newest is used.

| Flag                     | Meaning                                                                 |
|--------------------------+-------------------------------------------------------------------------|
| =-s=, =--session SESSION= | Socket path, PID, or any substring of the project or level path        |
| =-o=, =--output FORMAT=  | =yaml=, =json=, =table=, =wide= (extra columns such as GUIDs), =name= (=node/PATH=) |
| =--timeout SEC=          | Reply timeout (default 10)                                               |
| =-n=, =--node NODE=, =--target NODE= | Node and joint target of the =physics= verbs (0.9.0)       |
| =-h=, =--help=, =--license=, =-v=, =--version= |                                                  |

Exit status: 0 success, 1 the editor reported an error (unknown node, failed save, validation errors), 2 usage error.

** Changing nodes
:PROPERTIES:
:CUSTOM_ID: changing
:END:
Nodes are slash paths from the top of the level (=Props/Crate=) or GUIDs. Assignment values: =1,2,3= vectors, =true=/=false=, numbers, =null=, JSON, otherwise strings. Every change is one undo step in the editor.

| Command                                                   | Effect                                              |
|-----------------------------------------------------------+-----------------------------------------------------|
| =create node NAME [--parent P] [--kind K] [--primitive S] [--index N] [k=v...]= | New node, transform in the same step |
| =set node PATH k=v...=                                     | =name location rotation_degrees rotation scale visible locked visual= |
| =rename node PATH NEW=, =move node PATH [--parent P] [--index N] [--keep-world]= |                        |
| =duplicate node PATH=, =delete node PATH...=              |                                                      |
| =edit node PATH=                                          | YAML in =$VISUAL=/=$EDITOR=/=vi=, applied on save; unchanged or empty cancels |
| =apply -f FILE= (=-= for stdin)                           | YAML documents or JSON; each needs =node:=; existing nodes are updated, missing ones created (missing parents too) from =kind:=/=primitive:= |
| =select PATH... [--add]=, =select --clear=                |                                                      |

The =visual= value takes =kind=, =primitive=, =asset=, =color= =[r,g,b,a]=, =roughness=, =metallic= and =params=; color, roughness and metallic may also be nested under =material= (as in =.rlevel= files).

#+begin_src yaml
# lrgeditorctl apply -f props.yaml
node: Props/Crate
primitive: cube
location: [2, 0.5, -3]
rotation_degrees: [0, 45, 0]
visual:
  material:
    color: [0.6, 0.4, 0.2, 1]
---
node: Props/Lantern
kind: light
location: [2, 2, -3]
#+end_src

** 0.8.1 verbs
:PROPERTIES:
:CUSTOM_ID: verbs-0-8-1
:END:
Every IPC method added in 0.8.1 has a verb. They share one convention: positional arguments fill the method's main parameters in order (=NODE=, =PATH=, =NAME=, =DEST=...), any =key=value= argument is passed through as a parameter as is (values are parsed like =set node=: numbers, =true= / =false=, =null=, =a,b,c= number vectors, JSON), and the result prints as YAML (or =-o json=, =-o table=...). A path that exists relative to the current directory is sent absolute; anything else is passed through and the editor resolves it against the project. So a parameter the verb does not know about still reaches the editor, and =call METHOD k=v...= remains the generic escape hatch for every method.

| Verb | Method | Notes |
|------+--------+-------|
| =meta get PATH= | =asset.meta.get= | The sidecar the asset has, or the one the editor would create (=exists: false=; nothing written) |
| =meta set PATH k=v... [guid=G]= | =asset.meta.set= | Every =k=v= except =guid= goes into =settings= (=null= resets a setting); all or nothing, a bad value exits 1 |
| =vcs [PATH]= | =vcs.status= | Without a path: =branch NAME= then a STATUS / PATH table (=-o wide= adds the badge letter), or "not a git repository"; with a path: that path's badge |
| =prefab overrides NODE= | =prefab.overrides= | |
| =prefab apply NODE [keys=a,b]= | =prefab.apply= | =keys= is split on commas into the list the method takes |
| =prefab revert NODE [keys=a,b]= | =prefab.revert= | |
| =prefab relink NODE [path=P]=, =prefab unlink NODE= | =prefab.relink=, =prefab.unlink= | |
| =prefab sync [PATH]= | =prefab.sync= | |
| =code open PATH[:LINE]= | =code.open= | Prints =opened PATH:LINE= (=-o yaml= for the tab) |
| =code list=, =code save [PATH]= | =code.list=, =code.save= | |
| =inspector VERB [NODE] [NAME] [k=v...]= | =inspector.VERB= (=-= becomes =_=) | e.g. =inspector set Props/Crate scale section=transform value=2,2,2= |
| =hierarchy reveal NODE=, =hierarchy rename NODE [NEW_NAME]=, =hierarchy filter TEXT=, =hierarchy state= | =hierarchy.*= | |
| =asset reveal PATH=, =asset rename PATH NAME=, =asset move PATH DEST=, =asset duplicate PATH=, =asset trash PATH=, =asset orphans [trash=true]= | =asset.*= | |
| =profiler [frames=N] [enable=BOOL]= | =profiler.sample= | A SECTION / LAST_MS / AVG_MS / MAX_MS table (=-o wide= adds MIN_MS and COUNT) |
| =view layout NAME=, =view render-mode MODE=, =view overlay NAME on\vert{}off= | =view.layout=, =view.render_mode=, =view.overlay= | =viewport=N= picks a viewport (default the active one) |

| =data ...= | =data.*= | See [[#verbs-data][Data editors]] |
| =palette [commands\vert{}files] [QUERY...]= | =palette.open= | =mode= from the first word when it is =commands= or =files=; the rest is the =query= |
| =preferences [PAGE]= | =preferences.open= | Prints =preferences/PAGE opened=; an unknown page exits 1 |

lrgeditorctl code open scripts/door.lua:12

lrgeditorctl profiler frames=120

lrgeditorctl preferences keybindings

*** Data editors
:PROPERTIES:
:CUSTOM_ID: verbs-data
:END:
=data= drives the editor's data editors (input maps, locales, sound banks, themes, HUD layouts, UI layouts, dialog trees, dungeons; see [[file:data-editors.org][Data Editors]]) through the =data.*= methods. The file is optional everywhere except =open=: without it the command acts on the focused data editor, so after =data open= the following commands need no path. Locations inside the document are YAML paths such as =/actions/jump/bindings/0/key=.

Positional arguments are read in this order: first the file, when the argument does not start with =/= (=data/input.yaml=, resolved against the project when it does not exist relative to the current directory) or is an existing regular file; then the command's own arguments. Every =key=value= argument is passed through as a parameter (=yaml==, =as==, =gesture==, =save_as==, =index==, =key==, =old==, =new==, =from==, =to==, =line==...).

| Command | Method | Positionals after the file | Output |
|---------+--------+----------------------------+--------|
| =data list= (or =data=) | =data.list= | | A FORMAT / DIRTY / ISSUES / ERRORS / PATH table (=-o wide= adds EDITOR and UNDO) |
| =data open PATH= | =data.open= | | The editor status as YAML |
| =data get [PATH] [AT]= | =data.get= | =AT= (default the root) | ={at, kind, value, keys, length, yaml, line}= |
| =data set [PATH] AT VALUE= | =data.set= | =AT=, =VALUE= (parsed like assignment values: JSON, numbers, =true= / =false=, =null=, else a string; it may contain ===) | Status + =ok=; =yaml=TEXT= instead of =VALUE= sets a YAML subtree |
| =data edit [PATH] OP AT [k=v...]= | =data.edit= | =OP= (=insert=, =move=, =add_key=, =rename_key=, =remove=), =AT= | Status + =ok=. In =edit= the first positional is the file only when it contains a dot (op names never do) |
| =data undo\vert{}redo [PATH]= | =data.undo=, =data.redo= | | Status + =ok= (whether anything changed) |
| =data validate [PATH]= | =data.validate= | | ={ok, errors, issues}=; exit 1 when =errors= > 0 |
| =data save [PATH] [save_as=FILE]= | =data.save= | | Status + =ok= |
| =data reload [PATH]= | =data.reload= | | Status + =ok= (unsaved edits are discarded) |
| =data close [PATH] [--force]= | =data.close= | | ={closed}=; =false= while the unsaved prompt is up, =--force= discards |
| =data reveal [PATH] AT [line=N]= | =data.reveal= | =AT= | Status, after doing what clicking an issue does |

A headless editor (=lrgeditor --headless=, =lrgeditor --mcp= without a display) installs the same methods and runs the full document model, so every =data= command works there too (=make test-editorctl= drives them); only drawing the editor panels needs a window.

#+begin_src sh
lrgeditorctl data open data/input.yaml
lrgeditorctl data get /actions/jump/bindings/0
lrgeditorctl data set /actions/jump/bindings/0/key ENTER
lrgeditorctl data edit add_key /actions key=fire 'yaml={bindings: []}'
lrgeditorctl data edit rename_key /actions old=fire new=shoot
lrgeditorctl data validate && lrgeditorctl data save
lrgeditorctl data close --force
#+end_src

** 0.9.0 verbs
:PROPERTIES:
:CUSTOM_ID: verbs-0-9-0
:END:
The rendering tools of 0.9.0 (materials, user shaders, shader graphs, the level environment, post stacks, LOD preview, render layers and the debug view modes) have a verb family each. They follow the [[#verbs-0-8-1][0.8.1 convention]] with one addition: a family is a table of sub-commands whose positional arguments fill named parameters in order. File arguments (=PATH=, =DEST=) go through the same path rule (sent absolute when they exist relative to the current directory, else resolved by the editor against the project, which is what a file about to be created needs), value arguments (=VALUE=, =INDEX=, =FROM=, =TO=, =LEVEL=, =ENABLED=) are parsed like assignment values (JSON, numbers, =true= / =false=, =null=, =a,b,c= number vectors, and =on= / =off= as booleans), everything else is a string. =key=value= arguments are passed through as extra parameters, the result prints as YAML (=-o json= for JSON), and a wrong sub-command prints the family's usage and exits 2.

| Verb | Method | Notes |
|------+--------+-------|
| =material open PATH= | =material.open= | Opens the material editor tab |
| =material create PATH [parent=P] [shading_model=lit\vert{}unlit\vert{}custom] [shader=S]= | =material.create= | |
| =material variant PATH [DEST]= | =material.create_variant= | An instance whose parent is =PATH= |
| =material get PATH= | =material.get= | Every parameter, texture slot, uniform and the instance's =overrides= |
| =material set PATH KEY VALUE= | =material.set= | =KEY= is a =.rmat= key: =metallic=, =base_color= (=1,0.5,0.2,1=), =textures.albedo=, =uniforms.tint= ... |
| =material revert PATH KEY= | =material.revert= | Drops an instance's override |
| =material save PATH=, =material list= | =material.save=, =material.list= | |
| =material preview PATH [SHAPE] [rotate=BOOL]= | =material.preview= | =SHAPE=: =sphere=, =cube=, =plane= |
| =material assign NODE PATH [submesh=N]= | =material.assign= | Same as dropping the material on the node in the viewport (undoable) |
| =shader create PATH [lit=BOOL]= | =shader.create= | A =.rshader= with a fragment stub |
| =shader compile\vert{}diagnostics\vert{}uniforms\vert{}reload PATH= | =shader.*= | Compile needs a windowed editor (GL) |
| =shadergraph open\vert{}create\vert{}get\vert{}validate\vert{}glsl\vert{}save PATH= | =shadergraph.*= | =create= takes =master=pbr\vert{}unlit= |
| =shadergraph types= | =shadergraph.node_types= | The node library |
| =shadergraph add PATH TYPE [id=I] [x=X] [y=Y]= | =shadergraph.add_node= | |
| =shadergraph remove PATH ID= | =shadergraph.remove_node= | |
| =shadergraph connect PATH FROM FROM_PORT TO TO_PORT=, =shadergraph disconnect PATH TO TO_PORT= | =shadergraph.connect=, =shadergraph.disconnect= | |
| =shadergraph param PATH ID KEY VALUE=, =shadergraph input PATH ID PORT VALUE= | =shadergraph.set_param=, =shadergraph.set_input= | =VALUE= =null= clears an input constant |
| =env= or =env get= | =environment.get= | ={present, environment, baked, needs_bake}= |
| =env set KEY VALUE= | =environment.set= | =KEY= is a dotted path in the block (=fog.density=, =sky.source=, =sky.zenith=, =ibl.enabled=, =volumetric.steps=, =post_stack=); one undo step; =values={...}= sets several at once |
| =env reset= | =environment.reset= | Removes the block (undoable) |
| =env bake [--wait]= | =environment.bake= | Starts the IBL bake and probe capture (windowed editors). =--wait= polls =environment.progress= until it finishes (up to ten minutes, or =--timeout= seconds when longer) and exits 1 when the bake reports an error |
| =env progress=, =env show= | =environment.progress=, =environment.show= | |
| =post types= | =post.effect_types= | Effect types with their parameters |
| =post open\vert{}get\vert{}save\vert{}assign PATH= | =post.*= | =assign= makes the stack the level's =environment.post_stack= |
| =post create PATH [preset=default\vert{}empty]= | =post.create= | |
| =post add PATH TYPE [index=N]=, =post remove PATH INDEX=, =post move PATH FROM TO= | =post.add=, =post.remove=, =post.move= | |
| =post set PATH INDEX KEY VALUE= | =post.set= | =KEY= is =enabled=, =weight= or an effect parameter |
| =post preview [PATH] on\vert{}off= | =post.preview= | Live preview of a stack in the viewports, or back to the level's look |
| =post look PATH [viewport=N]= | =post.save_look= | "Save current look": what a viewport's post chain does now, as a =.rpost= |
| =lod get NODE= | =lod.get= | Levels with triangle counts, screen sizes and errors, the current and the forced level |
| =lod force NODE LEVEL= | =lod.force= | Preview only; =auto= (or =level=-1=) goes back to automatic selection. A bare =-1= would be read as an option, hence =auto= |
| =view layers [MASK]=, =view layers LAYER on\vert{}off= | =view.layers= | =MASK= is a number, =0x= hex, =all= or =none=; =LAYER= an index 0..31 or a layer name (=default=, =ui=, =editor-only=, =ignore-raycast=, =transparent-fx=, =water=, =sky=); =viewport=N= picks a viewport |
| =view render-mode MODE= (alias =view mode=) | =view.render_mode= | =MODE=: =lit=, =unlit=, =wireframe=, =normals=, =lighting-only= and the debug views =overdraw=, =uv=, =light-complexity=, =ao=, =reflections= |

lrgeditorctl post add looks/night.rpost vignette
lrgeditorctl post set looks/night.rpost 0 intensity 0.4
lrgeditorctl post assign looks/night.rpost
lrgeditorctl lod force Props/Statue 2; lrgeditorctl lod force Props/Statue auto
lrgeditorctl view layers 0x5 viewport=1

*** Lighting bake, sequences, 2D skeletons and animation (0.9.0)
:PROPERTIES:
:CUSTOM_ID: verbs-0-9-0-m34
:END:
The editor tools of the 0.9.0 M3/M4 wave have a family each, with the same conventions as above (positionals fill named parameters, =PATH= / =MODEL= go through the path rule, =~= values are typed, =key=value= passes extra parameters through). Every method and its parameters are in [[file:ipc-protocol.org][IPC Protocol]]: [[file:ipc-protocol.org::#ipc-bake][bake]], [[file:ipc-protocol.org::#sequence-methods][sequence]], and the skeleton, animation-graph, bone-map and clip sections of their editors ([[file:skeleton2d-editor.org][2D skeleton editor]], [[file:animation-editor.org][Animation editor]]).

| Verb | Method | Notes |

** MCP
:PROPERTIES:
:CUSTOM_ID: mcp
:END:
The editor's operations are MCP tools (mcp-glib), served two ways:

- =lrgeditorctl mcp [-s SESSION]= bridges to an editor that is already running. Each tool call finds the session again, so the bridge survives editor restarts and can be registered before any editor runs.
- =lrgeditor --mcp [PROJECT]= serves MCP from inside the editor. The editor keeps a private copy of stdout for the protocol and points fd 1 at stderr, so logs and libraries can never corrupt the stream; it runs headless without a display. A headless editor exits when the client disconnects unless the level has unsaved changes. The normal IPC socket stays up, so =lrgeditorctl= works alongside.
