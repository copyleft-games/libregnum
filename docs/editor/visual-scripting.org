* Visual Scripting in the Editor
:PROPERTIES:
:CUSTOM_ID: editor-visual-scripting
:END:
#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > Visual Scripting

=LrgEditorVscriptEditor= (=src/editor/ui/data/lrg-editor-vscript-editor.h=) edits an =LrgVscriptProgram= document. The format nick is =vscript= and the extension is =.rvscript=. The assets panel lists those files with the glyph =VS= and creates one from New Visual Script. Double-click opens the data editor. The program format itself is [[file:../modules/scripting/visual-scripting.org][Visual Scripting]].

=lrg_editor_vscript_editor_new()= takes the app and the document (construct-only properties =app= and =document=). =lrg_editor_vscript_editor_install()= registers the =vscript.*= IPC methods once per app. The assets panel calls it next to the other data-editor installs. =lrg_editor_vscript_editor_open()= opens or focuses the tab (transfer none) and returns =NULL= with =LRG_EDITOR_DOCUMENT_ERROR_WRONG_KIND= when the file is not a visual script. =lrg_editor_vscript_editor_create()= writes a starter program at =path= and refuses to overwrite. It does not open a tab and it does not take a name: the IPC method =vscript.create= applies =name= itself after the file exists. The starter is an =event.start= node wired to a =debug.log= whose text is =hello=.

=lrg_editor_vscript_editor_get_program()= is the program the editor last refreshed (transfer none). =lrg_editor_vscript_editor_get_canvas()= is the =LrgNodeGraph= and =lrg_editor_vscript_editor_get_blocks()= is the =LrgBlockEditor=. The content widget is one or the other, chosen by the program's =view=. Refresh rebuilds that widget from the document.

=lrg_editor_blocks_editor_new()= constructs the separate =LrgEditorBlocksEditor= =GObject=. That type is not a document editor and it is not registered as a format. The blocks view of a =.rvscript= is this visual-script editor with =view= set to blocks.

Undo, save and the dirty flag are the document's. Each IPC edit copies the program, changes the copy and commits it as one step (gesture 0). =data.undo= with the file's path reverts that step. =vscript.select= only changes which nodes are selected and is not a step.

** Editing with the mouse
:PROPERTIES:
:CUSTOM_ID: vscript-mouse
:END:

Since 0.9.2 the graph view is a two-way editor: what you do to the canvas is committed to the program.

- *Move* a card (or a selection) by dragging it. *Delete* cards or a selected wire with Delete. *Duplicate* with Ctrl+D: the copy keeps the original's kind, parameters and literals and gets a free id (=num= becomes =num2=). *Wire* by dragging from a pin to a pin; the drag only lands where the program's type rule allows it. Dragging onto a data input or out of an exec output that already has a wire replaces it, as the program does.
- *Add Node* in the toolbar opens the node picker (one submenu per category); the node lands at the centre of the view. Dropping a wire on empty canvas opens the same picker at the drop point, and the new node is wired to the pin the wire came from: the first pin on the other side that the program accepts, exec to exec first.
- The canvas does not write the program from inside its own signals. A change marks the canvas as ahead; an idle compares canvas and program (missing cards, moved cards, duplicated cards, the set of wires) and commits the difference as *one undo step* per gesture (a Delete over five cards and their wires is one step). A wire the program refuses is reported as an error toast and disappears when the canvas is rebuilt.
- Selection on the canvas is the editor's selection (=vscript.get= returns it) and is not an undo step.
- =lrg_editor_vscript_editor_add_node_at()= is the picker's action, =lrg_editor_vscript_editor_set_drop()= records a dropped wire, and =lrg_editor_vscript_editor_flush()= commits pending canvas edits immediately (tests and tools use it instead of waiting for the idle).

** IPC
:PROPERTIES:
:CUSTOM_ID: vscript-ipc
:END:

=path= is absolute or project-relative. When it is omitted the focused visual-script editor is used. A method that needs the file opens the tab. =graph= is a subgraph name; missing or =""= is the main graph. Mutating methods show that graph after the commit. =vscript.get= can read another graph without changing the one on screen. Pins are =node.pin=, split on the first dot.

Errors use the editor server nicks. =invalid-params= is a missing or bad parameter, a pin that is not =node.pin=, or a link the type checker rejects. =not-found= is a missing file, editor, node, variable, subgraph or comment. =failed= is a load, save or runtime error. =vscript.disconnect= of a link that is not there returns =removed: false= and does not commit.

| Method | Role |
|--------+------|
| =vscript.create= | write a starter; =view= =graph= or =blocks=; refuses to overwrite |
| =vscript.open= | open the file; an optional =view= is one undo step |
| =vscript.get= | snapshot: fields, variables, subgraphs, one graph's nodes, links, comments, selection, issues |
| =vscript.node_types= | catalogue rows; =query= is a case-sensitive substring of type, title or description; =category= is exact |
| =vscript.gi_search= | typelib search; =available= is false without a GI runtime; =limit= defaults to 50 |
| =vscript.add_node= | =type=, optional =id=, =x=, =y=, =params=, =inputs= |
| =vscript.remove_node= | drop a node and its links |
| =vscript.set_node= | position, params, inputs (null removes), optional =rename= |
| =vscript.connect= | =from= and =to= as =node.pin=; replaces a data input or an exec output |
| =vscript.disconnect= | the same pair; =removed= is a bool |
| =vscript.set_variable= | =name=, =type=, =default=; =remove: true= deletes it |
| =vscript.add_subgraph= | =name= plus optional =inputs= and =outputs= arrays of ={name, type}= |
| =vscript.remove_subgraph= | drop a named subgraph |
| =vscript.add_comment= | =text=, =x=, =y=; =width= defaults to 240 and =height= to 120 |
| =vscript.remove_comment= | by id |
| =vscript.set_program= | =name=, =description=, =seed=, =step_budget=, =fixed_step=; returns =vscript.get= |
| =vscript.select= | =nodes= is an array of ids; empty clears; not an undo step |
| =vscript.frame= | fits the shown graph in the canvas (Home); =selection: true= fits the selected nodes (F); =animate= glides; returns the target ={zoom, x, y}=; not an undo step (0.9.1) |
| =vscript.palette= | opens the Add Node picker under the toolbar chip, as clicking Add Node does; =category= (such as =Math=) opens that submenu too; =open: false= closes it; returns ={open, entries}= (the top-level rows); not an undo step (0.10.0) |
| =vscript.validate= | =ok= and =issues=; read-only |
| =vscript.run= | a copy: start, then =frames= updates (default 1, =dt= default 1/60), then an optional custom =event= with =args=; =variables= overlay the copy; =steps= sums each dispatch; =time= is completed frames times =dt=; =ok: false= is still a successful reply |

| =vscript.breakpoint= | =node= and =enabled=; stored for this path and applied to matching live instances; =graph= is ignored |
| =vscript.continue= | resumes paused instances; =resumed= is the count |

The shell verbs are the method tail with underscores turned into dashes: =lrgeditorctl vscript add-node math.add id=sum=. The full tables are generated into [[file:ipc-protocol.org][the IPC protocol]] and [[file:lrgeditorctl.org][lrgeditorctl]].

** What the views show
:PROPERTIES:
:CUSTOM_ID: views
:END:

The graph view clears the canvas and adds one node per program node, with a port per pin, then reconnects by pin name. Selection is reapplied after the rebuild.

- *Links.* The canvas asks the program's type rule before it draws a link (its =::can-connect= handler calls the same check =vscript.connect= uses): exec meets exec, =any= and =object= meet anything, =int= widens to =float=, everything else must match. Every link the program holds is therefore drawn. A link the canvas still refuses is logged as a warning naming both pins, never dropped silently. Before 0.9.1 the canvas used its default equal-type rule, so a =string= output into an =any= input (Concat into Log) was stored but not drawn.
- *Values.* A node with parameters or literal inputs shows them on one line under its pins. A =name= or =value= parameter is shown bare (Get Variable shows ="health"=, a Float shows =5=); other parameters are =key: value=; a literal input is =pin = value= and is hidden while a link feeds that pin. Strings are quoted. A line wider than the card ends in an ellipsis. A node with nothing to show has no value line.
- *Comment frames.* Each comment becomes a canvas note (=lrg_node_graph_add_note()=): a tinted rectangle in the comment's colour (the theme's selection colour when it has none) with the text along its top edge, drawn under the wires and the cards.
- *Framing.* The first time a graph is shown (opening the file, or switching to another subgraph) the canvas fits every node and comment frame. Later edits keep the view. Home and F in the canvas, and =vscript.frame= over IPC, fit again.

The blocks view clears its program, defines a block kind per catalogue kind it has not defined yet, and creates one block per node. Events are hat blocks. Pure logic and comparison nodes are boolean blocks. Other pure nodes are reporter blocks. Everything else is a statement. Comment frames are stored and returned by =vscript.get=; the graph view draws them, the blocks view does not.

A headless game that does not open the editor uses =LrgVscriptProgram= and =LrgScriptingGraph= directly. =examples/visual-script.c= is that program.
