* The libregnum Editor Application
:PROPERTIES:
:CUSTOM_ID: editor-app
:END:
#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > Editor Application
#+end_quote

=lrgeditor= is the libregnum editor: a level, scene and world editor in the spirit of the Unity, Godot and Unreal editors, built entirely from libregnum. Its UI is drawn by libregnum's own immediate-mode GUI toolkit (=LrgGuiContext=, =src/gui/=), its viewport renders with the engine's raylib backend, its documents are =LrgEditor= / =LrgLevel= and its play mode runs an =LrgWorld=. Code and data files open in your own editor (=$EDITOR= by default, with first-party Emacs integration), and every editor feature can be driven over a local socket.

The application lives in =src/editor/ui/= (=LrgEditorApp=, public header =lrg-editor-app.h=) and the program in =src/launcher/lrgeditor.c=.

** Building and running
:PROPERTIES:
:CUSTOM_ID: building
:END:
The editor is built by default (=BUILD_EDITOR=1=, =BUILD_EDITOR_UI=1= in =config.mk=):

#+begin_src sh
make -j"$(nproc)"                 # library, GIR, lrgldr and lrgeditor
make lrgeditor                   # just the editor program
make test-emacs                   # Emacs package byte-compile + ERT suite
make test-editor-x11              # real window + real X input (Xvfb, xdotool) checked over IPC
make BUILD_EDITOR_UI=0            # embedded hosts that bring their own UI
#+end_src

Fedora packages needed beyond the base libregnum build (fold these into the image build):

| Package                         | Why                                               |
|---------------------------------+---------------------------------------------------|
| =json-glib-devel=               | IPC server (=LrgEditorServer=)                    |
| =glib2-devel=                   | GIO sockets, file monitors, subprocesses          |
| =mesa-libGL-devel=, =libglvnd-devel= | raylib/OpenGL 3.3 viewport                   |
| =wayland-devel=, =libxkbcommon-devel=, =libX11-devel=, =libXrandr-devel=, =libXinerama-devel=, =libXcursor-devel=, =libXi-devel= | GLFW window backends (already required by graylib) |
| =google-noto-sans-fonts= or =dejavu-sans-fonts= (runtime) | UI font (searched at fixed paths; raylib's built-in font otherwise) |
| =emacs= (optional)              | =make test-emacs=, the first-party integration    |
| =xorg-x11-server-Xvfb=, =xdotool=, =socat=, =yq= (optional) | =make test-editor-x11= (real window, real input) |

Run it on a project folder or a level:

#+begin_src sh
lrgeditor ~/games/mygame                       # project folder
lrgeditor levels/arena.rlevel                  # a level; its folder is the root
lrgeditor -p ~/games/mygame -l levels/arena.rlevel
lrgeditor --new-project ~/games/newgame --name "New Game"
lrgeditor --editor emacsclient ~/games/mygame  # external editor for this session
lrgeditor --editor 'codium --goto {file}:{line}:{col}' .
lrgeditor --module build/libmygame.so .        # register the game's component types
lrgeditor --headless --socket /tmp/lrg.sock .  # IPC server only, no window
lrgeditor --mcp ~/games/mygame                # an AI agent drives it over MCP (stdio)
lrgeditor --validate levels/arena.rlevel       # CI: problems on stdout, status 1 on errors
#+end_src

| Option                   | Meaning                                                                   |
|--------------------------+---------------------------------------------------------------------------|
| =-p=, =--project DIR=    | Open a project (a folder with =project.ryaml=, or any folder)             |
| =-l=, =--level FILE=     | Open a level (relative to the project)                                    |
| =-n=, =--new-project DIR= | Create a project (levels/, scripts/, assets/, prefabs/, starter level)   |
| =--name NAME=            | Name for =--new-project=                                                  |
| =-s=, =--settings FILE=  | Preferences file (default =$XDG_CONFIG_HOME/libregnum/editor.yaml=)       |
| =-e=, =--editor EDITOR=  | External editor preset id, or a command template                          |
| =-m=, =--module SO=      | Load a game module so its component types can be edited and played        |
| =--socket PATH=          | IPC socket (default =$XDG_RUNTIME_DIR/libregnum/editor-PID.sock=)         |
| =--no-server=            | Do not start the IPC server                                               |
| =--headless=             | No window; serve IPC until SIGINT/SIGTERM or =editor.quit=                |
| =--mcp=                  | Serve MCP on stdin/stdout for an AI agent (headless without a display); see [[file:lrgeditorctl.org::#mcp][MCP]] |
| =--validate=             | Validate the level and exit                                               |
| =-W=, =-H=               | Initial window size                                                       |
| =--license=, =--version= | Print and exit                                                            |

With no project or level, the last project is reopened (=restore-last-session=).

** Window layout
:PROPERTIES:
:CUSTOM_ID: layout
:END:
#+begin_example
 File Edit Create Node View Play Tools Help
 [Select][Move][Rotate][Scale] [World][Snap] 1.00 m 15 deg 0.10  [3D]  [Play][Pause][Step][Stop] [Run Game]
+-----------+-------------------------------------+-------------+
| Hierarchy | Viewport                            | Inspector   |
|           |                                     | History     |
|           +-------------------------------------+             |
|           | Assets | Console | Problems         |             |
+-----------+-------------------------------------+-------------+
 main.rlevel *  status message             3 selected  12 nodes  0 errors  IPC emacs  60 fps

- *Menu bar*: every menu item is an action, showing its current shortcut and enabled/checked state. Alt + the first letter (Alt+F, Alt+E, Alt+C, Alt+N, Alt+V, Alt+P, Alt+T, Alt+H) opens a menu from the keyboard; Escape closes it.
- *Toolbar*: tools, space, snap with live-editable increments, 2D/3D, play controls, run game.
- *Status bar*: document and dirty marker, play state, a "changed on disk: Reload / Keep mine" prompt, the last status message, selection and node counts, log counters (click to open the console), IPC state ("emacs" when libregnum.el is connected), frame rate.
- *Toasts*: transient notifications in the bottom right (info, success, warning, error).

Panels can be closed (except the viewport), reopened from View > Panels, dragged by their tab onto another panel's edge or centre to split or tab them, and resized with the splitters. The layout is saved with the preferences.

** Viewport
:PROPERTIES:
:CUSTOM_ID: viewport
:END:
| Input                           | Action                                                         |
|---------------------------------+----------------------------------------------------------------|
| Drag the axis gizmo (bottom left) | Orbit; works with any mouse or touchpad                      |
| Click an end of the axis gizmo  | Look along that axis (orthographic until the next orbit)       |
| Right drag                      | Fly look; W A S D move, Q E down/up, Shift faster, wheel speed |
| Right click (no drag)           | Context menu: create, focus, delete, duplicate...              |
| Middle drag                     | Pan                                                            |
| Alt + left drag                 | Orbit around the focus point (Alt + Shift + left drag pans)    |
| Wheel, = / -, numpad + / -      | Zoom (dolly; ortho height in orthographic views)               |
| Num4 / Num6 / Num8 / Num2       | Orbit in 15 degree steps                                       |
| Num7 / Num1 / Num3 (+Ctrl)      | Top / front / right (opposite) views; Num5 toggles ortho       |
| Left click                      | Select (Shift add, Ctrl toggle); again on the same spot cycles |
| Left drag on empty space        | Box select (Shift adds)                                        |
| Left drag on the gizmo          | Move / rotate / scale; Ctrl inverts snapping; Esc/right cancels |
| Drop an asset                   | Model/texture: new node; prefab: instance; script: attach to the node under the pointer |

In 2D mode right and middle drag both pan and new nodes are created flat on the XY plane.

*Navigation schemes* (Preferences > Viewport > Navigation, =camera-navigation=): =default= is the table above; =blender= makes middle drag orbit, Shift + middle drag pan and Ctrl + middle drag zoom; =trackpad= makes two-finger scroll orbit, Shift + scroll pan and Ctrl + scroll zoom, for touchpads that cannot right- or middle-drag. The axis gizmo, the numpad and Alt + left drag work in every scheme. Orbiting out of an axis view returns to perspective (Blender's auto-perspective); an orthographic view chosen with Num5 stays orthographic.

Pointer movement made before a press never counts as part of the drag, so a press after a fast move does not snap the camera. A button or key held when the window loses focus is released (GLFW reports no releases while unfocused), so navigation cannot get stuck. Clicks and key chords faster than a frame (touchpad taps, xdotool) are latched by the input backend and never lost. Show Stats (View menu) adds a line with the pointer, buttons and modifiers as the editor sees them, the quickest way to diagnose an input device.

Rendering: primitives are unit-sized meshes matching the picking bounds (cube, spheres, plane, cylinder, cone, torus, disc, grid, 2D rectangle and circle), lit by a small GLSL 3.3 shader (flat colour fallback); mesh assets (glTF/OBJ/...) and sprite textures load on demand and are cached; missing assets show as magenta boxes and are reported once in the console. Lights, cameras, audio emitters and empty nodes draw as constant-size icons. Selection draws the bounds (primary brighter). The grid adapts to the zoom (=grid-size= times a power of ten, =grid-extent= cells each way) and shows the world axes. The gizmo is drawn in screen space from the same geometry its hit test uses. An overlay shows the view mode, stats (node count, selection, fps) and an orientation axis.

** Hierarchy, inspector, assets
:PROPERTIES:
:CUSTOM_ID: panels
:END:
- *Hierarchy*: tree with kind glyphs, visibility/lock toggles, inline rename (F2 or double click), drag to reparent (drop on a row) or reorder (drop between rows), Shift-click range and Ctrl-click toggle selection, filter by name or GUID (Ctrl+F), context menu (create submenu, copy GUID/path...), and the selection is revealed and scrolled to when it changes elsewhere.
- *Inspector*: name, flags, path, GUID; transform with world readout (edits apply to every selected node); visual kind, primitive, asset path (with picker and drop target), material colour/roughness/metallic/emission, custom parameters (number, text, bool, colour); components (add with a searchable list of registered types, edit properties with type-aware widgets, remove); scripts (new script from a template, attach existing, open in the external editor, enable, remove); prefab instances can open their prefab or be reverted to it. Drags merge into a single undo step.
- *Tiles* and *Timeline*: see [[file:editor-tools.org][Editor Tools]] (View > Panels; Tiles docks next to the inspector, Timeline next to Assets).
- *Assets*: breadcrumb navigation, list or grid view (with generated thumbnails, see [[file:editor-tools.org::#asset-thumbnails][Asset thumbnails]]), name filter and type filter, double click to open (levels and prefabs open in the editor, media in the desktop application, everything else in the external editor), drag into the viewport or the inspector, rename, move to the trash (never deleted), copy path, new folder, new script; refreshes itself through a file monitor.

** Console, history, problems
:PROPERTIES:
:CUSTOM_ID: console
:END:
The console shows every GLib log message (the editor installs a log writer), messages from the game when run with F6, and IPC activity. Filter by level and text, toggle auto-scroll, copy, clear. The input line (history with Up/Down) takes:

| Input                          | Effect                                                        |
|--------------------------------+---------------------------------------------------------------|
| =help=                         | List the commands and every IPC method                        |
| =clear=                        | Clear the log                                                 |
| =:ID=                          | Run an editor action, e.g. =:view.top=                        |
| =::= (or =:=)                  | List action ids                                               |
| =METHOD key=value ...=         | Call an IPC method, e.g. =node.find query=Door=, =node.rename node=Door name=Gate= |
| ={"method": ...}=              | A raw JSON request                                            |

The reply is printed in the console, so anything the IPC protocol can do is available from the console too.

The *History* panel lists undo steps (newest last) and the redo stack; clicking a row jumps there. *Problems* lists validation results for the open level (codes: =missing-guid=, =duplicate-guid=, =duplicate-name=, =unnamed=, =slash-in-name=, =non-finite-transform=, =zero-scale=, =missing-asset-ref=, =missing-asset=, =component-no-type=, =unknown-component=, =script-no-path=, =script-no-language=, =script-disabled=, =missing-script=); clicking one selects the node.

** Play in editor and running the game
:PROPERTIES:
:CUSTOM_ID: play
:END:
F5 starts play-in-editor: the level is materialised into a private =LrgWorld= with =lrg_level_instantiate()= (component descriptions resolved through the engine registry, script bindings as =LrgScriptComponent=), the world ticks every frame, and what the simulation moves is written back to the nodes so the viewport shows the game running. F7 pauses, F10 steps one frame, Shift+F5 (or F8) stops. Stopping restores the level exactly: edits made while playing are undone (and stay on the redo stack, so a change worth keeping is one Ctrl+Shift+Z away), transforms the simulation wrote are restored from a snapshot, and the document's dirty state is put back.

F6 runs the game as its own process. The command comes from the project (Project Settings > Run command), a template with ={project}=, ={level}= and ={module}= placeholders; the default is =lrgldr {module} -- --level {level}= with ={module}= the project's game output. The level is saved first, the template is split like a shell command before substitution (paths with spaces stay one argument), and the game's output streams into the console with warnings and errors highlighted. Shift+F6 stops it.

** Documents, autosave and live reload
:PROPERTIES:
:CUSTOM_ID: documents
:END:
- Unsaved work is never discarded silently: opening, creating, reloading or quitting asks Save / Don't Save / Cancel (=confirm-on-close=). Saving an untitled level goes through Save As and then carries on with what was asked.
- Autosave writes the open level every =autosave-interval= seconds while it has changes, into =<project>/.lrg-editor/autosave/<name>-<hash>.autosave= (next to the level without a project). Opening a level whose autosave is newer offers Restore / Discard (moves it to the trash) / Later.
- The open level file is watched. When it changes on disk (for example saved from Emacs) the editor reloads it if it has no unsaved changes (=reload-on-external-change=), keeping the selection by GUID; otherwise the status bar offers Reload / Keep mine.
- File > Import Scene reads a Blender-exported scene YAML into a new untitled level.

** Preferences (editor.yaml)
:PROPERTIES:
:CUSTOM_ID: preferences
:END:
Preferences are edited live in Edit > Preferences (Ctrl+,) and written when the dialog closes; "Edit editor.yaml" opens the file in your editor. The file is =$XDG_CONFIG_HOME/libregnum/editor.yaml= (override with =--settings= or =LRG_EDITOR_CONFIG=). Unknown keys are preserved, so a file written by a newer editor survives a round trip through an older one. Every key is a property of =LrgEditorSettings= under the same name.

*** Themes
:PROPERTIES:
:CUSTOM_ID: preferences-theme
:END:
=theme= takes one of three forms. An =LrgTheme= preset name (=midnight=, =daylight=, =catppuccin-mocha=, =catppuccin-latte=, =high-contrast=) selects that preset. A value with a directory separator or ending in =.yaml= / =.yml= is the path of a theme YAML file. The 0.8.0 names are still read: =mocha= resolves to =catppuccin-mocha=, =latte= to =catppuccin-latte=, and =macchiato= and =frappe= to the closest preset (=catppuccin-mocha=) unless their exact palettes ship as =data/editor/themes/<name>.yaml=. An unknown name falls back to =catppuccin-mocha=. The default value is still =mocha= so 0.8.0 reads the file back unchanged. ~lrg_editor_settings_get_theme_preset~ and ~lrg_editor_settings_get_theme_file~ do this resolution.

** Keybinding syntax
:PROPERTIES:
:CUSTOM_ID: keybindings
:END:
Since 0.8.1 shortcuts are GTK-style accelerators: zero or more modifiers in angle brackets followed by one key name. The 0.8.0 "Ctrl+Shift+S" syntax is still accepted wherever a shortcut comes in, so old =editor.yaml= files, scripts and embedders keep working.

*** Accelerators
:PROPERTIES:
:CUSTOM_ID: keybindings-accel
:END:
- Modifiers: =<Ctrl>= (also =<Control>=, =<Primary>=), =<Shift>=, =<Alt>=, =<Super>= (also =<Meta>=). The editor writes them in the order Ctrl, Alt, Shift, Super.
- Keys: letters in lower case (=<Shift>= is explicit: =<Ctrl><Shift>z=), digits, =F1= to =F12=, =KP_0= to =KP_9= and =KP_Add= / =KP_Subtract= / =KP_Multiply= / =KP_Divide= / =KP_Decimal= / =KP_Enter=, =Escape=, =Return=, =Tab=, =BackSpace=, =Delete=, =Insert=, =Home=, =End=, =Page_Up=, =Page_Down=, =Up=, =Down=, =Left=, =Right=, =space=, and punctuation by name: =minus=, =equal=, =plus= (the same key as =equal=), =comma=, =period=, =slash=, =backslash=, =semicolon=, =apostrophe=, =grave=, =bracketleft=, =bracketright=. The full list is in ~lrg_accel_parse~ ([[file:../modules/ui/actions.org][UI actions]]).
- Several alternatives go in one string separated by =|=, e.g. =<Ctrl><Shift>z|<Ctrl>y=; menus show the first.
- =""= unbinds an action; removing the key restores the default.

*** The 0.8.0 syntax
:PROPERTIES:
:CUSTOM_ID: keybindings-legacy
:END:
Strings like =Ctrl+Shift+2=, =Num7=, =Ctrl+,= or =Shift+F5|F8= are converted with ~lrg_editor_shortcut_to_accel~ when they are read: from =editor.yaml=, from ~lrg_editor_actions_add~ (the app's built-in defaults are still written this way) and from ~lrg_editor_actions_set_accels~. An alternative that already looks like an accelerator (it has a =<Modifier>= or is a bare accelerator key name such as =KP_7= or =comma=) passes through unchanged.

| 0.8.0                 | Accelerator              |
|-----------------------+--------------------------|
| =Ctrl+S=              | =<Ctrl>s=                |

| =Ctrl+Shift+2=        | =<Ctrl><Shift>2=         |

| =Meta+X= (0.8.0 Meta was Alt) | =<Alt>x=          |
| =Win+L= / =Logo+L=    | =<Super>l=               |

~lrg_editor_shortcut_to_accel~ is strict (one invalid alternative rejects the whole string, so a migration can drop it with a log line); bindings read from settings or defaults are lenient (an invalid alternative is dropped, the rest stay bound). ~lrg_editor_settings_get_keybinding~ returns the stored text as written; ~lrg_editor_settings_get_keybinding_accel~ returns it converted. The settings migration (=settings-version= 1 to 2) rewrites the stored values as accelerators.

*** Actions as a GActionGroup
:PROPERTIES:
:CUSTOM_ID: keybindings-gaction
:END:
=LrgEditorActions= implements =GActionGroup=. Every action is named by its id (=file.save=, =edit.select-all=; ids are letters, digits, =-= and =.=, checked with ~g_action_name_is_valid~ when registered), so with the registry inserted on a widget as group =editor= a menu item refers to =editor.file.save=. Actions are enabled when their enabled callback says so; toggles (actions with a checked callback, such as =view.grid=) have a boolean state, every other action is stateless, and none takes a parameter. Activating a toggle with a boolean target, or changing its state, runs it only when the value differs.

The callbacks are polled: ~lrg_editor_actions_refresh_state~ (called once per frame by the window) emits =action-enabled-changed= and =action-state-changed= only for actions whose value changed, and running an action refreshes right away.

| Function | Use |
|----------+-----|
| ~lrg_editor_actions_get_accels (actions, id)~ | Effective accelerators (user override or default), one per element |
| ~lrg_editor_actions_get_default_accels (actions, id)~ | Built-in accelerators |
| ~lrg_editor_actions_set_accels (actions, id, accels)~ | Override (written to =editor.yaml= when the registry has settings); an empty array unbinds, =NULL= restores the default |
| ~lrg_editor_actions_find_by_accel (actions, key, mods)~ | The enabled action bound to a =GrlKey= chord |
| =accels-changed= signal (detailed by id) | The effective accelerators of an action changed |
| ~lrg_editor_accel_to_label (accel)~ | Menu text: <Ctrl><Shift>z\vert{}<Ctrl>y becomes "Ctrl+Shift+Z, Ctrl+Y" |

The =LrgGuiKey= helpers of 0.8.0 (~lrg_editor_shortcut_parse~, ~lrg_editor_shortcut_format~, ~lrg_editor_actions_find_by_shortcut~, ~lrg_editor_actions_get_shortcut~, ~lrg_editor_actions_get_default_shortcut~) still work and are deprecated in =lrg-editor-shortcut-legacy.h= for one release. ~lrg_editor_actions_find_by_shortcut~ matches bindings in either syntax, and the two string getters return 0.8.0 text (as written, or converted from accelerators).

** Embedding and automation
:PROPERTIES:
:CUSTOM_ID: embedding
:END:
=LrgEditorApp= is public API (and introspectable), so tools can host the editor and extend it:

#+begin_src c
g_autoptr(LrgEditor)    editor = lrg_editor_new ();
g_autoptr(LrgEditorApp) app = lrg_editor_app_new (editor);

lrg_editor_app_load_settings (app, NULL, NULL);
lrg_editor_actions_add (lrg_editor_app_get_actions (app), "mytool.bake", "Bake Lighting",
                        "My Tool", "Ctrl+Alt+B", bake_cb, NULL, NULL, editor);
lrg_editor_server_register_method (lrg_editor_app_get_server (app), "mytool.bake",
                                   bake_method, editor, NULL);
lrg_editor_app_start_server (app, NULL, NULL);
return lrg_editor_app_run (app);
#+end_src

Custom actions appear in menus (via the palette), the keybinding editor and =action.run=. See =examples/editor-standalone.c=.

The app can also be driven without a window, one frame at a time, with =lrg_editor_app_frame()= and a synthetic =LrgGuiInput= -- this is how =tests/test-editor-app.c= exercises shortcuts, the palette, dialogs, play mode, saving and live reload. =lrg_editor_app_run_headless()= serves IPC only.

** Frame cost
:PROPERTIES:
:CUSTOM_ID: frame-cost
:END:
The editor redraws every frame, so panels avoid work proportional to the whole level or log when only a screenful is visible:

- *Pacing*: the window runs with vsync and caps at the largest whole fraction of the monitor's refresh rate that is at most 75 fps (60 on 60/120 Hz, 72 on 144 Hz, 55 on 165 Hz), so frames always span the same number of vblanks; a fixed 60 cap on a 144 Hz monitor alternated two- and three-vblank frames. Like games, the editor keeps its UI thread on a hybrid CPU's performance cores (=LRG_CPU_AFFINITY=none= to opt out) and bounds its frames in flight to 2 with graylib's frame sync (=grl_frame_sync_end_drawing()= in place of =EndDrawing()=; =LRG_MAX_FRAMES_IN_FLIGHT= overrides it, see [[file:../performance.org::#input-latency][input latency]]).

- *Console*: each log record is formatted (timestamp, level, domain), casefolded for the filter and measured once, when it first appears, into a row cache mirrored from the log ring; the filtered row list is extended incrementally and rebuilt only when the level toggles or the filter text change. Only the rows inside the scroll view are laid out; the rows above and below become one spacer each, of the same total height and of the widest row's width, so scrolling and the horizontal extent are unchanged. A row whose context menu is open keeps building it while it scrolls out of view. =LrgEditorLog= keeps running per-level tallies, so the console tab and status bar badges (=lrg_editor_log_count_level()=) do not walk the ring.
- *Hierarchy*: rows outside the tree's view submit only their tree node (keyed by GUID, so open state, layout, keyboard navigation order and a held row behave as before) and skip the toggles, label, measuring, drop targets and menu; the row being renamed, the one being revealed and one with an open context menu are always drawn in full. The node count (outliner header, status bar, viewport overlay) and the filter's match set are cached against a process-wide node tree serial (bumped when nodes are created, destroyed, re-parented, renamed or given a new GUID) and recomputed only when it or the filter text changes. =LrgEditorSelection= keeps a hash set beside its ordered array, so the per-row "is selected" test is constant time.
- *Viewport rendering*: the scene walk passes each node's world matrix down to its children (one local matrix composed per node instead of a walk back to the root), and icons take their position from it. Mesh and sprite assets are looked up by the node's asset string as written, one hash lookup per node per frame, with the absolute path built and the file loaded only on first use; that map is cleared when the project or level directory (what relative paths resolve against) changes. =grid-size= and =grid-extent= are re-read from the settings only after a =notify=.
