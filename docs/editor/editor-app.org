* The libregnum Editor Application
:PROPERTIES:
:CUSTOM_ID: editor-app
:END:
#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > Editor Application
#+end_quote

=lrgeditor= is the libregnum editor: a level, scene and world editor in the spirit of the Unity, Godot and Unreal editors, built entirely from libregnum. Since 0.8.1 its UI is drawn by libregnum's own retained UI toolkit (=LrgCanvas= and its widgets, =src/ui/=; 0.8.0 used the immediate-mode =src/gui/=, which stays in the engine), its viewport renders with the engine's raylib backend, its documents are =LrgEditor= / =LrgLevel= and its play mode runs an =LrgWorld=. Code and data files open in your own editor (=$EDITOR= by default, with first-party Emacs integration), and every editor feature can be driven over a local socket.

The application lives in =src/editor/ui/= (=LrgEditorApp=, public header =lrg-editor-app.h=) and the program in =src/launcher/lrgeditor.c=.

** Building and running
:PROPERTIES:
:CUSTOM_ID: building
:END:
The editor is built by default (=BUILD_EDITOR=1=, =BUILD_EDITOR_UI=1= in =config.mk=):

#+begin_src sh
make -j"$(nproc)"                 # library, GIR, lrgldr and lrgeditor
make lrgeditor                   # just the editor program
make test-emacs                   # Emacs package byte-compile + ERT suite
make test-editor-x11              # real window + real X input (Xvfb, xdotool) checked over IPC
make BUILD_EDITOR_UI=0            # embedded hosts that bring their own UI
#+end_src

Fedora packages needed beyond the base libregnum build (fold these into the image build):

| Package                         | Why                                               |
|---------------------------------+---------------------------------------------------|
| =json-glib-devel=               | IPC server (=LrgEditorServer=)                    |
| =glib2-devel=                   | GIO sockets, file monitors, subprocesses          |
| =mesa-libGL-devel=, =libglvnd-devel= | raylib/OpenGL 3.3 viewport                   |
| =wayland-devel=, =libxkbcommon-devel=, =libX11-devel=, =libXrandr-devel=, =libXinerama-devel=, =libXcursor-devel=, =libXi-devel= | GLFW window backends (already required by graylib) |
| =google-noto-sans-fonts= or =dejavu-sans-fonts= (runtime) | UI font (searched at fixed paths; raylib's built-in font otherwise) |
| =emacs= (optional)              | =make test-emacs=, the first-party integration    |
| =xorg-x11-server-Xvfb=, =xdotool=, =socat=, =yq= (optional) | =make test-editor-x11= (real window, real input) |

Run it on a project folder or a level:

#+begin_src sh
lrgeditor ~/games/mygame                       # project folder
lrgeditor levels/arena.rlevel                  # a level; its folder is the root
lrgeditor -p ~/games/mygame -l levels/arena.rlevel
lrgeditor --new-project ~/games/newgame --name "New Game"
lrgeditor --editor emacsclient ~/games/mygame  # external editor for this session
lrgeditor --editor 'codium --goto {file}:{line}:{col}' .
lrgeditor --module build/libmygame.so .        # register the game's component types
lrgeditor --headless --socket /tmp/lrg.sock .  # IPC server only, no window
lrgeditor --mcp ~/games/mygame                # an AI agent drives it over MCP (stdio)
lrgeditor --validate levels/arena.rlevel       # CI: problems on stdout, status 1 on errors
#+end_src

| Option                   | Meaning                                                                   |
|--------------------------+---------------------------------------------------------------------------|
| =-p=, =--project DIR=    | Open a project (a folder with =project.ryaml=, or any folder)             |
| =-l=, =--level FILE=     | Open a level (relative to the project)                                    |
| =-n=, =--new-project DIR= | Create a project (levels/, scripts/, assets/, prefabs/, starter level)   |
| =--name NAME=            | Name for =--new-project=                                                  |
| =-s=, =--settings FILE=  | Preferences file (default =$XDG_CONFIG_HOME/libregnum/editor.yaml=)       |
| =-e=, =--editor EDITOR=  | External editor preset id, or a command template                          |
| =-m=, =--module SO=      | Load a game module so its component types can be edited and played        |
| =--socket PATH=          | IPC socket (default =$XDG_RUNTIME_DIR/libregnum/editor-PID.sock=)         |
| =--no-server=            | Do not start the IPC server                                               |
| =--headless=             | No window; serve IPC until SIGINT/SIGTERM or =editor.quit=                |
| =--mcp=                  | Serve MCP on stdin/stdout for an AI agent (headless without a display); see [[file:lrgeditorctl.org::#mcp][MCP]] |
| =--validate=             | Validate the level and exit                                               |
| =-W=, =-H=               | Initial window size                                                       |
| =--license=, =--version= | Print and exit                                                            |

With no project or level, the last project is reopened (=restore-last-session=).

- *Menu bar*: every menu item is an action, showing its current shortcut and enabled/checked state. Alt + the first letter (Alt+F, Alt+E, Alt+C, Alt+N, Alt+V, Alt+P, Alt+T, Alt+H) opens a menu from the keyboard; Escape closes it.
- *Toolbar*: tools, space, snap with spin boxes for the increments, 2D/3D, play controls, run game, and the viewport layout picker (=single=, =split-h=, =split-v=, =quad=, see [[#editor-viewport-layouts][Layouts and the active viewport]]).
- *Status bar*: document and dirty marker, play state, a "changed on disk: Reload / Keep mine" prompt, the last status message, selection and node counts, log counters (click to open the console), IPC state ("emacs" when libregnum.el is connected), frame rate.
- *Toasts*: transient notifications in the bottom right (info, success, warning, error).

Panels can be closed (except the viewport), reopened from View > Panels, dragged by their tab onto another panel's edge or centre to split or tab them, and resized with the splitters. The layout (=LrgDockArea= YAML under =ui-layout=) is saved with the preferences; View > Reset Layout restores the default (viewport in the centre, hierarchy left, inspector and tiles right, assets, console, problems, history, timeline, profiler and code tabbed below).

** Viewport
:PROPERTIES:
:CUSTOM_ID: viewport
:END:
| Input                           | Action                                                         |
|---------------------------------+----------------------------------------------------------------|
| Drag the axis gizmo (bottom left) | Orbit; works with any mouse or touchpad                      |
| Click an end of the axis gizmo  | Look along that axis (orthographic until the next orbit)       |
| Right drag                      | Fly look; W A S D move, Q E down/up, Shift faster, wheel speed |
| Right click (no drag)           | Context menu: create, focus, delete, duplicate...              |
| Middle drag                     | Pan                                                            |
| Alt + left drag                 | Orbit around the focus point (Alt + Shift + left drag pans)    |
| Wheel, = / -, numpad + / -      | Zoom (dolly; ortho height in orthographic views)               |
| Num4 / Num6 / Num8 / Num2       | Orbit in 15 degree steps                                       |
| Num7 / Num1 / Num3 (+Ctrl)      | Top / front / right (opposite) views; Num5 toggles ortho       |
| Left click                      | Select (Shift add, Ctrl toggle); again on the same spot cycles |
| Left drag on empty space        | Box select (Shift adds)                                        |
| Left drag on the gizmo          | Move / rotate / scale; Ctrl inverts snapping; Esc/right cancels |
| Drop an asset                   | Model/texture: new node; prefab: instance; script: attach to the node under the pointer |

In 2D mode right and middle drag both pan and new nodes are created flat on the XY plane.

*Navigation schemes* (Preferences > Viewport > Navigation, =camera-navigation=): =default= is the table above; =blender= makes middle drag orbit, Shift + middle drag pan and Ctrl + middle drag zoom; =trackpad= makes two-finger scroll orbit, Shift + scroll pan and Ctrl + scroll zoom, for touchpads that cannot right- or middle-drag. The axis gizmo, the numpad and Alt + left drag work in every scheme. Orbiting out of an axis view returns to perspective (Blender's auto-perspective); an orthographic view chosen with Num5 stays orthographic.

Pointer movement made before a press never counts as part of the drag, so a press after a fast move does not snap the camera. A button or key held when the window loses focus is released (GLFW reports no releases while unfocused), so navigation cannot get stuck. Clicks and key chords faster than a frame (touchpad taps, xdotool) are latched by the input backend and never lost. Show Stats (View menu) adds a line with the pointer, buttons and modifiers as the editor sees them, the quickest way to diagnose an input device.

Rendering: primitives are unit-sized meshes matching the picking bounds (cube, spheres, plane, cylinder, cone, torus, disc, grid, 2D rectangle and circle), lit by a small GLSL 3.3 shader (flat colour fallback); mesh assets (glTF/OBJ/...) and sprite textures load on demand and are cached; missing assets show as magenta boxes and are reported once in the console. Lights, cameras, audio emitters and empty nodes draw as constant-size icons. Selection draws the bounds (primary brighter). The grid adapts to the zoom (=grid-size= times a power of ten, =grid-extent= cells each way) and shows the world axes. The gizmo is drawn in screen space from the same geometry its hit test uses. An overlay shows the view mode, stats (node count, selection, fps) and an orientation axis.

** Hierarchy, inspector, assets
:PROPERTIES:
:CUSTOM_ID: panels
:END:
- *Hierarchy*: tree with kind glyphs, visibility/lock toggles, inline rename (F2 or double click), drag to reparent (drop on a row) or reorder (drop between rows), Shift-click range and Ctrl-click toggle selection, filter by name or GUID (Ctrl+F), context menu (create submenu, copy GUID/path...), and the selection is revealed and scrolled to when it changes elsewhere.
- *Inspector*: name, flags, path, GUID; transform with world readout (edits apply to every selected node); visual kind, primitive, asset path (with picker and drop target), material colour/roughness/metallic/emission, custom parameters (number, text, bool, colour); components (add with a searchable list of registered types, edit properties with type-aware widgets, remove); scripts (new script from a template, attach existing, open in the external editor, enable, remove); prefab instances can open their prefab or be reverted to it. Drags merge into a single undo step.
- *Tiles* and *Timeline*: see [[file:editor-tools.org][Editor Tools]] (View > Panels; Tiles docks next to the inspector, Timeline next to Assets).
- *Sources* (0.8.3): the asset sources registered by game modules (assets that are not project files, such as models in game archives): browse, filter or search, preview through a cached export, Import into =assets/<source>/=, Place in the scene, Export to a folder. See [[file:asset-sources.org][Asset Sources]].
- *Assets*: breadcrumb navigation, list or grid view (with generated thumbnails, see [[file:editor-tools.org::#asset-thumbnails][Asset thumbnails]]), name filter and type filter, double click to open (levels and prefabs open in the editor, media in the desktop application, everything else in the external editor), drag into the viewport or the inspector, rename, move to the trash (never deleted), copy path, new folder, new script; refreshes itself through a file monitor.

** Console, history, problems
:PROPERTIES:
:CUSTOM_ID: console
:END:
The console shows every GLib log message (the editor installs a log writer), messages from the game when run with F6, and IPC activity. Filter by level and text, toggle auto-scroll, copy, clear. The input line (history with Up/Down) takes:

| Input                          | Effect                                                        |
|--------------------------------+---------------------------------------------------------------|
| =help=                         | List the commands and every IPC method                        |
| =clear=                        | Clear the log                                                 |
| =:ID=                          | Run an editor action, e.g. =:view.top=                        |
| =::= (or =:=)                  | List action ids                                               |
| =METHOD key=value ...=         | Call an IPC method, e.g. =node.find query=Door=, =node.rename node=Door name=Gate= |
| ={"method": ...}=              | A raw JSON request                                            |

The reply is printed in the console, so anything the IPC protocol can do is available from the console too.

The *History* panel lists undo steps (newest last) and the redo stack; clicking a row jumps there. *Problems* lists validation results for the open level (codes: =missing-guid=, =duplicate-guid=, =duplicate-name=, =unnamed=, =slash-in-name=, =non-finite-transform=, =zero-scale=, =missing-asset-ref=, =missing-asset=, =component-no-type=, =unknown-component=, =script-no-path=, =script-no-language=, =script-disabled=, =missing-script=); clicking one selects the node.

** Play in editor and running the game
:PROPERTIES:
:CUSTOM_ID: play
:END:
F5 starts play-in-editor: the level is materialised into a private =LrgWorld= with =lrg_level_instantiate()= (component descriptions resolved through the engine registry, script bindings as =LrgScriptComponent=), the world ticks every frame, and what the simulation moves is written back to the nodes so the viewport shows the game running. F7 pauses, F10 steps one frame, Shift+F5 (or F8) stops. Stopping restores the level exactly: edits made while playing are undone (and stay on the redo stack, so a change worth keeping is one Ctrl+Shift+Z away), transforms the simulation wrote are restored from a snapshot, and the document's dirty state is put back.

F6 runs the game as its own process. The command comes from the project (Project Settings > Run command), a template with ={project}=, ={level}= and ={module}= placeholders; the default is =lrgldr {module} -- --level {level}= with ={module}= the project's game output. The level is saved first, the template is split like a shell command before substitution (paths with spaces stay one argument), and the game's output streams into the console with warnings and errors highlighted. Shift+F6 stops it.

** Documents, autosave and live reload
:PROPERTIES:
:CUSTOM_ID: documents
:END:
- Unsaved work is never discarded silently: opening, creating, reloading or quitting asks Save / Don't Save / Cancel (=confirm-on-close=). Saving an untitled level goes through Save As and then carries on with what was asked.
- Autosave writes the open level every =autosave-interval= seconds while it has changes, into =<project>/.lrg-editor/autosave/<name>-<hash>.autosave= (next to the level without a project). Opening a level whose autosave is newer offers Restore / Discard (moves it to the trash) / Later.
- The open level file is watched. When it changes on disk (for example saved from Emacs) the editor reloads it if it has no unsaved changes (=reload-on-external-change=), keeping the selection by GUID; otherwise the status bar offers Reload / Keep mine.
- File > Import Scene reads a Blender-exported scene YAML into a new untitled level.

** Preferences (editor.yaml)
:PROPERTIES:
:CUSTOM_ID: preferences
:END:
Preferences are edited live in Edit > Preferences (Ctrl+,) and written when the dialog closes; "Edit editor.yaml" opens the file in your editor. The file is =$XDG_CONFIG_HOME/libregnum/editor.yaml= (override with =--settings= or =LRG_EDITOR_CONFIG=). Unknown keys are preserved, so a file written by a newer editor survives a round trip through an older one. Every key is a property of =LrgEditorSettings= under the same name.

*** Themes
:PROPERTIES:
:CUSTOM_ID: preferences-theme
:END:
=theme= takes one of three forms. An =LrgTheme= preset name (=midnight=, =daylight=, =catppuccin-mocha=, =catppuccin-latte=, =high-contrast=) selects that preset. A value with a directory separator or ending in =.yaml= / =.yml= is the path of a theme YAML file. The 0.8.0 names are still read: =mocha= resolves to =catppuccin-mocha=, =latte= to =catppuccin-latte=, and =macchiato= and =frappe= to the shipped theme files =data/editor/themes/catppuccin-macchiato.yaml= and =catppuccin-frappe.yaml= (the settings migration rewrites them to those names, see [[#settings-migration][Settings migration]]; without the files they fall back to =catppuccin-mocha=). An unknown name falls back to =catppuccin-mocha=. The default value is still =mocha= so 0.8.0 reads the file back unchanged. ~lrg_editor_settings_get_theme_preset~ and ~lrg_editor_settings_get_theme_file~ do this resolution; the app builds its =LrgTheme= from the file when there is one (=lrg_theme_new_from_file()=), else from the preset, and scales every theme metric by =ui-scale= x =font-size= / 16. Changing =theme=, =ui-scale= or =font-size= applies live.

** Keybinding syntax
:PROPERTIES:
:CUSTOM_ID: keybindings
:END:
Since 0.8.1 shortcuts are GTK-style accelerators: zero or more modifiers in angle brackets followed by one key name. The 0.8.0 "Ctrl+Shift+S" syntax is still accepted wherever a shortcut comes in, so old =editor.yaml= files, scripts and embedders keep working.

*** Accelerators
:PROPERTIES:
:CUSTOM_ID: keybindings-accel
:END:
- Modifiers: =<Ctrl>= (also =<Control>=, =<Primary>=), =<Shift>=, =<Alt>=, =<Super>= (also =<Meta>=). The editor writes them in the order Ctrl, Alt, Shift, Super.
- Keys: letters in lower case (=<Shift>= is explicit: =<Ctrl><Shift>z=), digits, =F1= to =F12=, =KP_0= to =KP_9= and =KP_Add= / =KP_Subtract= / =KP_Multiply= / =KP_Divide= / =KP_Decimal= / =KP_Enter=, =Escape=, =Return=, =Tab=, =BackSpace=, =Delete=, =Insert=, =Home=, =End=, =Page_Up=, =Page_Down=, =Up=, =Down=, =Left=, =Right=, =space=, and punctuation by name: =minus=, =equal=, =plus= (the same key as =equal=), =comma=, =period=, =slash=, =backslash=, =semicolon=, =apostrophe=, =grave=, =bracketleft=, =bracketright=. The full list is in ~lrg_accel_parse~ ([[file:../modules/ui/actions.org][UI actions]]).
- Several alternatives go in one string separated by =|=, e.g. =<Ctrl><Shift>z|<Ctrl>y=; menus show the first.
- =""= unbinds an action; removing the key restores the default.

*** The 0.8.0 syntax
:PROPERTIES:
:CUSTOM_ID: keybindings-legacy
:END:
Strings like =Ctrl+Shift+2=, =Num7=, =Ctrl+,= or =Shift+F5|F8= are converted with ~lrg_editor_shortcut_to_accel~ when they are read: from =editor.yaml=, from ~lrg_editor_actions_add~ (the app's built-in defaults are still written this way) and from ~lrg_editor_actions_set_accels~. An alternative that already looks like an accelerator (it has a =<Modifier>= or is a bare accelerator key name such as =KP_7= or =comma=) passes through unchanged.

| 0.8.0                 | Accelerator              |
|-----------------------+--------------------------|
| =Ctrl+S=              | =<Ctrl>s=                |
| Ctrl+Shift+Z\vert{}Ctrl+Y | <Ctrl><Shift>z\vert{}<Ctrl>y |
| =Ctrl+Shift+2=        | =<Ctrl><Shift>2=         |
| =Num7=, =Ctrl+Num7=   | =KP_7=, =<Ctrl>KP_7=     |
| =Ctrl+,= / =Ctrl+/=   | =<Ctrl>comma= / =<Ctrl>slash= |
| === / =-= / =Ctrl++=  | =equal= / =minus= / =<Ctrl>plus= |
| =[= / =]=             | =bracketleft= / =bracketright= |
| =PageUp= / =Backspace= / =Enter= / =Esc= / =Del= | =Page_Up= / =BackSpace= / =Return= / =Escape= / =Delete= |
| =Alt+Up=, =Shift+F5=  | =<Alt>Up=, =<Shift>F5=   |
| =Meta+X= (0.8.0 Meta was Alt) | =<Alt>x=          |
| =Win+L= / =Logo+L=    | =<Super>l=               |

~lrg_editor_shortcut_to_accel~ is strict (one invalid alternative rejects the whole string, so a migration can drop it with a log line); bindings read from settings or defaults are lenient (an invalid alternative is dropped, the rest stay bound). ~lrg_editor_settings_get_keybinding~ returns the stored text as written; ~lrg_editor_settings_get_keybinding_accel~ returns it converted. The settings migration (=settings-version= 1 to 2) rewrites the stored values as accelerators.

*** Actions as a GActionGroup
:PROPERTIES:
:CUSTOM_ID: keybindings-gaction
:END:
=LrgEditorActions= implements =GActionGroup=. Every action is named by its id (=file.save=, =edit.select-all=; ids are letters, digits, =-= and =.=, checked with ~g_action_name_is_valid~ when registered), so with the registry inserted on a widget as group =editor= a menu item refers to =editor.file.save=. Actions are enabled when their enabled callback says so; toggles (actions with a checked callback, such as =view.grid=) have a boolean state, every other action is stateless, and none takes a parameter. Activating a toggle with a boolean target, or changing its state, runs it only when the value differs.

The callbacks are polled: ~lrg_editor_actions_refresh_state~ (called once per frame by the window) emits =action-enabled-changed= and =action-state-changed= only for actions whose value changed, and running an action refreshes right away.

| Function | Use |
|----------+-----|
| ~lrg_editor_actions_get_accels (actions, id)~ | Effective accelerators (user override or default), one per element |
| ~lrg_editor_actions_get_default_accels (actions, id)~ | Built-in accelerators |
| ~lrg_editor_actions_set_accels (actions, id, accels)~ | Override (written to =editor.yaml= when the registry has settings); an empty array unbinds, =NULL= restores the default |
| ~lrg_editor_actions_find_by_accel (actions, key, mods)~ | The enabled action bound to a =GrlKey= chord |
| =accels-changed= signal (detailed by id) | The effective accelerators of an action changed |
| ~lrg_editor_accel_to_label (accel)~ | Menu text: <Ctrl><Shift>z\vert{}<Ctrl>y becomes "Ctrl+Shift+Z, Ctrl+Y" |

The =LrgGuiKey= helpers of 0.8.0 (~lrg_editor_shortcut_parse~, ~lrg_editor_shortcut_format~, ~lrg_editor_actions_find_by_shortcut~, ~lrg_editor_actions_get_shortcut~, ~lrg_editor_actions_get_default_shortcut~) still work and are deprecated in =lrg-editor-shortcut-legacy.h= for one release. ~lrg_editor_actions_find_by_shortcut~ matches bindings in either syntax, and the two string getters return 0.8.0 text (as written, or converted from accelerators).

** Architecture
:PROPERTIES:
:CUSTOM_ID: architecture

*** The frame
:PROPERTIES:
:CUSTOM_ID: architecture-frame
:END:
=lrg_editor_app_run()= opens the window and loops: drain the GLib main context (IPC, file monitors, file dialogs, the game process), poll an =LrgCanvasInput= from raylib (=lrg_canvas_input_poll()=, plus a GLFW latch so presses and chords shorter than a frame are not lost), =lrg_editor_app_process_frame()=, then =BeginDrawing()=, =lrg_canvas_render()=, the pending window screenshot and =EndDrawing()= (through graylib's frame sync).

=lrg_editor_app_process_frame (app, input, width, height)= is the whole per-frame logic and needs no window:

1. Size the canvas, window and toast overlay; take the "editor" action group off the canvas while a modal dialog is open (so shortcuts cannot fire behind it).
2. =editor_window_refresh()=: =lrg_editor_actions_refresh_state()= (menus follow enabled / checked states), re-register canvas shortcuts when bindings changed, copy the model into the toolbar and status bar.
3. Lay out, then =lrg_canvas_process_input()=: shortcuts, menus, dialogs and the viewport get the input; the canvas clock advances (springs, the viewport's render into its texture).
4. Tick navigation (held fly keys), the play session, timeline playback, thumbnails, autosave and the debounced validation; update the window title.
5. Headless (no window), record the canvas so popups and widgets are laid out for =ui.state=.

=lrg_editor_app_run_headless()= runs step 4 every 100 ms from a GLib timeout instead.

*** Actions, menus and shortcuts
:PROPERTIES:
:CUSTOM_ID: architecture-actions
:END:
=LrgEditorActions= is a plain =GActionGroup=; =LrgMenu= looks actions up with =lrg_widget_lookup_action()=, which needs a =GActionMap=. The window therefore mirrors the registry into a =GSimpleActionGroup= inserted as =editor= (boolean-stateful actions for toggles), kept in step through the registry's =action-added= / =-removed= / =-enabled-changed= / =-state-changed= signals; activating a mirror action runs the registry action. A second group, =win=, holds what has no registry action: =win.open-recent-level= / =win.open-recent-project= (string target), =win.create= (node kind: =empty cube sphere plane cylinder cone torus rectangle circle light camera audio sprite mesh tilemap=) and =win.panel-<id>= (boolean, View > Panels).

The menu bar's =GMenuModel= (=lrg_editor_window_get_menu_model()=) has the 0.8.0 menus in the 0.8.0 order and contents, with mnemonics (=_File=), so Alt+F, Alt+E, Alt+C, Alt+N, Alt+V, Alt+P, Alt+T and Alt+H open them. Every accelerator of every action is registered with =lrg_canvas_add_shortcut()= on =editor.<id>=, and re-registered on =accels-changed=. The canvas offers a key to the focused widget first (a text field keeps Ctrl+C), then to shortcuts, then to the menu bar's mnemonics. The viewport consumes W A S D Q E only while flying.

*** The viewport
:PROPERTIES:
:CUSTOM_ID: architecture-viewport
:END:
=LrgEditorViewportPanel= holds an =LrgViewport= in =LRG_VIEWPORT_MODE_RENDER= whose render function hands its texture to =LrgEditorSceneRenderer= (grid, nodes, icons, selection bounds, transform gizmo, orientation axes, box-select rectangle and overlay text; the same look as 0.8.0). Input follows the view model's "Wave 3 wiring": a press goes to tile painting (paint mode on a tilemap), then =lrg_editor_viewport_nav_pointer_press()=, then the transform gizmo, else =lrg_editor_viewport_nav_press_empty()=; the navigator's =click= picks (with cycling through overlapping nodes), =box-select= selects and =context-menu= opens the viewport menu. *** Scene renderer
:PROPERTIES:
:CUSTOM_ID: scene-renderer
:END:
=LrgEditorSceneRenderer= draws what an editor viewport shows. Since 0.9.0 every pixel of scene geometry goes through the engine's shared renderer, =LrgWorld3DRenderer= ([[file:../modules/world3d/renderer.org][page]]), so the viewport and a game draw the same scene the same way; the editor renderer keeps only what an editor alone shows (grid, icons, selection bounds, tilemap grids, placeholders and the 2D overlays), with fixed Catppuccin Mocha colours. Create one per editor with =lrg_editor_scene_renderer_new (editor)= and bind its inputs: =set_settings()= (=grid-size= and =grid-extent=, re-read on notify), =set_base_dir()= (what relative asset paths resolve against; forwarded to the runtime renderer, which forgets its per-asset lookups), =set_gizmo()=, =set_playing()= (darker background during play) and =set_play_session()= (the play session whose 3D world is drawn while playing). =get_runtime_renderer()= returns the shared renderer (its caches, light set, shadow renderer and sky dome are the viewport's).

Call =lrg_editor_scene_renderer_render (renderer, view_state, viewport, nav, active, width, height)= from an =LrgViewport= render callback, inside =BeginTextureMode()= on a =width= x =height= target; it clears the target itself. =viewport= is the camera index (-1 for the active one). One render:

1. converts the camera's =LrgEditorView= into an =LrgWorld3DView= (same matrices, so picking and the image agree), the render mode into =LrgWorld3DRenderMode= (the values are equal) and the overlays into =LrgWorld3DRenderFlags=: /Shadows/ and /Sky/ in perspective, non-2D views, /Post Processing/ with the viewport's own =LrgPostProcessor= (=get_post_processor (slot)=);
2. while the play session runs a 3D level (=lrg_editor_play_session_get_world3d()= returns a world), draws that world with =lrg_world3d_renderer_render_view()= and the world's own lights: play-in-editor shows exactly what the game draws;
3. otherwise walks the level once, turning each visible node into a render item (primitives; mesh assets as models from the runtime cache; sprites as textured quads keeping the image's aspect ratio; CAD parts as orange cubes; translucent materials into the transparent pass; grids, 2D shapes and sprites cast no shadows) and, with /Scene Lighting/, each LIGHT node into an =LrgLight3DDesc=, then draws the sorted list with =lrg_world3d_renderer_render_list()=;
4. draws the grid from the runtime renderer's =draw-background= hook and, per node, tilemap grids (rlgl quads, layer by layer), missing-asset and prefab placeholders, icons (/Icons/) and selection bounds from its =draw-overlay= hook (in wire mode for the wireframe mode, as before);
5. draws the 2D pass when =get_draw_overlays()= is on: the transform gizmo (only when =active=, overlay /Gizmos/), the orientation axes and box-select rectangle from =nav= (nullable, so they match its hit testing), the view label and, with /Stats/, the counts.

While the play world is drawn the node overlays (icons, bounds, tilemap grids) are left out: the play entities are not the authoring nodes. =get_drawn()= returns the draw calls of the last render (the runtime renderer's, shadow casters included, plus tilemap layers). =render_view()= renders through an arbitrary camera (the camera preview).

GPU resources live in the runtime renderer and are created on the first render; =render()= returns =FALSE= and draws nothing without a window. =forget_asset (abs_path)= drops one cached model or texture (live reload); =get_generation()= adds the runtime renderer's generation (assets, base directory) to the grid-settings counter. =release()= frees all GPU resources (the runtime renderer's, the thumbnail shader, and replaces the post processors) and must be called before =CloseWindow()=. =render_model_thumbnail()= and =render_font_thumbnail()= return a size x size =GrlImage= for the thumbnail cache's GPU hooks (models lit by their own copy of the fallback =lit.fs= shader; font samples "Aa Bb 123" at the size and code points of the font's =.meta= sidecar); they run outside any texture mode.

*** Projects, assets and version control
:PROPERTIES:
:CUSTOM_ID: architecture-projects

*** Migrating from LrgGui embedding
:PROPERTIES:
:CUSTOM_ID: embedding-migration
:END:
Code that drove the 0.8.0 editor with =lrg_editor_app_frame()= and an =LrgGuiInput= keeps compiling (with a deprecation warning) and working: the frame is translated into an =LrgCanvasInput= by =lrg_editor_gui_input_to_canvas()=. Button presses and releases are found by comparing with the previous call's buttons, key releases by comparing =key_down= arrays (so release a held key by clearing its =key_down= entry), key presses, repeats, typed text, the wheel and the modifiers are copied, and =LrgGuiKey= values are mapped to =GrlKey=. To move over:

- Build an =LrgCanvasInput= yourself (=lrg_canvas_input_init()=, set =pointer_x/y=, =buttons_down= / =buttons_pressed= / =buttons_released= with =LRG_CANVAS_BUTTON_MASK()=, =lrg_canvas_input_add_key()=, =lrg_canvas_input_add_key_release()=, =lrg_canvas_input_add_text()=, =modifiers=, =delta_time=) and call =lrg_editor_app_process_frame()=; or poll it from raylib with =lrg_canvas_input_poll()=.
- Drawing: =lrg_canvas_render (lrg_editor_app_get_canvas (app))= between =BeginDrawing()= and =EndDrawing()= replaces rendering the GUI draw list.
- =lrg_editor_app_get_gui()= returns =NULL=; inspect widgets through the canvas instead (=lrg_widget_find()=, =lrg_canvas_record()= and the paint list), and use =ui.state= for menu and viewport rectangles.
- Custom panels: wrap your widget in an =LrgDockPanel= and call =lrg_editor_app_add_panel()= instead of drawing into an =LrgGuiDock= panel.
- Shortcuts: write accelerators (=<Ctrl><Alt>b=); the 0.8.0 =Ctrl+Alt+B= syntax is still accepted (see [[#keybindings][Keybinding syntax]]).

=tests/editor-app-fixture.h= shows the headless pattern: it builds frames with pointer, button, key and text helpers, clicks widgets by their rectangles and sends IPC requests through =lrg_editor_server_dispatch()=.

** Frame cost
:PROPERTIES:
:CUSTOM_ID: frame-cost
:END:
The editor redraws every frame, so panels avoid work proportional to the whole level or log when only a screenful is visible:

- *Pacing*: the window runs with vsync and caps at the largest whole fraction of the monitor's refresh rate that is at most 75 fps (60 on 60/120 Hz, 72 on 144 Hz, 55 on 165 Hz), so frames always span the same number of vblanks; a fixed 60 cap on a 144 Hz monitor alternated two- and three-vblank frames. Like games, the editor keeps its UI thread on a hybrid CPU's performance cores (=LRG_CPU_AFFINITY=none= to opt out) and bounds its frames in flight to 2 with graylib's frame sync (=grl_frame_sync_end_drawing()= in place of =EndDrawing()=; =LRG_MAX_FRAMES_IN_FLIGHT= overrides it, see [[file:../performance.org::#input-latency][input latency]]).

- *Panels*: the console, hierarchy and asset panels of 0.8.0 kept row caches against the log ring and the node tree serial (below); their retained replacements use list and tree views over =GListModel=, which lay out only visible rows. =LrgEditorLog= still keeps per-level tallies, so the status bar counters (=lrg_editor_log_count_level()=) do not walk the ring.
- *0.8.0 console*: each log record is formatted (timestamp, level, domain), casefolded for the filter and measured once, when it first appears, into a row cache mirrored from the log ring; the filtered row list is extended incrementally and rebuilt only when the level toggles or the filter text change. Only the rows inside the scroll view are laid out; the rows above and below become one spacer each, of the same total height and of the widest row's width, so scrolling and the horizontal extent are unchanged. A row whose context menu is open keeps building it while it scrolls out of view. =LrgEditorLog= keeps running per-level tallies, so the console tab and status bar badges (=lrg_editor_log_count_level()=) do not walk the ring.
- *0.8.0 hierarchy*: rows outside the tree's view submit only their tree node (keyed by GUID, so open state, layout, keyboard navigation order and a held row behave as before) and skip the toggles, label, measuring, drop targets and menu; the row being renamed, the one being revealed and one with an open context menu are always drawn in full. The node count (outliner header, status bar, viewport overlay) and the filter's match set are cached against a process-wide node tree serial (bumped when nodes are created, destroyed, re-parented, renamed or given a new GUID) and recomputed only when it or the filter text changes. =LrgEditorSelection= keeps a hash set beside its ordered array, so the per-row "is selected" test is constant time.
- *Viewport rendering*: the scene walk passes each node's world matrix down to its children (one local matrix composed per node instead of a walk back to the root), and icons take their position from it. Mesh and sprite assets are looked up by the node's asset string as written, one hash lookup per node per frame, with the absolute path built and the file loaded only on first use; that map is cleared when the project or level directory (what relative paths resolve against) changes. =grid-size= and =grid-extent= are re-read from the settings only after a =notify=.

** Settings migration
:PROPERTIES:
:CUSTOM_ID: settings-migration
:END:
An =editor.yaml= written by 0.8.0 has no =settings-version= key and loads as version 1. On start-up the editor calls ~lrg_editor_settings_migrate (settings, NULL, &error)~ (=lrg-editor-settings-migrate.h=), which brings the file to version 2 once: it backs the file up, converts the layout, the keybindings and the theme name, sets =settings-version: 2= and saves. Everything else (=ui-scale=, fonts, camera and snap settings, recent files, keys the editor does not know) is kept as it is. A version-2 file is left alone, so the call is cheap on every start and running it twice changes nothing.

*** When it runs and the backup
:PROPERTIES:
:CUSTOM_ID: settings-migration-backup
:END:
~lrg_editor_settings_needs_migration~ is true while =settings-version= is below =LRG_EDITOR_SETTINGS_VERSION= (2). The file migrated is the =path= argument, else the file the settings were loaded from (~lrg_editor_settings_get_path~), else the default path. Before anything is rewritten the existing file is copied to =editor.yaml.v0.8.0.bak= (=LRG_EDITOR_SETTINGS_BACKUP_SUFFIX=); an existing backup is never overwritten, so after a downgrade and a second upgrade the backup is still the first 0.8.0 file. Settings that were never on disk get no backup. If the backup cannot be written the migration stops with an error and changes nothing. A symlinked =editor.yaml= (for example one managed by GNU Stow) is written through to its target instead of being replaced by a plain file.

*** Layout
:PROPERTIES:
:CUSTOM_ID: settings-migration-layout
:END:
The 0.8.0 window stored its dock layout under =layout= in the compact =LrgGuiDock= grammar: =split(D,RATIO,A,B)= with =D= =v= (children side by side) or =h= (stacked), and =tabs(ACTIVE,id,...)= for a tab stack. ~lrg_editor_settings_convert_legacy_layout~ parses it exactly as 0.8.0 did (blanks between tokens, ratios clamped to 0.05 - 0.95, the active index clamped to the tab count, at most 64 levels) and writes the =LrgDockArea= YAML of [[file:../modules/ui/widgets/dock-area.org::#dock-area-persistence][dock area persistence]] into =ui-layout=. The old =layout= key is left untouched so 0.8.0 still finds its layout after a downgrade. Panel ids are copied unchanged: =viewport=, =hierarchy=, =inspector=, =assets=, =console=, =problems=, =history=, =tiles= and =timeline= are the same panels in 0.8.1.

| 0.8.0                       | =LrgDockArea= YAML                                   |
|-----------------------------+------------------------------------------------------|
| =split(v,0.20,A,B)=         | ={ split: horizontal, ratio: 0.2, first: A, second: B }= |
| =split(h,0.72,A,B)=         | ={ split: vertical, ratio: 0.72, first: A, second: B }= |
| =tabs(1,console,assets)=    | ={ tabs: [console, assets], active: assets }=        |
| (no floating panels)        | =floating: []=                                       |

For example =split(v,0.20,tabs(0,hierarchy),split(h,0.72,tabs(0,viewport),tabs(1,console,assets)))= becomes the dock tree =H(0.20,[hierarchy*],V(0.72,[viewport*],[console,assets*]))= (in =lrg_dock_area_describe()= notation). A layout string that does not parse leaves =ui-layout= empty, so the window starts with its default layout, and logs a message with the parse error. A =ui-layout= that is already present is never replaced.

*** Keybindings
:PROPERTIES:
:CUSTOM_ID: settings-migration-keybindings
:END:
Every override is rewritten in accelerator syntax with ~lrg_editor_settings_convert_legacy_shortcut~, which runs ~lrg_editor_shortcut_to_accel~ on each =|=-separated alternative on its own: =Ctrl+Shift+Z|Ctrl+Y= becomes =<Ctrl><Shift>z|<Ctrl>y=, =Num7= =KP_7=, =Ctrl+,= =<Ctrl>comma=; values already in accelerator syntax stay as they are and =""= (an unbinding) stays =""=. An alternative that does not convert is dropped and the rest are kept (=Shift+F5|Wibble= becomes =<Shift>F5=); a value with no valid alternative is removed, so the action gets its default shortcut back. Both cases log a message naming the action and the old text.

*** Theme
:PROPERTIES:
:CUSTOM_ID: settings-migration-theme
:END:
~lrg_editor_settings_convert_legacy_theme~ maps the four 0.8.0 names (case-insensitively); any other value, a preset name or a theme file path, is kept.

| 0.8.0       | 0.8.1                  | Resolves to                                               |
|-------------+------------------------+-----------------------------------------------------------|
| =mocha=     | =catppuccin-mocha=     | the built-in preset                                       |
| =latte=     | =catppuccin-latte=     | the built-in preset                                       |
| =macchiato= | =catppuccin-macchiato= | =data/editor/themes/catppuccin-macchiato.yaml=            |
| =frappe=    | =catppuccin-frappe=    | =data/editor/themes/catppuccin-frappe.yaml=               |

The two theme files use the official Catppuccin Macchiato and Frappé palettes mapped onto the same colour roles and metrics as the =catppuccin-mocha= preset, and load with ~lrg_theme_new_from_file~. The migrated value is the bare name, not a path, so it survives the editor being moved or reinstalled. A bare theme name that is neither a preset nor a 0.8.0 name is looked up as a file by ~lrg_editor_settings_find_theme_file~: =NAME.yaml= (or =NAME= when it already ends in =.yaml= / =.yml=) in

1. each directory of =$LRG_EDITOR_THEME_PATH= (separated like =$PATH=),
2. =$XDG_DATA_HOME/libregnum/editor/themes= (your own themes),
3. =PREFIX/share/libregnum/editor/themes= when the library was built with =LRG_DATADIR=,
4. =libregnum/editor/themes= under each directory of =$XDG_DATA_DIRS=,
5. =data/editor/themes= next to the running executable or in one of its parents (an uninstalled build tree).

When the file is found ~lrg_editor_settings_get_theme_file~ returns it and ~lrg_editor_settings_get_theme_preset~ returns =NULL=; when it is not, the name falls back to the =catppuccin-mocha= preset like any unknown name. The 0.8.0 names themselves keep resolving to presets (=macchiato= and =frappe= to =catppuccin-mocha=) in a file that has not been migrated yet.

*** Other keys
:PROPERTIES:
:CUSTOM_ID: settings-migration-other
:END:
=ui-scale= is not converted: the window applies it as the canvas pointer transform and the theme scale. The migration does not add keys; the 0.8.1 keys (=ui-layout=, =script-editor=, =viewport-layout= and =viewport-cameras=, the four viewport cameras as written by ~lrg_editor_view_state_cameras_to_string~, default =""=) are written with their defaults on the first save.

:PROPERTIES:

Both views show the same =GListStore= (the folder listing after the filters, folders first), so sorting the list also orders the grid and the selection carries over when switching. Hidden files and =.meta= sidecars are never listed.

*Grid* (=LrgTileView= =assets-grid=, 108 x 124 tiles, multi-selection): each tile is a preview, the ellipsized name and the git badge in the preview's top-right corner.

| Entry | Preview |
|-------+---------|
| Folder | the folder icon in the warning colour |
| Script | a live code tile: the first 12 lines of the file tokenized with its =LrgSyntax= language and painted run by run in the token colours (=lrg_syntax_get_token_color()=) on an =INPUT= sheet; nothing is cached as an image, so it follows the theme |

| Method | Params | Result |
|--------+--------+--------|

*** Implementation notes
:PROPERTIES:
:CUSTOM_ID: editor-panel-assets-impl
:END:
- *Following the app.* The panel is created before any project opens and the app replaces its =LrgAssetDatabase= and =LrgEditorVcs= on every project change, so =step()= (and every public entry point) compares the app's base directory and =vcs= pointer with what it follows: a new root shows that folder, a new =LrgEditorVcs= gets the =::changed= handler. Hidden panels do not step; IPC and API calls sync first.
- *Listing.* Non-recursive, like 0.8.0: a =GFileMonitor= on the folder marks the listing dirty and the next frame lists it again, carrying the selection over by path. Tiles and cells read the git status cached on their item, so =::changed= only recomputes the items.
- *Thumbnails.* Tiles call =editor_thumbnail_texture()= (=lrg-editor-thumbnails.c=), which requests a thumbnail on first use and uploads at most four textures per frame, only while a window exists; headless the type glyph is drawn. An import-settings edit calls =editor_thumbnails_file_changed()= so the preview is regenerated with the new settings hash.
- *Without a project.* A lone level's folder is browsed with a private =LrgAssetDatabase= (sidecars are written only by the operations that need them, as =lrg_asset_database_rename()= does).

*** Selection, multi-edit and undo
:PROPERTIES:
:CUSTOM_ID: editor-panel-inspector-multi
:END:
- On every selection change each grid gets =lrg_editor_node_source_new_for_nodes()= for the selection (the primary node first, so its order, scripts and prefab lead). Grids keep their rows when the schema stays the same, and component sections are pooled by key, so selecting another node of the same shape rebuilds nothing and keeps focus.
- Each grid is wired with =lrg_editor_node_source_connect_grid()= (=LRG_PROPERTY_APPLY_DELEGATE=): a scrub of the location's X axis across three nodes is ONE undo step, each node keeps its own Y and Z, and Escape during the drag restores every node and records nothing.
- Values the nodes disagree on show as mixed (an em dash per vector axis, an indeterminate check box …). A component section appears only when every inspected node has that component key.
- The structure (which sections, script rows, prefab bar) is rebuilt only when a signature of the inspected nodes changes (component keys, script paths, prefab link and override count, live object). Drag previews and value edits only refresh rows, through the sources' own =property-changed= emissions.
- Asset and script paths are checked against the project directory (=lrg_editor_node_source_set_asset_root()=), so missing files show the =INVALID= marker.

*** Scripts
:PROPERTIES:

*** Inspector lock
:PROPERTIES:
:CUSTOM_ID: editor-panel-inspector-lock
:END:
The lock button (and the action =inspector.toggle-lock=, View > Lock Inspector in the palette) keeps the inspector on the nodes it shows while the selection moves on (=lrg_editor_inspector_panel_set_locked()=). The first locked node's GUID is stored in the view state's =inspector-lock= (see [[file:view-model.org][View model]]); setting that property from elsewhere (IPC, a script) locks the inspector to that node, clearing it unlocks. When every locked node leaves the level (deleted, another level opened) the inspector unlocks itself.

*** Live inspection
:PROPERTIES:
:CUSTOM_ID: editor-panel-inspector-live
:END:
While play mode runs (=LrgEditorPlaySession=) the inspector shows a live object instead of the authoring sections:
- the object picked in the hierarchy's Live tab: the inspector connects to =LrgEditorHierarchyPanel::live-selected= (found with =lrg_editor_hierarchy_panel_find()=) and starts from =lrg_editor_hierarchy_panel_get_live_selection()=; =lrg_editor_inspector_panel_set_live_object()= does the same from code (=NULL= goes back to following the selection);
- otherwise the live object made from the inspected node (=lrg_editor_play_session_get_object_for_node()=).
Each component of the object gets a grid over an =LrgObjectPropertySource= in =LRG_PROPERTY_APPLY_DIRECT= mode (the =LrgComponent= base properties other than =enabled= are hidden), re-read on every =LrgEditorPlaySession::ticked=, so the values move with the simulation. Edits go straight into the play world and are discarded on Stop, as the warning banner says. A row's context menu adds "Apply to Level" (action =live.apply=, parameter the property name), which calls =lrg_editor_play_session_apply_to_level()=: the value is copied into the authoring node's component description as an undoable command and survives the restore on Stop. On Stop the live grids drop their components and the authoring sections return.

*** IPC methods
:PROPERTIES:
:CUSTOM_ID: editor-panel-inspector-ipc
:END:
Registered on the app's server by the panel. They build their own node sources, so they work for any node and in =--headless= mode. Targets: =nodes= (array of GUIDs or paths) or =node= (one); without either, the nodes the inspector shows (or the selection). =section= is =header=, =transform=, =visual=, =component= (with =component=, a component key) or =scripts=.
| Method                      | Params                                                    | Result                                                                                          |
|-----------------------------+-----------------------------------------------------------+-------------------------------------------------------------------------------------------------|
| =inspector.list=            | target, =section?=, =component?=                          | ={nodes, section, component?, rows}=, or without a section ={nodes, sections: [{section, component?, rows}]}= for every section (components every node has) |
| =inspector.get=             | target, =section=, =component?=, =name=                   | One row                                                                                          |
| =inspector.set=             | target, =section=, =component?=, =name=, =value=          | The row after the edit; ONE undo step across all nodes ("Set <label>")                           |
| =inspector.reset=           | target, =section=, =component?=, =name=                   | The row; overridden prefab properties revert to the prefab, others go to their default; one step |
| =inspector.revert_override= | target, =section=, =component?=, =name=                   | The row plus =count=; an error when nothing is overridden                                         |
| =inspector.apply_override=  | target, =section=, =component?=, =name=                   | The row plus =count= (writes and saves the prefab)                                               |
| =inspector.state=           | none                                                      | ={nodes, locked, lock, live, live_type?, components, prefab}=                                     |
A row is ={name, label, group, hint, type, read_only, value, mixed, state, override_path?}=: =type= is the =GType= name, =state= an array of ="default"=, ="overridden"=, ="animated"=, ="invalid"=. Values are JSON booleans, numbers and strings; vectors are arrays of numbers; enums and flags are nicks (="ranged"=, ="fire|acid"=); colours ="#rrggbbaa"=; anything else the text =lrg_property_value_to_string()= writes. =inspector.set= takes the same forms (numbers also fit enums and flags; strings are parsed with =lrg_property_value_from_string()=).
#+begin_src sh
# Move two nodes to the same X in one undo step
lrgeditorctl call inspector.set '{"nodes":["Crate","Crate 2"],"section":"transform","name":"location","value":[4,0,0]}'
# Set an enum component property by nick
lrgeditorctl call inspector.set '{"node":"Orc","section":"component","component":"health","name":"kind","value":"ranged"}'
#+end_src

*** Enum and flags values in levels

*** Console
:PROPERTIES:
:CUSTOM_ID: editor-panel-console-log
:END:
The console mirrors the =LrgEditorLog= ring: every GLib log record (the editor installs a log writer), the game's output when it runs with F6 (domain =game=, levels guessed from the usual =WARNING= / =CRITICAL= prefixes) and the console's own echo and replies. Each record is formatted once when it first appears; the rows passing the filter live in a =GListStore=. Records only leave the ring at the front and arrive at the back, so the mirror is updated incrementally every frame the panel is shown (and on demand by the getters); a ring that does not match (a clear, a race with a logging thread) is rebuilt.

| Part | Widget name | Behaviour |
|------+-------------+-----------|
| Level chips | =console-errors=, =console-warnings=, =console-messages=, =console-debug= | Toggle a level group; the badge is the number of records of that group in the ring, whatever the filter. Errors are =ERROR= and =CRITICAL=, messages are =MESSAGE= and =INFO=. Debug is off by default |
| Search | =console-search= | Case-insensitive; a row passes when its message or its domain contains the text |
| Follow | =console-follow= | Auto-scroll to the newest row when records arrive (on by default) |
| Copy, Copy All | =console-copy=, =console-copy-all= | The selected row, or every shown row, as "HH:MM:SS level domain: message" lines, to the clipboard |
| Clear | =console-clear= | Empties the log (=lrg_editor_log_clear()=) |
| Log | =console-list= | Rows: level icon, time, domain, message coloured by level; rows with a source location show a file mark, and double click (or Enter) opens the file at its line in the external editor. Right click: Copy Row, Copy All, Clear |
| Command line | =console-command=, =console-run= | Enter or Run executes; Up / Down walk the last 200 commands (newest first; Down past the newest clears the line) |

The command line accepts exactly what the 0.8.0 console did:

| Input | Effect |
|-------+--------|
| =help= | Lists the commands and every IPC method |
| =clear= | Clears the log |
| =:ID= | Runs an editor action, e.g. =:view.top=; a disabled or unknown id logs a warning |
| =::= (or =:=) | Lists the action ids |
| =METHOD key=value ...= | An IPC call; the words are split like a shell command line and the values become JSON booleans (=true=, =false=), integers, numbers, arrays (=[1,2,3]=) or strings, e.g. =node.create name="Big Door" primitive=cube= |
| ={"method": ...}= | A raw JSON request |

The request goes through =lrg_editor_server_dispatch()= and the reply is logged (as a warning when it carries an error), so anything the IPC protocol can do is available from the console.

Actions registered by the panel: =console.copy=, =console.copy-all=, =console.clear= and =console.focus= (show the panel and focus the command line).

** Profiler panel
:PROPERTIES:
:CUSTOM_ID: editor-panel-profiler
:END:
=LrgEditorProfilerPanel= (=src/editor/ui/lrg-editor-profiler-panel.{h,c}=, panel id =profiler=) shows frame times and the sections of the default =LrgProfiler= (=lrg_profiler_get_default()=).

- *When it records.* The profiler is enabled while the panel is shown (its tab raised and the panel docked) or play-in-editor runs, or while an IPC client pinned it; otherwise the panel turns it off again (only if it turned it on). Enabling, disabling and clearing happen in an idle between two frames, never while a section is open (a section begun with the profiler off and ended with it on would be reported as unmatched).
- *The frame tap.* The panel adds an invisible, pointer-transparent =LrgCustomWidget= as a canvas overlay; overlays are stepped by every =lrg_canvas_update()=, so the tap sees every frame even while the panel is a hidden tab. It records the frame's delta time in a ring of =LRG_EDITOR_PROFILER_FRAMES= (300) frames and refreshes the table four times a second. Times come only from the canvas clock, so tests are deterministic.
- *Graph* (=profiler-graph=): one bar per frame, newest on the right, green within 16.6 ms, amber within 33.3 ms, red above; dashed guides at 16.6 ms (60 fps) and 33.3 ms (30 fps); the scale grows with the peak (40 ms at least). Hovering a bar shows a marker and "12.30 ms (81 fps) frame -N".
- *Table* (=profiler-table=): section, last, average and maximum milliseconds and calls; every column sorts (the default is average, slowest first).
- *Toolbar*: a Recording / Idle indicator, Pause / Resume (freezes graph and table), Clear, and a readout of the last frame, fps, average and peak.
- *Play.* The panel hands the profiler to the play session (=lrg_editor_play_session_set_profiler()=), which times every tick under =play.tick=.

Actions: =profiler.pause= (checked while paused) and =profiler.clear=.

*IPC* =profiler.sample= (params optional): =frames= (how many recent frame times, default 60, at most what was recorded) and =enable= (=true= pins the profiler on, =false= unpins it). The reply:

#+begin_src json
{ "enabled": true, "pinned": false, "paused": false, "frame_ms": 16.67,
  "frames": [16.67, 16.67, 16.9],
  "sections": [ { "name": "play.tick", "last_ms": 0.21, "avg_ms": 0.2, "min_ms": 0.18, "max_ms": 0.4, "count": 120 } ] }
#+end_src

=LrgEditorTimelinePanel= (=src/editor/ui/lrg-editor-timeline-panel.{h,c}=, panel id =timeline=) edits the level's =LrgTimeline= s on an =LrgTimelineView=. The data model, the undoable =lrg_editor_timeline_*= API and the preview semantics are in [[file:editor-tools.org::#timeline-panel][Editor Tools > The Timeline panel]]; this section covers the widget.

- *Toolbar* (=timeline-toolbar=): the timeline picker (=timeline-picker=), a name field (=timeline-name=; Enter is New), New, Rename and Delete; Loop and Autoplay toggles; the length (=timeline-length=).
- *Transport* (=timeline-transport=): previous key, Play / Pause (=K=), Stop, next key (=Alt+Left= / =Alt+Right=); Key (=I=, every selected node's transform at the playhead, one undo step); Delete Keys; the easing picker (=timeline-easing=, every =LrgEasingType=; it sets the easing of new keys and re-eases the selected keys); the playhead readout.
- *View* (=timeline-view=): one group track per node in the order the timeline first mentions it (each node gets its own colour; missing nodes read "(missing GUID)"), one child track per animated channel (=location.x= ... =scale.z=, =color.r= ..., =roughness=, =metallic=, =param.NAME=). Keys are diamonds when linear and circles when eased. Click selects (Shift / Ctrl extend), a rubber band selects several, dragging retimes every selected key, Delete removes them. The ruler scrubs. Groups collapse and keep their state across rebuilds. Right click: Insert Keyframe, Delete Selected Keys and a *Key Easing* menu (Linear, then Ease In / Ease Out / Ease In Out by family).
- *One undo step per gesture.* The view edits its own copy first and reports keyframe-moved / -removed / -added when the gesture ends; the panel queues those and applies them on its next step inside one =lrg_editor_begin_group()= / =lrg_editor_end_group()=, so dragging five keys is one undo step. Times snap to 10 ms (the view's grid snapping runs at 100 frames per second, and the panel rounds again). A value changed on a curve lane becomes =lrg_editor_timeline_set_key()= with the key's easing.
- *Preview.* The view state's =timeline-time= is the truth: scrubbing calls the editor's preview seek (nodes posed outside the undo history, rest values restored on Stop, save, play or switching timelines), and the transport drives the editor's preview playback (ticked by the app). The view's own playback is never used and its play button is hidden, so the panel, the =timeline.*= IPC methods and the actions always agree.
- *Look.* The =look= property (=LrgCanvasLook=, default =LRG_CANVAS_LOOK_AUTO=, which follows the editor theme) is forwarded to the view.

Actions registered by the panel: =timeline.rename= and =timeline.delete= (the current timeline, the name field's text), and =timeline.delete-key= (now the view's whole selection, falling back to the single key IPC selected).

** Input latch
:PROPERTIES:
:CUSTOM_ID: editor-input-latch
:END:
raylib samples the mouse buttons and modifier keys once per frame, so a press and a release that both land between two frames (a touchpad tap, =xdotool=, a quick click on a slow software-GL frame) never show up as edges, and a chord typed faster than a frame (Ctrl down, S, Ctrl up) arrives without its Ctrl. Since 0.8.1 =lrg_canvas_input_poll()= (=src/ui/lrg-canvas-input.c=) handles this for every canvas, not only the editor: on the first poll on a window it chains GLFW mouse-button and key callbacks in front of raylib's (raylib's still run), counts the events between two polls, and merges them into the polled frame with =lrg_canvas_input_apply_latch()=:

- a latched button press missing from =buttons_pressed= becomes a press edge, plus a release edge when the button is no longer in =buttons_down=;
- latched key presses missing from =keys= are appended;
- when the frame has key presses, the modifiers latched with them are added to =modifiers=;
- a key pressed and released within the frame gets its release in =keys_released=.

| API | Use |
|-----+-----|
| =lrg_canvas_input_latch_button (button, pressed)= | Feed a button event (other backends, tests) |
| =lrg_canvas_input_latch_key (key, pressed, modifiers)= | Feed a key event with the modifiers reported with it |
| =lrg_canvas_input_apply_latch (frame)= | Merge and empty the latch (=lrg_canvas_input_poll()= calls it) |
| =lrg_canvas_input_clear_latch ()= | Forget what was latched |
| =lrg_canvas_input_set_latch_enabled= / =lrg_canvas_input_get_latch_enabled= | Turn the GLFW feed off (restores raylib's callbacks) |
| =lrg_canvas_input_detach_latch ()= | Restore raylib's callbacks on the current window before =CloseWindow()= (the next poll on a new window attaches again) |

=tests/test-editor-app-panels.c= covers the latch headless (=/editor-app/panels/latch/*=): a click within a frame, held presses, chords, appended presses, isolated releases, and a click shorter than a frame reaching an =LrgButton= through a canvas.

** Hierarchy panel
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy
:END:
The Hierarchy panel (=LrgEditorHierarchyPanel=, panel id =hierarchy=, docked left by default) is the outliner of the open level: every =LrgNode= as a row of an =LrgTreeView=, with its kind, its name and its visibility and lock toggles. It is where nodes are selected, renamed, re-parented, reordered, grouped, filtered and created, and where assets from the asset browser are dropped to become nodes. While play-in-editor runs a second tab lists the live game objects of the play world. It has every feature of the 0.8.0 immediate-mode outliner and adds the node model, a reveal that scrolls exactly to the node, drag and drop through the toolkit's DnD sessions with a refused-drop state, Alt drops that keep world transforms, the prefab menu and the Live tab.

*** At a glance
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-overview
:END:

+----------------------------------+
| [ Filter nodes             ] [+] |   search field (Ctrl+F), create menu
| (   Scene   |   Live  * )        |   only while playing
| Demo  .  12 nodes                |   level name and node count / matches
| v [] Lights               (o)    |   kind glyph, name, eye, lock
|     * Sun                 (o)    |
|   # Ground                (o) L  |   locked
|   <> Crate      oo .      (o)    |   prefab instance: accent, link, override dot
+----------------------------------+
#+end_example

| Feature | How |
|---------+-----|
| Select | Click a row. Ctrl+click toggles, Shift+click selects the range from the anchor (the last plain or Ctrl click), Shift+Up/Down extend from the keyboard. A click below the rows clears the selection. |
| Follow outside selections | Picking in the viewport, Emacs, the palette or IPC reveals the primary node: collapsed ancestors open and the tree scrolls by the smallest amount that shows the row. |
| Rename | F2 (the =node.rename= action), a double click, Enter on the cursor row, the context menu's Rename, or =hierarchy.rename=. Enter commits (one undo step through ~lrg_editor_rename_node~), Escape cancels, an empty name is refused. |
| Visibility and lock | The eye (and lock) toggles at the trailing edge of each row, or H and Ctrl+L for the selection. Each toggle is one undo step; a toggle click does not change the selection. The lock icon shows on hover and while locked. |
| Reparent / reorder | Drag a row: onto the middle of a row makes it a child, onto its top or bottom quarter places it before or after. Hold Alt to keep the world transform. A selected row drags the whole selection. One undo step. |
| Drop assets | Models and textures become mesh and sprite nodes, prefabs linked instances, scripts attach to the row's node. |
| Filter | Ctrl+F (=edit.find=) focuses the field; matches (case-insensitive name or GUID substring) and their ancestors are shown, expanded; ancestors that only lead to a match are muted. |

| Create | The + button (top level) or Create Child in the context menu. |

*** Rows
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-rows
:END:
A row is a private =HierarchyRow= widget (an =LrgContainer= with an =LrgLabel= for the name, so the tree's inline rename covers exactly the label). From the leading edge:

- *Indentation and arrow*: drawn by the tree view (16 units per level). The arrow turns with a spring; clicking it toggles the branch.
- *Kind glyph*, painted from SDF primitives in the theme's colours: a sun in the =warning= colour for lights, a camera body and lens in the =link= colour, a speaker in =success= for audio emitters, a filled triangle for mesh assets, a picture frame for sprites, four tiles for tilemaps, a gear for CAD parts, an outlined box for primitives, a folder for empty nodes with children and a ring for empty leaves. A linked prefab instance root (or a 0.8.0 instance) gets an accent diamond.
- *Name*: the =text= colour; the =accent= colour for every node of a linked prefab instance (root and mirrored children); half alpha for hidden nodes and for ancestors shown only because a descendant matches the filter.
- *Markers*: two linked rings for a linked instance root, a =warning= dot when that instance has overrides, a =success= dot when the node has scripts.
- *Eye and lock*: two squares of the row height at the trailing edge. The eye is drawn when visible and a small ring when hidden; the lock in the =warning= colour when locked, muted under the pointer otherwise.

Rows read their node live while painting, and follow =notify::name= for the label, so a rename, a toggle or an undo shows in the next frame without re-binding. All colours come from the theme, so the panel follows every preset and theme file.

*** Selection
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-selection
:END:
The tree runs in =LRG_SELECTION_MODE_MULTIPLE=; its gestures (REPLACE, TOGGLE, EXTEND) produce the set. Two handlers mirror it:

- *Tree to editor* (=LrgTreeView::selection-changed=): the tree's selected items become the editor selection with ~lrg_editor_select_nodes~, the cursor item last (primary). After a Ctrl or Shift click, selected nodes that have no row (inside collapsed branches) are kept, so a toggle never loses them.
- *Editor to tree* (=LrgEditorSelection::changed=): the primary node is revealed (~lrg_tree_view_reveal~ with the node model's parent function), then the tree's set becomes the selected nodes that have rows, primary last so it is the cursor and the range anchor. Nothing changes when the sets already agree.

A guard flag stops the two from feeding each other. A reveal requested before the panel is laid out (the panel was closed or just docked) is repeated on the next frame.

*** Rename
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-rename
:END:
~lrg_editor_hierarchy_panel_start_rename~ switches to the Scene tab, clears a filter that hides the node, reveals it and calls ~lrg_tree_view_start_editing~; when the tree is not laid out yet the edit starts on the next frame. The panel replaces the 0.8.1 placeholder of the =node.rename= action (F2, enabled with a primary selection), which first shows the panel. The tree's =edit-label= handler trims the text, refuses an empty name (the field stays open after Enter), renames through ~lrg_editor_rename_node~ (one undo step) and reports it in the status bar. The tree view's own F2 (cursor row) and =row-activated= (double click, Enter) do the same.

*** Drag and drop
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-dnd
:END:
The panel follows the [[file:../modules/ui/drag-and-drop.org::#dnd-types][payload conventions]].

*Source.* Every row carries an =LrgDragSource=. =prepare= returns an object payload of type =application/x-lrg-node= holding the grabbed =LrgNode=, allowing MOVE and LINK, labelled with the node name or "N nodes" when the row is part of a larger selection. Presses on the eye and lock toggles and presses while a rename is open do not drag.

*Target.* The tree view carries one =LrgDropTarget= for =application/x-lrg-node=, =application/x-lrg-asset= and =application/x-lrg-prefab= (all actions, =paint-highlight= off: the tree paints its own indicator). On =motion= the panel asks ~lrg_tree_view_get_drop_position~ for the row and position (top quarter BEFORE, middle INTO, bottom quarter AFTER; below the last row AFTER the last root item) and shows it with ~lrg_tree_view_set_drop_indicator~ (an insertion line or a highlighted row). For node payloads the moving set is the selected roots when the grabbed node is selected, else the node; a drop whose new parent is one of them or inside one of them is refused (=motion= returns NONE: no indicator, the chip fades, a release is not a drop). =leave= clears the indicator.

*Node drops.* INTO appends to the row's node and expands it; BEFORE / AFTER insert next to it under its parent, adjusting the index for nodes that move down within the same parent. All moves are one undo group ("Move Node" / "Move Nodes") of ~lrg_editor_move_node~ calls. The LINK action (Alt held, or Ctrl+Shift) passes =keep_world= TRUE, like =node.move= with =--keep-world=: the node stays where it is in the world and its local transform is recomputed under the new parent. A plain drop keeps the local transform.

*Asset drops.* The payload string is the project-relative path, classified with ~lrg_asset_database_classify~:

| Asset | Result |
|-------+--------|
| =.rprefab= | ~lrg_editor_instantiate_prefab~ (a linked instance) under the target parent |
| model (=.glb=, =.gltf=, =.obj=...) | a =mesh= node named after the file, its visual asset set to the path, one undo group |
| texture (=.png=...) | a =sprite= node, the same way |
| script (=.lua=, =.py=...) | attached to the row's node with ~lrg_editor_add_script~ (needs a row) |
| anything else | refused with a status message |

INTO makes the new node a child of the row's node, BEFORE / AFTER a sibling at the indicated index, empty space a top-level node. The new node is selected.

*** Filter
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-filter
:END:
The search field filters as you type: ~lrg_editor_node_model_set_filter~ narrows every store to the matches and their ancestors and the panel expands every shown branch. Clearing the field shows everything again and reveals the primary selection. =edit.find= (Ctrl+F) shows the panel, switches to the Scene tab, focuses the field and selects its text. *** Live tab
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-live
:END:
When the play session emits =started= a pill switch "Scene | Live" appears under the search field (with a red dot: the simulation runs). The Live page is a flat =LrgTreeView= named =hierarchy-live= over ~lrg_editor_play_session_get_objects~ (the session's =GListModel= of =LrgGameObject=, updated as the world changes); rows show the name of the authoring node (~lrg_editor_play_session_get_node_for_object~), or the object's type. *** The node model
:PROPERTIES:
:CUSTOM_ID: editor-panel-hierarchy-model
:END:
=LrgEditorNodeModel= (=src/editor/lrg-editor-node-model.h=, headless, usable by any GListModel consumer) presents a level's node tree as one =GListStore= of =LrgNode= per parent:

- ~lrg_editor_node_model_get_root_model~ is the top level (children of the level root); ~lrg_editor_node_model_get_children~ returns a node's store, created on first use and the same object from then on (a leaf gets an empty store that fills later, so the tree view keeps following it).
- *Incremental sync.* =LrgLevel::node-added= reconciles the parent's store and the stores of the added subtree; =node-removed= the store that showed the node; =node-changed= and the shown properties of a node (=name=, =guid=, =visible=, =locked=, =is-2d=, =visual=, =prefab-link=, not transforms) emit =items-changed (pos, 1, 1)=. Re-parenting, reordering and prefab syncs are not signalled by the level: the model listens to =LrgEditor::changed= and reconciles every store when the process-wide node tree serial moved. Each reconcile is the smallest =g_list_store_splice= (the common prefix and suffix stay), so views keep rows, expansion and selection. Stores of detached subtrees (deleted, waiting in the undo history) stay current for the undo.
- *Level replacement.* =LrgEditor::level-replaced= drops every store and makes a new root store (=notify::root-model=); views bound with ~lrg_editor_node_model_bind_tree_view~ follow it.
- *Filter.* ~lrg_editor_node_model_set_filter~ (case-insensitive substring of the name or the GUID) keeps the matches and their ancestors in the stores; ~lrg_editor_node_model_is_match~ tells a match from an ancestor, ~lrg_editor_node_model_get_n_matches~ counts them (or all nodes without a filter). Renames, additions, removals and moves re-apply it.
- *Parent function.* ~lrg_editor_node_model_get_parent~ (=NULL= for top-level nodes) is the tree view's parent function, so ~lrg_tree_view_reveal~ opens exactly the ancestors of a node that never had a row.
- A model made with ~lrg_editor_node_model_new_for_level~ (no editor) follows the level signals; call ~lrg_editor_node_model_sync~ after moving nodes directly.

#+begin_src C
g_autoptr(LrgEditorNodeModel) model = lrg_editor_node_model_new (editor);
LrgTreeView *view = lrg_tree_view_new ();

lrg_tree_view_set_selection_mode (view, LRG_SELECTION_MODE_MULTIPLE);
lrg_editor_node_model_bind_tree_view (model, view);    /* model, children and parent functions */
lrg_editor_node_model_set_filter (model, "light");     /* lights and their ancestors */
#+end_src

** Viewport panel
:PROPERTIES:
:CUSTOM_ID: editor-panel-viewport
:END:
The viewport area is =LrgEditorViewportSplit= (=src/editor/ui/lrg-editor-viewport-split.{h,c}=) holding up to four =LrgEditorViewportPanel= widgets (=src/editor/ui/lrg-editor-viewport-panel.{h,c}=). Each panel shows one camera of the =LrgEditorViewState= with its own render mode and overlays; the scene is drawn by =LrgEditorSceneRenderer= (=lrg-editor-scene-renderer.{h,c}=) with the engine's lights, shadows, sky and post effects, and every 2D overlay (gizmo, orientation axes, box select, stats, play frame) is painted with =LrgPaintList= by =lrg-editor-gizmo-paint.{h,c}=. A lone =lrg_editor_viewport_panel_new()= still works (viewport 0, no splitting) for embedders.

*** Layouts and the active viewport
:PROPERTIES:
:CUSTOM_ID: editor-viewport-layouts
:END:
- *Layouts* follow =LrgEditorViewState:layout=: =single= (panel 0), =split-h= (0 | 1), =split-v= (0 / 1) and =quad= (top 0 | 1, bottom 2 | 3) in nested =LrgSplitter= panes. Panel /i/ always shows camera /i/, so switching layouts keeps every viewport's camera, render mode, overlays and the splitter positions (the split owns all four panels and three splitters and only re-parents them).
- *Default cameras*: viewport 0 is the perspective camera; 1, 2 and 3 start as the orthographic Top, Front and Right axis views (the view state's defaults), so =quad= is the classic four-view layout.
- *Active viewport*: a press in a viewport, a wheel turn over it, or hovering it while no gesture runs makes it the view state's active viewport. Keyboard shortcuts, =view.*= actions and IPC calls without a =viewport= parameter act on it. In split layouts it carries an accent outline that fades in with a spring.
- *Maximise* (header button, =lrg_editor_viewport_split_set_maximized()=): shows one viewport alone without changing the layout; a second press or any layout change restores the layout.
- *Navigation* is shared: one =LrgEditorViewportNav= acts on the active camera, and only the panel that took the press of a gesture ("nav owner") reacts to its =click=, =box-select= and =context-menu= signals, so a split layout picks once.

*** Rendering
:PROPERTIES:
:CUSTOM_ID: editor-viewport-rendering
:END:
- *Render on demand.* Viewports are =LrgViewport= widgets in render mode with =continuous= off. A panel marks itself dirty on =LrgEditorViewState::camera-changed= / =::viewport-changed= for its index, on the active viewport, layout, tile mode and timeline time changing, on =LrgEditor::changed= and =::level-replaced=, on the level's =node-added= / =node-removed= / =node-changed=, on selection changes, on play start/stop/pause and when =lrg_editor_scene_renderer_get_generation()= moves (an asset reloaded, the base directory or the grid settings changed). Its step (which runs before the viewport's) queues one render. It renders every frame only while playing, while the timeline plays, during a gizmo drag or tile stroke, and while the active viewport navigates (fly, orbit, pan, zoom, axis gizmo). =lrg_editor_viewport_panel_get_render_pending()= exposes the flag.
- *Lights* (=lrg_editor_scene_renderer_sync_lights()=): every visible LIGHT node becomes an =LrgLight3DDesc= that =lrg_world3d_renderer_sync_lights()= puts into the light set, exactly as a game's light components do. A light whose =light_type= visual param is the string ="directional"= is the sun (the first one; it shines down the node's local -Z); every other light is a point light at the node's world position with =range= as radius (default 10), =intensity= as intensity (default 1) and the material colour (white without a material), or a spot light (=light_type: spot= or =spot_angle= > 0) along local -Z with =spot_angle= as its full outer cone and =spot_inner_angle= as its full inner cone (degrees; 80 % of the outer half-angle without it); =cast_shadows: true= gives point and spot lights shadow maps. A level without a directional light gets the default editor sun (travelling along (0.5, -0.75, -0.45), from the upper left of the default camera, so shadows fall into view) so the scene stays readable; turning the /Scene Lighting/ overlay off lights the scene with that sun only. Ambient is a fixed dark blue-grey.
- *Shadows*: with /Shadows/ on, in perspective viewports and the lit modes, an =LrgShadowRenderer= (3 cascades of 2048 texels reaching 60 units, 3 x 3 filter, strength 0.85) renders the directional light's cascades for that viewport's camera before the scene and hands them to the light set. Orthographic and 2D viewports draw without shadows. Point-light cube shadows are not used (no shadow priorities in the level format yet).
- *Sky*: with /Sky/ on, perspective viewports draw an =LrgSkyDome= behind the scene with its sun along the directional light. Weather and day/night preview are not wired: a level has no environment block declaring them yet (see the gap analysis, "Lights"); when it does, the dome's time of day and =LrgWeatherManager= fog plug in here.
- *Post processing* (preview only, never saved into the level): with /Post Processing/ on, each viewport (and the camera preview) has an =LrgPostProcessor= (=lrg_editor_scene_renderer_get_post_processor()=, made by =lrg_world3d_renderer_new_preview_post_processor()=) holding, in order, =LrgBloom= (="bloom"=, threshold 0.75, intensity 0.6), =LrgTonemap= (="tonemap"=, filmic, +1 EV), =LrgVignette= (="vignette"=, intensity 0.35), =LrgFxaa= (="fxaa"=) and =LrgColorGrade= (="color-grade"=, contrast 1.05, saturation 1.08). The shared renderer draws the scene into a half-float image kept per processor and runs the effects with =lrg_post_processor_process()=. When the level's environment names a =post_stack:= (=.rpost=), that stack is the look instead (the renderer's fallback look, resolved and cached by path, reloaded after =forget_asset()=); a stack the post-stack editor previews overrides both.
- *Level look* (0.9.0): while authoring, the level's =environment:= block (sky, image-based light, reflection probes, fog, volumetric fog) and its post stack are the shared renderer's fallback look (=lrg_world3d_renderer_set_fallback_look()=); during play the play world's own look is used. Decal nodes become decals of the renderer's decal set (=size_x= / =size_y= / =size_z= box over the node, the asset as albedo, the material colour, =opacity=, =fade_angle=, =fade_width=, =sort_order=, =roughness=, =metallic=), reflection-probe nodes become probes on the environment for the frame (=extents_x/y/z=, default 5; =blend_distance=, =intensity=, =box_projection=, =resolution=, default 128), captured when they move or resize and on =lrg_editor_scene_renderer_recapture_probes()=. Mesh-asset nodes whose =.meta= asks for two or more LOD levels draw the level the viewport camera selects, or the level the inspector forces on =lrg_editor_scene_renderer_get_lod_group()=. =material:= references (=.rmat=) draw through =lrg_world3d_renderer_get_material()=. Each viewport (and the preview slot) has a render-layer mask, =lrg_editor_scene_renderer_set_cull_mask()=.
- *Render modes*: Lit (the light set's shader with shadows; falls back to the editor's =lit.fs= one-light shader without GLSL 330), Unlit (=unlit.fs=, texture times material colour), Wireframe (unlit in rlgl wire mode), Normals (=normals.fs=, world normals as colours) and Lighting Only (the light set's shader on white surfaces). Tilemaps and icon lines use rlgl's default shader in every mode.
- *Shaders*: =data/editor/shaders/scene.vs.glsl=, =lit.fs.glsl=, =unlit.fs.glsl= and =normals.fs.glsl= are the readable sources (the 0.8 =post.fs= is gone: post effects run through =lrg_post_processor_process()=). They are the shared renderer's shaders since 0.9.0: the library embeds them as string literals generated byte for byte from those files (=lrg_world3d_renderer_get_shader_source()=; =lrg_editor_scene_renderer_get_shader_source()= returns the same strings), so an installed editor or game needs no data files; =/editor-app/viewport/shader-sources= fails when a =.glsl= and its literal drift apart. Edit the =.glsl=, then regenerate the literal block in =src/world3d/lrg-world3d-renderer.c= (each line becomes ="...\n"=).
- *Missing assets*: mesh, sprite and tileset references that do not resolve (=lrg_editor_scene_renderer_is_asset_missing()=) are drawn as magenta wire boxes in the scene and get a magenta screen box with a "missing: file" tag in the overlay, in every render mode.

*** Keybindings
:PROPERTIES:
:CUSTOM_ID: editor-panel-preferences-keys
:END:
The Keybindings page lists every registered action under its category: the label, one chip per accelerator (=lrg_editor_accel_to_label()=, e.g. =Ctrl+Shift+Z=), an =x= after each chip, =+= and, when the bindings differ from the defaults, *Reset*.

- *Capture.* Click a chip to replace that alternative, or =+= to add one: the chip reads "Press keys..." and the table takes keyboard focus. The next key press with its modifiers becomes the accelerator (=lrg_accel_name()=, e.g. =<Ctrl>j=); a modifier key alone keeps waiting; Escape cancels; Backspace or Delete alone removes the alternative. The result is stored with =lrg_editor_actions_set_accels()=, which writes the =keybindings= override of =editor.yaml=, and the window re-registers its canvas shortcuts on the registry's =accels-changed= signal, so the new key works as soon as the dialog closes (shortcuts never fire behind a dialog). Rebinding a key that another action uses moves nothing: both keep it and the conflict is shown.
- *Conflicts.* Every chip whose accelerator is bound to more than one action is drawn in the theme's warning colour, and a summary next to the filter counts them (=lrg_editor_actions_find_conflicts()=).
- *Search.* The filter field matches labels, categories and ids (the registry's fuzzy search) and the key names of the shortcuts, so "ctrl+s" finds every action bound to Ctrl+S.
- *Reset.* *Reset* restores one action's defaults; *Reset All Shortcuts* every overridden one.

The same table, read-only, is Help > Keyboard Shortcuts (=lrg_editor_preferences_create_keymap (app, FALSE)=): bound actions only, plus the viewport's mouse navigation, live while open (it follows rebinding), with *Edit Keybindings...* to jump to this page.

** Command palette and Quick Open
:PROPERTIES:
:CUSTOM_ID: editor-panel-palette
:END:
The command palette (Ctrl+Shift+P or F1, action =tools.palette=) and quick open (Ctrl+P, =tools.quick-open=) are one widget, =LrgEditorPalette= (=src/editor/ui/lrg-editor-palette.{h,c}=): a popup that springs down (=LRG_APPEAR_FLY_DOWN=) centred under the menu bar, with a query field and up to twelve ranked rows. It is not modal: a click outside or Escape closes it. While it shows, =LrgEditorViewState:palette-open= is true, which =ui.state= reports as ="palette": true=. The editor makes one palette per app when its code panel is created and keeps it as object data =lrg-editor-palette= on the app.

#+begin_example
+------------------------------------------------------------------+
| (search) select a|                                                |
|------------------------------------------------------------------|
|| > Edit: Select All                                   [Ctrl+A]   |
|  > Edit: Deselect                                 [Ctrl+Shift+A] |
|  > Node: Save as Prefab...                                       |
| 3 commands   @ jumps to a node   Enter run   Esc close           |
+------------------------------------------------------------------+
#+end_example

| Mode | Lists | Row | Enter |
|------+-------+-----+-------|
| Commands (=LRG_EDITOR_PALETTE_MODE_COMMANDS=) | Every action, ranked by =lrg_editor_actions_search()= (fuzzy over "Category: Label" and the id) | "Category: Label" with the matched letters in the accent colour, the first shortcut as a chip on the right; actions that cannot run now are greyed | Closes the palette, then runs the action. A disabled action does not run; the palette stays and the status bar says why |
| Nodes (a query starting with =@=) | The level's nodes whose name fuzzy-matches the rest of the query | The name, then the parent path | Selects the node and frames it (=lrg_editor_view_state_focus_selection()=) |
| Files (=LRG_EDITOR_PALETTE_MODE_FILES=) | The project's files (=lrg_editor_fuzzy_score()= over the relative path; a match in the file name ranks above a match in folder names) | The relative path with matches lit | Levels and prefabs open in the editor (asking about unsaved changes); textures, audio, models and fonts with the desktop's application; everything else (scripts, YAML, text) where =script-editor= says, i.e. the code editor when it is =internal= |

Keys: typing filters at once; Up / Down move the highlight (wrapping), Page Up / Page Down by a page, the mouse wheel scrolls, a click runs a row, Enter runs the highlighted one. The footer counts the matches and repeats the keys.

*Project scan.* Each time quick open opens it scans the project folder (the open project, else the level's folder) on a worker thread (=GTask=): hidden entries (=.git=, =.cache=...), =build/=, =node_modules/=, =trees/=, =.meta= sidecars and backup files (=~=) are skipped, symbolic links are not followed, and the walk stops at =LRG_EDITOR_PALETTE_FILE_LIMIT= (20000) files. The previous list stays usable while the new one is built (the row area says "Scanning the project..." when there is none yet); a newer scan cancels an older one. Only the visible rows are painted, so 20000 files cost one fuzzy pass per keystroke.

** Code editor
:PROPERTIES:
:CUSTOM_ID: editor-panel-code
:END:
The Code panel (=LrgEditorCodePanel=, =src/editor/ui/lrg-editor-code-panel.{h,c}=, dock id =code=, a tab of the bottom area) is a built-in editor for scripts and data files: an =LrgTabView= with one =LrgTextEditor= per open file (line numbers, current-line highlight, auto indent, undo, find, bracket matching), coloured with the =LrgSyntax= that =lrg_syntax_get_for_filename()= picks (Lua, Python, JavaScript, C, Emacs Lisp, YAML, Markdown, INI and the other registered languages). A toolbar row holds Save, Reload, Close and Go to Line and a status line "Ln 12, Col 4 · lua · scripts/door.lua (modified)". With no file open, a hint takes the tab view's place.

*Where files open.* =LrgEditorSettings:script-editor= (Preferences > External Editor > Scripts open in) decides: =internal= opens scripts here; =external= (the default) and =emacs= keep the external editor and Emacs flows. =lrg_editor_code_panel_open_script (app, path, line)= applies the setting; it is what Node > Open Scripts in Editor (=node.open-scripts=, Ctrl+E, re-registered by the panel), the New Script dialog, quick open and Edit editor.yaml use. The =code.open= action and IPC method always open here.

| Feature | Behaviour |
|---------+-----------|
| Dirty marks | A tab whose text differs from the file shows a dot after its title (undoing back to the saved text clears it) |
| Save | The File > Save shortcut (Ctrl+S by default, or whatever =file.save= and =code.save= are bound to) saves the focused tab while keyboard focus is inside the panel; anywhere else it still saves the level. The key reaches the text editor first and bubbles up to the panel, which handles it before the canvas shortcuts. =code.save-all= saves every dirty tab |
| Close | Ctrl+W in the panel, the toolbar or =code.close-tab=. A dirty tab asks "Save changes?" (Save / Don't Save / Cancel; =ui.state= dialog ="confirm"=) |
| Go to line | Ctrl+G in the panel, the toolbar or =code.goto-line=: a small dialog (="goto-line"=); also =code.open= with a line |
| Reload on external change | Each tab has a =GFileMonitor=. A changed file is compared with the text last read or written (so our own saves are ignored): a clean tab reloads silently keeping the caret; a dirty one asks "File changed on disk" (="code-reload"=): *Reload* takes the disk version, *Keep Mine* keeps the tab (and does not ask again for that change). =lrg_editor_code_panel_check_disk()= runs the same check on demand |
| Text only | Files that are not UTF-8 text, contain NUL bytes or exceed 8 MiB are refused with an error |

*** Shaders (0.9.0)
:PROPERTIES:
:CUSTOM_ID: editor-panel-code-shaders
:END:
- *Highlighting*: =.rshader=, =.rmat=, =.rshadergraph= and =.rpost= open with the YAML syntax; GLSL stages (=.glsl .vert .frag .vs .fs=) with the GLSL syntax.
- *Compile on save*: saving a =.rshader= compiles it; saving a stage file compiles every =.rshader= of its folder whose vertex or fragment stage is that file. With a window this is a real GL compile and link (=lrg_shader_asset_compile()=); headless (=--headless=, tests) the document is only loaded, which still catches YAML errors, unknown keys and missing stage files. A toast reports the error count, the status line "Shader compiled".
- *Mapped diagnostics*: driver messages are mapped back to the user's file and line (=LrgShaderDiagnostic=): a stage file at its own line, an inline stage at the line of the =.rshader= below its =fragment:= / =vertex:= key, preamble messages at the =.rshader=. A strip under the editor (=code-diagnostics=, up to six rows) lists the active file's messages with an error or warning icon; clicking one jumps to its line and column. Opening a file that has errors (without an explicit line) puts the caret on the first one.
- *Problems panel*: the diagnostics are problems with the codes =shader-error= / =shader-warning= and the project-relative file; they stay listed when a level validation replaces the problem list, and go away with a clean save.
- *Hot reload*: after the save the material preview's copies of the shader reload (keep-last-good on failure), so open material editors, the shader graph preview and material thumbnails show the new code at once. Games get the same through =lrg_shader_asset_set_watch()=.
- *IPC*: =shader.create=, =shader.compile=, =shader.diagnostics=, =shader.uniforms=, =shader.reload= ([[file:ipc-protocol.org::#material-methods][IPC protocol]]).

** Physics panel and physics gizmos
:PROPERTIES:
:CUSTOM_ID: editor-panel-physics
:END:
Since 0.9.0 M5. The physics tools are described in [[file:physics.org][Physics in Levels]]; this section lists what they add to the window and the widgets for tests and =ui.state=.

- *Panel.* =LrgEditorPhysicsPanel= (=lrg_editor_physics_panel_new()=, dock id "physics", a tab of the Inspector's stack; View > Panels > Physics, action =physics.show=). Widgets: =physics-panel=; header =physics-top= / =physics-header= (=physics-title=, =physics-node=, =physics-add-body=, =physics-remove-body=); content =physics-scroll= / =physics-content=: =physics-live-section= (=physics-live=, playing only), =physics-body-grid=, =physics-shapes-heading= (=physics-shape-kind=, =physics-add-shape=), the painted list =physics-shape-list= (24 px rows from y + 1; per row up, down and remove buttons, 22 px each, right aligned), =physics-fit-row= (=physics-fit-kind=, =physics-fit=), =physics-shape-grid=, =physics-joints-heading= (=physics-joint-kind=, =physics-add-joint=), =physics-joint-list= (one remove button per row), =physics-joint-grid=; empty state =physics-empty= (=physics-hint-none=, =physics-hint-2d=, =physics-hint=, =physics-empty-kind=, =physics-empty-add=). Every edit is one level command.
- *Viewport.* Collider, joint and 2D collider gizmos with drag handles for the selected node (one undo step per drag, Escape cancels, Ctrl snaps); the overlays menu's Physics section (=vp.physics-shapes=, =vp.physics-joints=, =vp.physics-aabbs=, =vp.physics-contacts=, =vp.physics-sleeping=, =vp.physics-com=, =vp.physics-velocity=, =vp.physics-broadphase=, per viewport); while a 3D level plays the play world's physics debug draw inside the 3D pass.
- *Inspector.* =inspector-section-physics= (=inspector-physics-summary=, =inspector-physics-open=) for one inspected 3D node.
- *Hierarchy.* A body-kind badge on rows with a body; =hierarchy.state= rows carry ="physics"=.
- *IPC.* =physics.*= ([[file:ipc-protocol.org::#ipc-physics][IPC: physics methods]]), registered when the panel is created; =physics.overlay= by the viewport panel.
