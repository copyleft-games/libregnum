* The libregnum Editor Application
:PROPERTIES:
:CUSTOM_ID: editor-app
:END:
#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > Editor Application
#+end_quote

=lrgeditor= is the libregnum editor: a level, scene and world editor in the spirit of the Unity, Godot and Unreal editors, built entirely from libregnum. Since 0.8.1 its UI is drawn by libregnum's own retained UI toolkit (=LrgCanvas= and its widgets, =src/ui/=; 0.8.0 used the immediate-mode =src/gui/=, which stays in the engine), its viewport renders with the engine's raylib backend, its documents are =LrgEditor= / =LrgLevel= and its play mode runs an =LrgWorld=. Code and data files open in your own editor (=$EDITOR= by default, with first-party Emacs integration), and every editor feature can be driven over a local socket.

The application lives in =src/editor/ui/= (=LrgEditorApp=, public header =lrg-editor-app.h=) and the program in =src/launcher/lrgeditor.c=.

** Building and running
:PROPERTIES:
:CUSTOM_ID: building
:END:
The editor is built by default (=BUILD_EDITOR=1=, =BUILD_EDITOR_UI=1= in =config.mk=):

#+begin_src sh
make -j"$(nproc)"                 # library, GIR, lrgldr and lrgeditor
make lrgeditor                   # just the editor program
make test-emacs                   # Emacs package byte-compile + ERT suite
make test-editor-x11              # real window + real X input (Xvfb, xdotool) checked over IPC
make BUILD_EDITOR_UI=0            # embedded hosts that bring their own UI
#+end_src

Fedora packages needed beyond the base libregnum build (fold these into the image build):

| Package                         | Why                                               |
|---------------------------------+---------------------------------------------------|
| =json-glib-devel=               | IPC server (=LrgEditorServer=)                    |
| =glib2-devel=                   | GIO sockets, file monitors, subprocesses          |
| =mesa-libGL-devel=, =libglvnd-devel= | raylib/OpenGL 3.3 viewport                   |
| =wayland-devel=, =libxkbcommon-devel=, =libX11-devel=, =libXrandr-devel=, =libXinerama-devel=, =libXcursor-devel=, =libXi-devel= | GLFW window backends (already required by graylib) |
| =google-noto-sans-fonts= or =dejavu-sans-fonts= (runtime) | UI font (searched at fixed paths; raylib's built-in font otherwise) |
| =emacs= (optional)              | =make test-emacs=, the first-party integration    |
| =xorg-x11-server-Xvfb=, =xdotool=, =socat=, =yq= (optional) | =make test-editor-x11= (real window, real input) |

Run it on a project folder or a level:

#+begin_src sh
lrgeditor ~/games/mygame                       # project folder
lrgeditor levels/arena.rlevel                  # a level; its folder is the root
lrgeditor -p ~/games/mygame -l levels/arena.rlevel
lrgeditor --new-project ~/games/newgame --name "New Game"
lrgeditor --editor emacsclient ~/games/mygame  # external editor for this session
lrgeditor --editor 'codium --goto {file}:{line}:{col}' .
lrgeditor --module build/libmygame.so .        # register the game's component types
lrgeditor --headless --socket /tmp/lrg.sock .  # IPC server only, no window
lrgeditor --mcp ~/games/mygame                # an AI agent drives it over MCP (stdio)
lrgeditor --validate levels/arena.rlevel       # CI: problems on stdout, status 1 on errors
#+end_src

| Option                   | Meaning                                                                   |
|--------------------------+---------------------------------------------------------------------------|
| =-p=, =--project DIR=    | Open a project (a folder with =project.ryaml=, or any folder)             |
| =-l=, =--level FILE=     | Open a level (relative to the project)                                    |
| =-n=, =--new-project DIR= | Create a project (levels/, scripts/, assets/, prefabs/, starter level)   |
| =--name NAME=            | Name for =--new-project=                                                  |
| =-s=, =--settings FILE=  | Preferences file (default =$XDG_CONFIG_HOME/libregnum/editor.yaml=)       |
| =-e=, =--editor EDITOR=  | External editor preset id, or a command template                          |
| =-m=, =--module SO=      | Load a game module so its component types can be edited and played        |
| =--socket PATH=          | IPC socket (default =$XDG_RUNTIME_DIR/libregnum/editor-PID.sock=)         |
| =--no-server=            | Do not start the IPC server                                               |
| =--headless=             | No window; serve IPC until SIGINT/SIGTERM or =editor.quit=                |
| =--mcp=                  | Serve MCP on stdin/stdout for an AI agent (headless without a display); see [[file:lrgeditorctl.org::#mcp][MCP]] |
| =--validate=             | Validate the level and exit                                               |
| =-W=, =-H=               | Initial window size                                                       |
| =--license=, =--version= | Print and exit                                                            |

With no project or level, the last project is reopened (=restore-last-session=).

** Window layout
:PROPERTIES:
:CUSTOM_ID: layout
:END:
#+begin_example
 File Edit Create Node View Play Tools Help
 [Select][Move][Rotate][Scale] [World][Snap] [-1.00+][-15+][-0.10+] [3D] [Play][Pause][Step][Stop] [Run Game] Layout [single]
+-----------+-------------------------------------+-------------+
| Hierarchy | Viewport                            | Inspector   |
|           |                                     |             |
|           +-------------------------------------+             |
|           | Assets | Console | Problems | ...     | Tiles       |
+-----------+-------------------------------------+-------------+

- *Menu bar*: every menu item is an action, showing its current shortcut and enabled/checked state. Alt + the first letter (Alt+F, Alt+E, Alt+C, Alt+N, Alt+V, Alt+P, Alt+T, Alt+H) opens a menu from the keyboard; Escape closes it.
- *Toolbar*: tools, space, snap with spin boxes for the increments, 2D/3D, play controls, run game, and the viewport layout picker (=single=, =split-h=, =split-v=, =quad=; drawing split viewports arrives with the viewport panel work, the layout is already stored in the view state).
- *Status bar*: document and dirty marker, play state, a "changed on disk: Reload / Keep mine" prompt, the last status message, selection and node counts, log counters (click to open the console), IPC state ("emacs" when libregnum.el is connected), frame rate.
- *Toasts*: transient notifications in the bottom right (info, success, warning, error).

Panels can be closed (except the viewport), reopened from View > Panels, dragged by their tab onto another panel's edge or centre to split or tab them, and resized with the splitters. The layout (=LrgDockArea= YAML under =ui-layout=) is saved with the preferences; View > Reset Layout restores the default (viewport in the centre, hierarchy left, inspector and tiles right, assets, console, problems, history, timeline, profiler and code tabbed below).

In 0.8.1 Wave 3 the hierarchy, inspector, assets, console, problems, history, tiles, timeline, profiler and code panels are placeholders ("Hierarchy (Wave 4)") while their widgets are rebuilt on the new toolkit; their features stay available through actions and IPC. The command palette, quick open and the preferences editor are also Wave 4: their actions show a notification meanwhile.

** Viewport
:PROPERTIES:
:CUSTOM_ID: viewport
:END:
| Input                           | Action                                                         |
|---------------------------------+----------------------------------------------------------------|
| Drag the axis gizmo (bottom left) | Orbit; works with any mouse or touchpad                      |
| Click an end of the axis gizmo  | Look along that axis (orthographic until the next orbit)       |
| Right drag                      | Fly look; W A S D move, Q E down/up, Shift faster, wheel speed |
| Right click (no drag)           | Context menu: create, focus, delete, duplicate...              |
| Middle drag                     | Pan                                                            |
| Alt + left drag                 | Orbit around the focus point (Alt + Shift + left drag pans)    |
| Wheel, = / -, numpad + / -      | Zoom (dolly; ortho height in orthographic views)               |
| Num4 / Num6 / Num8 / Num2       | Orbit in 15 degree steps                                       |
| Num7 / Num1 / Num3 (+Ctrl)      | Top / front / right (opposite) views; Num5 toggles ortho       |
| Left click                      | Select (Shift add, Ctrl toggle); again on the same spot cycles |
| Left drag on empty space        | Box select (Shift adds)                                        |
| Left drag on the gizmo          | Move / rotate / scale; Ctrl inverts snapping; Esc/right cancels |
| Drop an asset                   | Model/texture: new node; prefab: instance; script: attach to the node under the pointer |

In 2D mode right and middle drag both pan and new nodes are created flat on the XY plane.

*Navigation schemes* (Preferences > Viewport > Navigation, =camera-navigation=): =default= is the table above; =blender= makes middle drag orbit, Shift + middle drag pan and Ctrl + middle drag zoom; =trackpad= makes two-finger scroll orbit, Shift + scroll pan and Ctrl + scroll zoom, for touchpads that cannot right- or middle-drag. The axis gizmo, the numpad and Alt + left drag work in every scheme. Orbiting out of an axis view returns to perspective (Blender's auto-perspective); an orthographic view chosen with Num5 stays orthographic.

Pointer movement made before a press never counts as part of the drag, so a press after a fast move does not snap the camera. A button or key held when the window loses focus is released (GLFW reports no releases while unfocused), so navigation cannot get stuck. Clicks and key chords faster than a frame (touchpad taps, xdotool) are latched by the input backend and never lost. Show Stats (View menu) adds a line with the pointer, buttons and modifiers as the editor sees them, the quickest way to diagnose an input device.

Rendering: primitives are unit-sized meshes matching the picking bounds (cube, spheres, plane, cylinder, cone, torus, disc, grid, 2D rectangle and circle), lit by a small GLSL 3.3 shader (flat colour fallback); mesh assets (glTF/OBJ/...) and sprite textures load on demand and are cached; missing assets show as magenta boxes and are reported once in the console. Lights, cameras, audio emitters and empty nodes draw as constant-size icons. Selection draws the bounds (primary brighter). The grid adapts to the zoom (=grid-size= times a power of ten, =grid-extent= cells each way) and shows the world axes. The gizmo is drawn in screen space from the same geometry its hit test uses. An overlay shows the view mode, stats (node count, selection, fps) and an orientation axis.

** Hierarchy, inspector, assets
:PROPERTIES:
:CUSTOM_ID: panels
:END:
- *Hierarchy*: tree with kind glyphs, visibility/lock toggles, inline rename (F2 or double click), drag to reparent (drop on a row) or reorder (drop between rows), Shift-click range and Ctrl-click toggle selection, filter by name or GUID (Ctrl+F), context menu (create submenu, copy GUID/path...), and the selection is revealed and scrolled to when it changes elsewhere.
- *Inspector*: name, flags, path, GUID; transform with world readout (edits apply to every selected node); visual kind, primitive, asset path (with picker and drop target), material colour/roughness/metallic/emission, custom parameters (number, text, bool, colour); components (add with a searchable list of registered types, edit properties with type-aware widgets, remove); scripts (new script from a template, attach existing, open in the external editor, enable, remove); prefab instances can open their prefab or be reverted to it. Drags merge into a single undo step.
- *Tiles* and *Timeline*: see [[file:editor-tools.org][Editor Tools]] (View > Panels; Tiles docks next to the inspector, Timeline next to Assets).
- *Assets*: breadcrumb navigation, list or grid view (with generated thumbnails, see [[file:editor-tools.org::#asset-thumbnails][Asset thumbnails]]), name filter and type filter, double click to open (levels and prefabs open in the editor, media in the desktop application, everything else in the external editor), drag into the viewport or the inspector, rename, move to the trash (never deleted), copy path, new folder, new script; refreshes itself through a file monitor.

** Console, history, problems
:PROPERTIES:
:CUSTOM_ID: console
:END:
The console shows every GLib log message (the editor installs a log writer), messages from the game when run with F6, and IPC activity. Filter by level and text, toggle auto-scroll, copy, clear. The input line (history with Up/Down) takes:

| Input                          | Effect                                                        |
|--------------------------------+---------------------------------------------------------------|
| =help=                         | List the commands and every IPC method                        |
| =clear=                        | Clear the log                                                 |
| =:ID=                          | Run an editor action, e.g. =:view.top=                        |
| =::= (or =:=)                  | List action ids                                               |
| =METHOD key=value ...=         | Call an IPC method, e.g. =node.find query=Door=, =node.rename node=Door name=Gate= |
| ={"method": ...}=              | A raw JSON request                                            |

The reply is printed in the console, so anything the IPC protocol can do is available from the console too.

The *History* panel lists undo steps (newest last) and the redo stack; clicking a row jumps there. *Problems* lists validation results for the open level (codes: =missing-guid=, =duplicate-guid=, =duplicate-name=, =unnamed=, =slash-in-name=, =non-finite-transform=, =zero-scale=, =missing-asset-ref=, =missing-asset=, =component-no-type=, =unknown-component=, =script-no-path=, =script-no-language=, =script-disabled=, =missing-script=); clicking one selects the node.

** Play in editor and running the game
:PROPERTIES:
:CUSTOM_ID: play
:END:
F5 starts play-in-editor: the level is materialised into a private =LrgWorld= with =lrg_level_instantiate()= (component descriptions resolved through the engine registry, script bindings as =LrgScriptComponent=), the world ticks every frame, and what the simulation moves is written back to the nodes so the viewport shows the game running. F7 pauses, F10 steps one frame, Shift+F5 (or F8) stops. Stopping restores the level exactly: edits made while playing are undone (and stay on the redo stack, so a change worth keeping is one Ctrl+Shift+Z away), transforms the simulation wrote are restored from a snapshot, and the document's dirty state is put back.

F6 runs the game as its own process. The command comes from the project (Project Settings > Run command), a template with ={project}=, ={level}= and ={module}= placeholders; the default is =lrgldr {module} -- --level {level}= with ={module}= the project's game output. The level is saved first, the template is split like a shell command before substitution (paths with spaces stay one argument), and the game's output streams into the console with warnings and errors highlighted. Shift+F6 stops it.

** Documents, autosave and live reload
:PROPERTIES:
:CUSTOM_ID: documents
:END:
- Unsaved work is never discarded silently: opening, creating, reloading or quitting asks Save / Don't Save / Cancel (=confirm-on-close=). Saving an untitled level goes through Save As and then carries on with what was asked.
- Autosave writes the open level every =autosave-interval= seconds while it has changes, into =<project>/.lrg-editor/autosave/<name>-<hash>.autosave= (next to the level without a project). Opening a level whose autosave is newer offers Restore / Discard (moves it to the trash) / Later.
- The open level file is watched. When it changes on disk (for example saved from Emacs) the editor reloads it if it has no unsaved changes (=reload-on-external-change=), keeping the selection by GUID; otherwise the status bar offers Reload / Keep mine.
- File > Import Scene reads a Blender-exported scene YAML into a new untitled level.

** Preferences (editor.yaml)
:PROPERTIES:
:CUSTOM_ID: preferences
:END:
Preferences are edited live in Edit > Preferences (Ctrl+,) and written when the dialog closes; "Edit editor.yaml" opens the file in your editor. The file is =$XDG_CONFIG_HOME/libregnum/editor.yaml= (override with =--settings= or =LRG_EDITOR_CONFIG=). *** Themes
:PROPERTIES:
:CUSTOM_ID: preferences-theme
:END:
=theme= takes one of three forms. An =LrgTheme= preset name (=midnight=, =daylight=, =catppuccin-mocha=, =catppuccin-latte=, =high-contrast=) selects that preset. A value with a directory separator or ending in =.yaml= / =.yml= is the path of a theme YAML file. The 0.8.0 names are still read: =mocha= resolves to =catppuccin-mocha=, =latte= to =catppuccin-latte=, and =macchiato= and =frappe= to the shipped theme files =data/editor/themes/catppuccin-macchiato.yaml= and =catppuccin-frappe.yaml= (the settings migration rewrites them to those names, see [[#settings-migration][Settings migration]]; without the files they fall back to =catppuccin-mocha=). An unknown name falls back to =catppuccin-mocha=. The default value is still =mocha= so 0.8.0 reads the file back unchanged. ~lrg_editor_settings_get_theme_preset~ and ~lrg_editor_settings_get_theme_file~ do this resolution; the app builds its =LrgTheme= from the file when there is one (=lrg_theme_new_from_file()=), else from the preset, and scales every theme metric by =ui-scale= x =font-size= / 16. Changing =theme=, =ui-scale= or =font-size= applies live.

** Keybinding syntax
:PROPERTIES:
:CUSTOM_ID: keybindings
:END:
Since 0.8.1 shortcuts are GTK-style accelerators: zero or more modifiers in angle brackets followed by one key name. The 0.8.0 "Ctrl+Shift+S" syntax is still accepted wherever a shortcut comes in, so old =editor.yaml= files, scripts and embedders keep working.

*** Accelerators
:PROPERTIES:
:CUSTOM_ID: keybindings-accel
:END:
- Modifiers: =<Ctrl>= (also =<Control>=, =<Primary>=), =<Shift>=, =<Alt>=, =<Super>= (also =<Meta>=). The editor writes them in the order Ctrl, Alt, Shift, Super.
- Keys: letters in lower case (=<Shift>= is explicit: =<Ctrl><Shift>z=), digits, =F1= to =F12=, =KP_0= to =KP_9= and =KP_Add= / =KP_Subtract= / =KP_Multiply= / =KP_Divide= / =KP_Decimal= / =KP_Enter=, =Escape=, =Return=, =Tab=, =BackSpace=, =Delete=, =Insert=, =Home=, =End=, =Page_Up=, =Page_Down=, =Up=, =Down=, =Left=, =Right=, =space=, and punctuation by name: =minus=, =equal=, =plus= (the same key as =equal=), =comma=, =period=, =slash=, =backslash=, =semicolon=, =apostrophe=, =grave=, =bracketleft=, =bracketright=. The full list is in ~lrg_accel_parse~ ([[file:../modules/ui/actions.org][UI actions]]).
- Several alternatives go in one string separated by =|=, e.g. =<Ctrl><Shift>z|<Ctrl>y=; menus show the first.
- =""= unbinds an action; removing the key restores the default.

*** The 0.8.0 syntax
:PROPERTIES:
:CUSTOM_ID: keybindings-legacy
:END:
Strings like =Ctrl+Shift+2=, =Num7=, =Ctrl+,= or =Shift+F5|F8= are converted with ~lrg_editor_shortcut_to_accel~ when they are read: from =editor.yaml=, from ~lrg_editor_actions_add~ (the app's built-in defaults are still written this way) and from ~lrg_editor_actions_set_accels~. An alternative that already looks like an accelerator (it has a =<Modifier>= or is a bare accelerator key name such as =KP_7= or =comma=) passes through unchanged.

| 0.8.0                 | Accelerator              |
|-----------------------+--------------------------|
| =Ctrl+S=              | =<Ctrl>s=                |
| Ctrl+Shift+Z\vert{}Ctrl+Y | <Ctrl><Shift>z\vert{}<Ctrl>y |
| =Ctrl+Shift+2=        | =<Ctrl><Shift>2=         |
| =Num7=, =Ctrl+Num7=   | =KP_7=, =<Ctrl>KP_7=     |
| =Ctrl+,= / =Ctrl+/=   | =<Ctrl>comma= / =<Ctrl>slash= |
| === / =-= / =Ctrl++=  | =equal= / =minus= / =<Ctrl>plus= |
| =[= / =]=             | =bracketleft= / =bracketright= |
| =PageUp= / =Backspace= / =Enter= / =Esc= / =Del= | =Page_Up= / =BackSpace= / =Return= / =Escape= / =Delete= |
| =Alt+Up=, =Shift+F5=  | =<Alt>Up=, =<Shift>F5=   |
| =Meta+X= (0.8.0 Meta was Alt) | =<Alt>x=          |
| =Win+L= / =Logo+L=    | =<Super>l=               |

~lrg_editor_shortcut_to_accel~ is strict (one invalid alternative rejects the whole string, so a migration can drop it with a log line); bindings read from settings or defaults are lenient (an invalid alternative is dropped, the rest stay bound). ~lrg_editor_settings_get_keybinding~ returns the stored text as written; ~lrg_editor_settings_get_keybinding_accel~ returns it converted. The settings migration (=settings-version= 1 to 2) rewrites the stored values as accelerators.

*** Actions as a GActionGroup
:PROPERTIES:
:CUSTOM_ID: keybindings-gaction
:END:
=LrgEditorActions= implements =GActionGroup=. Every action is named by its id (=file.save=, =edit.select-all=; ids are letters, digits, =-= and =.=, checked with ~g_action_name_is_valid~ when registered), so with the registry inserted on a widget as group =editor= a menu item refers to =editor.file.save=. Actions are enabled when their enabled callback says so; toggles (actions with a checked callback, such as =view.grid=) have a boolean state, every other action is stateless, and none takes a parameter. Activating a toggle with a boolean target, or changing its state, runs it only when the value differs.

The callbacks are polled: ~lrg_editor_actions_refresh_state~ (called once per frame by the window) emits =action-enabled-changed= and =action-state-changed= only for actions whose value changed, and running an action refreshes right away.

| Function | Use |
|----------+-----|
| ~lrg_editor_actions_get_accels (actions, id)~ | Effective accelerators (user override or default), one per element |
| ~lrg_editor_actions_get_default_accels (actions, id)~ | Built-in accelerators |
| ~lrg_editor_actions_set_accels (actions, id, accels)~ | Override (written to =editor.yaml= when the registry has settings); an empty array unbinds, =NULL= restores the default |
| ~lrg_editor_actions_find_by_accel (actions, key, mods)~ | The enabled action bound to a =GrlKey= chord |
| =accels-changed= signal (detailed by id) | The effective accelerators of an action changed |
| ~lrg_editor_accel_to_label (accel)~ | Menu text: <Ctrl><Shift>z\vert{}<Ctrl>y becomes "Ctrl+Shift+Z, Ctrl+Y" |

The =LrgGuiKey= helpers of 0.8.0 (~lrg_editor_shortcut_parse~, ~lrg_editor_shortcut_format~, ~lrg_editor_actions_find_by_shortcut~, ~lrg_editor_actions_get_shortcut~, ~lrg_editor_actions_get_default_shortcut~) still work and are deprecated in =lrg-editor-shortcut-legacy.h= for one release. ~lrg_editor_actions_find_by_shortcut~ matches bindings in either syntax, and the two string getters return 0.8.0 text (as written, or converted from accelerators).

** Architecture
:PROPERTIES:
:CUSTOM_ID: architecture
:END:
Since 0.8.1 the application is three layers: the editor core (=LrgEditor=, documents, commands, IPC server; unchanged), a headless view model (=LrgEditorViewState=, =LrgEditorViewportNav=, =LrgEditorPlaySession=, see [[file:view-model.org][View Model]]) and a retained UI on =src/ui/=. Everything a tool, test or IPC client can see or change lives in the first two, so the same state is driven by the widgets, by =view.*= / =play.*= / =timeline.*= IPC and by =lrgeditor --headless=.

#+begin_example
LrgEditorApp
 |- core: LrgEditor, LrgEditorSettings, LrgEditorActions, LrgEditorServer, LrgEditorLog,
 |        LrgExternalEditor, LrgProject, LrgAssetDatabase (write-meta), LrgEditorVcs, thumbnails
 |- view model: LrgEditorViewState, LrgEditorViewportNav, LrgEditorPlaySession,
 |              LrgEditorGizmo, LrgEditorTilePainter
 '- UI: LrgCanvas
         |- LrgEditorWindow (LrgContainer)
         |    |- LrgMenuBar          GMenuModel from the action registry ("editor.<id>")
         |    |- toolbar             tool / snap / play buttons, snap spin boxes, layout picker
         |    |- LrgDockArea         one LrgDockPanel per panel
         |    |    '- viewport: LrgEditorViewportPanel > LrgViewport (render mode)
         |    |                     > LrgEditorSceneRenderer
         |    '- status bar
         '- overlay: LrgToastQueue
#+end_example

*** The frame
:PROPERTIES:
:CUSTOM_ID: architecture-frame
:END:
=lrg_editor_app_run()= opens the window and loops: drain the GLib main context (IPC, file monitors, file dialogs, the game process), poll an =LrgCanvasInput= from raylib (=lrg_canvas_input_poll()=, plus a GLFW latch so presses and chords shorter than a frame are not lost), =lrg_editor_app_process_frame()=, then =BeginDrawing()=, =lrg_canvas_render()=, the pending window screenshot and =EndDrawing()= (through graylib's frame sync).

=lrg_editor_app_process_frame (app, input, width, height)= is the whole per-frame logic and needs no window:

1. Size the canvas, window and toast overlay; take the "editor" action group off the canvas while a modal dialog is open (so shortcuts cannot fire behind it).
2. =editor_window_refresh()=: =lrg_editor_actions_refresh_state()= (menus follow enabled / checked states), re-register canvas shortcuts when bindings changed, copy the model into the toolbar and status bar.
3. Lay out, then =lrg_canvas_process_input()=: shortcuts, menus, dialogs and the viewport get the input; the canvas clock advances (springs, the viewport's render into its texture).
4. Tick navigation (held fly keys), the play session, timeline playback, thumbnails, autosave and the debounced validation; update the window title.
5. Headless (no window), record the canvas so popups and widgets are laid out for =ui.state=.

=lrg_editor_app_run_headless()= runs step 4 every 100 ms from a GLib timeout instead.

*** Actions, menus and shortcuts
:PROPERTIES:
:CUSTOM_ID: architecture-actions
:END:
=LrgEditorActions= is a plain =GActionGroup=; =LrgMenu= looks actions up with =lrg_widget_lookup_action()=, which needs a =GActionMap=. The window therefore mirrors the registry into a =GSimpleActionGroup= inserted as =editor= (boolean-stateful actions for toggles), kept in step through the registry's =action-added= / =-removed= / =-enabled-changed= / =-state-changed= signals; activating a mirror action runs the registry action. A second group, =win=, holds what has no registry action: =win.open-recent-level= / =win.open-recent-project= (string target), =win.create= (node kind: =empty cube sphere plane cylinder cone torus rectangle circle light camera audio sprite mesh tilemap=) and =win.panel-<id>= (boolean, View > Panels).

The menu bar's =GMenuModel= (=lrg_editor_window_get_menu_model()=) has the 0.8.0 menus in the 0.8.0 order and contents, with mnemonics (=_File=), so Alt+F, Alt+E, Alt+C, Alt+N, Alt+V, Alt+P, Alt+T and Alt+H open them. Every accelerator of every action is registered with =lrg_canvas_add_shortcut()= on =editor.<id>=, and re-registered on =accels-changed=. The canvas offers a key to the focused widget first (a text field keeps Ctrl+C), then to shortcuts, then to the menu bar's mnemonics. The viewport consumes W A S D Q E only while flying.

*** The viewport
:PROPERTIES:
:CUSTOM_ID: architecture-viewport
:END:
=LrgEditorViewportPanel= holds an =LrgViewport= in =LRG_VIEWPORT_MODE_RENDER= whose render function hands its texture to =LrgEditorSceneRenderer= (grid, nodes, icons, selection bounds, transform gizmo, orientation axes, box-select rectangle and overlay text; the same look as 0.8.0). Input follows the view model's "Wave 3 wiring": a press goes to tile painting (paint mode on a tilemap), then =lrg_editor_viewport_nav_pointer_press()=, then the transform gizmo, else =lrg_editor_viewport_nav_press_empty()=; the navigator's =click= picks (with cycling through overlapping nodes), =box-select= selects and =context-menu= opens the viewport menu. Key releases bubble to the panel (held fly keys), and losing focus releases them. =view.screenshot= reads the viewport's render texture back.

*** Scene renderer
:PROPERTIES:
:CUSTOM_ID: scene-renderer
:END:
=LrgEditorSceneRenderer= draws what an editor viewport shows. It uses only raylib and rlgl, never the immediate-mode GUI, with fixed Catppuccin Mocha colours. Create one per editor with =lrg_editor_scene_renderer_new (editor)= and bind its inputs: =set_settings()= (=grid-size= and =grid-extent=, re-read on notify), =set_base_dir()= (what relative asset paths resolve against; changing it forgets the per-asset lookups), =set_gizmo()= and =set_playing()= (darker background during play).

Call =lrg_editor_scene_renderer_render (renderer, view_state, viewport, nav, active, width, height)= from an =LrgViewport= render callback, inside =BeginTextureMode()= on a =width= x =height= target; it clears the target itself. =viewport= is the camera index (-1 for the active one); the camera's render mode (=WIREFRAME= draws in wire mode, the other modes are lit for now) and overlay flags (=GRID=, =ICONS=, =GIZMOS=, =STATS=) are honoured. The transform gizmo is drawn only when =active=; the orientation axes and the box-select rectangle come from =nav= (nullable) so they match its hit testing. =get_drawn()= returns the draw calls of the last render.

GPU resources (lit shader, primitive meshes, model and texture caches) are created on the first render; =render()= returns =FALSE= and draws nothing without a window. =forget_asset (abs_path)= drops one cached model or texture (live reload). =release()= frees all GPU resources and must be called before =CloseWindow()=. =render_model_thumbnail()= and =render_font_thumbnail()= return a size x size =GrlImage= for the thumbnail cache's GPU hooks (models; font samples "Aa Bb 123" at the size and code points of the font's =.meta= sidecar); they run outside any texture mode.

*** Dialogs
:PROPERTIES:
:CUSTOM_ID: architecture-dialogs
:END:
Modal dialogs are =LrgDialog= and =LrgFileDialog= (in-app, not the desktop portal): unsaved changes (Save / Don't Save / Cancel), open level and save level as (=.rlevel= filter), open project (folder), import scene, save as prefab and instantiate prefab (=.rprefab=), new project, new script, crash recovery (Restore / Discard / Later), about, keyboard shortcuts and a project settings summary. *** Projects, assets and version control
:PROPERTIES:
:CUSTOM_ID: architecture-projects
:END:
Opening a project scans it with an =LrgAssetDatabase= that has =write-meta= on, so missing =.meta= sidecars are created (the editor is the only writer; =lrgeditorctl=, validators and the =asset.list= IPC method scan read-only). An =LrgEditorVcs= follows the project's git status. *** Migrating from LrgGui embedding
:PROPERTIES:
:CUSTOM_ID: embedding-migration
:END:
Code that drove the 0.8.0 editor with =lrg_editor_app_frame()= and an =LrgGuiInput= keeps compiling (with a deprecation warning) and working: the frame is translated into an =LrgCanvasInput= by =lrg_editor_gui_input_to_canvas()=. Button presses and releases are found by comparing with the previous call's buttons, key releases by comparing =key_down= arrays (so release a held key by clearing its =key_down= entry), key presses, repeats, typed text, the wheel and the modifiers are copied, and =LrgGuiKey= values are mapped to =GrlKey=. To move over:

- Build an =LrgCanvasInput= yourself (=lrg_canvas_input_init()=, set =pointer_x/y=, =buttons_down= / =buttons_pressed= / =buttons_released= with =LRG_CANVAS_BUTTON_MASK()=, =lrg_canvas_input_add_key()=, =lrg_canvas_input_add_key_release()=, =lrg_canvas_input_add_text()=, =modifiers=, =delta_time=) and call =lrg_editor_app_process_frame()=; or poll it from raylib with =lrg_canvas_input_poll()=.
- Drawing: =lrg_canvas_render (lrg_editor_app_get_canvas (app))= between =BeginDrawing()= and =EndDrawing()= replaces rendering the GUI draw list.
- =lrg_editor_app_get_gui()= returns =NULL=; inspect widgets through the canvas instead (=lrg_widget_find()=, =lrg_canvas_record()= and the paint list), and use =ui.state= for menu and viewport rectangles.
- Custom panels: wrap your widget in an =LrgDockPanel= and call =lrg_editor_app_add_panel()= instead of drawing into an =LrgGuiDock= panel.
- Shortcuts: write accelerators (=<Ctrl><Alt>b=); the 0.8.0 =Ctrl+Alt+B= syntax is still accepted (see [[#keybindings][Keybinding syntax]]).

=tests/editor-app-fixture.h= shows the headless pattern: it builds frames with pointer, button, key and text helpers, clicks widgets by their rectangles and sends IPC requests through =lrg_editor_server_dispatch()=.

** Frame cost
:PROPERTIES:
:CUSTOM_ID: frame-cost
:END:
The editor redraws every frame, so panels avoid work proportional to the whole level or log when only a screenful is visible:

- *Pacing*: the window runs with vsync and caps at the largest whole fraction of the monitor's refresh rate that is at most 75 fps (60 on 60/120 Hz, 72 on 144 Hz, 55 on 165 Hz), so frames always span the same number of vblanks; a fixed 60 cap on a 144 Hz monitor alternated two- and three-vblank frames. Like games, the editor keeps its UI thread on a hybrid CPU's performance cores (=LRG_CPU_AFFINITY=none= to opt out) and bounds its frames in flight to 2 with graylib's frame sync (=grl_frame_sync_end_drawing()= in place of =EndDrawing()=; =LRG_MAX_FRAMES_IN_FLIGHT= overrides it, see [[file:../performance.org::#input-latency][input latency]]).

- *Panels*: the console, hierarchy and asset panels of 0.8.0 kept row caches against the log ring and the node tree serial (below); their retained replacements (Wave 4) use list and tree views over =GListModel=, which lay out only visible rows. =LrgEditorLog= still keeps per-level tallies, so the status bar counters (=lrg_editor_log_count_level()=) do not walk the ring.
- *0.8.0 console*: each log record is formatted (timestamp, level, domain), casefolded for the filter and measured once, when it first appears, into a row cache mirrored from the log ring; the filtered row list is extended incrementally and rebuilt only when the level toggles or the filter text change. Only the rows inside the scroll view are laid out; the rows above and below become one spacer each, of the same total height and of the widest row's width, so scrolling and the horizontal extent are unchanged. A row whose context menu is open keeps building it while it scrolls out of view. =LrgEditorLog= keeps running per-level tallies, so the console tab and status bar badges (=lrg_editor_log_count_level()=) do not walk the ring.
- *0.8.0 hierarchy*: rows outside the tree's view submit only their tree node (keyed by GUID, so open state, layout, keyboard navigation order and a held row behave as before) and skip the toggles, label, measuring, drop targets and menu; the row being renamed, the one being revealed and one with an open context menu are always drawn in full. The node count (outliner header, status bar, viewport overlay) and the filter's match set are cached against a process-wide node tree serial (bumped when nodes are created, destroyed, re-parented, renamed or given a new GUID) and recomputed only when it or the filter text changes. =LrgEditorSelection= keeps a hash set beside its ordered array, so the per-row "is selected" test is constant time.
- *Viewport rendering*: the scene walk passes each node's world matrix down to its children (one local matrix composed per node instead of a walk back to the root), and icons take their position from it. Mesh and sprite assets are looked up by the node's asset string as written, one hash lookup per node per frame, with the absolute path built and the file loaded only on first use; that map is cleared when the project or level directory (what relative paths resolve against) changes. =grid-size= and =grid-extent= are re-read from the settings only after a =notify=.

** Settings migration
:PROPERTIES:
:CUSTOM_ID: settings-migration
:END:
An =editor.yaml= written by 0.8.0 has no =settings-version= key and loads as version 1. On start-up the editor calls ~lrg_editor_settings_migrate (settings, NULL, &error)~ (=lrg-editor-settings-migrate.h=), which brings the file to version 2 once: it backs the file up, converts the layout, the keybindings and the theme name, sets =settings-version: 2= and saves. Everything else (=ui-scale=, fonts, camera and snap settings, recent files, keys the editor does not know) is kept as it is. A version-2 file is left alone, so the call is cheap on every start and running it twice changes nothing.

*** When it runs and the backup
:PROPERTIES:
:CUSTOM_ID: settings-migration-backup
:END:
~lrg_editor_settings_needs_migration~ is true while =settings-version= is below =LRG_EDITOR_SETTINGS_VERSION= (2). The file migrated is the =path= argument, else the file the settings were loaded from (~lrg_editor_settings_get_path~), else the default path. Before anything is rewritten the existing file is copied to =editor.yaml.v0.8.0.bak= (=LRG_EDITOR_SETTINGS_BACKUP_SUFFIX=); an existing backup is never overwritten, so after a downgrade and a second upgrade the backup is still the first 0.8.0 file. Settings that were never on disk get no backup. If the backup cannot be written the migration stops with an error and changes nothing. A symlinked =editor.yaml= (for example one managed by GNU Stow) is written through to its target instead of being replaced by a plain file.

*** Layout
:PROPERTIES:
:CUSTOM_ID: settings-migration-layout
:END:
The 0.8.0 window stored its dock layout under =layout= in the compact =LrgGuiDock= grammar: =split(D,RATIO,A,B)= with =D= =v= (children side by side) or =h= (stacked), and =tabs(ACTIVE,id,...)= for a tab stack. ~lrg_editor_settings_convert_legacy_layout~ parses it exactly as 0.8.0 did (blanks between tokens, ratios clamped to 0.05 - 0.95, the active index clamped to the tab count, at most 64 levels) and writes the =LrgDockArea= YAML of [[file:../modules/ui/widgets/dock-area.org::#dock-area-persistence][dock area persistence]] into =ui-layout=. The old =layout= key is left untouched so 0.8.0 still finds its layout after a downgrade. Panel ids are copied unchanged: =viewport=, =hierarchy=, =inspector=, =assets=, =console=, =problems=, =history=, =tiles= and =timeline= are the same panels in 0.8.1.

| 0.8.0                       | =LrgDockArea= YAML                                   |
|-----------------------------+------------------------------------------------------|
| =split(v,0.20,A,B)=         | ={ split: horizontal, ratio: 0.2, first: A, second: B }= |
| =split(h,0.72,A,B)=         | ={ split: vertical, ratio: 0.72, first: A, second: B }= |
| =tabs(1,console,assets)=    | ={ tabs: [console, assets], active: assets }=        |
| (no floating panels)        | =floating: []=                                       |

For example =split(v,0.20,tabs(0,hierarchy),split(h,0.72,tabs(0,viewport),tabs(1,console,assets)))= becomes the dock tree =H(0.20,[hierarchy*],V(0.72,[viewport*],[console,assets*]))= (in =lrg_dock_area_describe()= notation). A layout string that does not parse leaves =ui-layout= empty, so the window starts with its default layout, and logs a message with the parse error. A =ui-layout= that is already present is never replaced.

*** Keybindings
:PROPERTIES:
:CUSTOM_ID: settings-migration-keybindings
:END:
Every override is rewritten in accelerator syntax with ~lrg_editor_settings_convert_legacy_shortcut~, which runs ~lrg_editor_shortcut_to_accel~ on each =|=-separated alternative on its own: =Ctrl+Shift+Z|Ctrl+Y= becomes =<Ctrl><Shift>z|<Ctrl>y=, =Num7= =KP_7=, =Ctrl+,= =<Ctrl>comma=; values already in accelerator syntax stay as they are and =""= (an unbinding) stays =""=. An alternative that does not convert is dropped and the rest are kept (=Shift+F5|Wibble= becomes =<Shift>F5=); a value with no valid alternative is removed, so the action gets its default shortcut back. Both cases log a message naming the action and the old text.

*** Theme
:PROPERTIES:
:CUSTOM_ID: settings-migration-theme
:END:
~lrg_editor_settings_convert_legacy_theme~ maps the four 0.8.0 names (case-insensitively); any other value, a preset name or a theme file path, is kept.

| 0.8.0       | 0.8.1                  | Resolves to                                               |
|-------------+------------------------+-----------------------------------------------------------|
| =mocha=     | =catppuccin-mocha=     | the built-in preset                                       |
| =latte=     | =catppuccin-latte=     | the built-in preset                                       |
| =macchiato= | =catppuccin-macchiato= | =data/editor/themes/catppuccin-macchiato.yaml=            |
| =frappe=    | =catppuccin-frappe=    | =data/editor/themes/catppuccin-frappe.yaml=               |

The two theme files use the official Catppuccin Macchiato and Frappé palettes mapped onto the same colour roles and metrics as the =catppuccin-mocha= preset, and load with ~lrg_theme_new_from_file~. The migrated value is the bare name, not a path, so it survives the editor being moved or reinstalled. A bare theme name that is neither a preset nor a 0.8.0 name is looked up as a file by ~lrg_editor_settings_find_theme_file~: =NAME.yaml= (or =NAME= when it already ends in =.yaml= / =.yml=) in

1. each directory of =$LRG_EDITOR_THEME_PATH= (separated like =$PATH=),
2. =$XDG_DATA_HOME/libregnum/editor/themes= (your own themes),
3. =PREFIX/share/libregnum/editor/themes= when the library was built with =LRG_DATADIR=,
4. =libregnum/editor/themes= under each directory of =$XDG_DATA_DIRS=,
5. =data/editor/themes= next to the running executable or in one of its parents (an uninstalled build tree).

When the file is found ~lrg_editor_settings_get_theme_file~ returns it and ~lrg_editor_settings_get_theme_preset~ returns =NULL=; when it is not, the name falls back to the =catppuccin-mocha= preset like any unknown name. The 0.8.0 names themselves keep resolving to presets (=macchiato= and =frappe= to =catppuccin-mocha=) in a file that has not been migrated yet.

*** Other keys
:PROPERTIES:
:CUSTOM_ID: settings-migration-other
:END:
=ui-scale= is not converted: the window applies it as the canvas pointer transform and the theme scale. The migration does not add keys; the 0.8.1 keys (=ui-layout=, =script-editor=, =viewport-layout= and =viewport-cameras=, the four viewport cameras as written by ~lrg_editor_view_state_cameras_to_string~, default =""=) are written with their defaults on the first save.

*** API
:PROPERTIES:
:CUSTOM_ID: settings-migration-api
:END:
| Function                                        | Use                                                        |
|-------------------------------------------------+------------------------------------------------------------|
| ~lrg_editor_settings_migrate (settings, path, error)~ | Back up, convert, set version 2 and save; no-op when current |
| ~lrg_editor_settings_needs_migration (settings)~ | =settings-version= is below 2                              |
| ~lrg_editor_settings_convert_legacy_layout (layout, error)~ | 0.8.0 layout string to =LrgDockArea= YAML, or =NULL= with =G_IO_ERROR_INVALID_DATA= |
| ~lrg_editor_settings_convert_legacy_shortcut (shortcut)~ | Lenient conversion to accelerators, or =NULL= if nothing is valid |
| ~lrg_editor_settings_convert_legacy_theme (theme)~ | 0.8.1 theme value for a 0.8.0 name                         |
| ~lrg_editor_settings_find_theme_file (name)~    | The theme file for a bare name, or =NULL=                  |
| ~lrg_editor_settings_get_path (settings)~       | The file the settings were loaded from                     |
