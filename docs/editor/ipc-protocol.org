* Editor IPC Protocol
:PROPERTIES:
:CUSTOM_ID: ipc-protocol
:END:
#+begin_quote
*[[file:../index.org][Home]]* > *[[file:overview.org][Editor Module]]* > IPC Protocol
#+end_quote

The editor exposes its document and its UI over a local socket, so anything can drive it: the first-party Emacs package, shell scripts, test harnesses, build tools, other editors. Protocol version 1 (=LRG_EDITOR_SERVER_PROTOCOL_VERSION=).

The server is =LrgEditorServer= (=src/editor/lrg-editor-server.h=). It serves the document methods on its own, so they work in any embedding and with =lrgeditor --headless=. =LrgEditorApp= registers the application methods (actions, view, play, run, project, assets) on top, and since 0.8.1 the panels of the rebuilt editor register their own methods when they are constructed (hierarchy, inspector, viewport split, assets, code, palette, preferences, data editors, profiler). The [[#method-index][method index]] lists all 130 methods of 0.8.1 and where each is documented; =methods= returns the same list at run time. Protocol version 1 is unchanged in 0.8.1: every addition is a new method or a new reply field, and no 0.8.0 method changed its parameters or replies.

For the command line, =lrgeditorctl= wraps every method below (see [[file:lrgeditorctl.org][lrgeditorctl and MCP]]); AI agents get the same operations as MCP tools.

** Transport
:PROPERTIES:
:CUSTOM_ID: transport
:END:
- A Unix stream socket, mode 0600, at =$XDG_RUNTIME_DIR/libregnum/editor-PID.sock= by default; =--socket PATH=, the =server-socket= preference or =LRG_EDITOR_SOCKET= choose another. Paths longer than the =sun_path= limit (107 bytes) are rejected instead of truncated. A stale socket file is replaced; a live one (another editor) is an error.
- Many clients can be connected at once.
- Each message is one JSON object on one line, UTF-8, terminated by =\n=.
- The editor processes requests on its main loop between frames, in order, one connection at a time; replies come back in request order per connection.

** Messages
:PROPERTIES:
:CUSTOM_ID: messages
:END:
#+begin_example
request   {"id": 7, "method": "node.get", "params": {"node": "House/Door"}}
result    {"id": 7, "result": {...}}
error     {"id": 7, "error": {"code": "not-found", "message": "No node 'House/Door'"}}
event     {"event": "selection", "data": {"nodes": ["8c1e..."], "primary": "8c1e..."}}
#+end_example

- =id= is any JSON number or string chosen by the client; it is echoed back. A request without an =id= is a notification: it runs and gets no reply.
- =params= is an object (may be omitted).
- Events never carry an =id=.

Error codes:

| Code               | Meaning                                         |
|--------------------+-------------------------------------------------|
| =parse=            | The line is not JSON                            |
| =invalid-request=  | Not a request object / no method                |
| =method-not-found= | Unknown method                                  |
| =invalid-params=   | Missing or mistyped parameter                   |
| =not-found=        | The node, file, action or path does not exist   |
| =failed=           | The operation failed (message says why)         |

Node parameters (=node=, =parent=) accept either a GUID or a slash-separated name path from the top of the level (="House/Door"=).

** Session
:PROPERTIES:
:CUSTOM_ID: session
:END:
Start with =hello=:

#+begin_example
-> {"id":1,"method":"hello","params":{"client":"emacs","capabilities":["open-file"],
                                     "subscribe":["changed","selection","level","saved","log"]}}
<- {"id":1,"result":{"server":"libregnum-editor","protocol":1,"pid":4242,
                     "project":"/home/me/games/mygame","level":"/home/me/games/mygame/levels/main.rlevel",
                     "client_id":3}}
#+end_example

- =client= names the client in the editor's console.
- =capabilities=: =open-file= means "I can visit files for the user"; the editor then sends =open-file= events to the most recently active such client instead of launching an external editor (see [[file:external-editor.org][External code editor]]).
- =subscribe= lists the events wanted; ="*"= means all. Without =subscribe= a client gets every event except =log= (chatty, opt-in).

** Events
:PROPERTIES:
:CUSTOM_ID: events
:END:
| Event       | Data                                                                       | When                                   |
|-------------+----------------------------------------------------------------------------+----------------------------------------|
| =changed=   | =dirty=, =undo=, =redo=, =nodes=, =last= (label of the last command)       | After edits, undo, redo (coalesced)    |
| =selection= | =nodes= (GUIDs), =primary=                                                 | The selection changed                  |
| =level=     | =path=, =name=                                                             | A level was opened, created, reloaded  |
| =saved=     | =path=                                                                     | The level was written                  |
| =tool=      | =tool=, =space=, =snap=                                                    | Gizmo tool, space or snapping changed  |
| =log=       | =serial=, =time=, =level=, =domain=, =message=                             | A log record (subscribe explicitly)    |
| =play=      | (none)                                                                     | Play started, paused, stopped          |
| =run=       | (none)                                                                     | An external game run started or ended  |
| =open-file= | =file=, =line=, =col=                                                      | Sent only to one =open-file= client    |

0.8.1 adds no events: panels that need to follow the editor poll a =*.state= method or subscribe to =changed= and =selection=.

** Tilemap methods
:PROPERTIES:
:CUSTOM_ID: tilemap-methods
:END:
Tile painting on nodes whose visual kind is =tilemap= (see [[file:editor-tools.org::#tilemap-painting][Tilemap painting]]). Every call is one undo step; a node without a grid gets an empty 16x16 one in the same step. =layer= is a layer index or name (default 0); =tile= is a tile id, 1-based into the tileset (0 or =erase: true= erases).

** Timeline methods
:PROPERTIES:
:CUSTOM_ID: timeline-methods
:END:
Keyframed animation stored in the level (see [[file:editor-tools.org::#animation-timeline][Animation timeline]]). =channel= is one of =location.x|y|z=, =rotation.x|y|z= (radians), =scale.x|y|z=, =color.r|g|b|a=, =roughness=, =metallic=, =param.NAME=. =easing= is an =LrgEasingType= nick (=linear=, =ease-in-quad=, =ease-out-cubic=, =ease-in-out-sine=, =ease-out-bounce=, ...) and shapes the segment after the key. Times are seconds; key matches use a 1 ms tolerance. All mutations are undoable.

| =timeline.remove=   | =name=                                                                 | =true= |
| =timeline.set=      | =name=, any of =rename length loop autoplay=                           | summary |
| =timeline.key=      | =name= (created if missing), =node=, =time=, =easing=; with =channel= (+ optional =value=, default the node's current value) keys one channel, otherwise =channels= (default the nine transform channels) | =keys= written |
| =timeline.unkey=    | =name=, =node=, =time=, =channel= (default every track of the node); empty tracks are dropped | =removed= |

** Asset sidecar methods
:PROPERTIES:
:CUSTOM_ID: asset-meta-methods
:END:
Read and edit an asset's =.meta= sidecar (see [[file:projects-and-assets.org][Projects and Assets]]). Headless: they work on a plain =LrgEditorServer=. =path= is the asset (or its =.meta= file), absolute or relative to the project directory (=lrg_editor_server_set_project_dir()=, else the current directory). The reply describes the sidecar as =lrg_asset_meta_to_variant()= does: =guid=, =importer= and =settings= (an object with every known setting of the importer at its effective value, defaults included, plus any unknown keys), plus =path= (the absolute asset path) and =exists= (whether the =.meta= file is on disk).

| Method           | Params                                                                 | Result |
|------------------+------------------------------------------------------------------------+--------|
| =asset.meta.get= | =path=                                                                 | =guid importer settings path exists=; without a sidecar, the one the asset database would create in memory (importer from the extension, the 0.8.0 legacy guid of the project-relative path); nothing is written |
| =asset.meta.set= | =path=, =settings= (={key: value or null}=, null resets to the default), =guid= (optional, replaces the identifier); at least one of the two | same as =asset.meta.get= with =exists: true= |

=asset.meta.set= is all or nothing: every value is validated with =lrg_asset_meta_set_setting_variant()= (booleans, integral numbers, choices such as =filter= =point bilinear trilinear=, numeric ranges such as =max-size= 0..16384) and the sidecar is written only when all of them are accepted; one bad key or value is =invalid-params= and the file is left untouched. A sidecar that cannot be parsed (for instance mid merge conflict) is =failed= and is never overwritten. A missing asset is =not-found=. The write goes straight to =<path>.meta= and is not on the undo stack (like a file save).

** Linked prefab methods
:PROPERTIES:
:CUSTOM_ID: prefab-link-methods
:END:
Overrides and links of prefab instances (see [[file:prefabs.org][Prefabs]]). Headless; every mutation is undoable. =node= may be an instance root or any node inside an instance: a node that carries a link is used as is (a nested instance root acts on its own link), otherwise the instance that governs it (=lrg_prefab_find_owner()=). Override keys are the =LrgPrefabLink= keys: a property path for the root (=visible=, =transform/scale=, =components/Health/max=), =<guid>:path= for other nodes, =children/+<guid>= and =children/-<source-guid>= for added and removed children.

The instance description returned by several methods is ={node name source source_guid linked overrides}=: =node= is the instance root's guid, =source= the prefab path (for an unlinked node the 0.8.0 marker, i.e. what =prefab.relink= would use, or null), =source_guid= the prefab's asset guid or null, =linked= a boolean and =overrides= the sorted key list (empty when unlinked).

| Method             | Params                                                                 | Result |
|--------------------+------------------------------------------------------------------------+--------|
| =prefab.overrides= | =node=                                                                 | instance description; an unlinked node is not an error (=linked: false=) |
| =prefab.apply=     | =node=, =keys= (optional array; default every override)                | instance description plus =applied= (keys written to the prefab) and =synced= (instances that changed when the dependents were synced) |
| =prefab.revert=    | =node=, =keys= (optional array; default every override, then a full sync) | instance description (the remaining overrides) |
| =prefab.sync=      | =path= (optional prefab file)                                          | =synced= (instances that changed), =prefabs= (sources synced); without =path= every prefab used by an outermost linked instance in the level |
| =prefab.relink=    | =node=, =path= (optional; default the node's 0.8.0 marker)             | instance description |
| =prefab.unlink=    | =node=                                                                 | =node=, =linked: false=, =unlinked= (whether there was a link to break) |

=prefab.apply= writes the source file, saves it and syncs every other dependent instance as one undo group (undo restores the file too). =prefab.revert= with several keys is one undo step. =prefab.sync= with a =path= also syncs instances of prefabs that nest it; instances that are already current record nothing, so a second sync reports 0. Errors: a missing =node= or a =keys= value that is not an array of strings is =invalid-params=; an unknown node, a key that is not in the instance's override set (checked before anything changes) or a missing prefab file is =not-found=; acting on a node that is not part of a linked instance (=apply=, =revert=), or a prefab that cannot be loaded or saved, is =failed= with the reason.

** Examples
:PROPERTIES:
:CUSTOM_ID: examples
:END:
With =socat= from a shell:

#+begin_src sh
sock="$(ls -t "${XDG_RUNTIME_DIR}"/libregnum/editor-*.sock | head -n 1)"

lrg () {
	if [[ $# -lt 1 ]]
	then
		echo 'lrg <method> [params-json]'
		return 1
	fi

	local method="${1}"
	local params="${2:-{\}}"

	printf '{"id":1,"method":"%s","params":%s}\n' "${method}" "${params}" \
		| socat -t 2 - UNIX-CONNECT:"${sock}"
}

lrg editor.info
lrg node.create '{"name":"Crate","primitive":"cube","parent":"Props"}'
lrg node.set '{"node":"Props/Crate","location":[2,0.5,-3]}'
lrg action.run '{"id":"view.focus"}'
lrg view.screenshot '{"path":"/tmp/viewport.png"}'
lrg level.save
#+end_src

Watching events (one long-lived connection):

#+begin_src sh
{ echo '{"id":1,"method":"hello","params":{"subscribe":["*"]}}'; cat; } \
	| socat - UNIX-CONNECT:"${sock}" | yq -p json -o yaml
#+end_src

From the editor's own console the short form works too: =node.rename node=Props/Crate name=Barrel=.

From C, in-process, =lrg_editor_server_dispatch()= runs one request line exactly as a client would; =lrg_editor_server_register_method()= adds methods (the editor's own app methods are registered this way).
