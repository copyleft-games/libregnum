* Tilemap painting
:PROPERTIES:
:CUSTOM_ID: tilemap-painting
:END:
A node whose visual kind is =tilemap= (Create > Tilemap) carries a tile grid. Select it, press =B= (Tilemap > Paint Tiles) and the viewport's left button paints instead of selecting.

** Data model
:PROPERTIES:
:CUSTOM_ID: tilemap-model
:END:
=LrgNodeTilemap= (=src/editor/lrg-node-tilemap.h=) is plain data held by the node's =LrgNodeVisual= (=lrg_node_visual_get_tilemap()=). It is deep-copied and compared with the visual, so node snapshots, copy/paste, duplicate, prefabs and play-mode restore all carry it without special cases.

- A fixed grid of =width= x =height= cells (1..4096 each) with one or more named layers (bottom first), each with a visibility flag and a row-major array of tile ids.
- Tile ids follow the runtime =LrgTilemapLayer= convention: =0= is empty and id =N= draws tile =N - 1= of the tileset (left to right, top to bottom).
- =tile_width= / =tile_height= slice the tileset image (pixels, default 16x16). The tileset image is the visual's =asset=.
- The world size of a cell is the visual param =tile_size= (default 1.0).
- Geometry in node-local space: cell =(x, y)= covers =[x * size, (x + 1) * size]= horizontally and =[-(y + 1) * size, -y * size]= vertically. Row 0 is the top row and the grid grows right and down from the node origin, so it reads like the image it was painted from. =lrg_node_tilemap_local_to_cell()= and =lrg_editor_tile_painter_cell_at()= (world point, honours the node's full world transform) do the mapping.
- =lrg_node_tilemap_flood_region()= returns the 4-connected region of the seed's id (breadth first, O(cells)).
- =lrg_node_tilemap_to_runtime()= builds an =LrgTilemap= with the same layers for a game that loads tilemaps from a level.

** Tools and undo
:PROPERTIES:
:CUSTOM_ID: tilemap-tools
:END:
=LrgEditorTilePainter= (=src/editor/lrg-editor-tile-painter.h=) is the one implementation behind the viewport, the IPC methods and the tests. It holds the current tile, layer and brush size and turns gestures into =LRG_EDITOR_CMD_TILES= commands (a list of =(x, y, before, after)= cell changes on one layer; the grid is looked up on the node when the command runs, so it survives node-state undos replacing the visual).

| Tool | Gesture | Undo |
|------+---------+------|
| Brush | =begin_stroke()=, =stroke_to()= per pointer sample, =end_stroke()=; samples are joined with a Bresenham line so a fast drag leaves no gaps; square brush of 1..64 cells | the whole stroke is one undo group ("Paint Tiles") |
| Eraser | a brush stroke painting 0 (Shift + drag erases with the brush too) | one group ("Erase Tiles") |
| Rect | press, drag, release; corners in any order, clipped to the grid (Shift erases) | one step |
| Fill | flood fill of the seed's 4-connected region (Shift erases) | one step |
| Pick | eyedropper: the clicked cell's id becomes the current tile (Ctrl + click with any tool) | none |

Cells that already hold the painted id are skipped, so re-painting records nothing. A node that has never been painted gets an empty 16x16 grid in the same undo step as its first edit. Escape cancels a rectangle; otherwise it leaves paint mode.

** The Tiles panel
:PROPERTIES:
:CUSTOM_ID: tiles-panel
:END:
View > Panels > Tiles (docked as a tab next to the inspector; Tilemap > Tiles Panel). Since 0.8.1 it is =LrgEditorTilesPanel= on the retained toolkit (widget details and API: [[file:editor-app.org::#editor-panel-tiles][Editor Application > Tiles panel]]). For the selected tilemap node it shows, in a scrolling column:

- the node name and the paint-mode toggle (=B=);
- the five tools as chips (the checked one is the view state's =tile-tool=; picking one turns paint mode on), brush size (also =[= / =]=) and the current tile id;
- grid settings: Create Grid for a node that has none, else width, height and the tileset slicing (each change is one undo step);
- the tileset: a drop zone that takes an image dragged from the Assets panel (payload =application/x-lrg-asset=); it lights up while a matching drag hovers it and stores project paths relative to the project;
- layers, top first: an eye to show / hide (undoable), click a name to make it current, + / - Layer (undoable), and a name field with Rename (undoable, also =tilemap.rename-layer=);
- the palette: the tileset image sliced into its tiles, click one to paint with it (eraser and eyedropper switch back to the brush), hovered and current tiles highlighted. Without an image (or headless) it shows 8 x 4 numbered colour swatches with the same colours the viewport uses for untextured tiles.

The panel and the viewport share the view state's =tile-tool= / =tile-mode= and the app's =LrgEditorTilePainter=, so =tilemap.tool= over IPC, the actions and the panel always show the same tool, tile, layer and brush.

The viewport shows the grid outline always, cell lines while painting the node, the brush footprint under the pointer, a rectangle preview, and a "Tiles: tool tile layer brush" readout. Tiles render as textured quads from the tileset in the node's XY plane (layers stack bottom first); 2D mode (=Ctrl+Shift+2=) is the natural way to paint.

** Saved format
:PROPERTIES:
:CUSTOM_ID: tilemap-yaml
:END:
Additive in =.rlevel= / =.rprefab= (older files load unchanged; files without a grid keep their old shape). Each layer's cells are one string per row, which keeps diffs line-oriented:

#+begin_src yaml
- name: Ground
  visual:
    kind: tilemap
    asset: assets/tiles/terrain.png
    params:
      tile_size: 1.0
    tilemap:
      width: 4
      height: 2
      tile_width: 16
      tile_height: 16
      layers:
        - name: base
          visible: true
          rows:
            - "1 1 2 2"
            - "0 0 9 9"
#+end_src

Loading is tolerant: short rows are padded with 0, long rows and extra rows are ignored, separators may be spaces, tabs or commas.

* Animation timeline
:PROPERTIES:
:CUSTOM_ID: animation-timeline
:END:
Levels hold named timelines that keyframe node properties. The Timeline panel (View > Panels > Timeline, docked next to Assets) edits them; autoplay timelines run during play-in-editor.

** Data model
:PROPERTIES:
:CUSTOM_ID: timeline-model
:END:
- =LrgTimeline= (=src/level/lrg-timeline.h=): =name= (unique in the level), =length= in seconds (default 2), =loop=, =autoplay=, and tracks. =lrg_timeline_wrap_time()= wraps (loop) or clamps a running time; =lrg_timeline_apply()= samples every track and writes the values onto the nodes.
- =LrgTimelineTrack=: one channel of one node (by GUID) on an =LrgKeyframeCurve= (=src/tween=) with key times in seconds. Each key has an =LrgEasingType= that shapes the segment to the next key (=lrg_easing_interpolate()=); sampling clamps before the first and after the last key. Keys within half a millisecond replace each other.
- Channels (=lrg_timeline_channel_read/write()=):

| Channel | Writes |
|---------+--------|
| =location.x= =location.y= =location.z= | node location |
| =rotation.x= =rotation.y= =rotation.z= | node rotation (radians) |
| =scale.x= =scale.y= =scale.z= | node scale |
| =color.r= =color.g= =color.b= =color.a= | the visual's material colour (0..1; the material is created on first write) |
| =roughness=, =metallic= | the visual's material |
| =param.NAME= | a numeric entry of the visual's param bag (light intensity, camera fov, CAD parameters, ...) |
| =bone.BONE.location.x= ... =bone.BONE.scale.z= (0.9.0) | an offset from the bind pose of bone =BONE= of the node's skinned mesh (see [[#timeline-bone-tracks][Bone tracks]]) |

- Bézier keys (0.9.0): any key can be made a Bézier key with =lrg_timeline_track_set_key_tangents()=; see [[#timeline-bezier][Bézier tangents]].

- =LrgLevel= owns the timelines (=lrg_level_get_n_timelines()=, =lrg_level_find_timeline()=, =lrg_level_insert_timeline()=, =lrg_level_remove_timeline()=).

** Bézier tangents
:PROPERTIES:
:CUSTOM_ID: timeline-bezier
:END:
Since 0.9.0 a timeline key is either an /eased/ key (the 0.8 behaviour: its =LrgEasingType= shapes the segment to the next key) or a /Bézier/ key. A Bézier key carries an =LrgSequenceTangentMode= and user slopes in value units per second, exactly like the keys of a sequence curve ([[file:../modules/animation/sequence.org::#sequence-curves][Sequence curves]]):

| Mode | Handles |
|------+---------|
| =auto= | smooth, from the neighbours (clamped Catmull-Rom; flat at the ends and at extrema) |
| =user= | one slope on both sides (aligned handles) |
| =broken= | independent in and out slopes |
| =linear= | pointing straight at the neighbouring key |
| =constant= | the value holds until the next key (step) |

The segment that /starts/ at a Bézier key is the cubic =lrg_sequence_curve_hermite()= between the two keys: the start key gives its outgoing slope, the end key gives its incoming slope when it is a Bézier key too, else the straight secant. The segment after an eased key keeps its easing, so files and tools from 0.8 behave exactly as before. A constant key holds its value.

| Function | Does |
|----------+------|
| =lrg_timeline_track_set_key_tangents()= | makes key /index/ a Bézier key with a mode and slopes (=out= only used by =broken=) |
| =lrg_timeline_track_get_key_tangents()= | =TRUE= with the mode and slopes for a Bézier key, =FALSE= for an eased key |
| =lrg_timeline_track_clear_key_tangents()= | turns a Bézier key back into an eased key |
| =lrg_timeline_track_move_key()= | retimes a key keeping value, easing and handles |

The handles live beside the =LrgKeyframeCurve= (matched to keys by time), so =lrg_timeline_track_get_curve()= still returns the eased curve. Re-keying a key's time with =lrg_timeline_track_set_key()= keeps its handles; removing the key, or clearing the curve directly, drops them. =lrg_timeline_track_equal()= and =lrg_timeline_track_copy()= include them.

In the editor (0.9.0): =lrg_editor_timeline_move_key()= retimes keys with =lrg_timeline_track_move_key()=, so dragging a Bézier key in the Timeline panel keeps its handles (0.8.1 moved keys with remove + set and lost them); =lrg_editor_timeline_set_tangents()= / =lrg_editor_timeline_clear_tangents()= are the undoable way to change them, and =lrg_editor_timeline_set_easing()= turns a Bézier key back into an eased key (picking an easing means "ease this segment"). The panel's Tangent picker, the Key Tangents context menu and =timeline.tangent= over IPC use them ([[#timeline-panel][The Timeline panel]]).

** Bone tracks
:PROPERTIES:
:CUSTOM_ID: timeline-bone-tracks
:END:
A channel =bone.BONE.GROUP.AXIS= (GROUP =location=, =rotation= or =scale=; AXIS =x=, =y=, =z=) animates one bone of a skinned node. The bone name is everything between =bone.= and the last two parts, so it may contain dots (=bone.upper.arm.L.rotation.z=); =lrg_timeline_channel_get_bone()= splits a channel. Values are /offsets from the bind pose/: location is added, the Euler rotation (radians) is applied after the bind rotation, scale multiplies (=lrg_sequence_compose_bone_offset()=). A zero offset with unit scale is the bind pose, so an unkeyed bone and a preview restore both give the rest pose. In the Timeline panel, type a bone name into the Bone field and press Key Bone (or Enter): the nine offset channels of that bone are keyed on every selected node at the playhead, as one undo step; their rows read =head  rotation.y=.

On an authoring =LrgNode= the offsets go into a runtime side table, never into the document: =lrg_timeline_channel_write()= stores them, =lrg_timeline_channel_read()= and =lrg_timeline_get_bone_offset()= read them back (identity when none), =lrg_timeline_clear_bone_offsets()= forgets them. The editor viewport poses the node's skinned mesh from that table (sequencer wave). At runtime, =lrg_sequence_new_from_timeline()= turns bone channels into bone transform tracks of an =LrgSequence= that an =LrgSequencePlayer= applies to a bound =LrgSkeleton=.

** Playing a timeline on the 3D runtime
:PROPERTIES:
:CUSTOM_ID: timeline-runtime
:END:
=lrg_timeline_apply()= poses authoring nodes. To play a level timeline on =LrgWorld3D= entities (which share their node's GUID) convert it: =lrg_sequence_new_from_timeline (timeline, fps)= makes one transform track per node (and per bone) from the location/rotation/scale and bone channels, keeps Bézier handles, turns linear keys into =linear= keys and bakes other easings into linear keys at /fps/; colour, roughness, metallic and param channels are skipped. Play the result with an =LrgSequencePlayer= or an =LrgSequenceComponent= ([[file:../modules/animation/sequence.org][Sequences]]).

** Undoable editing
:PROPERTIES:
:CUSTOM_ID: timeline-undo
:END:
=src/editor/lrg-editor-timeline.h= is the editing API shared by the panel, IPC and tests. Each call copies the live timeline, edits the copy and executes one =LRG_EDITOR_CMD_TIMELINE= command (before/after copies; apply/undo swap the level's timeline in place by name, so renames work and the index is kept):

| Function | Undo label |
|----------+------------|
| =lrg_editor_timeline_add()= / =_remove()= | Add / Remove Timeline |
| =lrg_editor_timeline_configure()= (rename, length, loop, autoplay) | Timeline Settings |
| =lrg_editor_timeline_set_key()= (creates the timeline when missing) | Set Keyframe |
| =lrg_editor_timeline_key_node()= (current values; default the nine transform channels) | Insert Keyframe |
| =lrg_editor_timeline_remove_key()= (empty tracks are dropped) | Delete Keyframe |
| =lrg_editor_timeline_move_key()= (=merge= while dragging; keeps value, easing and Bézier handles) | Move Keyframe |
| =lrg_editor_timeline_set_easing()= (a Bézier key becomes eased) | Set Easing |
| =lrg_editor_timeline_set_tangents()= (0.9.0; a mode and slopes; no step when nothing changes) | Set Tangents |
| =lrg_editor_timeline_clear_tangents()= (0.9.0) | Clear Tangents |
| =lrg_editor_timeline_remove_track()= | Delete Track |

=lrg_editor_execute_merged()= (new on =LrgEditor=) folds a command into the previous compatible one, so a key drag is one undo step.

** The Timeline panel
:PROPERTIES:
:CUSTOM_ID: timeline-panel
:END:
Since 0.8.1 the panel is =LrgEditorTimelinePanel= on an =LrgTimelineView= (widget details and API: [[file:editor-app.org::#editor-panel-timeline][Editor Application > Timeline panel]]).

- Toolbar: timeline picker, name field + New (Enter), Rename, Delete; Loop and Autoplay toggles; the length; To Sequence (0.9.0: writes the timeline as =sequences/<name>.rseq= with =lrg_sequence_new_from_timeline()= and opens it in the [[file:sequencer.org][Sequencer]]; also =timeline.to-sequence= and the context menu's Convert to Sequence).
- Transport: previous key, Play/Pause (=K=), Stop, next key; Key (=I=: insert transform keys for every selected node at the playhead, as one undo step); Delete Keys; the easing used for new keys (changing it also re-eases every selected key, one undo step); the Tangent picker (0.9.0: =Eased=, =Auto=, =User=, =Broken=, =Linear=, =Constant=; it shows the first selected key's mode and sets it on every selected key as one undo step, keeping the slopes the key is drawn with, so switching an auto key to user or broken does not change its shape); Curves (0.9.0: channel rows become curve lanes that draw values, eased segments and Bézier segments with their slopes); the Bone field and Key Bone (0.9.0, see [[#timeline-bone-tracks][Bone tracks]]); the playhead time.
- Tracks: one group per node (its own colour; missing nodes show "(missing GUID)"), one row per animated channel inside it, collapsible. Keys are diamonds when linear (eased linear or Bézier =linear=), circles when eased or smooth Bézier, bars when Bézier =constant= (a step); node summary keys are squares. Click selects a key (Shift / Ctrl add), drag a rubber band to select several, drag selected keys to retime them (snapped to 10 ms, one undo step for the whole drag, however many keys), Delete removes them. Right click offers Insert Keyframe, Delete Selected Keys, a Key Easing menu (Linear, Ease In / Out / In Out by family), a Key Tangents menu (the six tangent rows) and Convert to Sequence.
- Ruler: click or drag to scrub (a non-destructive preview, see below).
- =Alt+Left= / =Alt+Right= jump the playhead to the previous / next key of any track.

Every edit goes through the undoable =lrg_editor_timeline_*= API and every scrub / play through the view state's timeline properties, so the panel, the =timeline.*= IPC methods, =lrgeditorctl timeline= and Emacs always agree.

** Preview semantics
:PROPERTIES:
:CUSTOM_ID: timeline-preview
:END:
Scrubbing and playing write sampled values straight onto the nodes, outside the undo history (like other editors' animation mode), so the viewport, the inspector and the gizmo show the pose. The value each animated channel had when the preview started is remembered and written back when the preview ends: Stop, saving (=File > Save=, =level.save= over IPC), starting play-in-editor, or switching timelines. A previewed pose is therefore never saved and never marks the document dirty. Keying while previewing records the node's current (posed or moved) values at the playhead.

** Play-in-editor
:PROPERTIES:
:CUSTOM_ID: timeline-play
:END:
When play starts, every timeline with =autoplay= is sampled at the play clock after each simulation tick (wrapped when looping) and applied to the authoring nodes, which the viewport shows. Stopping play restores the nodes from the play snapshot as for any other play-time change. Timelines animate the authoring nodes, not the runtime entities: scripts reading =LrgGameObject= positions do not see the animation (see [[#tools-limits][Limits]]).

** Saved format
:PROPERTIES:
:CUSTOM_ID: timeline-yaml
:END:
An optional top-level =timelines:= sequence; files without timelines keep their old shape and old readers ignore it. =easing= is the =LrgEasingType= nick and is omitted for =linear=. Since 0.9.0 a Bézier key adds =tangent= (the =LrgSequenceTangentMode= nick) plus =slope= (=user=) or =in= and =out= (=broken=); readers before 0.9.0 ignore these keys and play the key eased. Bone channels need no new keys.

#+begin_src yaml
timelines:
  - name: Bounce
    length: 2.0
    loop: true
    autoplay: true
    tracks:
      - node: 3f0c9a52-6d0e-4c1b-9a51-0b0f5f3c2e11
        channel: location.y
        keys:
          - time: 0.0
            value: 0.0
            easing: ease-out-bounce
          - time: 1.0
            value: 3.0
      - node: 3f0c9a52-6d0e-4c1b-9a51-0b0f5f3c2e11
        channel: bone.spine.rotation.z     # bind-pose offset of bone "spine"
        keys:
          - time: 0.0
            value: 0.0
            tangent: user                  # Bézier key, aligned handles
            slope: 1.5                     # radians per second
          - time: 0.5
            value: 0.4
            tangent: broken
            in: -0.5
            out: 2.0
          - time: 1.0
            value: 0.0
            tangent: constant              # hold (last key: no effect)
#+end_src

* Asset thumbnails
:PROPERTIES:
:CUSTOM_ID: asset-thumbnails
:END:
The Assets panel's grid view (the Grid/List button, or View > Asset Thumbnails) shows thumbnails instead of type glyphs for textures and sprites, models, levels and prefabs. Folders and other files keep their glyphs; a dimmed glyph means the thumbnail is on its way.

** Cache
:PROPERTIES:
:CUSTOM_ID: thumbnail-cache
:END:
=LrgThumbnailCache= (=src/editor/lrg-thumbnail-cache.h=) stores PNGs named =<sha1 of the absolute path>-<mtime in microseconds>-<size in bytes>.png= (=lrg_thumbnail_cache_make_key()=):

- in =<project>/.cache/thumbnails/= when a project is open, else =$XDG_CACHE_HOME/libregnum/thumbnails/=;
- an edited file has a new mtime/size and simply misses; storing its new thumbnail sweeps the older versions of the same path;
- =lrg_thumbnail_cache_invalidate()= deletes every version of a path;
- thumbnails are scaled down to the cache size (96 px longest edge in the editor), tiny pixel art is scaled up by whole multiples with nearest-neighbour so it stays crisp; files are written to a temporary name and renamed into place.

** Generation off the frame path
:PROPERTIES:
:CUSTOM_ID: thumbnail-generation
:END:
- =lrg_thumbnail_cache_request()= answers hits immediately and queues misses. CPU kinds run on a one-thread =GThreadPool= worker: textures are decoded and scaled (=GrlImage=), levels and prefabs become a top-down schematic of their nodes (positions and sizes from the YAML, coloured by visual kind; XZ plane for 3D levels, XY for 2D ones). The worker never touches the cache object: jobs carry their own paths and a reference to the result queue, and dispose drops queued jobs and waits for the running one.
- GPU kinds (models) need the GL context, so they queue on the main thread and run through a renderer callback (=lrg_thumbnail_cache_set_renderer()=). In the editor that is =editor_render_model_thumbnail()=: load the model, frame its bounding box from a 3/4 angle with the viewport's lighting into a render texture, read it back, unload.
- =lrg_thumbnail_cache_process (cache, max_gpu_jobs)= runs on the main thread every frame (and every 100 ms headless) with one GPU job per frame, then emits =ready (path, thumbnail)= for finished requests. The panel uploads at most four thumbnail textures per frame.
- Live reload: the Assets panel's directory monitor invalidates the thumbnail (file and texture) of a file that changes, is created, deleted or moved, and drops the renderer's cached GPU copy of that file so the viewport reloads changed textures and models too. Tools > Rebuild Thumbnails regenerates everything shown.

** IPC, CLI, MCP, Emacs
:PROPERTIES:
:CUSTOM_ID: thumbnail-automation
:END:
- IPC (app): =asset.thumbnail {path, wait}= returns =path=, =thumbnail= (or null), =pending= and =cache=; with =wait= it generates synchronously (models need a windowed editor).
- =lrgeditorctl thumbnail PATH= prints the PNG path; MCP =get_thumbnail=; Emacs =libregnum-thumbnail= (=C-c L h=) opens it.

* Limits
:PROPERTIES:
:CUSTOM_ID: tools-limits
:END:
- Tilemaps: one tileset per node; no auto-tiling/terrain rules, no per-tile flips or rotation, no collision editing in the panel (the runtime =LrgTileset= properties are not authored here). =lrg_level_instantiate()= does not create runtime tilemaps; games convert with =lrg_node_tilemap_to_runtime()=.
- Timelines: scalar channels only (colour is four tracks); Bézier handles are edited through the tangent modes and slopes (picker, IPC), not dragged on the timeline rows (the [[file:sequencer.org][Sequencer]]'s curve editor drags handles); play-in-editor animates the authoring nodes, not the runtime entities (convert to a sequence to play on =LrgWorld3D=).
- Thumbnails: no thumbnails for audio, fonts, scripts, tilesets (=.tileset=/=.tsx=) or CAD parts; a request still in flight when its file is invalidated may deliver the old image once (the next change or Rebuild Thumbnails fixes it).
