#+description: Building libregnum for Windows, Linux aarch64 and Android from one checkout

* Cross-Compilation Guide
:PROPERTIES:
:CUSTOM_ID: cross-compilation-guide
:END:
One checkout builds libregnum for the machine you are on (the /native/ build) and for other /targets/: Windows on x86_64, Linux on aarch64 and Android on arm64-v8a. Every target has its own output directory, so a cross build never touches the native one, and switching back and forth costs nothing.

** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
| Target          | Switch      | Toolchain                                  | Output                                 |
|-----------------+-------------+--------------------------------------------+----------------------------------------|
| native          | (none)      | the host's =gcc=                           | =build/release=, =build/debug=         |
| =windows-amd64= | =WINDOWS=1= | MinGW-w64 gcc                              | =build/{release,debug}-windows-amd64= |
| =linux-arm64=   | =ARM64=1=   | aarch64 gcc against a Fedora sysroot       | =build/{release,debug}-arm64=         |
| =android-arm64= | =ANDROID=1= | Android NDK clang (API 29+)                | =build/{release,debug}-android-arm64= |

Guarantees the build system keeps:

- *The native build is unchanged.* =make -j16 all= on its own builds for the host, into =build/release=, exactly as before cross targets existed. =make test-native-unchanged= proves it (see [[#testing-cross-builds][Testing cross builds]]).
- *Targets never share outputs.* Objects, libraries, executables and the bundled dependencies' archives of a cross target all live under that target's directory.
- *One profile per target.* Everything that defines a target is in =build-aux/mk/targets/<target>.mk=.

** Quick start
:PROPERTIES:
:CUSTOM_ID: quick-start
:END:
#+begin_src sh
make -j16                     # native, build/release
make -j16 DEBUG=1             # native, build/debug
make -j16 WINDOWS=1           # build/release-windows-amd64
make -j16 ARM64=1 DEBUG=1     # build/debug-arm64
make -j16 ANDROID=1           # build/release-android-arm64
make targets                  # every target, its directories and toolchain
make WINDOWS=1 print-target   # what a build with these switches would do
#+end_src

** Target model
:PROPERTIES:
:CUSTOM_ID: target-model
:END:
A target is named =<os>-<arch>= (=linux-amd64=, =linux-arm64=, =windows-amd64=, =android-arm64=); the arch half uses the Debian/OCI spellings =amd64= and =arm64=. =build-aux/mk/target.mk= resolves it before anything else is read, using nothing but =uname=, and both =config.mk= and the subdirectory makefiles (=tests/=, =examples/=, =bench/=) include it, so they always agree on the target and the output directory.

*** Choosing a target
:PROPERTIES:
:CUSTOM_ID: choosing-a-target
:END:
| Spelling                     | Target          | Notes                               |
|------------------------------+-----------------+-------------------------------------|
| =LRG_TARGET=<target>=        | =<target>=      | the canonical spelling              |
| =WINDOWS=1=                  | =windows-amd64= |                                     |
| =ARM64=1=                    | =linux-arm64=   |                                     |
| =ANDROID=1=                  | =android-arm64= |                                     |
| =CROSS=x86_64-w64-mingw32=   | =windows-amd64= | legacy; no other triple is accepted |

At most one may be given. =make ARM64=1 WINDOWS=1=, or =LRG_TARGET= naming a different target than a switch, stops with =Conflicting targets requested=. An unknown =LRG_TARGET= stops with the list of known ones. =SANITIZE=1= is native-only and stops when combined with a cross target.

*** Host and native builds
:PROPERTIES:
:CUSTOM_ID: host-and-native-builds
:END:
The host target comes from =uname -s= and =uname -m= (=x86_64= → =amd64=, =aarch64= → =arm64=). A request for the host's own target is a native build: on an Asahi (aarch64) machine =make ARM64=1= builds into =build/release= with the host compiler, exactly like a plain =make=. =LRG_HOST_TARGET= can be set on the command line; the build-system tests use it to behave like an aarch64 host on an x86_64 one.

*** Directory suffix
:PROPERTIES:
:CUSTOM_ID: directory-suffix
:END:
A cross target's build directory is =build/<release|debug>-<target>=, with a leading =linux-= dropped: =-windows-amd64=, =-arm64=, =-android-arm64=. The native build has no suffix. =LRG_BUILD_SUFFIX= holds it; inside a build container it is handed in by the make that started the container rather than derived again (an aarch64 container would otherwise see itself as native).

*** Target profiles
:PROPERTIES:
:CUSTOM_ID: target-profiles
:END:
=config.mk= reads the target's profile right after its own tool defaults, so the profile's =CC=, =AR=, =RANLIB= and =PKG_CONFIG= replace them while anything given on the command line (=make WINDOWS=1 CC=my-gcc=) still wins. A profile sets:

| Variable                  | Meaning                                                                 |
|---------------------------+-------------------------------------------------------------------------|
| =LRG_TARGET_TRIPLE=       | the GNU triple (=x86_64-w64-mingw32=, =aarch64-linux-gnu=, ...)         |
| =CC=, =AR=, =RANLIB=      | the toolchain (one word each: the dependencies get them on their command lines) |
| =PKG_CONFIG=              | a pkg-config that answers for the target's libraries                    |
| =LRG_TOOLCHAIN_CHECK=     | a shell test that the toolchain (and sysroot) is installed, for =NO_BUILD_CONTAINER=1= |
| =TARGET_PLATFORM=         | =windows=, =linux= or =android=; =config.mk= turns it into =LRG_PLATFORM_WINDOWS=, =_LINUX= or =_ANDROID= |
| forced defaults           | =BUILD_GIR := 0= (GIR runs the library it scans); =$(call lrg_default,VAR,value)= for defaults the command line may still override (=BUILD_TOOLS=, =BUILD_EDITOR_UI=, =CRISPY=, =SOUP=, =LIBPQ=) |
| =LRG_DEP_FLAGS=           | what every bundled dependency's make gets (the toolchain)               |
| =LRG_GRAYLIB_FLAGS=       | what graylib's make gets on top (=RAYLIB_PLATFORM=, =RAYLIB_EXTRA_FLAGS=) |
| =LRG_PLATFORM_LIBS=       | replaces the desktop system libraries (Android: EGL, GLES 3, libandroid, liblog) |
| =LRG_PLATFORM_LDFLAGS=, =LRG_TARGET_CFLAGS= | extra link and compile flags                          |
| =LRG_CC_IS_GCC=, =LRG_DIALECT_WARN_CFLAGS= | a non-gcc compiler: =WARN_CFLAGS= is probed flag by flag, plus the profile's documented dialect gaps |
| =LRG_EXEC_WRAPPER=        | how to run the target's test binaries (=wine=, =qemu-aarch64-static -L ...=) |
| =LRG_TEST_SKIP_PATHS=, =LRG_TEST_KNOWN_FAILURES= | test paths not run there, and known bugs (see [[#testing-cross-builds][Testing]]) |
| =LRG_CONTAINER_PLATFORM=  | the =--platform= of its build container, empty for the host's arch      |

The first line under the copyright, =# description: ...=, is what =make targets= prints.

When the target's toolchain is not installed (its =LRG_TOOLCHAIN_CHECK= fails; by default: =CC= or =PKG_CONFIG= not on =PATH=), any goal that compiles stops with one message naming the missing tool, instead of a screen of failed pkg-config probes. Goals that never compile (=clean=, =clean-targets=, =distclean=, =print-target=, =targets=, =help=) work without it.

** Output layout
:PROPERTIES:
:CUSTOM_ID: output-layout
:END:
#+begin_example
build/
├── release/                     native (unchanged)
├── debug/                       native DEBUG=1 (unchanged)
├── sanitize/                    native SANITIZE=1 (unchanged)
├── release-windows-amd64/
│   ├── obj/  lib/  tests/  ...  same layout as build/release
│   └── deps/                    graylib, raylib, yaml-glib built for windows
├── debug-arm64/
└── release-android-arm64/
#+end_example

Native builds keep their dependency archives where they always were (=deps/graylib/build/lib=, raylib inside =deps/graylib/deps/raylib/src=, =deps/yaml-glib/build/<type>=, =deps/crispy/build/<type>=), because cmacs links against those paths. Cross builds put their dependency builds under =$(BUILDDIR)/deps/=:

| Dependency | Cross output                                   | Passed to its make as                 |
|------------+------------------------------------------------+---------------------------------------|
| graylib    | =$(BUILDDIR)/deps/graylib/{obj,lib}=           | =BUILDDIR=                            |
| raylib     | =$(BUILDDIR)/deps/raylib/= (an rsync'd copy of its sources) | =RAYLIB_BUILD_DIR= (to graylib) |
| yaml-glib  | =$(BUILDDIR)/deps/yaml-glib/<type>/=           | =BUILDDIR=                            |
| crispy     | =$(BUILDDIR)/deps/crispy/<type>/=              | =BUILDDIR=                            |

raylib's Makefile writes objects and generated headers next to its sources, so a cross target gets a copy of =deps/graylib/deps/raylib/src= that graylib refreshes with =rsync= on every build; raylib rebuilds only when the copy changed (graylib's =docs/guides/building.org=, "Out-of-tree builds"). All of these paths are decided in one block of =config.mk= (=GRAYLIB_BUILDDIR=, =RAYLIB_BUILD_DIR=, =YAMLGLIB_BUILDDIR=, =CRISPY_BUILDDIR=), and the =Makefile= hands them to the sub-makes through =GRAYLIB_MAKE_FLAGS=, =YAMLGLIB_MAKE_FLAGS= and =CRISPY_MAKE_FLAGS=. A profile adds what its dependencies must know with =LRG_DEP_FLAGS= (all of them) and =LRG_GRAYLIB_FLAGS= (graylib only). =rsync= is required for cross builds.

The generated headers =src/lrg-version.h= and =src/config.h= hold only version numbers, identical for every target, so they stay in =src/= and are shared.

:CUSTOM_ID: cleaning
:END:
| Goal                  | Removes                                                                               |
|-----------------------+---------------------------------------------------------------------------------------|
| =make clean=          | everything under =build/= except the cross targets' directories, and the generated headers |
| =make WINDOWS=1 clean= | =build/release-windows-amd64= and =build/debug-windows-amd64= only                    |

** How dispatch works
:PROPERTIES:
:CUSTOM_ID: how-dispatch-works
:END:
Cross builds run inside a podman container that has the target's toolchain; the host needs nothing but podman. The native build never uses a container.

*** Entry point: GNUmakefile
:PROPERTIES:
:CUSTOM_ID: gnumakefile
:END:
GNU make reads =GNUmakefile= before =Makefile=, so every =make= in the checkout starts there. It includes =build-aux/mk/target.mk= (cheap: no pkg-config, no compiler) and =build-aux/mk/dispatch.mk= (which sets =LRG_USE_CONTAINER= and =LRG_DISPATCH=; another project's =GNUmakefile= includes the same two files, see [[#consumers][Consuming the cross builds from another project]]) and then decides:

| Situation                                                    | What happens                                                  |
|--------------------------------------------------------------+---------------------------------------------------------------|
| native target                                                | =Makefile=, exactly as before                                 |
| cross target, =NO_BUILD_CONTAINER=1=                         | =Makefile= on the host, with the target's toolchain          |
| cross target, already inside the container (=LRG_IN_CONTAINER=1=) | =Makefile= (this is the inner make)                      |
| cross target, every goal is host-only (see below)            | =Makefile= on the host; nothing compiles                      |
| cross target, anything else                                  | =build-aux/mk/container.mk=: the goals run in the container   |

Host-only goals: =clean=, =clean-targets=, =distclean=, =print-target=, =targets=, =help=, =container-image=, =container-shell=, =container-prune=, =print-container= (and the Android goals that run on the host: =apk-install=, =apk-run=, =apk-push=, =keystore=, =test-device=, =test-emulator=). A cross build cannot skip the root makefile: =make -C tests WINDOWS=1= or =make -f Makefile WINDOWS=1 lib= stops and names =make WINDOWS=1 ...= from the top level, or =NO_BUILD_CONTAINER=1=.

*** The container run
:PROPERTIES:
:CUSTOM_ID: container-run
:END:
All goals on the command line become one =make <goals>= in one container, in the order given (=make WINDOWS=1 clean all test=):

#+begin_src sh
podman run --rm \
    --userns=keep-id \                       # output files belong to you (not as root)
    --security-opt label=disable \           # no SELinux relabelling of the checkout
    -v $ROOT:$ROOT \                         # the checkout, at the same path
    -v $GIT_COMMON_DIR:$GIT_COMMON_DIR:ro \  # only in a worktree (see below)
    -w $PWD -e HOME=/tmp -e TERM \
    -e LRG_IN_CONTAINER=1 \                  # the inner make builds, it does not dispatch
    -e LRG_BUILD_SUFFIX=-windows-amd64 \     # decided by the outer make
    -e MAKEFLAGS="s -j16 -- WINDOWS=1 DEBUG=1" \
    $BUILD_CONTAINER_ARGS \
    localhost/libregnum-build-windows-amd64:<hash> make all test
#+end_src

- *Same path:* dependency files, rpaths and =compile_commands.json= entries written in the container are valid on the host.
- *MAKEFLAGS:* the outer make's own =MAKEFLAGS= with the jobserver removed (a host fifo the container cannot reach). =-j16= stays, so the inner make starts its own jobserver with the same number of slots, and every =VAR=value= from the command line arrives with make's own escaping (values with spaces survive).
- *Worktrees:* in a =git worktree= (=trees/<name>=), the submodules' =.git= files point into the main checkout's =.git=, outside the mounted tree. graylib asks git about the raylib submodule, so that directory is mounted read-only at the same path.

*** Escape hatches
:PROPERTIES:
:CUSTOM_ID: escape-hatches
:END:
- =NO_BUILD_CONTAINER=1=: build on the host with the target's toolchain installed there (see [[#building-without-containers][Building without containers]]).
- =make WINDOWS=1 container-shell=: an interactive shell in the build container, set up like a build (same mounts, same directory), for debugging the toolchain.
- =make -f Makefile ...=: skips =GNUmakefile= entirely; fine for native goals, refused for a cross target without =NO_BUILD_CONTAINER=1=.

** Container images
:PROPERTIES:
:CUSTOM_ID: container-images
:END:
Each target has a recipe in =build-aux/containers/<target>/=: a =Containerfile= that copies the recipe in and runs its =setup.sh=. Shared steps are in =build-aux/containers/common/common.sh=; =build-aux/cross/= holds the toolchain wrappers some images install. The build context is =build-aux/=.

*** Tags follow the recipe
:PROPERTIES:
:CUSTOM_ID: image-tags
:END:
An image is tagged =localhost/libregnum-build-<target>:<hash>=, where the hash covers every file (names and contents) in =containers/common/=, =containers/<target>/= and =cross/=, plus the base image and the platform. A build builds the image only when no image has that tag, so:

- an unchanged recipe reuses the image; the first cross build of a target pays for the image once,
- editing a recipe gives a new tag, so the next build makes a new image (nothing goes stale),
- editing another target's recipe does not touch this one's.

=make WINDOWS=1 print-container= shows the tag and what it is made of; =make WINDOWS=1 container-image= builds it ahead of time; =make WINDOWS=1 container-prune= removes that target's images other than the current one (they carry the label =org.libregnum.build-target=<target>=).

*** Smoke tests
:PROPERTIES:
:CUSTOM_ID: image-smoke-tests
:END:
Every =setup.sh= ends by compiling =containers/common/smoke.c= (GObject, GIO and json-glib) with the target's compiler and pkg-config, at =-std=gnu89 -Wall -Wextra -Werror=, and running it where the target can run in the container (Wine for Windows, qemu for aarch64). If that fails, the image build fails and no image is tagged.

*** Variables
:PROPERTIES:
:CUSTOM_ID: container-variables
:END:
| Variable                | Default                                  | Meaning                                                 |
|-------------------------+------------------------------------------+---------------------------------------------------------|
| =CONTAINER_ENGINE=      | =podman=                                 | the container CLI                                       |
| =BUILD_CONTAINER_BASE=  | =registry.fedoraproject.org/fedora:45=   | the image every recipe starts =FROM=                    |
| =BUILD_CONTAINER_IMAGE= | (empty)                                  | run this image as-is; nothing is built or checked       |
| =BUILD_CONTAINER_ARGS=  | (empty)                                  | extra =podman run= arguments                            |
| =NO_BUILD_CONTAINER=    | 0                                        | =1= builds on the host                                  |

#+begin_src sh
# another base image (its own tag; the recipe is unchanged)
make WINDOWS=1 BUILD_CONTAINER_BASE=registry.fedoraproject.org/fedora:44

# a prebuilt image, e.g. pushed to a GitLab registry for CI or other machines
make WINDOWS=1 container-image
podman tag "$(make -s WINDOWS=1 print-container | sed -n 's/^Image: *//p')" \
    registry.gitlab.com/you/libregnum/build-windows-amd64:latest
podman push registry.gitlab.com/you/libregnum/build-windows-amd64:latest
make WINDOWS=1 BUILD_CONTAINER_IMAGE=registry.gitlab.com/you/libregnum/build-windows-amd64:latest

# keep a ccache across container runs
make WINDOWS=1 BUILD_CONTAINER_ARGS='-v ccache-win:/ccache -e CCACHE_DIR=/ccache'
#+end_src

A prebuilt image must have been built from the same recipe; the build does not check. Offline, an existing local image keeps working, since only a missing tag triggers a build.

** Building without containers
:PROPERTIES:
:CUSTOM_ID: building-without-containers
:END:
=NO_BUILD_CONTAINER=1= runs the cross build on the host. The host then needs exactly what the image's =setup.sh= installs; the scripts are the authoritative package lists:

| Target          | Packages (Fedora)                                                                                     | Variables                    |
|-----------------+-------------------------------------------------------------------------------------------------------+------------------------------|
| =windows-amd64= | =mingw64-gcc mingw64-binutils mingw64-filesystem mingw64-glib2 mingw64-json-glib mingw64-zlib mingw64-libyaml mingw64-libsoup3 mingw64-openssl mingw64-sqlite mingw64-postgresql wine-core= | none                         |
| =linux-arm64=   | =gcc-aarch64-linux-gnu binutils-aarch64-linux-gnu wayland-devel qemu-user-static-aarch64= and an aarch64 sysroot | =ARM64_SYSROOT= (default =/opt/sysroot/aarch64=) |
| =android-arm64= | see [[file:platforms/android.org][Android]]                                                         | =ANDROID_NDK=, =ANDROID_SDK= |

Common to all: =make gcc pkgconf-pkg-config glib2-devel python3 git-core rsync=. On an image-based host (Silverblue and friends) these belong in the image, which is why the container is the default.

** Consuming the cross builds from another project
:PROPERTIES:
:CUSTOM_ID: consumers
:END:
A project that embeds libregnum (as a submodule, e.g. =deps/libregnum=) can build itself for the same targets in the same images: its own =GNUmakefile= includes libregnum's =target.mk=, =dispatch.mk= and =container.mk=, exactly as libregnum's does. The image is libregnum's (same recipe, same hash, same tag), so a parent never builds an image of its own and shares the one libregnum already built.

*** The parent's GNUmakefile
:PROPERTIES:
:CUSTOM_ID: consumer-gnumakefile
:END:
A complete example, for a project =game/= with libregnum in =deps/libregnum= and its real build in =Makefile=:

#+begin_src makefile
# GNUmakefile - game: native here, cross targets in libregnum's containers
PROJECT_ROOT := $(realpath $(dir $(lastword $(MAKEFILE_LIST))))

# libregnum's checkout: the submodule, or another one (a worktree falling
# back to the main checkout's submodule); target.mk sets LRG_ROOT itself
# when it is left out
LRG_ROOT := $(PROJECT_ROOT)/deps/libregnum

# This project's goals that never compile: they run on the host even for
# a cross target (set before dispatch.mk)
LRG_EXTRA_HOST_SAFE_GOALS := help distclean apk-install apk-push

# Data outside the tree the build reads, and the names (never the values)
# of environment variables the build needs inside the container
LRG_CONTAINER_EXTRA_MOUNTS := $(HOME)/game-data
LRG_CONTAINER_ENV := GAME_BUILD_ID

include $(LRG_ROOT)/build-aux/mk/target.mk
include $(LRG_ROOT)/build-aux/mk/dispatch.mk

ifeq ($(LRG_DISPATCH),1)
    # the goals run as one `make <goals>' in libregnum's image
    # (container.mk reads the target's profile)
    .DEFAULT_GOAL := all
    include $(LRG_ROOT)/build-aux/mk/container.mk
else
    # native, NO_BUILD_CONTAINER=1, host-safe goals, or the inner make
    # inside the container (LRG_IN_CONTAINER=1)
    include $(PROJECT_ROOT)/Makefile
    ifeq ($(LRG_USE_CONTAINER),1)
        include $(LRG_ROOT)/build-aux/mk/container.mk
    endif
endif
#+end_src

=make ANDROID=1=, =make WINDOWS=1 DEBUG=1 all test= and the rest then behave as in libregnum: one container run per invocation, the parent's tree mounted at the same path, =MAKEFLAGS= forwarded. =make ANDROID=1 print-container=, =container-image=, =container-shell= and =container-prune= work from the parent too.

*** Building libregnum from the inner make
:PROPERTIES:
:CUSTOM_ID: consumer-inner-make
:END:
Inside the container the parent's =Makefile= builds libregnum for the target with a sub-make; =LRG_IN_CONTAINER=1= (set by the run) lets libregnum's =config.mk= accept it, and =LRG_BUILD_SUFFIX= comes from the environment, so libregnum lands in its own =build/<type>-<target>/=:

#+begin_src makefile
libregnum:
	$(MAKE) -C deps/libregnum LRG_TARGET=$(LRG_TARGET) lib
#+end_src

(=ANDROID=1= and the other switches are in =MAKEFLAGS= already, so =$(MAKE) -C deps/libregnum lib= is enough.) An Android parent links its own =libmain.so= with the profile's =LRG_APK_LDFLAGS= and packages it with =$(LRG_MKAPK)= (=build-aux/android/mkapk.sh=); see [[file:platforms/android.org::#consumer-apk][Another project's APK]]. The target's toolchain is the profile's: after =include $(LRG_TARGET_PROFILE)= (the parent's =Makefile= may include it too when =LRG_IS_CROSS= is =1=) =CC=, =AR=, =PKG_CONFIG= and =LRG_PLATFORM_LIBS= are set, and the profile's paths into libregnum (the cross wrappers) go through =LRG_ROOT=, not =PROJECT_ROOT=.

*** Variables for a parent
:PROPERTIES:
:CUSTOM_ID: consumer-variables
:END:
| Variable                     | Default                         | Meaning                                                                                                         |
|------------------------------+---------------------------------+-----------------------------------------------------------------------------------------------------------------|
| =LRG_ROOT=                   | libregnum's directory (=target.mk='s =../..=) | where the profiles, the container recipes (the build context) and the cross wrappers are                          |
| =LRG_CONTAINER_MOUNT_ROOT=   | =PROJECT_ROOT=                  | the tree mounted at its own path; its git directory is checked as libregnum's is                               |
| =LRG_CONTAINER_EXTRA_MOUNTS= | (empty)                         | more host directories, each mounted read-write at its own path; =LRG_ROOT= is added when outside the mount root |
| =LRG_CONTAINER_RO_MOUNTS=    | (empty; =APK_KEYSTORE= when set) | host files or directories mounted read-only at their own path                                                  |
| =LRG_CONTAINER_ENV=          | (empty)                         | names of environment variables passed in with =-e NAME=: the engine copies the value, no command line shows it   |
| =LRG_EXTRA_HOST_SAFE_GOALS=  | (empty)                         | the parent's goals that never compile (set before =dispatch.mk=)                                               |

Every git directory of a mounted tree that lies outside the mounts (the main checkout's =.git= of a worktree, of the parent or of libregnum) is mounted read-only at the same path, as for libregnum itself. With all of them left at their defaults, libregnum's own runs are unchanged (=tests/test-build-dispatch.sh= checks both, with a throwaway parent).

** Per-target notes
:PROPERTIES:
:CUSTOM_ID: per-target-notes
:END:
Each target has its own page; this is the summary.

| Target          | Toolchain | Builds | Tests | Page |
|-----------------+-----------+--------+-------+------|
| =windows-amd64= | MinGW-w64 gcc (Fedora packages) | =libregnum.dll= + import library, static library, every tool as =.exe=; graylib and yaml-glib as DLLs | under Wine; POSIX-only suites not built | [[file:platforms/windows.org][Windows]] |
| =linux-arm64=   | Fedora's aarch64 gcc + a Fedora aarch64 sysroot (wrappers in =build-aux/cross/=) | everything the native build does except GIR | under qemu-aarch64; emulation limits skipped, four known aarch64 bugs | [[file:platforms/linux-arm64.org][Linux aarch64]] |
| =android-arm64= | NDK r30 clang + a static GLib stack | static and shared library; APKs (=make ANDROID=1 apk=) | APK structure, shaders as GLSL ES; the game on a device | [[file:platforms/android.org][Android]] |

What every cross target leaves out: GObject Introspection (=g-ir-scanner= runs the library it scans) and with it the gjs and pygobject backends. Windows and Android have no libdex either, so the =DexFuture= loaders are not built there.

** Testing cross builds
:PROPERTIES:
:CUSTOM_ID: testing-cross-builds
:END:
*** The build system itself
:PROPERTIES:
:CUSTOM_ID: testing-build-system
:END:
=make test-build-system= checks the build system without compiling or starting a container, and =make test= runs the first part of it natively:

| Script | Checks |
|--------+--------|
| =tests/test-build-targets.sh= | target resolution for every spelling (=WINDOWS=1=, =LRG_TARGET==, legacy =CROSS==) and host (=LRG_HOST_TARGET=), build directories, dependency output paths and flags, profile defaults, refused requests, subdirectory makefiles agreeing with the root, goals that work without a toolchain |
| =tests/test-build-clean.sh= | what =clean=, a cross =clean=, =clean-targets= and =distclean= remove, in a scratch project |
| =tests/test-build-dispatch.sh= | the container command line, through a stub =CONTAINER_ENGINE= that records its arguments: one run for all goals, mounts, user namespace, =MAKEFLAGS= without the jobserver, values with spaces, image tags following the recipe, prebuilt images, extra arguments, per-target platforms, the worktree's git directory, prune, refused bypasses, and a throwaway parent project including the mk files (its mounts, extra mounts, environment by name, its host-safe goals, libregnum's image, the inner make building libregnum) |
| =tests/test-pipefail-pipes.sh= | no build-system script pipes into an early-exit reader (=grep -q=, =grep -m=, =head=, a =sed= that quits) under =pipefail=: the reader exits, the writer dies of SIGPIPE and the pipe fails at random; read the output whole instead (=[[ "$(cmd)" == *x* ]]=). Lines ending in =\|\| true= are allowed. Its detector is checked first on known good and bad lines |
| ShellCheck | every build-system script (=build-aux/cross=, =build-aux/containers=, =build-aux/android=, the tests) |
| =tests/test-native-unchanged.sh= | the native build's commands against a base ref (below) |

*** The native build did not change
:PROPERTIES:
:CUSTOM_ID: native-unchanged
:END:
=make test-native-unchanged [BASE=ref]= hard-links the tree, puts every file that differs from =BASE= (default: the merge-base with master) back to its base content, in the superproject and every submodule at the commit the base records, and diffs =make -Bn= for =all=, =tests all= and =examples= between the two trees. It needs a native =make all= first (graylib's raylib rule tests for the archive). A branch that adds source files changes those commands legitimately; =EXCLUDE_ADDED=1= (=--exclude-added=) removes every mention of an added file (its compile, its object, its test binary, its entries in link lists) and compares the distinct command lines, so any changed flag or path still shows. =make test-build-system= uses that form.

The same run also compares against a stored baseline, =tests/golden/native-make-n/=: =commands.log.xz= holds master's distinct native commands (the tree's path written as =@ROOT@=) and =host.txt= the machine that recorded them (architecture, OS release, =cc= version, a hash of the versions of every package the build asks =pkg-config= about, and the base commit). The commands embed =pkg-config= output and probe results, so they are only comparable on a matching host: there the stored file must match (files added since its base are left out, as with =EXCLUDE_ADDED=1=, and version numbers are masked, so a release does not invalidate it); anywhere else the run prints =SKIP: stored baseline recorded on another host= and the live comparison is the gate. =make update-native-golden [BASE=ref]= records it again from the base; review the result and commit both files.

#+begin_src sh
make update-native-golden BASE=master   # record master's commands for this host
make test-native-unchanged EXCLUDE_ADDED=1
#+end_src

*** Each target
:PROPERTIES:
:CUSTOM_ID: testing-targets
:END:
- *Images* end with a smoke test (=build-aux/containers/common/smoke.c=, GLib + json-glib at =-std=gnu89 -Werror=), run under Wine or qemu where the target can run, checked for AArch64 and 16 KB alignment on Android.
- =make WINDOWS=1 test= and =make ARM64=1 test= run the unit tests through the profile's =LRG_EXEC_WRAPPER=. A profile lists test paths the target cannot run (=LRG_TEST_SKIP_PATHS=, each with its reason in the profile) and known bugs (=LRG_TEST_KNOWN_FAILURES=); both are passed to every binary as GTest =-s PATH=, so the rest of the binary still runs, and every run ends by naming them, the known bugs in yellow. Windows also leaves out the suites whose test code is POSIX-only (=LRG_WINDOWS_UNPORTED_TESTS= in =tests/Makefile=). Emulated runs set =ulimit -c 0= so an aborting test leaves no qemu core file.
- Android: =make ANDROID=1 test-apk= and =make ANDROID=1 test-shaders= ([[file:platforms/android.org::#testing][Android, Testing]]); =make ANDROID=1 test-device APK_GAME=...= on the host runs the APK on a device or emulator ([[*On a device][On a device]]).
- =make <TARGET>=1 test-cross-artifacts= checks the binaries themselves, which the unit tests cannot see (=tests/test-cross-artifacts.sh=, in the target's container):

  | Target | Checks |
  |--------+--------|
  | linux-arm64 | every shared library, program and static-archive member (libregnum, graylib) is AArch64 |
  | windows-amd64 | =libregnum.dll=, =graylib.dll= and every =.exe= are PE32+ x86-64; =libregnum.dll= exports =lrg_*=, =graylib.dll= exports =grl_*= and raylib's functions; every DLL =libregnum.dll= imports is found next to it, in the MinGW runtime or among Windows' own DLLs (Wine's copies) |
  | android-arm64 | the static archive's members and every shared library are AArch64; every shared library's LOAD segments are 16 KB aligned |

- Do not run =make all test= in one invocation with =-j=: both goals build the library at the same time. Run =make all= then =make test=.

*** The whole gate per target
:PROPERTIES:
:CUSTOM_ID: test-cross
:END:
One goal per target runs everything above in order, each step its own make (so =all= and =test= never build the library at once). They run from the host; each step dispatches to the container as usual:

| Goal | Runs |
|------+------|
| =make test-cross-arm64= | =ARM64=1 all=, =test= (qemu), =examples=, =test-cross-artifacts= |
| =make test-cross-windows= | =WINDOWS=1 all=, =test= (Wine), =examples=, =test-cross-artifacts= |
| =make test-cross-android= | =ANDROID=1 all=, =test-cross-artifacts=, =test-shaders=, =test-apk= with =TEST_CROSS_APK_GAME= (default the clicker example), =test-mkapk= (=mkapk.sh= with the real build tools) |
| =make test-cross= | the three, one after another |

A full =make test-cross= takes a while (the arm64 unit tests under qemu alone run for most of an hour); run the one target a change touches.

*** On a device
:PROPERTIES:
:CUSTOM_ID: on-a-device
:END:
=make ANDROID=1 test-device APK_GAME=examples/game-chocolate-chip-clicker.c= runs on the host, where =adb= (Fedora: =android-tools=) sees the device (=ANDROID_SERIAL= picks one of several). =tests/test-apk-device.sh= installs the APK, starts its NativeActivity, waits (=--wait=, 8 s), then checks that the process is still alive, that logcat has no warning, error or fatal line from the app's GLib log domains (the platform layer sends GLib's log to logcat with the domain as tag) and that a screenshot is not one flat colour, and stops the app. With no =adb= or no device it prints why and passes, so it is safe in a script; the APK's structure is still checked without a device by =test-apk=.

Without a phone, =make ANDROID=1 test-emulator APK_GAME=...= builds the APK, boots a pinned Android 15 emulator in a container with =/dev/kvm= and runs the same test there, keeping the screenshot next to the APK ([[file:platforms/android.org::#emulator][Android, On an emulator]]).

*** Optional features, natively
:PROPERTIES:
:CUSTOM_ID: minimal-features
:END:
Android builds without libsoup and libpq (=SOUP=0 LIBPQ=0=), and so can any host that asks. =make test-minimal-features= keeps those stubs tested on the host: it builds the library with =MINIMAL_FEATURES=1= (every optional dependency off) into =build/minimal= and runs =test-optional-features= (each stub fails with its documented error: [[file:reference/error-codes.org::#features-built-out][Features built out]]), =test-analytics= and =test-mmo= against it. =MINIMAL_FEATURES= is native-only; a cross target's features come from its profile.

** Adding a new target
:PROPERTIES:
:CUSTOM_ID: adding-a-target
:END:
A worked example: =linux-riscv64=, built like =linux-arm64=.

1. *Profile.* Copy =build-aux/mk/targets/linux-arm64.mk= to =linux-riscv64.mk=. Keep the =# description:= line (=make targets= prints it). Set =LRG_TARGET_TRIPLE=, the toolchain (one-word =CC= etc.: write a wrapper in =build-aux/cross/= when flags are needed), =TARGET_PLATFORM=, =LRG_TOOLCHAIN_CHECK=, =LRG_DEP_FLAGS=/=LRG_GRAYLIB_FLAGS=, =LRG_EXEC_WRAPPER= (=qemu-riscv64-static -L ...=), =LRG_CONTAINER_PLATFORM=. =make targets= now lists it; =LRG_TARGET=linux-riscv64= works and builds into =build/release-riscv64=.
2. *Image.* Create =build-aux/containers/linux-riscv64/Containerfile= (copy one: it only copies the recipe and runs =setup.sh=) and =setup.sh=: source =common.sh=, =lrg_install_base=, install the toolchain, build or install the sysroot, end with =lrg_smoke=. Pin every download with a checksum. =make LRG_TARGET=linux-riscv64 container-image= builds it.
3. *Build.* =make -j16 LRG_TARGET=linux-riscv64= until it is warning-free. Fix portability problems in the code, guarded by =G_OS_*=, =__linux__=, =LRG_PLATFORM_*= or a feature macro, so the native commands stay identical (=make test-native-unchanged=).
4. *Tests.* Add the target to =tests/test-build-targets.sh= (directories, alias if any, defaults) and =tests/test-build-dispatch.sh= (its image and platform); run =make LRG_TARGET=linux-riscv64 test=; list environment limits in =LRG_TEST_SKIP_PATHS= with reasons and real bugs in =LRG_TEST_KNOWN_FAILURES=.
5. *Docs.* A =docs/platforms/<target>.org= page (toolchain, output, differences, testing, shipping), a row in the tables of this page, =docs/building.org= and =README.org=, a =CHANGELOG.org= entry.

** Troubleshooting
:PROPERTIES:
:CUSTOM_ID: troubleshooting
:END:
*** "The <target> toolchain is not installed"
:PROPERTIES:
:CUSTOM_ID: toolchain-not-installed
:END:
The target's =PKG_CONFIG= is not on =PATH=. Install the target's packages, or point the build at your own with =PKG_CONFIG=, =CC=, =AR= and =RANLIB= on the command line. =make <switch> print-target= shows what the build is looking for.

*** "Conflicting targets requested"
:PROPERTIES:
:CUSTOM_ID: conflicting-targets
:END:
Two switches named different targets (=WINDOWS=1 ARM64=1=), or =LRG_TARGET= disagrees with a switch. Give exactly one.

*** "SANITIZE=1 is native-only"
:PROPERTIES:
:CUSTOM_ID: sanitize-native-only
:END:
ASan and UBSan builds run on the host (=build/sanitize=). Sanitize the native build; cross targets are tested with their own runners.

*** Steam API not found
:PROPERTIES:
:CUSTOM_ID: steam-api-not-found
:END:
Initialise the Steamworks SDK submodule: =git submodule update --init deps/steamworks_sdk=.

*** The image build fails
:PROPERTIES:
:CUSTOM_ID: image-build-fails
:END:
The recipe's output is in the =make <switch> container-image= log; every step logs a ===>= line, and a failed download or checksum names the URL. Nothing is tagged until the smoke test passes, so the next build retries. A Fedora mirror returning 404 for metadata is retried by dnf on its own.

*** Permission denied, or files owned by another user
:PROPERTIES:
:CUSTOM_ID: container-permissions
:END:
The container runs with =--userns=keep-id= (files it writes are yours) and =--security-opt label=disable= (no SELinux relabelling of the checkout). Run as root (=id -u= is 0, e.g. a CI job running podman inside a privileged container) it leaves =keep-id= out: there is no user to map, and with it podman must copy every image layer with remapped owners, which nested container storage refuses ("creating an ID-mapped copy of layer ...: lchown ...: invalid argument", exit 125). =LRG_CONTAINER_UID= overrides the detected uid and =LRG_CONTAINER_USERNS= the flag itself. An engine other than podman needs equivalents in =BUILD_CONTAINER_ARGS=. Wine needs its prefix in a directory you own, hence =build/<type>-windows-amd64/wine=.

*** A recipe change is not picked up
:PROPERTIES:
:CUSTOM_ID: stale-image
:END:
The tag is a hash of =build-aux/containers/common/=, =build-aux/containers/<target>/=, =build-aux/cross/=, the base image and the platform; =make <switch> print-container= shows it. A change anywhere else (for example a file a =setup.sh= downloads whose URL did not change) needs a recipe edit, such as a version bump in =versions.sh=. =BUILD_CONTAINER_IMAGE= bypasses all of this.

*** "unknown warning option" from clang
:PROPERTIES:
:CUSTOM_ID: unknown-warning-option
:END:
Only on Android, and only if the profile's =LRG_CC_IS_GCC := 0= is missing: then =WARN_CFLAGS= is not probed against the NDK's clang. =make ANDROID=1 print-target= shows the warning flags that were dropped.

*** Undefined symbols when running make all test
:PROPERTIES:
:CUSTOM_ID: all-test-race
:END:
=make -j all test= builds the library twice at the same time (both goals recurse into it). Run =make all=, then =make test=. This is true natively as well.

*** A cross build from tests/ or with -f Makefile is refused
:PROPERTIES:
:CUSTOM_ID: bypass-refused
:END:
Cross builds start from the top-level directory, where =GNUmakefile= decides about the container. Run =make WINDOWS=1 test= there, or add =NO_BUILD_CONTAINER=1= to build on the host on purpose.
