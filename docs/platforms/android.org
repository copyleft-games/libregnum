* Android
:PROPERTIES:
:CUSTOM_ID: android
:END:
#+begin_quote
*[[file:../index.org][Home]]* > Platforms > Android
#+end_quote

libregnum builds for Android on arm64-v8a, API 29 (Android 10) and newer, and packages a game as an APK with no Java or Kotlin code: a =NativeActivity= that loads the game as one shared library. Everything runs in the =android-arm64= build container; the host needs podman, plus =adb= (Fedora: =android-tools=) to install on a device.

#+begin_src sh
make -j16 ANDROID=1                                     # libraries: build/release-android-arm64/lib
make -j16 ANDROID=1 apk APK_GAME=examples/game-chocolate-chip-clicker.c
make ANDROID=1 apk-install apk-run APK_GAME=examples/game-chocolate-chip-clicker.c
adb logcat -s libregnum Libregnum-Core Libregnum-I18N   # the game's GLib logs
#+end_src

** How it fits together
:PROPERTIES:
:CUSTOM_ID: how-it-fits
:END:
#+begin_example
Android            loads lib/arm64-v8a/libmain.so from the APK (no extraction)
  ANativeActivity_onCreate      (NDK native_app_glue, inside raylib)
    android_main(app)           (raylib's rcore_android.c)
      main(argc, argv)          the game's main(), unchanged
        lrg_platform_prepare()  data dirs, assets, logcat (see below)
        ... the game, as on the desktop ...
#+end_example

raylib's =PLATFORM_ANDROID= owns the activity: it creates the EGL context for GLES 3, turns touches into mouse and touch input, handles pause/resume and calls the game's =main()= on its own thread. A game that compiles for the desktop compiles for Android unchanged; what differs is below.

** The toolchain
:PROPERTIES:
:CUSTOM_ID: toolchain
:END:
The image (=build-aux/containers/android-arm64/=, pins in =versions.sh=) holds:

| Path                     | What                                                                 |
|--------------------------+----------------------------------------------------------------------|
| =/opt/android/ndk=       | Android NDK r30: clang, the bionic sysroot, =llvm-ar=, =llvm-readelf= |
| =/opt/android/sdk=       | build-tools 37.0.0 (=aapt2=, =zipalign=, =apksigner=), =platforms/android-36= |
| =/opt/android/arm64-v8a= | the GLib stack, cross-built static: GLib 2.90 (with libffi, pcre2, proxy-libintl), json-glib, libyaml, fribidi, sqlite, OpenSSL 4.0; and LuaJIT 2.1 (pkg-config =luajit=), bzip2 1.0.8 (=bzip2=, a Fedora-style =.pc= written by the image) and libjpeg-turbo 3.1 (=libjpeg=) |
| =/opt/android/versions.env= | the paths above, for scripts                                     |

Every download is pinned to a version and checked: SDK archives against the SHA-1 in Google's repository manifest (what sdkmanager checks), sources against SHA-256 sums. Changing a pin changes the image's tag, so the next build makes a new image. The image ends with smoke tests: a GLib + json-glib program linked against the static stack, checked to be AArch64 with every LOAD segment 16 KB aligned; and =smoke-extras.c=, which calls LuaJIT, bzip2 and libjpeg (=luaL_newstate()=, =BZ2_bzlibVersion()=, =jpeg_std_error()=) and is linked through their =.pc= files both as a program and as a shared object like =libmain.so=, so an archive that is missing, wrongly described or not position-independent fails the image build. LuaJIT, bzip2 and libjpeg-turbo are built unmodified with their own build systems (LuaJIT's Makefile cross from x86_64 with 64-bit host tools, bzip2's Makefile for =libbz2.a= only, libjpeg-turbo's CMake with the NDK toolchain file); each archive is compiled with =-fPIC=. With LuaJIT in the sysroot, =config.mk='s pkg-config probe turns Lua scripting on for Android (=LRG_HAS_LUAJIT=: =LrgScriptingLua=, =LrgScriptTaskLua=); bzip2 and libjpeg are there for games that read those formats themselves.

** Compiler
:PROPERTIES:
:CUSTOM_ID: compiler
:END:
The NDK has only clang, so Android is the one target not built with gcc. The code is still gnu89 and the same warning list applies, with every warning an error:

- Flags this clang does not know are dropped after a probe (=make ANDROID=1 print-target= lists them; with NDK r30 none are).
- One gcc/clang dialect gap is accepted: =-Wno-typedef-redefinition=. libregnum and graylib forward-declare types (=typedef struct _LrgWidget LrgWidget;=) and =G_DECLARE_*_TYPE= declares them again. An identical typedef redefinition is valid GNU C in gnu89 (gcc never warns) and valid C11; clang calls it a C11 extension. It is not a bug, so clang is told to accept what gcc accepts (decided 2026-11-24). Set in the profile (=LRG_DIALECT_WARN_CFLAGS=) and graylib's Android flags.
- Everything else clang reported when Android was first built was fixed in the code (see the 0.12.0 changelog): printf attributes, dead helpers, a misleading indentation, the =volatile= =g_once_init_*= pattern, a long/double range bug.

The NDK headers define a few plain =inline= helpers that call APIs newer than API 29. Under gnu89 such a helper is emitted in every file that includes it, so =src/core/lrg-platform.c= (the only file that includes them) defines =__ANDROID_UNAVAILABLE_SYMBOLS_ARE_WEAK__= first: the NDK's own switch that makes newer-API references weak.

** Graphics: OpenGL ES 3
:PROPERTIES:
:CUSTOM_ID: graphics
:END:
raylib runs on OpenGL ES 3 (=GRAPHICS_API_OPENGL_ES3=); the APK requires GLES 3.2, which every arm64 device with API 29 has.

- *Shaders.* Every built-in shader starts with =LRG_GLSL_HEADER= (=src/graphics/lrg-glsl-private.h=) instead of a literal =#version=: =#version 330= on the desktop, =#version 300 es= with default precisions on Android. The shaders are written in the common subset of GLSL 3.30 and GLSL ES 3.00; the rules are in [[file:../guides/rendering-pipeline.org::#es-compatibility][Rendering pipeline, ES compatibility]]. =make ANDROID=1 test-shaders= compiles all of them both ways with glslang.
- *Terrain* uses its per-mesh path on GLES (the shared-page path needs desktop GL 3.3 base-vertex draws); it chooses at run time.
- *Clipboard images* are not available (graylib returns =NULL=); text clipboard works.
- *Input events with modifiers* (graylib's GLFW callback chain) are not hooked; input is polled, as raylib does on Android.

** Files, data and logs: lrg_platform_prepare()
:PROPERTIES:
:CUSTOM_ID: platform-prepare
:END:
An Android app has a private directory in internal storage, its files sit compressed in the APK, and stderr goes nowhere. =lrg_platform_prepare()= (=src/core/lrg-platform.h=) makes that look like a desktop before the game runs; it does nothing on other platforms.

1. *Logging first.* GLib's log writer sends every message to logcat, the log domain as the tag and the level mapped to a priority (error → fatal, critical → error, warning → warn, message and info → info, debug → debug). =adb logcat -s Libregnum-Core= shows one domain.
2. *Data directories.* =lrg_platform_set_data_root()= points =HOME= at the internal storage path and =XDG_DATA_HOME=, =XDG_CONFIG_HOME=, =XDG_CACHE_HOME=, =TMPDIR= at =data=, =config=, =cache=, =tmp= below it, creating them. Saves, settings and anything else that asks GLib for those directories lands there.
3. *Assets.* =lrg_platform_extract_assets()= copies the APK's =assets/= into =<internal>/assets= and the process changes into that directory, so a game's relative paths (=data/levels/one.yaml=) open as on the desktop. The NDK cannot list subdirectories of APK assets, so the packager writes =assets/lrg-assets.list=: a stamp line (=# lrg-assets <hash>=, a hash of every path and file) and the file list. Extraction:
   - does nothing when =<internal>/assets/.lrg-assets-stamp= already holds the stamp (every launch after the first, until the APK changes),
   - otherwise writes into =assets.new=, then swaps it in place of =assets= and deletes the old copy, so an interrupted extraction never leaves two versions mixed and files a new version dropped disappear,
   - refuses a manifest with an absolute path, an empty, =.= or =..= component or a backslash before writing anything.

   Reading straight from the APK still works: raylib's Android layer wraps =fopen()= (=-Wl,--wrap=fopen=) to look in the APK's assets first, so =LoadTexture("data/x.png")= finds the file with or without extraction. Extraction is what makes GLib file APIs (=g_file_get_contents()= and the rest, used throughout libregnum) see the same files. Extracting costs storage once per version; a future =LrgVfs= source reading APK assets directly would avoid that.

Who calls it:

| Game                                  | Call                                                               |
|---------------------------------------+--------------------------------------------------------------------|
| uses =LRG_DEFINE_GAME_MODULE()=       | automatic: the generated =main()= calls it first                   |
| calls =lrg_game_run_standalone()=     | automatic (and again harmlessly)                                    |
| its own =main()=                      | call =lrg_platform_prepare()= first, as =examples/game-chocolate-chip-clicker.c= does |
| any game                              | =lrg_engine_startup()= calls it as a safety net                    |

Only the first call does the work; a failure is reported to every caller.

** The APK
:PROPERTIES:
:CUSTOM_ID: the-apk
:END:
=make ANDROID=1 apk APK_GAME=<game.c>= builds the libraries, then:

1. *libmain.so.* The game's source compiled like an example and linked with the static =liblibregnum.a= (graylib and raylib with its NativeActivity glue inside) and the static GLib stack into one shared object, with =-Wl,--no-undefined= (every symbol resolved at build time, not on a phone), =-u ANativeActivity_onCreate= (keep the entry point), =-Wl,--wrap=fopen= (raylib's APK asset reader) and 16 KB page alignment. It needs only Android's own libraries (=libc=, =libm=, =libdl=, =liblog=, =libandroid=, =libEGL=, =libGLESv3=, =libz=).
2. *build-aux/android/mkapk.sh* packages it: stages =APK_ASSETS= and writes =lrg-assets.list=, fills =build-aux/android/AndroidManifest.xml.in=, links the base APK with =aapt2=, adds =lib/arm64-v8a/libmain.so= /stored/ (=android:extractNativeLibs="false"= maps it from the APK), aligns with =zipalign -P 16= (uncompressed libraries on 16 KB boundaries for Android 15+), and signs with =apksigner=.

Output: =build/release-android-arm64/apk/<name>.apk= (=build/debug-android-arm64/...= with =DEBUG=1=).

| Variable           | Default                                 | Meaning                                     |
|--------------------+-----------------------------------------+---------------------------------------------|
| =APK_GAME=         | (required)                              | the game's source file                      |
| =APK_NAME=         | its basename                            | APK and directory name                      |
| =APK_ASSETS=       | none                                    | directories packed as =assets/= (merged; one path in two of them is an error) |
| =APK_FORBID_GLOBS= | none                                    | globs no asset path may match (=*.MPQ secret/*=); the build fails naming each match |
| =APK_KEYSTORE=     | none (debug key)                        | release keystore ([[#signing-release][Signing a release]])  |
| =APK_KEY_ALIAS=    | none                                    | the key's alias in =APK_KEYSTORE=           |
| =APK_PACKAGE=      | =org.libregnum.<name>= (=-= → =_=)       | application id                              |
| =APK_LABEL=        | =APK_NAME=                              | launcher label                              |
| =APK_VERSION_CODE= | 1                                       | integer version (raise it for each release)  |
| =APK_VERSION_NAME= | libregnum's version                     | version string                              |
| =APK_ORIENTATION=  | =landscape=                             | =landscape=, =portrait=, =sensor=, ...      |

*** Signing
:PROPERTIES:
:CUSTOM_ID: signing
:END:
Without =--keystore=, =mkapk.sh= signs with a debug key it creates on first use (=build/<type>-android-arm64/apk/debug.keystore=, password =android=); keep that file, or every rebuild has a new key and =adb install -r= refuses the update. A release is signed with your own key ([[#signing-release][Signing a release]]). Never commit a keystore.

*** Signing a release
:PROPERTIES:
:CUSTOM_ID: signing-release
:END:
Android accepts an update only when it is signed with the same key as the installed app, for the app's whole life: make the key once, back it up outside the checkout, never commit it.

#+begin_src sh
# once, on the host (keytool from a JDK; Fedora: java-21-openjdk-headless):
# PKCS12, RSA 4096, valid 10000 days; keytool asks for the password and the
# certificate's name (or KEYSTORE_DNAME='CN=...,O=...'); refuses to overwrite
make keystore                       # ~/.local/share/libregnum-android/release.jks, alias "release"
make keystore KEYSTORE_OUT=~/keys/game.jks KEYSTORE_ALIAS=game

# every release build: the passwords come from the environment, by name
read -rs APK_KEYSTORE_PASSWORD && export APK_KEYSTORE_PASSWORD
make ANDROID=1 apk APK_GAME=game.c APK_VERSION_CODE=7 \
    APK_KEYSTORE=~/.local/share/libregnum-android/release.jks APK_KEY_ALIAS=release
#+end_src

How the passwords travel: =APK_KEYSTORE_PASSWORD= (and =APK_KEY_PASSWORD=, needed only when the key's password differs; a PKCS12 keystore made by =make keystore= has one password) are environment variables. The container run forwards them as =-e APK_KEYSTORE_PASSWORD= (the name only; podman copies the value), mounts =APK_KEYSTORE= read-only at its own path, and =mkapk.sh= passes =--ks-pass env:APK_KEYSTORE_PASSWORD= to =apksigner=, which reads the variable itself. No command line (=ps=, the make log, the shell history) holds a password, so never put one on make's command line (=APK_KEYSTORE_PASSWORD=x make ...= in the environment is fine; =make ... APK_KEYSTORE_PASSWORD=x= is not: it would land in =MAKEFLAGS= and the container's argv).

=mkapk.sh= directly:

| Option               | Meaning                                                                            |
|----------------------+------------------------------------------------------------------------------------|
| =--keystore FILE=    | the keystore; with =--ks-pass-env= it must exist (a release key is never created) |
| =--ks-key-alias A=   | the key's alias (needed when the keystore holds several keys)                      |
| =--ks-pass-env VAR=  | keystore password from =VAR= (=apksigner --ks-pass env:VAR=)                       |
| =--key-pass-env VAR= | key password from =VAR= (default: the keystore's variable)                         |
| =--ks-pass PASS=     | kept for compatibility and the debug key; on the command line, so not for a release |

=apksigner verify --print-certs <apk>= (in =make ANDROID=1 container-shell=) shows the certificate an APK carries.

*** Forbidden files
:PROPERTIES:
:CUSTOM_ID: forbidden-files
:END:
=APK_FORBID_GLOBS= (=mkapk.sh --forbid GLOB=, repeatable) names files that must never ship, such as a game's licensed data the player provides at run time or key material; each glob is matched against every staged path relative to =assets/= (=*= also matches =/=, so =*.MPQ= matches at any depth). Any match fails the build and lists every offending path. Several =APK_ASSETS= roots are merged; the same path in two roots is an error naming both, never a silent override.

*** Another project's APK
:PROPERTIES:
:CUSTOM_ID: consumer-apk
:END:
A project that embeds libregnum builds for =android-arm64= in libregnum's build container through its own =GNUmakefile= (see [[file:../cross-compile.org::#consumers][Consuming the cross builds from another project]]); inside it, its =Makefile= builds libregnum with =$(MAKE) -C deps/libregnum lib=, links its own =libmain.so= and packages it. The profile exports what that needs:

| Variable             | Value                                                                                               |
|----------------------+-----------------------------------------------------------------------------------------------------|
| =LRG_APK_LDFLAGS=    | =-shared -Wl,--no-undefined -Wl,-z,max-page-size=16384 -u ANativeActivity_onCreate -Wl,--wrap=fopen= |
| =LRG_MKAPK=          | =$(LRG_ROOT)/build-aux/android/mkapk.sh= (=--help= lists every option)                              |
| =LRG_PLATFORM_LIBS=  | =-lEGL -lGLESv3 -landroid -llog -lm -ldl=                                                           |
| =LRG_TARGET_CFLAGS=  | the NativeActivity glue's include directory                                                         |
| =CC=, =ANDROID_MIN_API= | the NDK's clang for API 29                                                                       |

#+begin_src makefile
# in the parent's Makefile, inside the container (LRG_TARGET_OS = android)
GAME_APK_LIB := build/android/libmain.so

game-apk: libregnum $(GAME_OBJS)
	$(CC) $(LRG_APK_LDFLAGS) -o $(GAME_APK_LIB) $(GAME_OBJS) \
		deps/libregnum/build/release-android-arm64/lib/liblibregnum.a \
		$(GAME_DEP_LIBS) $(LRG_PLATFORM_LIBS)
	bash $(LRG_MKAPK) --lib $(GAME_APK_LIB) \
		--out build/android/game.apk --package org.example.game --label Game \
		--assets data --assets build/android/generated --forbid '*.MPQ' \
		$(if $(APK_KEYSTORE),--keystore $(APK_KEYSTORE) --ks-pass-env APK_KEYSTORE_PASSWORD) \
		$(if $(APK_KEY_ALIAS),--ks-key-alias $(APK_KEY_ALIAS)) \
		--min-sdk $(ANDROID_MIN_API)
#+end_src

=$(GAME_DEP_LIBS)= is the static GLib stack the game needs (=$(PKG_CONFIG) --libs --static ...= with the profile's =PKG_CONFIG=). For the release key, set =APK_KEYSTORE= in the parent's =GNUmakefile= before including =container.mk= (or add the keystore to =LRG_CONTAINER_RO_MOUNTS= and the password names to =LRG_CONTAINER_ENV=): =container.mk= then mounts it and forwards the password variables, as for libregnum's own =apk=.

*** Manifest
:PROPERTIES:
:CUSTOM_ID: manifest
:END:
=hasCode="false"= (no Java), =android.app.NativeActivity= as the launcher with =android.app.lib_name= = =main=, GLES 3.2 required, =appCategory="game"=, fullscreen, configuration changes handled by the activity (raylib reacts to them) instead of restarting it. =minSdkVersion= 29, =targetSdkVersion= the platform's API (36).

** Running on a device
:PROPERTIES:
:CUSTOM_ID: running
:END:
=apk-install= and =apk-run= run on the host, not in the container: they need =adb= (Fedora: =android-tools=) and a device with USB debugging on (=adb devices= lists it).

#+begin_src sh
make ANDROID=1 apk-install APK_GAME=examples/game-chocolate-chip-clicker.c  # adb install -r
make ANDROID=1 apk-run APK_GAME=examples/game-chocolate-chip-clicker.c      # am start NativeActivity
adb logcat -s libregnum Libregnum-Core
#+end_src

*** Pushing data to the device
:PROPERTIES:
:CUSTOM_ID: apk-push
:END:
Data too large for the APK, or that must not ship in it (=APK_FORBID_GLOBS=), goes to the app's external files directory, =/sdcard/Android/data/<package>/files/= (what =getExternalFilesDir()= returns; the app reads and writes it without any permission, and it is removed with the app). =apk-push= runs on the host with =adb=:

#+begin_src sh
make ANDROID=1 apk-push APK_GAME=game.c PUSH_FILES='~/games/data/Data' PUSH_DEST=client
# adb shell mkdir -p /sdcard/Android/data/org.libregnum.game/files/client
# adb push ~/games/data/Data /sdcard/Android/data/org.libregnum.game/files/client/
make apk-push APK_PACKAGE=org.example.game PUSH_FILES='a.cfg b.cfg'   # a parent's package
#+end_src

=PUSH_FILES= is one or more files or directories (=adb push= copies directories recursively); =PUSH_DEST= is a directory below =files/= (empty: =files/= itself). The package is =APK_PACKAGE= (derived from =APK_GAME= unless set).

** Testing
:PROPERTIES:
:CUSTOM_ID: testing
:END:
| Goal                          | Where         | Checks                                                              |
|-------------------------------+---------------+---------------------------------------------------------------------|
| =make ANDROID=1 test-apk=     | container     | =tests/test-apk-layout.sh=: signature, manifest (package, minSdk, NativeActivity, no code, libraries not extracted, GLES 3.2), =libmain.so= stored, 16 KB aligned in the zip and in its LOAD segments, AArch64, =ANativeActivity_onCreate= exported, only system libraries needed, every listed asset present (and equal to =APK_ASSETS=) |
| =make test-mkapk= / =make ANDROID=1 test-mkapk= | host / container | =tests/test-mkapk.sh=: merged asset roots, a duplicate path and a forbidden file fail, a release key's password reaches =apksigner= as =env:VAR= and is in no argv (stub build tools, any host); in the container also a real PKCS12 release key with an alias, verified by =apksigner= |
| =make ANDROID=1 test-shaders= | container     | every built-in shader compiles as GLSL ES 3.00 (and GLSL 3.30)      |
| =make test= (native)          | host          | =tests/test-platform.c=: data root, extraction (first run, same stamp, new stamp, interrupted run, unsafe paths, bad and missing manifests), the logcat priority mapping |
| =make ANDROID=1 test-device APK_GAME=...= | host, adb | =tests/test-apk-device.sh= on a phone or emulator adb sees: installs, starts, still running, no GLib warning in logcat, screenshot not blank |
| =make ANDROID=1 test-emulator APK_GAME=...= | host, container with =/dev/kvm= | the same test on an Android 15 emulator it boots itself ([[#emulator][On an emulator]]) |

The unit tests themselves do not run on Android: there is nothing in the build container to run arm64 Android binaries. The game itself runs on a device or the emulator.

*** On an emulator
:PROPERTIES:
:CUSTOM_ID: emulator
:END:
=make ANDROID=1 test-emulator APK_GAME=examples/game-chocolate-chip-clicker.c= needs nothing on the host but podman, =curl=, =sha1sum= and a =/dev/kvm= you can open (the =kvm= group). It:

1. builds the APK (=make ANDROID=1 apk=, in the build container);
2. downloads the emulator, =platform-tools= (=adb=) and the =system-images;android-35;google_apis;x86_64= image pinned in =build-aux/android/emulator/versions.sh= into =EMULATOR_CACHE= (default =build/android-emulator=), checking each archive's SHA-1, and unpacks them once;
3. builds =localhost/libregnum-android-emulator:<hash>= from =build-aux/android/emulator/Containerfile= (Fedora with the X and GL libraries the emulator loads; the tag is a hash of that directory and =BUILD_CONTAINER_BASE=);
4. runs =build-aux/android/emulator/run-emulator.sh= in it with =--device /dev/kvm=: a fresh AVD, a headless boot (about 20 s), then =tests/test-apk-device.sh= with a 15 s wait;
5. leaves the screenshot next to the APK, =build/release-android-arm64/apk/<game>-emulator.png=, and the emulator's log in =EMULATOR_CACHE/work/emulator.log=.

The image is x86_64 so KVM runs it at native speed; Google API images from Android 11 on run =arm64-v8a= apps through a translation layer, so the APK is the one a phone gets. Rendering is =-gpu guest= (SwiftShader inside Android, GLES 3): the host-side renderers need a GPU stack the container does not have, and emulator 37 crashes with =swiftshader_indirect= there. On an aarch64 host, pin the =arm64-v8a= system image of the same release in =versions.sh=.

#+begin_src sh
make ANDROID=1 test-emulator APK_GAME=examples/game-chocolate-chip-clicker.c
make ANDROID=1 test-emulator APK_GAME=... EMULATOR_CACHE=~/.cache/lrg-emulator   # share the 2 GB of downloads between checkouts
build-aux/android/emulator-test.sh --help
#+end_src

** Licensing
:PROPERTIES:
:CUSTOM_ID: licensing
:END:
The NDK, build-tools and platform archives are Google's, distributed under the Android Software Development Kit License Agreement, which is not a free software licence; using them means accepting it. Nothing from them ends up in libregnum's sources; the APK contains only the game, libregnum, its free dependencies and Android's system libraries by reference. They are pinned and confined to the build container (=versions.sh=). The emulator, =platform-tools= and system image that =test-emulator= uses are under the same agreement; they are downloaded only when that goal runs, into its cache, and never enter a build image. Fedora packages no usable free replacement (=android-tools= has =adb= only).

** Troubleshooting
:PROPERTIES:
:CUSTOM_ID: troubleshooting
:END:
*** Black screen, then the app closes
:PROPERTIES:
:CUSTOM_ID: black-screen
:END:
Look at =adb logcat=: GLib's messages are there under their domains. A game whose =main()= returns ends the activity. =lrg_platform_prepare()= failing (no storage, a bad asset manifest) is logged, and the game should exit when it fails.

*** A file is not found on the device
:PROPERTIES:
:CUSTOM_ID: file-not-found
:END:
Only files under =APK_ASSETS= are in the APK, and paths are relative to it: =APK_ASSETS=data= puts =data/x.png= at =x.png=; pass the parent (=APK_ASSETS=.=, or a staging directory) to keep the =data/= prefix. =unzip -l <apk> 'assets/*'= shows what is inside.

*** INSTALL_FAILED_UPDATE_INCOMPATIBLE
